## 1. Introduction to Path Planning

Path planning is a fundamental aspect of mobile robotics, enabling robots to navigate from a starting point to a goal point in an environment while avoiding obstacles. This module focuses on one of the most widely used and effective algorithms for this task: the **A* (A-star) algorithm**.

**Relevance to Course Outcomes:**
*   **CO5: Perform navigation and path planning mobile robots (Knowledge Level: K3)** - A* directly addresses this outcome by providing a method for path planning.
*   **CO6: Control the mobile robots to follow different paths (Knowledge Level: K3)** - Once a path is planned by A*, control algorithms are needed to execute it.

**Key Concepts:**
*   **Environment:** The space in which the robot operates, often represented as a grid, graph, or continuous space.
*   **Obstacles:** Regions in the environment that the robot must avoid.
*   **Start State:** The initial position of the robot.
*   **Goal State:** The desired final position of the robot.
*   **Path:** A sequence of states or configurations that the robot can follow to move from the start to the goal.
*   **Cost:** A measure of the "badness" or "difficulty" of a path, often related to distance, time, or energy consumption.

## 2. The A* Search Algorithm

A* is an informed search algorithm, meaning it uses a heuristic function to guide its search towards the goal. It's an extension of Dijkstra's algorithm, which finds the shortest path in a graph. A* achieves better performance by prioritizing nodes that are likely to lead to the goal.

**Core Idea:** A* aims to find a path with the minimum cost from a start node to a goal node in a graph. It does this by evaluating nodes based on the sum of two costs:
1.  **g(n):** The actual cost to reach node `n` from the start node.
2.  **h(n):** An **estimated** cost (heuristic) from node `n` to the goal node.

The evaluation function `f(n)` is defined as:
$$f(n) = g(n) + h(n)$$

**Key Concepts:**
*   **Nodes:** Points or configurations in the search space (e.g., grid cells, waypoints).
*   **Edges:** Transitions between nodes, representing possible robot movements.
*   **Cost Function (g(n)):** The cumulative cost incurred to reach a particular node from the start.
*   **Heuristic Function (h(n)):** An estimate of the cost from the current node to the goal.
*   **Evaluation Function (f(n)):** The sum of the actual cost and the estimated cost.
*   **Open Set:** A set of nodes that have been discovered but not yet evaluated.
*   **Closed Set:** A set of nodes that have already been evaluated.
*   **Admissible Heuristic:** A heuristic that never overestimates the actual cost to reach the goal. This is crucial for A* to guarantee finding the optimal path.
*   **Consistent Heuristic (Monotonic):** A heuristic `h(n)` is consistent if for every node `n` and every successor `n'` of `n` generated by any action `a`, the estimated cost of reaching the goal from `n` is no greater than the cost of stepping from `n` to `n'` plus the estimated cost of reaching the goal from `n'`:
    $$h(n) \le cost(n, a, n') + h(n')$$
    If a heuristic is consistent, it is also admissible. Consistency ensures that when a node is expanded, the `g` value found for it is the optimal `g` value.

**Textbook Reference:**
*   Corke (2011) - Chapter 10: Path Planning
*   La Valle (2009) - Chapter 4: Informed Search

## 3. A* Algorithm Steps (Pseudocode)

The A* algorithm works by iteratively expanding nodes that have the lowest `f(n)` value.

**Algorithm:**

1.  **Initialization:**
    *   Create an `openSet` containing the start node.
    *   Create a `closedSet` that is initially empty.
    *   Initialize `gScore` for the start node to 0 and for all other nodes to infinity.
    *   Initialize `fScore` for the start node to `h(start)` and for all other nodes to infinity.
    *   Store the path: `cameFrom` map to reconstruct the path.

2.  **Main Loop:**
    *   While `openSet` is not empty:
        *   Select the node `current` in `openSet` with the lowest `fScore`.
        *   If `current` is the goal node, reconstruct the path using `cameFrom` and return it.
        *   Move `current` from `openSet` to `closedSet`.
        *   For each `neighbor` of `current`:
            *   If `neighbor` is in `closedSet`, skip it.
            *   Calculate the tentative `gScore` for `neighbor`: `tentative_gScore = gScore[current] + distance(current, neighbor)`.
            *   If `neighbor` is not in `openSet` OR `tentative_gScore < gScore[neighbor]`:
                *   Update `cameFrom[neighbor] = current`.
                *   Update `gScore[neighbor] = tentative_gScore`.
                *   Update `fScore[neighbor] = gScore[neighbor] + h(neighbor)`.
                *   If `neighbor` is not in `openSet`, add it to `openSet`.

3.  **Failure:** If the `openSet` becomes empty and the goal was not reached, it means no path exists.

**Important Point to Remember:** The choice of heuristic function significantly impacts A*'s performance. A good heuristic is admissible and close to the actual cost.

## 4. Heuristic Functions for A*

The effectiveness and optimality of A* depend heavily on the choice of the heuristic function `h(n)`.

**Common Heuristics:**

*   **Manhattan Distance:** For grid-based environments where movement is restricted to horizontal and vertical steps.
    *   Formula: $$h(n) = |x_n - x_{goal}| + |y_n - y_{goal}|$$
    *   **Admissibility:** Yes, as it represents the shortest path if there were no obstacles.
    *   **Consistency:** Yes.

*   **Euclidean Distance:** For continuous or diagonal movement in grid-based environments.
    *   Formula: $$h(n) = \sqrt{(x_n - x_{goal})^2 + (y_n - y_{goal})^2}$$
    *   **Admissibility:** Yes.
    *   **Consistency:** Yes.

*   **Diagonal Distance (Chebyshev Distance):** For grid-based environments where diagonal movement has the same cost as horizontal/vertical movement (cost of 1).
    *   Formula: $$h(n) = \max(|x_n - x_{goal}|, |y_n - y_{goal}|)$$
    *   **Admissibility:** Yes, if diagonal moves have cost 1.

*   **Octile Distance:** For grid-based environments where diagonal movement has a higher cost (e.g., $\sqrt{2}$).
    *   Formula: Let `dx = |x_n - x_{goal}|`, `dy = |y_n - y_{goal}|`.
    *   $$h(n) = (\max(dx, dy) - \min(dx, dy)) + \sqrt{2} \times \min(dx, dy)$$
    *   **Admissibility:** Yes, if diagonal moves have cost $\sqrt{2}$.

**Textbook Reference:**
*   Siegwart, Nourbakhsh, & Scaramuzza (2011) - Section 7.2: Path Planning Algorithms
*   La Valle (2009) - Section 4.2.3: Heuristics

## 5. A* in Mobile Robotics Applications

A* is widely used in mobile robotics for various tasks, often with adaptations for the specific application.

**Applications:**

*   **Grid-Based Navigation:**
    *   The robot's environment is discretized into a grid. Each grid cell is a node.
    *   Edges connect adjacent cells, representing possible movements (up, down, left, right, or diagonals).
    *   Obstacles are marked as impassable cells.
    *   **Example:** A robot navigating a warehouse floor represented by a grid.

*   **Graph-Based Navigation:**
    *   The environment is represented as a graph where nodes are waypoints or configurations, and edges represent feasible paths between them.
    *   **Example:** A robot navigating a campus using a pre-defined road network graph.

*   **Continuous Space Planning:**
    *   While A* is fundamentally a discrete search algorithm, it can be applied to continuous spaces using techniques like:
        *   **Discretization:** Converting the continuous space into a grid or graph.
        *   **Sampling-Based Methods:** Combining A* with algorithms like Probabilistic Roadmaps (PRM) or Rapidly-exploring Random Trees (RRTs).

**Considerations for Mobile Robots:**

*   **Robot Kinematics and Dynamics:** The planned path must be kinematically and dynamically feasible for the robot. A* itself typically plans in a state space, and then kinematic constraints are applied during path following.
*   **Computational Cost:** For large environments, A* can be computationally intensive. Techniques like hierarchical path planning or using more efficient data structures can mitigate this.
*   **Dynamic Environments:** A* is primarily for static environments. For dynamic environments with moving obstacles, replanning or adaptive path planning algorithms are needed.
*   **Map Representation:** The accuracy and resolution of the robot's map of the environment directly affect the performance of A*.

**Textbook Reference:**
*   Siegwart, Nourbakhsh, & Scaramuzza (2011) - Chapter 7: Motion Planning
*   Thrun, Burgard, & Fox (2005) - Chapter 10: Path Planning

## 6. Example: A* on a Grid

Let's illustrate A* with a simple grid example.

**Scenario:** A robot needs to move from Start (0,0) to Goal (4,4) in a 5x5 grid. Some cells are blocked.

**Grid:**
```
S . . # .
. . . # .
. # . . .
. . . # .
. . . . G
```
Where:
*   `S`: Start (0,0)
*   `G`: Goal (4,4)
*   `.`: Free space
*   `#`: Obstacle

**Heuristic:** Manhattan Distance (assuming movement cost of 1 for horizontal/vertical steps)

**Initialization:**
*   `openSet = {(0,0)}`
*   `closedSet = {}`
*   `gScore[(0,0)] = 0`
*   `fScore[(0,0)] = gScore[(0,0)] + h((0,0)) = 0 + |0-4| + |0-4| = 8`

**Iteration 1:**
*   `current = (0,0)` (lowest fScore in openSet)
*   Move (0,0) from `openSet` to `closedSet`. `closedSet = {(0,0)}`
*   Neighbors of (0,0): (0,1), (1,0).

    *   **Neighbor (0,1):**
        *   `tentative_gScore = gScore[(0,0)] + 1 = 0 + 1 = 1`
        *   `h((0,1)) = |0-4| + |1-4| = 4 + 3 = 7`
        *   `fScore[(0,1)] = 1 + 7 = 8`
        *   Add (0,1) to `openSet`. `cameFrom[(0,1)] = (0,0)`. `gScore[(0,1)] = 1`. `fScore[(0,1)] = 8`.
        *   `openSet = {(0,1)}`

    *   **Neighbor (1,0):**
        *   `tentative_gScore = gScore[(0,0)] + 1 = 0 + 1 = 1`
        *   `h((1,0)) = |1-4| + |0-4| = 3 + 4 = 7`
        *   `fScore[(1,0)] = 1 + 7 = 8`
        *   Add (1,0) to `openSet`. `cameFrom[(1,0)] = (0,0)`. `gScore[(1,0)] = 1`. `fScore[(1,0)] = 8`.
        *   `openSet = {(0,1), (1,0)}`

**Iteration 2:**
*   Both (0,1) and (1,0) have `fScore = 8`. Let's pick (1,0) (arbitrary tie-breaking).
*   `current = (1,0)`
*   Move (1,0) from `openSet` to `closedSet`. `closedSet = {(0,0), (1,0)}`
*   Neighbors of (1,0): (0,0) (in closedSet), (1,1), (2,0).

    *   **Neighbor (1,1):**
        *   `tentative_gScore = gScore[(1,0)] + 1 = 1 + 1 = 2`
        *   `h((1,1)) = |1-4| + |1-4| = 3 + 3 = 6`
        *   `fScore[(1,1)] = 2 + 6 = 8`
        *   Add (1,1) to `openSet`. `cameFrom[(1,1)] = (1,0)`. `gScore[(1,1)] = 2`. `fScore[(1,1)] = 8`.
        *   `openSet = {(0,1), (1,1)}`

    *   **Neighbor (2,0):**
        *   `tentative_gScore = gScore[(1,0)] + 1 = 1 + 1 = 2`
        *   `h((2,0)) = |2-4| + |0-4| = 2 + 4 = 6`
        *   `fScore[(2,0)] = 2 + 6 = 8`
        *   Add (2,0) to `openSet`. `cameFrom[(2,0)] = (1,0)`. `gScore[(2,0)] = 2`. `fScore[(2,0)] = 8`.
        *   `openSet = {(0,1), (1,1), (2,0)}`

**Iteration 3:**
*   All nodes in `openSet` have `fScore = 8`. Let's pick (0,1).
*   `current = (0,1)`
*   Move (0,1) from `openSet` to `closedSet`. `closedSet = {(0,0), (1,0), (0,1)}`
*   Neighbors of (0,1): (0,0) (in closedSet), (1,1), (0,2).

    *   **Neighbor (1,1):** (already in openSet with fScore=8, gScore=2)
        *   `tentative_gScore = gScore[(0,1)] + 1 = 1 + 1 = 2`
        *   Since `tentative_gScore (2) == gScore[(1,1)] (2)`, no update needed.

    *   **Neighbor (0,2):**
        *   `tentative_gScore = gScore[(0,1)] + 1 = 1 + 1 = 2`
        *   `h((0,2)) = |0-4| + |2-4| = 4 + 2 = 6`
        *   `fScore[(0,2)] = 2 + 6 = 8`
        *   Add (0,2) to `openSet`. `cameFrom[(0,2)] = (0,1)`. `gScore[(0,2)] = 2`. `fScore[(0,2)] = 8`.
        *   `openSet = {(1,1), (2,0), (0,2)}`

... and so on. The algorithm continues, prioritizing nodes with the lowest `fScore` until the goal is reached.

**Example Path Reconstruction:**
If A* successfully finds the goal, say at node G, you trace back:
`G <- cameFrom[G] <- cameFrom[cameFrom[G]] <- ... <- Start`

## 7. Practice Questions and Answers

**Question 1:**
What is the primary advantage of A* search over Dijkstra's algorithm for path planning?

**Answer 1:**
A* uses a heuristic function (`h(n)`) to estimate the cost to the goal, which guides the search more efficiently than Dijkstra's algorithm (which only considers the actual cost from the start, `g(n)`). This makes A* generally faster in finding the optimal path.

**Question 2:**
Consider a grid where you can move horizontally, vertically, and diagonally with costs: 1 for horizontal/vertical, and $\sqrt{2}$ for diagonal. If the current node is (3,3) and the goal is (7,6), calculate the Euclidean distance and the Octile distance for the heuristic `h(n)`.

**Answer 2:**
*   Current node `n = (3,3)`, Goal `G = (7,6)`
*   `dx = |7 - 3| = 4`
*   `dy = |6 - 3| = 3`

*   **Euclidean Distance:**
    $h(n) = \sqrt{dx^2 + dy^2} = \sqrt{4^2 + 3^2} = \sqrt{16 + 9} = \sqrt{25} = 5$

*   **Octile Distance (cost for diagonal is $\sqrt{2}$):**
    Here, we have `min(dx, dy) = 3` diagonal moves and `max(dx, dy) - min(dx, dy) = 4 - 3 = 1` straight move.
    $h(n) = (\max(dx, dy) - \min(dx, dy)) \times 1 + \sqrt{2} \times \min(dx, dy)$
    $h(n) = (4 - 3) \times 1 + \sqrt{2} \times 3 = 1 \times 1 + \sqrt{2} \times 3 = 1 + 3\sqrt{2} \approx 1 + 3 \times 1.414 = 1 + 4.242 = 5.242$

**Question 3:**
What condition must a heuristic function satisfy to guarantee that A* finds the shortest path?

**Answer 3:**
The heuristic function must be **admissible**. An admissible heuristic never overestimates the actual cost to reach the goal. If the heuristic is also **consistent (monotonic)**, A* is guaranteed to find the optimal path without re-expanding nodes.

**Question 4:**
If a robot is navigating a dynamic environment with moving obstacles, how might A* need to be modified or augmented?

**Answer 4:**
For dynamic environments, standard A* might need to be re-run frequently (replanning) as obstacles move. More advanced approaches include:
*   **Dynamic Window Approach (DWA) or Timed Elastic Band (TEB):** These are reactive methods that consider the robot's velocity and acceleration constraints to find collision-free trajectories in real-time.
*   **Incremental A*:** To efficiently re-plan by reusing information from previous searches.
*   **Predictive Path Planning:** Anticipating the movement of dynamic obstacles.

**Question 5:**
Explain the difference between `g(n)` and `h(n)` in the A* evaluation function `f(n) = g(n) + h(n)`.

**Answer 5:**
*   `g(n)`: The **actual cost** incurred to reach node `n` from the starting node. This is the cost that has already been paid.
*   `h(n)`: The **estimated cost** (heuristic) from node `n` to the goal node. This is an educated guess about the remaining cost.

## 8. Summary and Key Takeaways

*   **A* Search:** An informed graph traversal algorithm that finds the shortest path from a start node to a goal node.
*   **Evaluation Function:** `f(n) = g(n) + h(n)`, where `g(n)` is the cost from the start and `h(n)` is the estimated cost to the goal.
*   **Heuristic Function:** Crucial for A*'s efficiency. Must be **admissible** (never overestimates) to guarantee optimality. **Consistent** heuristics are also desirable.
*   **Common Heuristics:** Manhattan distance, Euclidean distance, Octile distance.
*   **Applications:** Grid-based navigation, graph-based navigation, and can be adapted for continuous spaces.
*   **Limitations:** Primarily designed for static environments. Can be computationally expensive for large search spaces.
*   **Mobile Robotics Relevance:** A* is a fundamental tool for path planning, enabling robots to navigate autonomously. It complements kinematic and dynamic control systems.

**Important Point to Remember:** The trade-off in A* is between the accuracy of the heuristic and its computational cost. A more accurate (but still admissible) heuristic leads to faster convergence but might be more complex to compute.
