# DIGITAL FORENSICS - Module 1: Introduction to Digital Forensics

## Topic: EXT2 (Second Extended Filesystem)

This module introduces the fundamental concepts of Digital Forensics. This specific topic focuses on the EXT2 filesystem, a foundational filesystem widely used in early Linux distributions. Understanding filesystems is crucial in digital forensics as it dictates how data is stored, organized, and retrieved from storage media.

---

Upon successful completion of this topic, you will be able to:

*   **Understand the role of filesystems in digital forensics:** Recognize how filesystem structure impacts evidence acquisition and analysis.
*   **Identify the key components of the EXT2 filesystem:** Describe the inode, data block, directory entry, and superblock structures.
*   **Explain the concept of file allocation and deallocation in EXT2:** Understand how files are written to and deleted from an EXT2 filesystem.
*   **Discuss the evidentiary value of EXT2 metadata:** Explain how information within inodes and directory entries can be used as evidence.
*   **Analyze the limitations of EXT2 for forensic purposes:** Recognize why newer filesystems are often preferred.

### 2. Key Concepts and Definitions

#### 2.1 What is a Filesystem?

A filesystem is a method and data structure that an operating system uses to control how data is stored and retrieved. It dictates the organization of files and directories on a storage device (e.g., hard drive, USB drive).

**In Digital Forensics:** Filesystems are critical because they:
*   Determine how evidence is stored and organized.
*   Influence how deleted files can be recovered.
*   Provide metadata that can be crucial for establishing timelines and file provenance.

#### 2.2 Introduction to EXT2

**EXT2 (Second Extended Filesystem):**
*   The second major revision of the extended filesystem, developed for the Linux operating system.
*   It was the standard filesystem for many Linux distributions before the introduction of EXT3 and EXT4.
*   Known for its simplicity, robustness, and good performance for its time.
*   **Key characteristic:** It is **non-journaling**. This means that in case of a system crash or power failure, data corruption is more likely compared to journaling filesystems.

#### 2.3 Key Components of the EXT2 Filesystem

The EXT2 filesystem is structured into several core components that work together to manage file storage.

*   **Superblock:**
    *   **Definition:** A critical data structure that contains overall information about the filesystem, such as its size, number of inodes, number of data blocks, block size, and pointers to other important data structures.
    *   **Forensic Significance:** Crucial for mounting and understanding the filesystem. If the primary superblock is damaged, backup superblocks (located at specific offsets) can be used to recover the filesystem.
    *   **Example:** Contains the total number of blocks, free blocks, total number of inodes, free inodes, and the filesystem's creation time.

*   **Group Descriptors (Block Group Descriptors):**
    *   **Definition:** The filesystem is divided into "block groups." Each block group has its own set of descriptors that describe the location of its data block bitmap, inode bitmap, and inode table.
    *   **Forensic Significance:** Allows for efficient traversal and analysis of the filesystem, especially for large disks.

*   **Block Allocation:**
    *   **Data Blocks:** The actual storage units where file content is stored.
    *   **Block Bitmap:** A bit array where each bit corresponds to a data block. A '1' indicates the block is allocated, and a '0' indicates it is free.
    *   **Forensic Significance:** Used to identify which blocks are currently occupied by file data and which are available. Recovering deleted files often involves scanning free blocks for residual data.

*   **Inode (Index Node):**
    *   **Definition:** A data structure that stores metadata about a file or directory, but NOT its name or actual data.
    *   **Key Information Stored:**
        *   File type (regular file, directory, symbolic link, etc.)
        *   Permissions (read, write, execute for owner, group, others)
        *   Owner ID and Group ID
        *   File size
        *   Timestamps:
            *   **atime (Access Time):** Last time the file was accessed.
            *   **ctime (Change Time):** Last time the file's metadata was changed.
            *   **mtime (Modification Time):** Last time the file's content was modified.
            *   **dtime (Deletion Time):** Timestamp when the file was deleted (set to zero if not deleted).
        *   Pointers to the data blocks where the file's content is stored.
    *   **Forensic Significance:** Inodes are central to digital forensics. Timestamps are vital for establishing timelines, permissions can indicate access control, and the link count can indicate if a file is still referenced.

*   **Inode Bitmap:**
    *   **Definition:** Similar to the block bitmap, but each bit corresponds to an inode. A '1' means the inode is allocated, and a '0' means it is free.
    *   **Forensic Significance:** Used to identify which inodes are in use and which are available.

*   **Inode Table:**
    *   **Definition:** An array of inodes. Each entry in the table corresponds to a specific inode number.
    *   **Forensic Significance:** Contains the metadata for all files and directories within a block group.

*   **Directory Entry:**
    *   **Definition:** A structure within a directory data block that maps a filename to its corresponding inode number.
    *   **Key Information:**
        *   Inode number of the file/directory.
        *   Length of the directory entry.
        *   Length of the filename.
        *   File type (a single character).
        *   Filename.
    *   **Forensic Significance:** Crucial for reconstructing the directory structure and linking filenames to their inode metadata. Deleted directory entries can be recovered to reveal previously existing file structures.

#### 2.4 File Allocation and Deallocation in EXT2

*   **File Allocation (Writing a File):**
    1.  An available inode is found using the inode bitmap.
    2.  The inode is updated with file metadata (permissions, timestamps, etc.).
    3.  Available data blocks are found using the block bitmap.
    4.  The inode's data block pointers are updated to point to these allocated blocks.
    5.  The file's content is written to the allocated data blocks.
    6.  The corresponding inode and data blocks are marked as allocated in their respective bitmaps.
    7.  A directory entry is created in the appropriate directory, linking the filename to the inode number.

*   **File Deallocation (Deleting a File):**
    1.  The directory entry linking the filename to the inode is removed.
    2.  The inode's data block pointers are cleared.
    3.  The inode itself is marked as free in the inode bitmap.
    4.  The data blocks pointed to by the inode are marked as free in the block bitmap.
    5.  **Important Note:** The actual data in the data blocks is **not** immediately erased. It remains until those blocks are reallocated for new files. The inode's `dtime` (deletion time) field is set.

#### 2.5 Evidentiary Value of EXT2 Metadata

*   **Timestamps (atime, ctime, mtime):**
    *   **Value:** Crucial for reconstructing the sequence of events.
    *   **Example:** An investigator might examine the `mtime` of a document to determine when it was last modified, or the `atime` of a system file to see when it was last accessed, potentially indicating malicious activity.

*   **Permissions:**
    *   **Value:** Can indicate ownership and access control, helping to understand who could have created, modified, or accessed a file.

*   **Inode Link Count:**
    *   **Value:** Indicates how many directory entries point to this inode. If the count drops to zero, the inode is considered unlinked and the data blocks are free for reallocation.

*   **Directory Entries:**
    *   **Value:** Even after deletion, the inode number and filename might be recoverable from unallocated directory blocks, allowing reconstruction of deleted files and their original locations.

*   **Unallocated Space:**
    *   **Value:** The residual data in data blocks that were previously used by deleted files can be recovered, potentially revealing deleted files or fragments of files.

#### 2.6 Limitations of EXT2 for Forensic Purposes

*   **Non-Journaling:**
    *   **Limitation:** The lack of journaling makes EXT2 susceptible to data corruption in the event of unexpected shutdowns. This can lead to filesystem inconsistencies, making recovery more challenging.

*   **No Built-in Integrity Checks (like journaling):**
    *   **Limitation:** Unlike journaling filesystems (EXT3, EXT4), EXT2 doesn't inherently track changes in a way that guarantees consistency.

*   **Simpler Structure (compared to modern filesystems):**
    *   **Limitation:** While simpler, it lacks some advanced features found in modern filesystems like journaling, extended attributes, and support for larger file sizes and volumes.

### 3. Practice Questions and Exercises

**Question 1:**
What is the primary role of an inode in the EXT2 filesystem?
a) To store the actual content of a file.
b) To map filenames to their corresponding data blocks.
c) To store metadata about a file, such as its permissions, timestamps, and pointers to data blocks.
d) To manage the free and allocated data blocks on the filesystem.

**Question 2:**
In EXT2, what does the `dtime` field in an inode signify?
a) The last time the file's metadata was changed.
b) The last time the file's content was modified.
c) The last time the file was accessed.
d) The time the file was deleted.

**Question 3:**
Why is the non-journaling nature of EXT2 considered a limitation in digital forensics?

**Question 4:**
Imagine you are analyzing a hard drive formatted with EXT2. You discover a deleted file. What components of the EXT2 filesystem would you typically examine to recover the file's metadata and potentially its content?

---

### 4. Answers to Practice Questions

**Answer 1:**
**c) To store metadata about a file, such as its permissions, timestamps, and pointers to data blocks.**
*   Explanation: Inodes are the central metadata structures for files in EXT2. They do not store the file content directly (that's in data blocks) nor do they store filenames (that's in directory entries).

**Answer 2:**
**d) The time the file was deleted.**
*   Explanation: `dtime` (deletion time) is specifically set when a file is removed from the filesystem. `ctime` is for metadata changes, `mtime` for content modifications, and `atime` for access.

**Answer 3:**
The non-journaling nature of EXT2 is a limitation because in the event of an unexpected shutdown or system crash, the filesystem is more prone to data corruption and inconsistencies. This can make it harder to recover data and may even render parts of the filesystem unreadable, complicating forensic analysis. Journaling filesystems maintain a log of changes, which helps in restoring consistency quickly after a failure.

**Answer 4:**
To recover a deleted file in an EXT2 filesystem, an investigator would typically examine:
*   **Unallocated Space:** Scan the raw disk sectors for residual data that was previously part of the deleted file's data blocks.
*   **Inode Table:** Look for inodes that have their `dtime` field set and whose data blocks might still contain relevant information.
*   **Directory Entries (in unallocated directory blocks):** Attempt to find deleted directory entries that map the file's name to its inode number.
*   **Inode Bitmap:** Identify inodes marked as free but which might have contained metadata for the deleted file.
*   **Block Bitmap:** Identify data blocks marked as free but which might still contain the file's content.

---

### 5. Important Points to Remember

*   **EXT2 is a non-journaling filesystem.** This is its most significant limitation from a data integrity perspective.
*   **Inodes are the backbone of file metadata in EXT2.** They contain crucial information for forensic analysis, especially timestamps.
*   **Directory entries link filenames to inode numbers.** Recovery of deleted files often involves finding these links.
*   **Deleted data in EXT2 is not immediately erased.** It remains in data blocks until those blocks are reallocated, making file recovery possible.
*   **Superblocks are vital for understanding the filesystem structure.** Backup superblocks are important for recovery.
*   Understanding the basic structure of EXT2 provides a foundational understanding for analyzing more modern filesystems.
