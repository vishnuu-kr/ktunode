# THEORY OF COMPUTATION - MODULE 4: TURING MACHINES (KOZEN)

## Topic: Linear Bounded Automaton as a Restricted TM

**Learning Outcomes:**

*   Understand the definition of a Linear Bounded Automaton (LBA).
*   Explain how an LBA is a restricted form of a Turing Machine.
*   Describe the limitations of an LBA compared to a general Turing Machine.
*   Identify the class of languages that LBAs can recognize (Context-Sensitive Languages).
*   Distinguish between LBAs and other automata like Pushdown Automata and Finite Automata.
*   Explain the significance of LBAs in the Chomsky Hierarchy.

**1. Definition of a Linear Bounded Automaton (LBA)**

*   **Definition:** A Linear Bounded Automaton (LBA) is a non-deterministic Turing Machine with the following restrictions:
    *   **Limited Tape:** The LBA's tape is bounded by the length of the input. That is, the machine can only read from or write to the portion of the tape initially occupied by the input string.  This length can be represented as 'n', where 'n' is the length of the input string.  The LBA's head cannot move beyond the input string's boundaries.
    *   **Tape Alphabet:** LBAs have a tape alphabet that usually includes special symbols denoting the left and right ends of the input.
    *   **Input:** The input string is written on the tape.
    *   **Acceptance:** The LBA accepts its input string if it halts in an accepting state.

*   **Formal Definition:** An LBA is a tuple `M = (Q, Σ, Γ, δ, q0, q_accept, q_reject)` where:
    *   `Q` is a finite set of states.
    *   `Σ` is a finite input alphabet.
    *   `Γ` is a finite tape alphabet, where `Σ ⊆ Γ`.
    *   `δ: Q × Γ → P(Q × Γ × {L, R})` is the transition function.  It maps a state and a tape symbol to a set of possible next states, symbols to write on the tape, and head movements (left or right).  `P` denotes the power set.
    *   `q0 ∈ Q` is the initial state.
    *   `q_accept ∈ Q` is the accept state.
    *   `q_reject ∈ Q` is the reject state.

**2. LBA as a Restricted Turing Machine**

*   **Restriction:** The defining characteristic of an LBA is its limited tape length. A standard Turing Machine has an infinite tape, whereas an LBA's tape is restricted to the length of the input.
*   **Comparison:**
    *   **Turing Machine:** Can move its read/write head arbitrarily on an infinite tape, allowing unlimited storage and processing capability.
    *   **Linear Bounded Automaton:**  Limited to the space initially allocated to the input string.  This limits the amount of intermediate data it can store and manipulate.
*   **Implication:** This restriction significantly reduces the computational power of the LBA compared to a standard Turing Machine.  An LBA can solve problems that a Turing Machine can solve, but it *cannot* solve all problems that a Turing Machine can solve.

**3. Limitations of an LBA compared to a General Turing Machine**

*   **Space Constraint:**  The most prominent limitation is the restriction to using only the input string's length on the tape.  This limits the amount of data it can remember and manipulate during computation.
*   **Complexity:** Due to the limited space, some algorithms that could be implemented easily on a Turing Machine become significantly more complex and potentially impossible to implement on an LBA within reasonable time.
*   **Recursion:** Recursive computations that rely on storing intermediate results extensively become harder, if not impossible, because of the tape boundary.

**4. The Class of Languages LBAs Can Recognize: Context-Sensitive Languages (CSL)**

*   **Context-Sensitive Languages:**  LBAs are equivalent in power to Context-Sensitive Grammars (CSGs).  This means that any language generated by a CSG can be recognized by an LBA, and vice versa.
*   **Relationship to the Chomsky Hierarchy:** CSLs are higher up in the Chomsky Hierarchy than Context-Free Languages (CFLs) but lower than Recursively Enumerable Languages (RELs).
    *   **Type-0 (Recursively Enumerable):** Turing Machines
    *   **Type-1 (Context-Sensitive):** Linear Bounded Automata
    *   **Type-2 (Context-Free):** Pushdown Automata
    *   **Type-3 (Regular):** Finite Automata

*   **Examples of CSLs:**
    *   `{a^n b^n c^n | n >= 1}`:  This language requires counting and comparing the number of a's, b's, and c's.  A PDA cannot handle this, but an LBA can (within the input's space limitation).
    *   `{w w | w ∈ {a, b}*}`:  Duplicate words, also beyond the capabilities of PDAs.

**5. Distinguishing LBAs from Other Automata**

*   **Finite Automata (FA):**  FA have no memory (no tape). They recognize regular languages, which are a strict subset of CSLs. FAs are less powerful than LBAs.
*   **Pushdown Automata (PDA):**  PDA have a stack for memory. They recognize context-free languages, which are also a strict subset of CSLs. PDAs are less powerful than LBAs.
*   **Turing Machines (TM):** TM have an infinite tape for memory. They recognize recursively enumerable languages, which are a superset of CSLs. TMs are more powerful than LBAs.

**6. Significance of LBAs in the Chomsky Hierarchy**

*   **Position:** LBAs bridge the gap between PDAs and Turing Machines in terms of computational power. They provide a model for understanding computation with limited memory.
*   **Real-World Applications:** LBAs, and more generally, the concepts behind them, are useful for modeling systems with finite resources. They represent computations with limited memory, relevant in resource-constrained environments.
*   **Theoretical Importance:** The relationship between LBAs and Context-Sensitive Languages helps in understanding the complexity of language recognition and parsing.  The question of whether deterministic LBAs (DLBAs) and nondeterministic LBAs (NLBAs) are equivalent (the DLBA=NLBA problem) is an open question in theoretical computer science.

**Important Points to Remember:**

*   An LBA is a *restricted* Turing Machine.
*   The restriction is the limited tape length (proportional to the input size).
*   LBAs recognize Context-Sensitive Languages (CSLs).
*   LBAs are more powerful than PDAs and FAs, but less powerful than general TMs.
*   DLBA=NLBA is an unresolved problem.

**Practice Questions/Exercises with Answers:**

**Question 1:**  Explain why a Pushdown Automaton (PDA) cannot recognize the language L = {a<sup>n</sup>b<sup>n</sup>c<sup>n</sup> | n >= 0}.  Explain how a Linear Bounded Automaton (LBA) *can* recognize this language.

**Answer:**

*   **PDA Limitation:** A PDA has a stack as its memory. While it can push 'a's onto the stack while reading 'a's in the input, and then pop 'a's when reading 'b's to verify a<sup>n</sup>b<sup>n</sup>, it cannot simultaneously remember the number of 'a's (or 'b's) to compare with the number of 'c's.  The stack is used for one comparison (a's and b's), and it cannot be reset for the comparison with the c's. Therefore, PDAs can't accurately compare the counts of all three symbols.

*   **LBA Capability:** An LBA can recognize L = {a<sup>n</sup>b<sup>n</sup>c<sup>n</sup> | n >= 0} by marking the tape. It can:
    1.  Check the input is of the form a*b*c*.  If not, reject.
    2.  Replace the first 'a' with some marker 'X', move right to find the first 'b', replace it with 'Y', move right to find the first 'c', replace it with 'Z'.
    3.  Move left to find 'X', move right to find 'Y', move right to find 'Z'.
    4.  Repeat steps 2 and 3 until all a's, b's and c's are marked.
    5.  If, at any point, there are unmatched a's, b's or c's, reject. If all are matched and marked, accept.
    This process can be done within the space of the input string.

**Question 2:**  What is the main difference between a Turing Machine and a Linear Bounded Automaton?  Why does this difference matter?

**Answer:**

The main difference is the **tape length**.  A Turing Machine has an *infinite* tape, while an LBA's tape length is bounded by the *length of the input*.

This difference matters because:

*   **Computational Power:** It significantly restricts the computational power of the LBA. TMs can solve a broader class of problems than LBAs.
*   **Language Recognition:**  TMs recognize Recursively Enumerable Languages, while LBAs recognize Context-Sensitive Languages.
*   **Memory Constraints:** The LBA's limited tape represents computations with limited memory. This is relevant for modeling real-world systems with finite resources.

**Question 3:**  Provide an example of a language that is context-sensitive but not context-free.

**Answer:**

The language `L = {a^n b^n c^n | n >= 1}` is a classic example of a context-sensitive language that is *not* context-free. As explained above, a PDA cannot reliably recognize this language because it lacks the ability to compare the count of three different symbols simultaneously.

**Question 4:** True or False: All context-free languages can be recognized by a Linear Bounded Automaton.

**Answer:** True. Since CSLs are a superset of CFLs, any context-free language can also be recognized by an LBA.
