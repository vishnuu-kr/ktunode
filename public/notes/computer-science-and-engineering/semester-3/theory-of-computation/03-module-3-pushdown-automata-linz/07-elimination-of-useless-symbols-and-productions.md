# THEORY OF COMPUTATION - Module 3: Pushdown Automata (Linz) - Elimination of Useless Symbols and Productions

## Learning Outcomes:

*   Understand the concepts of useless symbols and productions in the context of Context-Free Grammars (CFGs).
*   Learn the algorithms for eliminating useless symbols and productions from CFGs.
*   Apply these algorithms to simplify CFGs and create equivalent, reduced grammars.
*   Understand why eliminating useless symbols and productions is important.

## 1. Introduction to Useless Symbols and Productions

### 1.1 Definition: Useless Symbol

A symbol (variable or terminal) in a CFG is *useless* if it does not appear in any derivation of a terminal string from the start symbol.  A useless symbol can be one of two types:

*   **Non-generating:**  The symbol cannot derive any terminal string.
*   **Non-reachable:** The symbol cannot be derived from the start symbol.

### 1.2 Definition: Useless Production

A production in a CFG is *useless* if it contains a useless symbol. Removing useless productions does not change the language generated by the grammar.

### 1.3 Motivation for Elimination

*   **Simplification:** Useless symbols and productions add complexity to the grammar without contributing to the generated language.  Removing them makes the grammar easier to understand and analyze.
*   **Efficiency:**  When implementing parsing algorithms, useless symbols and productions can lead to unnecessary computations.  Eliminating them improves efficiency.
*   **Canonical Forms:** Many algorithms and proofs in formal language theory rely on grammars being in specific normal forms (e.g., Chomsky Normal Form, Greibach Normal Form).  Eliminating useless symbols and productions is often a prerequisite for converting a CFG to such normal forms.

## 2. Eliminating Non-Generating Symbols

### 2.1 Algorithm: Finding and Removing Non-Generating Symbols

1.  **Initialization:**
    *   Let `Generating = {terminals}`.  We know all terminal symbols can generate themselves.
2.  **Iteration:**
    *   Repeat until `Generating` no longer changes:
        *   For each production `A -> α` (where `A` is a variable and `α` is a string of variables and terminals):
            *   If all symbols in `α` are in `Generating`, then add `A` to `Generating`.
3.  **Identification:**  Symbols that are *not* in `Generating` are non-generating symbols.
4.  **Elimination:**  Remove all productions that contain non-generating symbols.

### 2.2 Example

Consider the following grammar:

```
S -> AB | a
A -> a
B -> Cb
C -> d
D -> e
```

1.  **Initialization:** `Generating = {a, b, d, e}`
2.  **Iteration 1:**
    *   `S -> AB`: Neither A nor B are in `Generating` yet.
    *   `S -> a`: `a` is in `Generating`, but the production is not relevant to finding *non-generating* symbols.
    *   `A -> a`: `a` is in `Generating`, so add `A` to `Generating`.  `Generating = {a, b, d, e, A}`
    *   `B -> Cb`: Neither C nor b are in `Generating` yet.
    *   `C -> d`: `d` is in `Generating`, so add `C` to `Generating`. `Generating = {a, b, d, e, A, C}`
    *   `D -> e`: `e` is in `Generating`, so add `D` to `Generating`. `Generating = {a, b, d, e, A, C, D}`
3.  **Iteration 2:**
    *   `S -> AB`: `A` is in `Generating`, but `B` is not.
    *   `S -> a`: `a` is in `Generating`.
    *   `A -> a`: `a` is in `Generating`.
    *   `B -> Cb`: `C` and `b` are in `Generating`, so add `B` to `Generating`. `Generating = {a, b, d, e, A, C, D, B}`
    *   `C -> d`: `d` is in `Generating`.
    *   `D -> e`: `e` is in `Generating`.
4.  **Iteration 3:**
    *   `S -> AB`: `A` and `B` are in `Generating`, so add `S` to `Generating`. `Generating = {a, b, d, e, A, C, D, B, S}`
    *   `S -> a`: `a` is in `Generating`.
    *   `A -> a`: `a` is in `Generating`.
    *   `B -> Cb`: `C` and `b` are in `Generating`.
    *   `C -> d`: `d` is in `Generating`.
    *   `D -> e`: `e` is in `Generating`.

5.  `Generating` has stopped changing.
6.  **Identification:** No symbols are non-generating, since all are in `Generating`.
7. **Elimination:** No productions are eliminated.

Now consider this grammar:

```
S -> AB | a
A -> a
B -> Cb
```

1. **Initialization:** `Generating = {a, b}`
2. **Iteration 1:**
    * `S -> AB`: Neither A nor B are in `Generating`.
    * `S -> a`: `a` is in `Generating`.
    * `A -> a`: `a` is in `Generating`, so `Generating = {a, b, A}`
    * `B -> Cb`:  `b` is in `Generating` but `C` is not.
3. **Iteration 2:**
    * `S -> AB`: `A` is in `Generating`, but `B` is not.
    * `S -> a`: `a` is in `Generating`.
    * `A -> a`: `a` is in `Generating`.
    * `B -> Cb`: `b` is in `Generating` but `C` is not.
4. The algorithm stops. `Generating = {a, b, A}`
5. Non-generating symbols: `S, B, C`
6. Productions removed:  `S -> AB`, `B -> Cb`.

The new grammar is:

```
S -> a
A -> a
```

## 3. Eliminating Non-Reachable Symbols

### 3.1 Algorithm: Finding and Removing Non-Reachable Symbols

1.  **Initialization:**
    *   `Reachable = {Start Symbol}`. We can always reach the start symbol.
2.  **Iteration:**
    *   Repeat until `Reachable` no longer changes:
        *   For each production `A -> α` where `A` is in `Reachable`:
            *   Add all variables and terminals in `α` to `Reachable`.
3.  **Identification:** Symbols that are *not* in `Reachable` are non-reachable.
4.  **Elimination:** Remove all productions that contain non-reachable symbols.

### 3.2 Example

Consider the following grammar (assuming 'S' is the start symbol):

```
S -> aA | bB
A -> cA | d
C -> eC | f
B -> g
```

1.  **Initialization:** `Reachable = {S}`
2.  **Iteration 1:**
    *   `S -> aA`: Add `a` and `A` to `Reachable`. `Reachable = {S, a, A}`
    *   `S -> bB`: Add `b` and `B` to `Reachable`. `Reachable = {S, a, A, b, B}`
3.  **Iteration 2:**
    *   `S -> aA`:  `a` and `A` already in `Reachable`.
    *   `S -> bB`:  `b` and `B` already in `Reachable`.
    *   `A -> cA`: Add `c` to `Reachable`.  `Reachable = {S, a, A, b, B, c}`
    *   `A -> d`: Add `d` to `Reachable`.  `Reachable = {S, a, A, b, B, c, d}`
    *   `B -> g`: Add `g` to `Reachable`. `Reachable = {S, a, A, b, B, c, d, g}`
4.  **Iteration 3:** No new symbols added.
5.  **Identification:** `C`, `e`, and `f` are not in `Reachable` and are therefore non-reachable.
6.  **Elimination:** Remove the production `C -> eC | f`.

The resulting grammar is:

```
S -> aA | bB
A -> cA | d
B -> g
```

## 4. Complete Elimination Process

To eliminate all useless symbols and productions from a CFG, perform the following steps in order:

1.  Eliminate non-generating symbols and productions.
2.  Eliminate non-reachable symbols and productions.

**Important:**  The order matters! Eliminating non-generating symbols *first* can reveal non-reachable symbols that were previously hidden.

### Example

Consider the following grammar (where 'S' is the start symbol):

```
S -> AB | a
A -> a
B -> Cb
C -> d
D -> e
```

1. **Eliminate non-generating symbols (as shown in the example in section 2.2):**
```
S -> a
A -> a
```
2. **Eliminate non-reachable symbols:**

    * `Reachable = {S}`
    * After processing `S -> a`: `Reachable = {S, a}`

    * A is unreachable.

3. **Elimination:** Remove the production `A -> a`.  (Although A is still there, any productions using it have been removed.)

The final simplified grammar is:

```
S -> a
```

## 5. Practice Questions and Exercises

1.  **Question:** Consider the grammar:
    ```
    S -> AB
    A -> a
    B -> C
    C -> b
    D -> d
    ```
    Eliminate useless symbols and productions from this grammar (S is the start symbol). Show each step.

    **Answer:**

    *   **Eliminate Non-Generating:**
        *   `Generating = {a, b, d}`
        *   Iteration 1: `A` to `Generating` (due to `A -> a`), `C` to `Generating` (due to `C -> b`), `D` to `Generating` (due to `D -> d`). So `Generating = {a, b, d, A, C, D}`
        *   Iteration 2: `B` to `Generating` (due to `B -> C`). So `Generating = {a, b, d, A, C, D, B}`
        *   Iteration 3: `S` to `Generating` (due to `S -> AB`). So `Generating = {a, b, d, A, C, D, B, S}`
        *   No symbols are removed, no productions are removed.
    *   **Eliminate Non-Reachable:**
        *   `Reachable = {S}`
        *   Iteration 1: `A` and `B` to `Reachable` (due to `S -> AB`). So `Reachable = {S, A, B}`
        *   Iteration 2: `a` to `Reachable` (due to `A -> a`), `C` to `Reachable` (due to `B -> C`). So `Reachable = {S, A, B, a, C}`
        *   Iteration 3: `b` to `Reachable` (due to `C -> b`). So `Reachable = {S, A, B, a, C, b}`
        *   No change in Reachable. Thus D is non-reachable.
        *   The production `D -> d` is removed.

    The simplified grammar is:

    ```
    S -> AB
    A -> a
    B -> C
    C -> b
    ```

2.  **Question:**  Explain why it's important to eliminate non-generating symbols *before* eliminating non-reachable symbols. Provide an example to illustrate your point.

    **Answer:**

    If you eliminate non-reachable symbols first, you might mistakenly keep symbols that are, in fact, non-generating because their productions are connected to the start symbol through potentially useless intermediate symbols. By eliminating non-generating symbols first, you clean up the grammar so that when you look for non-reachable symbols, you have a more accurate picture of what can actually generate terminal strings.

    **Example:**

    Consider the grammar:

    ```
    S -> AB
    A -> a
    B -> C
    C -> d
    D -> e
    ```

    *   **Incorrect Approach (Reachable First):**
        *   `Reachable = {S}`
        *   `Reachable = {S, A, B}`
        *   `Reachable = {S, A, B, C}`
        *   `Reachable = {S, A, B, C, d}`

        *   Symbols kept: S, A, B, C, d.
        *   Eliminating D and the production D -> e
        *   Then you are left with a grammar S -> AB, A -> a, B -> C, and C -> d

        *   If you then attempt to eliminate non-generating, you will see that none of the symbols can become terminal and should be removed - this leads to an empty set of rules.

    *   **Correct Approach (Generating First):**

    *   `Generating = {a, d, e}`
    *   Iteration 1:  `A` to `Generating`, `C` to `Generating`, `D` to `Generating`
    *   Iteration 2:  `B` to `Generating`.
    *   Iteration 3: `S` to `Generating`.
    *  Now, we need to eliminate all non-generating symbols: none exist.

        *   Now we eliminate unreachable symbols:
    *   `Reachable = {S}`
    *  `Reachable = {S,A,B}`
    *   `Reachable = {S,A,B,C}`
    *   `Reachable = {S,A,B,C,d}`

        * Now, we need to eliminate unreachable symbols: `e` is the only unreachable symbol.
        * The production D->e is removed.
3.  **Question:** Design a CFG that produces the language {a<sup>n</sup>b<sup>n</sup> | n >= 1} and then eliminate all useless symbols and productions (if any) to ensure the grammar is simplified.

    **Answer:**

    Initial CFG:

    ```
    S -> aSb | ab
    ```

    1.  **Eliminate Non-Generating:**
        *   `Generating = {a, b}`
        *   Iteration 1: Add `S` to `Generating` (because `S -> aSb`, `a`, `S` and `b` are in generating and `S -> ab` both `a` and `b` are in generating).  `Generating = {a, b, S}`
        *   No further changes.  No symbols are removed.

    2.  **Eliminate Non-Reachable:**
        *   `Reachable = {S}`
        *   Iteration 1: Add `a`, `S`, and `b` to `Reachable`. `Reachable = {S, a, b}`

        *No Symbols are removed.
The resulting simplified grammar is:

```
S -> aSb | ab
```

## 6. Important Points to Remember

*   Useless symbols and productions do not contribute to the language generated by the grammar.
*   Eliminate non-generating symbols *before* eliminating non-reachable symbols.
*   The algorithms for eliminating useless symbols and productions are iterative.
*   After eliminating useless symbols and productions, the resulting grammar is equivalent to the original grammar (generates the same language).
*   Eliminating useless symbols and productions is often a necessary step in converting CFGs to normal forms.
