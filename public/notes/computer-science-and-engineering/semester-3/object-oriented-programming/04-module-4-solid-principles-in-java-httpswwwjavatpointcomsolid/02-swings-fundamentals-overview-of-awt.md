## 1. Introduction to AWT (Abstract Window Toolkit)

*   **Definition:** AWT is Java's original platform-dependent GUI toolkit. It provides a set of classes and interfaces for creating and managing graphical user interfaces. AWT relies on the underlying operating system's native GUI components.

*   **Platform Dependence:** AWT components are heavyweight.  This means each AWT component is implemented using a native component of the host operating system.  The look and feel of an AWT application will change depending on the operating system it's running on.  This is a significant disadvantage.

*   **Key Concepts:**
    *   **Heavyweight Components:** AWT components are considered "heavyweight" because they rely on native operating system components. Each AWT component has a corresponding peer in the native operating system.
    *   **Peer Classes:** Each AWT component has a corresponding peer class that handles the interaction with the native operating system. For instance, `java.awt.Button` has a peer class that interacts with the native OS's button implementation.
    *   **Event Handling:** AWT uses an event-delegation model, where events are generated by components and handled by event listeners.
    *   **Layout Managers:** AWT provides layout managers (e.g., `FlowLayout`, `BorderLayout`, `GridLayout`) to arrange components within a container.

*   **Core AWT Components:**
    *   `Button`:  A simple push button.
    *   `Label`:  Displays a static text string.
    *   `TextField`:  Allows single-line text input.
    *   `TextArea`: Allows multi-line text input.
    *   `Checkbox`:  A checkable box.
    *   `Choice`:  A drop-down list (select menu).
    *   `List`:  A scrollable list of items.
    *   `Panel`:  A simple container for grouping components.
    *   `Frame`:  A top-level window with a title and border.
    *   `Dialog`: A pop-up window to display information or get input.

*   **Example:**

    ```java
    import java.awt.*;

    public class AWTExample {
        public static void main(String[] args) {
            Frame frame = new Frame("AWT Example");
            Button button = new Button("Click Me");
            frame.add(button);
            frame.setSize(300, 200);
            frame.setLayout(new FlowLayout());
            frame.setVisible(true);
        }
    }
    ```

## 2. Swing Fundamentals: An Overview

*   **Definition:** Swing is a GUI toolkit built on top of AWT. Unlike AWT, Swing components are lightweight. This means they are drawn directly by Java code and do not rely on native operating system components.

*   **Lightweight Components:** Swing components are "lightweight" because they are written entirely in Java and do not depend on native OS components. They provide a platform-independent look and feel.

*   **Look and Feel (L&F):** Swing supports pluggable look and feel, allowing developers to change the appearance of an application without modifying the code. Swing provides default L&Fs (Metal, Nimbus, etc.) and allows custom L&Fs to be created.

*   **Key Concepts:**
    *   **Model-View-Controller (MVC) Architecture:**  Swing is designed around the MVC pattern, separating data (Model), presentation (View), and user interaction (Controller).
    *   **JComponents:** Swing components inherit from `javax.swing.JComponent`, providing common features like borders, tooltips, and accessibility support.
    *   **Event Handling:** Swing uses the same event-delegation model as AWT.
    *   **Painting:** Swing components are responsible for painting themselves using Java's Graphics API.

*   **Core Swing Components:**
    *   `JFrame`:  A top-level window (replaces `Frame` from AWT).
    *   `JLabel`: Displays static text (replaces `Label`).
    *   `JTextField`: Single-line text input (replaces `TextField`).
    *   `JTextArea`: Multi-line text input (replaces `TextArea`).
    *   `JButton`: A push button (replaces `Button`).
    *   `JCheckBox`: A checkable box (replaces `Checkbox`).
    *   `JComboBox`: A drop-down list (replaces `Choice`).
    *   `JList`: A scrollable list of items (replaces `List`).
    *   `JPanel`: A container for grouping components (replaces `Panel`).
    *   `JTable`:  Displays data in a tabular format.
    *   `JTree`: Displays data in a hierarchical format.
    *   `JScrollPane`: Adds scrollbars to a component.
    *   `JMenu`, `JMenuItem`, `JMenuBar`:  Used for creating menus.

*   **Example:**

    ```java
    import javax.swing.*;
    import java.awt.*;

    public class SwingExample {
        public static void main(String[] args) {
            JFrame frame = new JFrame("Swing Example");
            JButton button = new JButton("Click Me");
            frame.add(button);
            frame.setSize(300, 200);
            frame.setLayout(new FlowLayout());
            frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); // Important for closing the application
            frame.setVisible(true);
        }
    }
    ```

## 3. AWT vs. Swing: Key Differences

| Feature          | AWT                       | Swing                     |
|-------------------|---------------------------|--------------------------|
| Components        | Heavyweight               | Lightweight              |
| Platform Dependence| Yes                      | No                        |
| Look and Feel      | OS Dependent            | Pluggable (L&F)          |
| Graphics           | Relies on native graphics | Uses Java 2D Graphics    |
| Functionality      | Limited                   | More extensive and flexible |
| Root Component    | `Frame`                   | `JFrame`                  |

## 4. Advantages of Swing Over AWT

*   **Platform Independence:** Swing applications have a consistent look and feel across different operating systems.
*   **Flexibility:** Swing provides a wider range of components and more options for customization.
*   **Extensibility:** Swing's architecture makes it easier to extend and create custom components.
*   **Look and Feel Customization:**  Swing allows you to easily change the appearance of your application through pluggable look and feels.
*   **Improved Performance:**  While AWT components use native resources that *could* be faster, Swing's lightweight nature, and the advancements in Java performance over time, usually results in better or comparable performance for most applications.
*   **MVC Architecture:** Encourages better code organization and maintainability.

## 5. Practice Questions and Exercises

**Question 1:** What is the main difference between AWT and Swing components?

**Answer:** AWT components are heavyweight (platform-dependent), while Swing components are lightweight (platform-independent).

**Question 2:** Why is Swing considered more flexible than AWT?

**Answer:** Swing provides a wider range of components, more customization options, and supports pluggable look and feels.

**Question 3:** Write a simple Java program using Swing to create a JFrame with a JLabel displaying "Hello, Swing!".

**Answer:**

```java
import javax.swing.*;
import java.awt.*;

public class SwingLabelExample {
    public static void main(String[] args) {
        JFrame frame = new JFrame("Swing Label Example");
        JLabel label = new JLabel("Hello, Swing!");
        frame.add(label);
        frame.setSize(300, 200);
        frame.setLayout(new FlowLayout());
        frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        frame.setVisible(true);
    }
}
```

## 6. Important Points to Remember

*   AWT is the older, platform-dependent GUI toolkit.
*   Swing is built on top of AWT but provides platform independence and more features.
*   Swing components are lightweight and drawn by Java code.
*   Swing supports pluggable look and feels.
*   Swing encourages the use of the MVC architecture.
*   Always set `setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE)` for JFrame to ensure the application closes properly.
