# OPERATING SYSTEMS LAB - Module 14: Paging Address Translation Simulation

## Topic: Simulating Address Translation in Paging Scheme

This module focuses on understanding and simulating the address translation process in a paging memory management scheme. You will learn to take a virtual address, consult a page table, and calculate the corresponding physical address.

## Learning Outcomes:

*   Understand the concept of paging and its role in memory management.
*   Understand the difference between virtual and physical addresses.
*   Learn how virtual addresses are translated to physical addresses using a page table.
*   Implement a program that simulates the address translation process using a page table.
*   Handle page table misses.
*   Understand the relationship between page size, page number, and offset.

## 1. Key Concepts and Definitions:

*   **Paging:** A memory management technique that divides both physical memory (RAM) and virtual memory (logical address space used by a process) into fixed-size blocks called *frames* and *pages*, respectively. Pages are the same size as frames.

*   **Virtual Address (Logical Address):** The address generated by the CPU for a process. This address is independent of the physical memory layout.  It's broken down into two parts:
    *   **Page Number (p):**  Used as an index into the page table.
    *   **Page Offset (d):** Represents the offset within the page.

*   **Physical Address:** The actual address in physical memory (RAM) where the data resides.  It's also broken down into two parts:
    *   **Frame Number (f):** Represents the physical frame in which the page is stored.
    *   **Frame Offset (d):**  The same as the page offset.

*   **Page Table:** A data structure used by the operating system to store the mapping between virtual pages and physical frames.  Each entry in the page table typically contains:
    *   **Frame Number:** The physical frame number where the page is loaded.
    *   **Valid/Invalid Bit:** Indicates whether the corresponding page is currently in memory. (Important for handling page faults, which we'll simulate as a "page table miss").
    *   (Optional) Protection bits (read/write/execute permissions)
    *   (Optional) Modified (dirty) bit: Indicates whether the page has been modified since being loaded into memory.
    *   (Optional) Reference bit: Indicates whether the page has been recently accessed.

*   **Frame:** A fixed-size block of physical memory.

*   **Page:** A fixed-size block of virtual memory. The page size is always equal to the frame size.

*   **Page Table Entry (PTE):** Each entry in the page table that maps a page to a frame.

*   **Page Table Miss (Page Fault):**  Occurs when the page number is not found in the page table (indicated by a "valid" bit being false) or when the page table entry doesn't exist.  In a real system, this triggers a page fault handler, which loads the page from secondary storage (e.g., hard drive) into a free frame and updates the page table. In this lab exercise, we simply report the miss.

## 2. Address Translation Process:

1.  **CPU Generates Virtual Address:** The CPU generates a virtual address (p, d), where 'p' is the page number and 'd' is the offset within the page.

2.  **Lookup Page Table:** The operating system uses the page number 'p' to index into the page table. `page_table[p]`

3.  **Check Valid Bit:** The page table entry (PTE) is checked to determine if the page is valid (i.e., present in physical memory).

    *   **If Valid Bit is True:**  The PTE contains the frame number 'f'. The physical address is then calculated as (f, d).

    *   **If Valid Bit is False (Page Table Miss):** A page table miss (or page fault) occurs. The OS will need to load the required page from disk into a frame.  In our simulation, we will simply output "Page Table Miss!".

4.  **Calculate Physical Address:** If the page is valid, the physical address is calculated by combining the frame number 'f' from the page table entry with the page offset 'd' from the virtual address. The physical address becomes (f, d).

5.  **Access Memory:** The CPU then uses the physical address to access the required data in physical memory.

## 3. Program Implementation:

Your program will take three command-line arguments:

1.  **Page Size:** The size of a page (and frame) in bytes (e.g., 4096).
2.  **Virtual Address:** The virtual address to translate (e.g., 8192).
3.  **Page Table:** A string representing the page table.  For example: "1,2,-1,3".  Each comma-separated value represents the frame number associated with the page table index.  A value of -1 indicates that the page is not present (a page table miss).

**Example Command Line:**

```bash
./address_translator 4096 8192 "1,2,-1,3"
```

**Program Logic:**

1.  **Parse Command Line Arguments:**
    *   Convert the page size and virtual address arguments to integers.
    *   Parse the page table string into an array of integers. Use `-1` to represent an invalid entry (page not present in memory).

2.  **Calculate Page Number and Offset:**
    *   **Page Number (p) = Virtual Address / Page Size**
    *   **Offset (d) = Virtual Address % Page Size**

3.  **Lookup Page Table:**
    *   Check if the page number 'p' is a valid index within the page table array. If `p` is out of bounds (greater than or equal to the size of the page table array), declare a page table miss.
    *   Retrieve the frame number from the page table using the page number as an index:  `frame_number = page_table[p]`.

4.  **Handle Page Table Miss:**
    *   If the `frame_number` is equal to -1 (or any predefined value indicating a miss), print "Page Table Miss!".

5.  **Calculate and Output Physical Address:**
    *   If the `frame_number` is valid (not a miss), the physical address is `<frame_number, offset>`.  Output the result in this format.

**Example C Code Snippet (Illustrative):**

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(int argc, char *argv[]) {
  if (argc != 4) {
    fprintf(stderr, "Usage: %s <page_size> <virtual_address> <page_table>\n", argv[0]);
    return 1;
  }

  int page_size = atoi(argv[1]);
  int virtual_address = atoi(argv[2]);
  char *page_table_str = argv[3];

  // Parse page table string into an array
  int page_table[100]; // Assuming a maximum of 100 page table entries.  Dynamically allocate if needed.
  int page_table_size = 0;
  char *token = strtok(page_table_str, ",");
  while (token != NULL) {
    page_table[page_table_size++] = atoi(token);
    token = strtok(NULL, ",");
  }

  // Calculate page number and offset
  int page_number = virtual_address / page_size;
  int offset = virtual_address % page_size;

  // Lookup page table
  if (page_number >= page_table_size) {
    printf("Page Table Miss!\n");
    return 0;
  }

  int frame_number = page_table[page_number];

  // Handle page table miss
  if (frame_number == -1) {
    printf("Page Table Miss!\n");
    return 0;
  }

  // Output physical address
  printf("<%d, %d>\n", frame_number, offset);

  return 0;
}
```

**Explanation of the C Code Snippet:**

*   **Includes:** Includes necessary header files for input/output, standard library functions, and string manipulation.
*   **Argument Parsing:**  Checks for the correct number of command-line arguments and converts them to the appropriate data types (integer for page size and virtual address, string for the page table).
*   **Page Table Parsing:**  Parses the comma-separated string representation of the page table into an integer array. The `strtok()` function is used to tokenize the string.  **Important:**  This example uses a fixed-size page table array. In a more robust solution, you would dynamically allocate the page table based on the number of entries.
*   **Calculation of Page Number and Offset:**  Calculates the page number and offset from the virtual address and page size.
*   **Page Table Lookup and Miss Handling:** Checks if the page number is within the bounds of the page table.  If not, a "Page Table Miss!" message is printed. Then, it retrieves the frame number from the page table. If the frame number is -1, indicating a miss, "Page Table Miss!" is printed.
*   **Output of Physical Address:**  If the frame number is valid, the physical address (frame number, offset) is printed to the console.

**Important Considerations:**

*   **Error Handling:** The provided code snippet offers basic error handling.  You should add more comprehensive error handling, such as checking for invalid input values (e.g., negative page size, non-numeric input).
*   **Dynamic Memory Allocation:** For a more general solution, use dynamic memory allocation (`malloc`, `calloc`, `realloc`) to create the page table array instead of using a fixed-size array.  This will allow your program to handle page tables of varying sizes.  You'll need to calculate the size of the page table based on the input string.
*   **Language Choice:**  While the example uses C, you can implement this program in any language you are comfortable with (e.g., Python, Java, C++).  The underlying logic remains the same.

## 5. Practice Questions/Exercises:

1.  **Question:** What are the benefits of using paging?
    *   **Answer:** Paging allows for non-contiguous allocation of physical memory, which reduces external fragmentation. It also supports virtual memory, allowing processes to execute even if they are larger than the available physical memory.  It allows for better memory utilization and protection.

2.  **Question:**  If the page size is 2048 bytes and the virtual address is 6000, what are the page number and offset?
    *   **Answer:** Page Number = 6000 / 2048 = 2.  Offset = 6000 % 2048 = 1904.

3.  **Question:** Explain what a page table miss is and what happens when it occurs.
    *   **Answer:** A page table miss occurs when the page number is not found in the page table or if the entry indicates the page is not present in memory (e.g., valid bit is false or frame number is -1). In a real OS, this triggers a page fault. The OS then locates the page on disk, finds a free frame in physical memory, loads the page into the frame, updates the page table entry with the new frame number, and resumes the process. In this simulation, we simply output "Page Table Miss!".

4.  **Question:**  Given a page size of 1024 bytes, a virtual address of 4500 bytes, and a page table with the following entries: `[2, 4, -1, 1]`, what is the physical address?
    *   **Answer:**
        *   Page Number = 4500 / 1024 = 4
        *   Offset = 4500 % 1024 = 412
        *   Since the page table only has entries up to index 3, accessing index 4 results in "Page Table Miss!"

5.  **Question:** How does the size of a page affect the degree of internal fragmentation?
    *   **Answer:**  A larger page size leads to increased internal fragmentation because a page might contain unused space at the end.  A smaller page size reduces internal fragmentation but increases the overhead of maintaining the page table (because there are more pages).
