# OPERATING SYSTEMS LAB: Module 14 - Paging Address Translation Simulation

## Topic: Simulate Address Translation in Paging Scheme

### Description:

This module focuses on simulating the address translation process in a paging scheme. The program will receive three command-line arguments, which will be used to determine the physical address corresponding to a logical address.  The goal is to understand how a virtual address (logical address) is translated into a physical address using page tables.

### Learning Outcomes:

*   Understand the fundamental concepts of paging and its importance in memory management.
*   Be able to describe the process of address translation in a paging scheme.
*   Implement a program that simulates the address translation using page tables.
*   Understand the role of the Page Table Base Register (PTBR).
*   Interpret command-line arguments and use them to perform address translation.
*   Calculate page offsets and page numbers from logical addresses.
*   Handle invalid page numbers (page faults).

### 1. Key Concepts and Definitions:

*   **Paging:** A memory management scheme that divides the logical address space of a process into fixed-size blocks called pages and divides the physical memory into fixed-size blocks called frames.

*   **Page:** A fixed-size block of logical memory (e.g., 4KB).

*   **Frame:** A fixed-size block of physical memory (e.g., 4KB). Pages are loaded into frames.

*   **Logical Address (Virtual Address):** An address generated by the CPU. It consists of two parts:
    *   **Page Number (p):** Used as an index into the page table.
    *   **Page Offset (d):** The displacement within the page.

*   **Physical Address:** The actual address in main memory. It consists of two parts:
    *   **Frame Number (f):** Identifies the frame in physical memory.
    *   **Page Offset (d):** The same as the page offset in the logical address.  The page offset remains unchanged during address translation.

*   **Page Table:** A table that maps page numbers to frame numbers.  Each process has its own page table.

*   **Page Table Base Register (PTBR):** A register that holds the base address of the page table for the current process.

*   **Page Table Entry (PTE):** Each entry in the page table contains information about a particular page, including the frame number if the page is in memory, and other control bits (e.g., valid/invalid bit, protection bits).

*   **Translation Lookaside Buffer (TLB):** A small, fast cache that stores recent page-to-frame mappings. It speeds up the address translation process. (Not covered in this simulation but important to know)

*   **Page Fault:** An exception that occurs when a process tries to access a page that is not currently in memory (i.e., the page is not mapped to a frame in the page table). The operating system must then retrieve the page from secondary storage (e.g., disk) and load it into a frame.

### 2. Address Translation Process:

The address translation process in a paging scheme can be summarized as follows:

1.  The CPU generates a logical address (p, d).
2.  The page number (p) is used as an index into the page table.
3.  The page table entry (PTE) at index `p` is retrieved.
4.  The PTE contains the frame number (f).
5.  The physical address is formed by combining the frame number (f) with the page offset (d): (f, d).

**Diagram:**

```
  Logical Address (Virtual Address)
  ----------------------------------
  |     Page Number (p)     | Page Offset (d) |
  ----------------------------------

  Page Table (Indexed by Page Number p)
  ----------------------------------
  | PTE[0] |
  | PTE[1] |
  | ...    |
  | PTE[p] |  -----> Contains Frame Number (f)
  | ...    |
  ----------------------------------

  Physical Address
  ----------------------------------
  |    Frame Number (f)    | Page Offset (d) |
  ----------------------------------
```

### 3. Command-Line Arguments and Simulation Implementation

In this simulation, the program receives three command-line arguments:

1.  **Page Size:** The size of a page (and frame) in bytes.  This is usually a power of 2 (e.g., 4096, representing 4KB).
2.  **Logical Address:** The virtual address to be translated.
3.  **Page Table:** A representation of the page table. This could be a string of comma-separated frame numbers.  `-1` can indicate that a page is not in memory (invalid).

**Example:**

```bash
./paging_simulator 4096 8196 "2, -1, 0, 5"
```

*   **Page Size:** 4096 bytes (4KB)
*   **Logical Address:** 8196
*   **Page Table:** Page 0 is in frame 2, page 1 is not in memory, page 2 is in frame 0, and page 3 is in frame 5.

**Steps for Simulation:**

1.  **Parse Command-Line Arguments:**  Retrieve the page size, logical address, and page table from the command-line arguments.  Error handling is crucial here.  Ensure the arguments are of the correct type and format.
2.  **Calculate Page Number and Page Offset:**
    *   Page Number = Logical Address / Page Size
    *   Page Offset = Logical Address % Page Size
3.  **Access the Page Table:**  Use the page number as an index into the page table.
4.  **Check for Validity:**  Check if the page is valid (i.e., present in memory).  This is often done by checking if the frame number in the PTE is a valid value (e.g., not -1).
5.  **Translate Address:** If the page is valid, combine the frame number from the page table and the page offset to create the physical address.
    *   Physical Address = (Frame Number * Page Size) + Page Offset
6.  **Handle Page Fault (if necessary):** If the page is invalid, indicate a page fault.  In a real operating system, this would trigger the OS to load the page from disk.  In this simulation, you will just print an error message.
7.  **Output Result:** Print the physical address or indicate a page fault.

**Example Code (Conceptual - C):**

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(int argc, char *argv[]) {
  if (argc != 4) {
    fprintf(stderr, "Usage: %s <page_size> <logical_address> <page_table>\n", argv[0]);
    return 1;
  }

  // 1. Parse Command-Line Arguments
  int page_size = atoi(argv[1]);
  int logical_address = atoi(argv[2]);
  char *page_table_str = argv[3];

  // 2. Parse Page Table (Example: "2, -1, 0, 5")
  //    This part needs more robust error handling and parsing!
  int page_table[10]; // Assuming a maximum of 10 pages
  int num_pages = 0;
  char *token = strtok(page_table_str, ",");
  while (token != NULL && num_pages < 10) {
    page_table[num_pages++] = atoi(token);
    token = strtok(NULL, ",");
  }

  // 3. Calculate Page Number and Page Offset
  int page_number = logical_address / page_size;
  int page_offset = logical_address % page_size;

  // 4. Access Page Table and Check Validity
  if (page_number < 0 || page_number >= num_pages) {
    fprintf(stderr, "Error: Invalid page number: %d\n", page_number);
    return 1;
  }

  int frame_number = page_table[page_number];

  // 5. Handle Page Fault
  if (frame_number == -1) {
    printf("PAGE FAULT: Page %d is not in memory.\n", page_number);
    return 0;
  }

  // 6. Translate Address
  int physical_address = (frame_number * page_size) + page_offset;

  // 7. Output Result
  printf("Logical Address: %d\n", logical_address);
  printf("Page Number: %d\n", page_number);
  printf("Page Offset: %d\n", page_offset);
  printf("Frame Number: %d\n", frame_number);
  printf("Physical Address: %d\n", physical_address);

  return 0;
}
```

**Important Considerations for Implementation:**

*   **Error Handling:**  The code above is a simplified example.  Robust error handling is crucial:
    *   Check if the correct number of command-line arguments is provided.
    *   Validate the page size (ensure it's a power of 2).
    *   Validate the logical address (ensure it's non-negative).
    *   Validate the page table entries (ensure frame numbers are within valid ranges, and the page table string is correctly formatted).
*   **Page Table Representation:** The example uses a simple integer array for the page table.  You might need to use more sophisticated data structures if you need to simulate more complex page table features (e.g., protection bits).
*   **Memory Allocation:**  If you are using dynamic memory allocation, be sure to deallocate memory to avoid memory leaks.

### 5. Practice Questions / Exercises:

**Question 1:**

What is the physical address for the logical address 5000, given a page size of 1024 and the following page table: `4, 7, 2, 9, 1, 6`?

**Answer 1:**

*   Page Size: 1024
*   Logical Address: 5000
*   Page Table: `4, 7, 2, 9, 1, 6`

Calculations:

*   Page Number = 5000 / 1024 = 4
*   Page Offset = 5000 % 1024 = 912
*   Frame Number = page_table[4] = 1
*   Physical Address = (1 * 1024) + 912 = 1936

**Question 2:**

Given a page size of 2048 and a page table `0, -1, 3, 5`, what happens when you try to access the logical address 3072?

**Answer 2:**

*   Page Size: 2048
*   Logical Address: 3072
*   Page Table: `0, -1, 3, 5`

Calculations:

*   Page Number = 3072 / 2048 = 1
*   Page Offset = 3072 % 2048 = 1024
*   Frame Number = page_table[1] = -1

Result: Page Fault. The page with page number 1 is not present in memory.

**Question 3:**

If a system has 64KB of physical memory and a page size of 512 bytes, how many frames are there?

**Answer 3:**

*   Physical Memory Size = 64 KB = 64 * 1024 = 65536 bytes
*   Page Size = 512 bytes

Number of Frames = Physical Memory Size / Page Size = 65536 / 512 = 128 frames
