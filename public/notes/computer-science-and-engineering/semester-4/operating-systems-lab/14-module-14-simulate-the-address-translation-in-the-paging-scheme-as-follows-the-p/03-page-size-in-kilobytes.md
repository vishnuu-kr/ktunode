## Operating Systems Lab: Module 14 - Paging Address Translation Simulation

**Topic:** Simulate the address translation in the paging scheme. Program receives three command line arguments: page size (in kilobytes).

**Learning Outcomes:**

*   Understand the concept of paging and its role in memory management.
*   Explain the address translation process in paging.
*   Implement a program to simulate paging address translation, taking page size as a command-line argument.
*   Calculate physical addresses from logical (virtual) addresses using a page table.
*   Understand the role of page tables in mapping virtual pages to physical frames.
*   Identify potential errors and issues in address translation.

**1. Introduction to Paging**

*   **Definition:** Paging is a memory management scheme that divides both the logical address space (program's view of memory) and the physical address space (actual RAM) into fixed-size blocks called *pages* and *frames*, respectively.

*   **Key Concepts:**
    *   **Page:** A fixed-size block of logical (virtual) memory.
    *   **Frame:** A fixed-size block of physical memory (RAM). Page size and frame size are *always equal*.
    *   **Page Table:** A data structure that maps logical pages to physical frames.  It's essentially an array where each entry corresponds to a page number and contains the frame number where the page is located in physical memory.
    *   **Logical Address:** An address generated by the CPU (virtual address).  It's composed of two parts:
        *   **Page Number (p):** Used as an index into the page table.
        *   **Page Offset (d):** Offset within the page.
    *   **Physical Address:** The actual address in RAM where the data is located. It's composed of two parts:
        *   **Frame Number (f):** Obtained from the page table entry corresponding to the page number.
        *   **Frame Offset (d):** Same as the page offset, as pages and frames are the same size.

*   **Why Paging?**
    *   **Solves External Fragmentation:**  No longer requires contiguous memory allocation, eliminating external fragmentation.
    *   **Allows Non-Contiguous Allocation:** Pages of a process can be scattered throughout physical memory.
    *   **Supports Larger Virtual Memory Space:** Programs can use more memory than physically available, enabling efficient memory utilization.

**2. Address Translation Process**

*   **Steps:**
    1.  The CPU generates a logical address (page number, page offset).
    2.  The page number is used as an index into the page table.
    3.  The page table entry at that index contains the corresponding frame number.
    4.  The frame number is combined with the page offset to form the physical address.
    5.  The physical address is used to access the desired memory location in RAM.

*   **Diagram:**

    ```
    Logical Address: | Page Number (p) | Page Offset (d) |
                     -------------------------------------
                     |       CPU       |
                     -------------------------------------
                                    |
                                    | Page Table Lookup
                                    V
    Page Table:     | Page Number | Frame Number (f) | Other Information |
                    |-------------|--------------------|-------------------|
                                    ^
                                    |
                                    | Frame Number (f)
                                    V
    Physical Address: | Frame Number (f) | Frame Offset (d) |
                     ---------------------------------------
                     |                  RAM                |
                     ---------------------------------------
    ```

*   **Mathematical Representation:**

    *   Let `page_size` be the size of a page (and frame) in bytes.
    *   Let `logical_address` be the logical address we want to translate.

    1.  **Calculate the page number:** `page_number = logical_address / page_size`
    2.  **Calculate the page offset:** `page_offset = logical_address % page_size`
    3.  **Look up the frame number in the page table:** `frame_number = page_table[page_number]`
    4.  **Calculate the physical address:** `physical_address = (frame_number * page_size) + page_offset`

**3. Simulation Implementation (C/C++)**

This section provides a C/C++ code outline for simulating the paging address translation process.

```c++
#include <iostream>
#include <vector>
#include <cstdlib> // for atoi

using namespace std;

int main(int argc, char *argv[]) {
    // 1. Get page size from command line arguments
    if (argc != 2) {
        cerr << "Usage: " << argv[0] << " <page_size_in_KB>" << endl;
        return 1;
    }

    int page_size_kb = atoi(argv[1]); // Convert string to integer
    int page_size = page_size_kb * 1024; // Convert KB to bytes

    // 2. Define the number of pages and frames (example values)
    int num_pages = 16; // Example: 16 virtual pages
    int num_frames = 8; // Example: 8 physical frames

    // 3. Create a page table (example mapping)
    vector<int> page_table(num_pages, -1); // Initialize with -1 (invalid frame)
    // Example Mapping:
    page_table[0] = 3; // Page 0 is in Frame 3
    page_table[1] = 5; // Page 1 is in Frame 5
    page_table[2] = 7; // Page 2 is in Frame 7
    page_table[3] = 1; // Page 3 is in Frame 1


    // 4. Input a logical address from the user
    int logical_address;
    cout << "Enter a logical address: ";
    cin >> logical_address;

    // 5. Calculate page number and page offset
    int page_number = logical_address / page_size;
    int page_offset = logical_address % page_size;

    // 6. Check if the page number is valid
    if (page_number >= num_pages || page_number < 0) {
        cerr << "Error: Invalid page number." << endl;
        return 1;
    }

    // 7. Check if the page is in memory (check if the frame number is valid)
    if (page_table[page_number] == -1) {
        cerr << "Error: Page fault! Page is not in memory." << endl;
        return 1;
    }

    // 8. Translate to physical address
    int frame_number = page_table[page_number];
    int physical_address = (frame_number * page_size) + page_offset;

    // 9. Output the results
    cout << "Logical Address: " << logical_address << endl;
    cout << "Page Number: " << page_number << endl;
    cout << "Page Offset: " << page_offset << endl;
    cout << "Frame Number: " << frame_number << endl;
    cout << "Physical Address: " << physical_address << endl;

    return 0;
}
```

*   **Explanation:**

    1.  **Command Line Argument:**  The program expects the page size (in KB) as a command line argument.  `atoi()` converts the string argument to an integer.  Error handling is included for incorrect usage.
    2.  **Page and Frame Numbers:**  Example values are used for `num_pages` and `num_frames`.  In a real system, these would be determined by the system's configuration.
    3.  **Page Table:** A `vector<int>` is used to represent the page table. The index is the page number, and the value at that index is the corresponding frame number. `-1` indicates that the page is not currently in memory (page fault).
    4.  **Logical Address Input:**  The program prompts the user to enter a logical address.
    5.  **Calculation:** The page number and page offset are calculated using division and the modulo operator (`%`).
    6.  **Validation:** The program checks if the page number is within the valid range.
    7.  **Page Fault Handling:** It checks if the page is present in memory (frame number is not -1).  A real OS would handle the page fault by loading the page from disk.
    8.  **Address Translation:** The physical address is calculated.
    9.  **Output:**  The program displays the logical address, page number, page offset, frame number, and physical address.

**4. Error Handling and Issues**

*   **Invalid Page Number:**  The page number exceeds the maximum number of pages.  This indicates a program trying to access memory outside of its allocated virtual address space.
*   **Page Fault:** The page is not present in physical memory.  This means the page table entry is marked as invalid (e.g., -1 in our example).  The OS needs to handle the page fault by loading the page from disk (swapping).
*   **Protection Fault:** The page exists in memory, but the process doesn't have the necessary permissions to access it (e.g., trying to write to a read-only page).  Page table entries often include protection bits to control access.
*   **TLB Miss:** Translation Lookaside Buffer (TLB) is a cache that stores recent translations. If the translation is not found in the TLB, it's a TLB miss, which increases address translation time.

**5. Practice Questions/Exercises**

1.  **Question:**  Assume a page size of 4KB and a logical address of 20480 bytes. What are the page number and page offset?
    *   **Answer:**
        *   Page Size = 4KB = 4096 bytes
        *   Page Number = 20480 / 4096 = 5
        *   Page Offset = 20480 % 4096 = 0

2.  **Question:**  Given a page size of 2KB, a page number of 3, and a frame number of 6, what is the physical address corresponding to a logical address with an offset of 512 bytes?
    *   **Answer:**
        *   Page Size = 2KB = 2048 bytes
        *   Frame Number = 6
        *   Physical Address = (6 * 2048) + 512 = 12288 + 512 = 12800 bytes

**6. Important Points to Remember**

*   Paging eliminates external fragmentation.
*   Page size and frame size are equal.
*   The page table maps logical pages to physical frames.
*   The logical address is divided into page number and page offset.
*   The physical address is divided into frame number and frame offset.
*   The page offset is the same in both the logical and physical address.
*   Page faults occur when a page is not in memory.
*   Address translation is performed by the Memory Management Unit (MMU).
*   The TLB caches recent address translations to improve performance.
