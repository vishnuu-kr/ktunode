## COMPUTER ORGANIZATION AND ARCHITECTURE: MODULE 4 - INPUT/OUTPUT: Interrupt Driven I/O

**Module Overview:** This module covers various aspects of input/output (I/O) operations in computer systems. We'll explore different I/O techniques, focusing on the advantages and disadvantages of each. This section will delve into Interrupt Driven I/O.

**Topic:** Interrupt Driven I/O

**Learning Outcomes:**

*   Understand the limitations of Programmed I/O.
*   Explain the concept of interrupt driven I/O and its advantages over Programmed I/O.
*   Describe the interrupt handling mechanism, including interrupt vectors and interrupt service routines (ISRs).
*   Differentiate between different interrupt types (hardware vs. software, vectored vs. non-vectored).
*   Analyze the process of handling multiple interrupts (priority interrupts and daisy chaining).
*   Understand the importance of interrupt masking and priority levels.
*   Illustrate interrupt driven I/O with practical examples.

### 1. The Problem with Programmed I/O

*   **Definition:** In Programmed I/O, the CPU constantly checks the status of the I/O device.
*   **How it works:** The CPU repeatedly polls the I/O device's status register to see if it's ready for data transfer.
*   **Limitations:**
    *   **CPU Time Wastage:** The CPU spends most of its time in a busy-wait loop, waiting for the I/O device. This wastes valuable CPU cycles that could be used for other tasks.
    *   **Inefficiency:** The CPU cannot perform other useful tasks while waiting for the I/O device to become ready.
    *   **Slow Overall System Performance:**  System performance is degraded because the CPU is tied up with I/O operations.

**Example:** Consider reading data from a keyboard using programmed I/O. The CPU would continuously check if a key has been pressed. Until a key is pressed, the CPU does nothing else.

### 2. Introducing Interrupt Driven I/O

*   **Definition:** Interrupt driven I/O allows the I/O device to signal (interrupt) the CPU when it is ready for data transfer, rather than the CPU constantly polling the device.
*   **How it works:**
    1.  The CPU initiates an I/O operation and continues executing other tasks.
    2.  The I/O device performs its operation.
    3.  When the I/O device is ready (e.g., data is available, an operation is complete), it sends an interrupt signal to the CPU.
    4.  The CPU suspends its current task, saves its state (registers, program counter), and executes a special routine called an Interrupt Service Routine (ISR) or interrupt handler.
    5.  The ISR handles the I/O operation.
    6.  After the ISR completes, the CPU restores its previous state and resumes the interrupted task.

*   **Advantages over Programmed I/O:**
    *   **Improved CPU Utilization:** The CPU can perform other tasks while waiting for I/O devices, increasing overall system efficiency.
    *   **Better Responsiveness:** The CPU can respond to I/O requests immediately when they occur, leading to faster I/O processing.
    *   **Increased System Throughput:**  The system can handle more I/O requests in a given period.
*   **Key Concepts:**
    *   **Interrupt:** A signal generated by a hardware or software event that causes the CPU to suspend its current task and execute a specific routine.
    *   **Interrupt Request (IRQ):** The actual signal sent by the I/O device to the CPU to request an interrupt.
    *   **Interrupt Controller:** A hardware component that manages interrupt requests from multiple devices and prioritizes them.
    *   **Interrupt Handler (ISR):** A software routine that is executed in response to an interrupt.
    *   **Interrupt Vector:** An address in memory that contains the starting address of the ISR for a particular interrupt.

**Example:**  Imagine you are cooking (the main task) and the doorbell rings (an interrupt). You stop cooking, answer the door (ISR), and then go back to cooking.  Without the doorbell, you'd have to keep checking the door every few seconds (programmed I/O) which would be inefficient.

### 3. The Interrupt Handling Mechanism

*   **Steps involved in interrupt handling:**

    1.  **Interrupt Request:** An I/O device asserts an interrupt request signal (IRQ) to the interrupt controller.
    2.  **Interrupt Acknowledgment:** The CPU, upon detecting an interrupt, asserts an interrupt acknowledge signal (INTA) to the interrupt controller.
    3.  **Interrupt Vector Transfer:** The interrupt controller provides the interrupt vector to the CPU. This vector points to the ISR in memory.
    4.  **Context Switching:** The CPU saves its current state (program counter, registers, etc.) onto the stack. This is known as a context switch.
    5.  **ISR Execution:** The CPU loads the starting address of the ISR from the interrupt vector and begins executing the ISR code.
    6.  **I/O Operation:** The ISR handles the I/O operation (e.g., reading data from the device, writing data to the device).
    7.  **Restore Context:** The ISR restores the CPU's previous state from the stack.
    8.  **Return from Interrupt:** The ISR executes a "return from interrupt" (RTI) instruction, which returns control to the interrupted program.
*   **Interrupt Vector Table:**
    *   A table in memory that contains the addresses of the ISRs for each possible interrupt.
    *   The interrupt vector is used as an index into this table to find the appropriate ISR's address.
    *   The location of the interrupt vector table is determined by the operating system or system architecture.
*   **Interrupt Service Routine (ISR):**
    *   A special routine designed to handle a specific interrupt.
    *   The ISR performs the necessary actions to service the interrupt, such as reading data from an I/O device or acknowledging the interrupt.
    *   ISRs are typically short and efficient to minimize the time the CPU spends servicing interrupts.
    *   An ISR must save and restore all registers it uses to avoid corrupting the state of the interrupted program.

### 4. Types of Interrupts

*   **Hardware Interrupts:** Generated by hardware devices. Examples include:
    *   **External Interrupts:** Signals from external devices (e.g., keyboard, mouse, network card).
    *   **Internal Interrupts (Traps):** Caused by exceptional conditions within the CPU (e.g., division by zero, overflow).
*   **Software Interrupts:** Generated by software instructions.  Often used to invoke system calls (e.g., requesting services from the operating system).
*   **Vectored Interrupts:** The interrupting device directly provides the interrupt vector to the CPU.  This is more efficient as the CPU doesn't need to poll the device to determine which interrupt occurred.
*   **Non-Vectored Interrupts:** The interrupting device signals the CPU that an interrupt has occurred, but does not provide the interrupt vector. The CPU must then poll the devices to determine the source of the interrupt.  This is less efficient.

**Example:**  Pressing a key on the keyboard generates a hardware (external, vectored) interrupt. A division by zero error generates a hardware (internal, typically non-vectored) interrupt.  A system call instruction (e.g., `int 80h` in x86) generates a software interrupt.

### 5. Handling Multiple Interrupts

*   **Challenges:** What happens if multiple devices interrupt the CPU simultaneously? How do we ensure that important interrupts are handled promptly?
*   **Priority Interrupts:**
    *   Each interrupt is assigned a priority level.
    *   The interrupt controller prioritizes interrupt requests based on their priority.
    *   If multiple interrupts occur simultaneously, the interrupt with the highest priority is handled first.
    *   The CPU can be configured to only respond to interrupts above a certain priority level.
*   **Daisy Chaining:**
    *   Devices are connected in a chain, with the interrupt request signal passing through each device.
    *   If a device requires an interrupt, it blocks the interrupt request signal and places its device ID on the bus.
    *   The CPU acknowledges the interrupt and the device with the highest priority (closest to the CPU) responds.
    *   Simpler to implement than priority interrupts, but slower due to the propagation delay along the chain.

**Example:**  Imagine a fire alarm (high priority) and a phone ringing (lower priority). The fire alarm should be handled first.

### 6. Interrupt Masking and Priority Levels

*   **Interrupt Masking:**
    *   The ability to disable or ignore certain interrupts.
    *   Used to prevent low-priority interrupts from interrupting critical operations.
    *   Implemented using an interrupt mask register, which contains bits that correspond to different interrupt sources. Setting a bit in the mask register disables the corresponding interrupt.
*   **Priority Levels:**
    *   Allow the system to prioritize interrupt requests and handle the most important interrupts first.
    *   Implemented using priority registers or interrupt controllers that support priority levels.

**Why are they important?**  Masking and priority levels prevent less important interrupts from delaying critical tasks.  For instance, a real-time system processing sensor data for a safety-critical system would mask out lower-priority interrupts like printing to a log file during critical data processing.

### 7. Interrupt Driven I/O Examples

*   **Keyboard Input:**  When a key is pressed, the keyboard controller sends an interrupt to the CPU. The ISR reads the key code from the keyboard buffer and stores it in memory.
*   **Disk I/O:**  When the disk controller completes a read or write operation, it sends an interrupt to the CPU. The ISR updates the system's data structures to reflect the completion of the I/O operation.
*   **Network Interface Card (NIC):**  When the NIC receives a packet, it generates an interrupt. The ISR reads the packet from the NIC's buffer and processes it.
*   **Timer Interrupts:**  A timer chip generates interrupts at regular intervals. These interrupts can be used to implement time-slicing for multitasking operating systems.

### 8. Important Points to Remember

*   Interrupt driven I/O is more efficient than programmed I/O because it allows the CPU to perform other tasks while waiting for I/O devices.
*   The interrupt handling mechanism involves the CPU saving its state, executing an ISR, and restoring its state.
*   Interrupts can be hardware or software, vectored or non-vectored.
*   Priority interrupts and daisy chaining are used to handle multiple interrupts.
*   Interrupt masking and priority levels are used to prevent low-priority interrupts from interrupting critical operations.
*   ISRs should be short and efficient to minimize the time the CPU spends servicing interrupts.

7.  **Question:**  A system uses interrupt-driven I/O. The CPU is currently executing a program that calculates the trajectory of a rocket launch. Suddenly, a network card receives data and sends an interrupt.  Describe what happens in detail, from the moment the interrupt is generated to the point where the CPU resumes calculating the rocket trajectory.  Assume a vectored interrupt.
    **Answer:**
    1.  The network card sends an interrupt request (IRQ) signal to the interrupt controller.
    2.  The interrupt controller detects the IRQ and, if the network card's interrupt is not masked and its priority is high enough, asserts an interrupt request to the CPU.
    3.  The CPU finishes the current instruction, then acknowledges the interrupt by sending an interrupt acknowledge (INTA) signal to the interrupt controller.
    4.  The network card (or the interrupt controller based on the network card's vector) places the interrupt vector onto the data bus.
    5.  The CPU reads the interrupt vector.
    6.  The CPU pushes the current program counter (PC) and other relevant registers (status register, potentially some general-purpose registers depending on the architecture and the ABI) onto the stack. This saves the current state of the rocket trajectory program.
    7.  The CPU loads the address of the network card's ISR from the interrupt vector table into the PC.
    8.  The CPU begins executing the network card's ISR.
    9.  The ISR reads the data from the network card's buffer and processes it (e.g., stores the data in a memory buffer).  The ISR also likely acknowledges the interrupt to the network card to prevent it from repeatedly asserting the interrupt.
    10. The ISR restores the saved registers from the stack, including the PC.
    11. The ISR executes a "return from interrupt" (RTI) instruction.
    12. The CPU resumes execution of the rocket trajectory program from the point where it was interrupted. The program continues its calculations as if nothing happened.
