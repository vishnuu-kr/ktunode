## COMPUTER ORGANIZATION AND ARCHITECTURE - Module 3: Memory Systems: Introduction - Page Table

**Learning Outcomes:**

*   Understand the purpose and functionality of a Page Table.
*   Describe the structure of a Page Table, including Page Table Entry (PTE) components.
*   Explain the relationship between Virtual Addresses, Page Numbers, and Page Offsets in the context of paging.
*   Explain how the Page Table is used in address translation (Virtual Address to Physical Address).
*   Understand the concept of multi-level page tables and their benefits.
*   Discuss Translation Lookaside Buffer (TLB) as a cache for Page Table entries and its role in improving performance.

**1. Introduction: The Need for Paging and Page Tables**

*   **Virtual Memory:** Allows programs to address more memory than is physically available. The operating system manages a virtual address space for each process, mapping virtual addresses to physical addresses.
*   **Paging:** Divides both the virtual address space of a process and the physical memory into fixed-size blocks called *pages* and *frames*, respectively.  This facilitates non-contiguous allocation of memory.
    *   **Pages:** Fixed-size blocks of virtual memory.
    *   **Frames:** Fixed-size blocks of physical memory.
*   **Why Paging?**
    *   **Efficient Memory Utilization:** Avoids external fragmentation by using fixed-size blocks.
    *   **Easier Memory Management:** Simplifies allocation and deallocation.
    *   **Allows Larger Programs:**  A program can run even if it's larger than physical memory, as only necessary pages are loaded.
    *   **Memory Protection:**  Enables protection mechanisms by controlling access rights to individual pages.
*   **The Role of the Page Table:**  The Page Table is a crucial data structure that maps virtual pages to physical frames.  It's the core component for address translation in a paged virtual memory system.

**2. Purpose and Functionality of a Page Table**

*   **Definition:**  A Page Table is a data structure used by the operating system to store the mapping between virtual page numbers and physical frame numbers.  Each process has its own Page Table (or set of Page Tables).
*   **Functionality:**
    *   **Address Translation:** Translates virtual addresses generated by a program into physical addresses that the memory controller can use to access physical memory.
    *   **Protection:**  Allows the operating system to control access rights to memory at the page level (e.g., read-only, execute-only, read-write).
    *   **Virtual Memory Management:**  Supports features like demand paging (loading pages only when needed), page sharing, and memory protection.

**3. Structure of a Page Table and Page Table Entry (PTE)**

*   **Page Table Organization:** Typically an array-like structure where each entry corresponds to a virtual page.
*   **Page Table Entry (PTE):** Contains information about a specific page. Common fields include:
    *   **Frame Number (Physical Page Number):** The physical frame number in memory where the page is located.  This is the core mapping information.
    *   **Present/Valid Bit:** Indicates whether the page is currently loaded in physical memory.  If the bit is 0 (invalid), it means the page is not present in RAM, and a page fault occurs.
    *   **Protection Bits:** Specify access rights to the page (e.g., read, write, execute).
    *   **Dirty Bit:** Indicates whether the page has been modified since it was loaded into memory.  Used for efficient page replacement.  If the bit is set, the page must be written back to disk before being replaced.
    *   **Reference Bit (Accessed Bit):** Set by the hardware when the page is accessed.  Used by page replacement algorithms to determine which pages are least recently used.
    *   **Other Metadata:** Can include information like caching policies (e.g., write-through, write-back).

**Example PTE Structure:**

| Bit(s) | Field            | Description                                                                     |
| :----- | :--------------- | :------------------------------------------------------------------------------ |
| 20-31   | Frame Number      | Physical frame number in memory (assuming 4KB pages and 4GB physical memory) |
| 1       | Present/Valid Bit | 1 = Page present in memory, 0 = Page not in memory                             |
| 3       | Protection Bits   | Defines access rights (Read, Write, Execute)                                    |
| 1       | Dirty Bit        | 1 = Page has been modified                                                      |
| 1       | Reference Bit    | 1 = Page has been accessed                                                      |

**4. Virtual Addresses, Page Numbers, and Page Offsets**

*   **Virtual Address Structure:** A virtual address is divided into two parts:
    *   **Page Number (Virtual Page Number):**  Used as an index into the Page Table to find the corresponding PTE.
    *   **Page Offset:** Represents the offset within the page. This is the same for both virtual and physical addresses (no translation needed).
*   **Calculating Page Number and Offset:**
    *   Given a page size of 2<sup>N</sup> bytes, the *N* least significant bits of the virtual address represent the page offset.
    *   The remaining bits (most significant bits) represent the page number.

**Example:**

*   **Virtual Address:** 32 bits
*   **Page Size:** 4KB (2<sup>12</sup> bytes)
*   **Page Offset:** 12 bits (least significant bits)
*   **Page Number:** 20 bits (most significant bits)

**5. Address Translation Process**

1.  **Extract Page Number and Offset:** The CPU extracts the page number and offset from the virtual address.
2.  **Access the Page Table:**  The page number is used as an index into the Page Table (stored in memory, often managed by the OS). The location of the Page Table is pointed to by a special register, often called the Page Table Base Register (PTBR) or similar.
3.  **Retrieve the PTE:** The corresponding PTE is retrieved from the Page Table.
4.  **Check the Valid Bit:**  The valid bit in the PTE is checked.
    *   **If Valid Bit = 1:** The page is present in memory. The frame number is extracted from the PTE.
    *   **If Valid Bit = 0:** A *page fault* occurs. The operating system handles the page fault by:
        *   Locating the page on disk.
        *   Finding a free frame in physical memory (or replacing an existing page using a page replacement algorithm).
        *   Loading the page from disk into the frame.
        *   Updating the Page Table entry (setting the valid bit to 1 and updating the frame number).
        *   Restarting the instruction that caused the page fault.
5.  **Construct the Physical Address:** The frame number from the PTE is combined with the original page offset to create the physical address.
6.  **Access Memory:** The physical address is used to access the desired location in physical memory.

**Diagram:**

```
Virtual Address: | Page Number (VPN) | Page Offset |

Page Table: [ PTE0, PTE1, PTE2, ... ]
            ^
            | Index (VPN)

PTE: | Frame Number (PFN) | Valid Bit | Protection Bits | ... |

Physical Address: | Frame Number (PFN) | Page Offset |
```

**6. Multi-Level Page Tables**

*   **Problem with Single-Level Page Tables:**  A large virtual address space requires a large Page Table. This can consume a significant amount of memory, even if the process isn't using all of its virtual address space.
*   **Solution: Multi-Level Page Tables:** Divides the Page Table into multiple levels.
    *   The top-level Page Table (e.g., Page Directory) points to second-level Page Tables.
    *   Second-level Page Tables point to third-level Page Tables, and so on.  The lowest-level Page Table points to the actual frames in physical memory.
*   **Advantages:**
    *   **Reduced Memory Consumption:**  Page Table space is allocated only for the portions of the virtual address space that are actually used.  If a large portion of the virtual address space is unused, the corresponding Page Table entries (and the lower-level tables they would point to) don't need to be created.
    *   **Improved Locality:**  Pages that are accessed together are likely to be located in the same second-level or third-level Page Table, which can improve caching performance.
*   **Disadvantages:**
    *   **Increased Address Translation Overhead:** Multiple memory accesses are required to traverse the multiple levels of the Page Table.  This overhead is mitigated by the TLB.
*   **Example: Two-Level Page Table**
    *   The virtual address is divided into three parts:
        *   **Page Directory Index (PDI):** Index into the Page Directory (top-level table).
        *   **Page Table Index (PTI):** Index into the Page Table (second-level table).
        *   **Page Offset:** Offset within the page.

**Diagram (Two-Level Page Table):**

```
Virtual Address: | Page Directory Index (PDI) | Page Table Index (PTI) | Page Offset |

Page Directory: [ Entry0, Entry1, Entry2, ... ] (Each entry points to a Page Table)
                  ^
                  | Index (PDI)

Page Table: [ PTE0, PTE1, PTE2, ... ]
            ^
            | Index (PTI)

PTE: | Frame Number (PFN) | Valid Bit | Protection Bits | ... |

Physical Address: | Frame Number (PFN) | Page Offset |
```

**7. Translation Lookaside Buffer (TLB)**

*   **Problem:** Accessing the Page Table in main memory for every memory access can be slow.
*   **Solution: TLB (Translation Lookaside Buffer):** A special cache in the Memory Management Unit (MMU) that stores recently used PTEs.
*   **How it Works:**
    1.  When a virtual address is generated, the MMU first checks the TLB to see if the corresponding PTE is present.
    2.  **TLB Hit:** If the PTE is found (TLB hit), the frame number is retrieved from the TLB, and the physical address is constructed directly. This is very fast.
    3.  **TLB Miss:** If the PTE is not found (TLB miss), the MMU accesses the Page Table in main memory to retrieve the PTE (as described in the address translation process). The PTE is then stored in the TLB, replacing an existing entry.
*   **TLB Structure:** Typically a set-associative cache. Each entry contains:
    *   **Virtual Page Number (VPN):** Tag used for matching the virtual page number from the virtual address.
    *   **Physical Frame Number (PFN):** The corresponding physical frame number.
    *   **Valid Bit:** Indicates whether the entry is valid.
    *   **Protection Bits:**  (Optional, may be stored separately) Protection information for the page.
*   **Benefits:**  Significantly improves performance by reducing the number of memory accesses required for address translation. High hit rates are crucial for good performance.
*   **TLB Management:** Can be managed by hardware (hardware TLB) or by the operating system (software TLB).

**Diagram (TLB):**

```
Virtual Address: | Page Number (VPN) | Page Offset |

TLB: [ (VPN1, PFN1, Valid1), (VPN2, PFN2, Valid2), ... ]
     ^
     | Search for VPN in TLB

If TLB Hit:  Retrieve PFN directly.
If TLB Miss:  Access Page Table in memory.
```

**Important Points to Remember:**

*   Page tables are essential for virtual memory management.
*   The Page Table maps virtual page numbers to physical frame numbers.
*   PTEs contain crucial information like the frame number, valid bit, and protection bits.
*   Multi-level page tables reduce memory consumption.
*   TLBs significantly improve performance by caching PTEs.
*   Page faults occur when a page is not present in memory (valid bit = 0).

**Practice Questions/Exercises:**

1.  **Question:**  Assume a system with a 32-bit virtual address space, a 4KB page size, and a 4GB physical memory.  How many bits are used for the page number and page offset? How many entries are in the page table if it is single-level?
    **Answer:**
    *   Page Offset: 12 bits (log<sub>2</sub>(4KB) = log<sub>2</sub>(2<sup>12</sup>) = 12)
    *   Page Number: 32 - 12 = 20 bits
    *   Number of Entries in Page Table: 2<sup>20</sup> = 1,048,576 entries

2.  **Question:** Explain the purpose of the "dirty bit" in a PTE.
    **Answer:** The dirty bit indicates whether the page has been modified since it was loaded into memory. It's used by page replacement algorithms. If a page is dirty, it must be written back to disk before being replaced to avoid losing data. If it's not dirty, it can simply be discarded.

3.  **Question:** What is a page fault, and how is it handled by the operating system?
    **Answer:** A page fault occurs when the CPU tries to access a virtual page that is not currently present in physical memory (the valid bit in the PTE is 0). The OS handles a page fault by:
    1.  Locating the page on disk.
    2.  Finding a free frame in physical memory (or replacing an existing page).
    3.  Loading the page from disk into the frame.
    4.  Updating the PTE to reflect the page's new location and setting the valid bit to 1.
    5.  Restarting the instruction that caused the fault.

4.  **Question:** Why are multi-level page tables used? What are their advantages and disadvantages?
    **Answer:** Multi-level page tables are used to reduce memory consumption, especially when the virtual address space is large but not fully utilized. Advantages: reduced memory footprint, better locality. Disadvantages: increased address translation overhead (mitigated by the TLB).

5.  **Question:** Explain the purpose and functionality of a Translation Lookaside Buffer (TLB).
    **Answer:** The TLB is a cache that stores recently used Page Table Entries (PTEs). Its purpose is to speed up address translation by reducing the need to access the Page Table in main memory for every memory access.  When the CPU needs to translate a virtual address, it first checks the TLB. If the PTE is found (TLB hit), the translation is performed quickly. If the PTE is not in the TLB (TLB miss), the page table must be accessed and the PTE is added to the TLB for future access.
