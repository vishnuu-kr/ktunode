## OPERATING SYSTEMS - Module 3: Memory Management - Address Translation: An Example

**Learning Outcomes:**

*   Understand the need for address translation in virtual memory systems.
*   Explain the steps involved in translating a logical address to a physical address.
*   Identify the roles of the Memory Management Unit (MMU), page table, and TLB (Translation Lookaside Buffer) in address translation.
*   Work through concrete examples of address translation scenarios.
*   Analyze the performance implications of address translation.

**1. Introduction to Address Translation**

*   **What is Address Translation?**  Address translation (also known as address mapping) is the process of converting a *logical address* (also called a virtual address) generated by the CPU into a *physical address* in main memory. This translation is crucial for implementing virtual memory.
*   **Why is Address Translation Necessary?**
    *   **Virtual Memory:**  Virtual memory allows processes to use more memory than is physically available.  Each process has its own virtual address space, which is independent of other processes. Address translation maps these virtual addresses to physical addresses in RAM.
    *   **Memory Protection:**  Address translation allows the operating system to control which physical memory locations a process can access.  This prevents processes from interfering with each other or the OS itself.
    *   **Memory Relocation:**  Address translation allows the OS to move processes in memory without requiring them to be recompiled.  The OS simply updates the address mapping tables.
    *   **Simplified Programming:** Programmers don't need to worry about the absolute physical addresses of data and code, simplifying program development.

**2. Key Concepts and Definitions**

*   **Logical (Virtual) Address:** The address generated by the CPU, as seen by the running process.  This is the address the program uses.
*   **Physical Address:** The actual address in physical memory (RAM) where the data is stored.
*   **Address Space:**
    *   **Logical Address Space:** The set of all logical addresses that a process can generate.
    *   **Physical Address Space:** The set of all physical addresses corresponding to actual physical memory locations.
*   **Memory Management Unit (MMU):**  A hardware component responsible for performing address translation.  It resides between the CPU and main memory.
*   **Page:**  A fixed-size contiguous block of virtual memory.  The size of a page is typically a power of 2 (e.g., 4KB).
*   **Frame:**  A fixed-size contiguous block of physical memory.  A frame is the same size as a page.
*   **Page Table:**  A data structure (typically stored in main memory) that maps virtual pages to physical frames. Each process has its own page table, or a pointer to one shared among processes that share memory.
*   **Page Table Entry (PTE):**  Each entry in the page table contains information about a specific virtual page, including:
    *   **Frame Number:** The physical frame number that the page is mapped to.
    *   **Valid Bit:** Indicates whether the page is currently in physical memory (valid) or on disk (invalid).
    *   **Protection Bits:** Indicate the access rights to the page (e.g., read-only, read-write, execute).
    *   **Reference Bit (Accessed Bit):** Set by the hardware when the page is accessed.  Used for page replacement algorithms.
    *   **Dirty Bit (Modified Bit):** Set by the hardware when the page is written to.  Used for page replacement algorithms.
*   **Translation Lookaside Buffer (TLB):** A high-speed cache that stores recently used page table entries.  It speeds up address translation by reducing the need to access the main memory page table.
*   **TLB Hit:**  When the TLB contains the page table entry for the requested virtual address.
*   **TLB Miss:**  When the TLB does not contain the page table entry for the requested virtual address.

**3. Steps in Address Translation**

1.  **CPU Generates a Logical Address:**  The CPU generates a logical address, which is typically divided into two parts:
    *   **Page Number (p):**  Specifies the virtual page being referenced.
    *   **Page Offset (d):**  Specifies the offset within the page.

2.  **MMU Checks the TLB:** The MMU first checks the TLB to see if the page table entry for the logical page number (p) is present.

3.  **TLB Hit:** If the page table entry is found in the TLB (TLB Hit):
    *   The MMU retrieves the corresponding physical frame number (f) from the TLB entry.
    *   The physical address is calculated by combining the frame number (f) and the page offset (d):  `Physical Address = (f << offset_bits) | d`  (where `offset_bits` is the number of bits used to represent the page offset).
    *   The MMU accesses the physical memory location at the calculated physical address.

4.  **TLB Miss:** If the page table entry is not found in the TLB (TLB Miss):
    *   The MMU consults the page table in main memory.
    *   The page table base register (PTBR) contains the address of the beginning of the page table for the current process.  The page number (p) is used as an index into the page table.
    *   `Page Table Entry Address = PTBR + (p * sizeof(PageTableEntry))`
    *   The MMU retrieves the page table entry from memory.

5.  **Page Table Entry is Valid:** If the valid bit in the page table entry is set:
    *   The MMU retrieves the corresponding physical frame number (f) from the page table entry.
    *   The physical address is calculated by combining the frame number (f) and the page offset (d):  `Physical Address = (f << offset_bits) | d`
    *   The MMU accesses the physical memory location at the calculated physical address.
    *   The MMU also updates the TLB with the new page table entry (if the TLB has space).

6.  **Page Table Entry is Invalid (Page Fault):** If the valid bit in the page table entry is not set:
    *   A **page fault** occurs.
    *   The operating system's page fault handler is invoked.
    *   The OS locates the page on disk.
    *   The OS finds a free frame in physical memory (possibly by replacing an existing page).
    *   The OS loads the page from disk into the free frame.
    *   The OS updates the page table entry to reflect the new location of the page (sets the valid bit to 1 and updates the frame number).
    *   The OS updates the TLB (if possible).
    *   The OS restarts the instruction that caused the page fault.

**4. Example Scenario**

Let's consider a system with the following characteristics:

*   Logical address space: 16 bits (65536 bytes or 64KB)
*   Physical address space: 12 bits (4096 bytes or 4KB)
*   Page size: 512 bytes (2<sup>9</sup> bytes)

Therefore:

*   Page offset: 9 bits (since page size is 2<sup>9</sup>)
*   Page number: 16 bits (total) - 9 bits (offset) = 7 bits (128 pages)
*   Frame number: 12 bits (total physical address) - 9 bits (offset) = 3 bits (8 frames)

Suppose a process generates the logical address `0x1A4B`.  Let's translate this to a physical address.

1.  **Logical Address Breakdown:**
    *   Binary representation of 0x1A4B: `0001 1010 0100 1011`
    *   Page Number (p):  `0001101` (binary) = 13 (decimal)
    *   Page Offset (d): `000 101011` (binary) = 43 (decimal)

2.  **TLB Lookup:**  Let's assume there's a TLB miss.

3.  **Page Table Lookup:**  The MMU consults the page table. Assume the Page Table Base Register (PTBR) points to address 0x1000 in memory. Also assume each PTE is 4 bytes.

    *   The MMU calculates the address of the page table entry:
        `Page Table Entry Address = 0x1000 + (13 * 4) = 0x1034`
    *   The MMU reads the PTE at address 0x1034.

4.  **Page Table Entry:** Suppose the PTE at 0x1034 contains the following information:
    *   Valid Bit: 1 (Page is in memory)
    *   Frame Number (f): 5 (decimal) = `101` (binary)

5.  **Physical Address Calculation:**
    *   The physical address is calculated as follows:
        *   Frame number (f): `101` (binary)
        *   Page offset (d): `000101011` (binary)
        *   Physical Address = `101000101011` (binary) = 0xA2B (hexadecimal) = 2603 (decimal)

Therefore, the logical address `0x1A4B` translates to the physical address `0xA2B`.

**5. Performance Implications of Address Translation**

*   **Overhead:** Address translation introduces overhead because of the need to consult the page table.
*   **TLB:** The TLB is used to mitigate this overhead.  A high TLB hit rate is crucial for good performance.
*   **Effective Access Time (EAT):**  A metric that quantifies the impact of the TLB on memory access time.  It considers the TLB hit rate, TLB access time, and main memory access time.

    *   `EAT = (TLB Hit Rate * TLB Access Time) + (TLB Miss Rate * (TLB Access Time + Memory Access Time))`

    For example, if TLB access time is 10ns, memory access time is 100ns, and the TLB hit rate is 90%, then:

    *   `EAT = (0.9 * 10ns) + (0.1 * (10ns + 100ns)) = 9ns + 11ns = 20ns`

    Without the TLB, the access time would be 100ns. The TLB significantly improves performance.

**6. Practice Questions/Exercises**

1.  **Question:**  A system uses a 32-bit virtual address, a 20-bit physical address, and a page size of 4KB.  How many bits are used for the page offset, page number, and frame number?

    **Answer:**
    *   Page size = 4KB = 2<sup>12</sup> bytes.  Therefore, page offset = 12 bits.
    *   Virtual address = 32 bits.  Page number = 32 - 12 = 20 bits.
    *   Physical address = 20 bits.  Frame number = 20 - 12 = 8 bits.

2.  **Question:**  Explain the difference between a logical address and a physical address.

    **Answer:**  A logical address (also called a virtual address) is the address generated by the CPU, as seen by the running process. A physical address is the actual address in physical memory (RAM) where the data is stored.  The MMU translates logical addresses to physical addresses.

3.  **Question:**  What is the purpose of the TLB?  How does it improve performance?

    **Answer:** The TLB (Translation Lookaside Buffer) is a high-speed cache that stores recently used page table entries. It improves performance by reducing the need to access the main memory page table, which is much slower.  When the TLB contains the required translation (TLB hit), the physical address can be calculated quickly.

4.  **Question:** If the page size is 8KB and the logical address is 0xABCDE, what are the page number and page offset? (Assume a standard hexadecimal representation)

    **Answer:**

    *   8KB = 8 * 1024 bytes = 8192 bytes = 2<sup>13</sup> bytes.
    *   Therefore, the page offset is 13 bits.

    *   Convert the logical address 0xABCDE to binary: `1010 1011 1100 1101 1110`

    *   The last 13 bits are the page offset: `011 1100 1101 1110` = 0x1CEC
    *   The remaining bits are the page number: `1010 1011 1100` = 0xABc

    *   Page Number: 0xABC
    *   Page Offset: 0x1CEC

**7. Important Points to Remember**

*   Address translation is fundamental to virtual memory.
*   The MMU is the hardware component responsible for address translation.
*   The page table maps virtual pages to physical frames.
*   The TLB is a cache that speeds up address translation.
*   Page faults occur when a page is not present in physical memory.
*   TLB hit rate is crucial for performance.
