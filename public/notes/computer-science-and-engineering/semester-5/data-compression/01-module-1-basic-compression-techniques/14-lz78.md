## Data Compression: Module 1 - Basic Compression Techniques - LZ78

**Introduction:**

This document provides detailed study notes on the LZ78 data compression algorithm, a crucial topic in understanding fundamental compression techniques. We will cover key concepts, provide illustrative examples, and include practice questions to solidify your understanding.

**Learning Outcomes:**

By the end of this study session, you should be able to:

*   Understand the fundamental principles of LZ78 compression.
*   Explain how LZ78 creates and uses a dictionary.
*   Encode and decode data using the LZ78 algorithm.
*   Analyze the advantages and disadvantages of LZ78.
*   Compare LZ78 with other compression algorithms (specifically LZ77).

**1. Key Concepts and Definitions:**

*   **LZ78 (Lempel-Ziv 78):** A lossless data compression algorithm that uses a dictionary of previously seen sequences to compress data. It is a dictionary-based compression technique.

*   **Lossless Compression:** A type of data compression that allows the original data to be perfectly reconstructed from the compressed data.

*   **Dictionary:**  A dynamic table of phrases (sequences of characters) that are encountered during the compression process.  New phrases are added to the dictionary as the algorithm processes the input data.

*   **Phrase:** A sequence of characters that forms an entry in the LZ78 dictionary.

*   **Index:** A unique numerical identifier assigned to each phrase in the dictionary.  Often starts at index 0 (representing the null or empty string).

*   **Token:**  A pair of values used to represent a phrase:  `(index, character)`.
    *   `index`: The index of the longest matching phrase in the dictionary.
    *   `character`: The next character in the input stream *after* the matching phrase.  This new character extends the matching phrase to create a new phrase for the dictionary.

**2. How LZ78 Works: The Encoding Process**

The LZ78 encoding process involves building a dictionary on-the-fly as the input data is processed.  Here's a step-by-step explanation:

1.  **Initialization:**
    *   Start with an empty dictionary.  Index 0 is typically reserved for the empty string (null).

2.  **Iterative Encoding:**
    *   **Matching:** Scan the input string to find the longest prefix that matches a phrase already in the dictionary.
    *   **Token Generation:** Once the longest match is found:
        *   The *index* of that matching phrase in the dictionary is recorded.
        *   The *next character* in the input stream (the character immediately following the matching phrase) is recorded.
        *   A token `(index, character)` is generated.  This token represents the matched phrase *plus* the next character.
    *   **Dictionary Update:** Add the combined sequence (matched phrase + next character) as a new phrase to the dictionary, assigning it the next available index.
    *   **Advance:** Move to the next part of the input stream, starting after the character that was just added to the token.
    *   **Repeat:** Continue matching, generating tokens, and updating the dictionary until the entire input string is processed.

**Example: Encoding the string "ABAABBCABABBA"**

Let's trace the LZ78 encoding process for the input string "ABAABBCABABBA":

| Step | Input Remaining | Longest Match | Index | Next Char | Token  | Dictionary Update   | Dictionary                                    |
|------|-----------------|---------------|-------|-----------|--------|--------------------|-----------------------------------------------|
| 1    | ABAABBCABABBA   | ""            | 0     | A         | (0, A) | Add "A" at index 1 | {0: "", 1: "A"}                             |
| 2    | BAABBCABABBA    | ""            | 0     | B         | (0, B) | Add "B" at index 2 | {0: "", 1: "A", 2: "B"}                       |
| 3    | AABBCABABBA     | "A"           | 1     | A         | (1, A) | Add "AA" at index 3| {0: "", 1: "A", 2: "B", 3: "AA"}              |
| 4    | BBCABABBA       | "B"           | 2     | B         | (2, B) | Add "BB" at index 4| {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB"}     |
| 5    | CABABBA         | ""            | 0     | C         | (0, C) | Add "C" at index 5 | {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB", 5: "C"}|

| 7    | ABBA            | "AB"          | 6     | B         | (6, B) | Add "ABB" at index 7| {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB", 5: "C", 6: "AB", 7: "ABB"} |

**3. Decoding Process:**

The LZ78 decoding process reconstructs the original data using the tokens and the dictionary that was built during encoding.  The decoder *simultaneously* constructs the same dictionary as the encoder.

1.  **Initialization:** Start with an empty dictionary, identical to the encoder's initial dictionary.

2.  **Iterative Decoding:** For each token `(index, character)`:
    *   **Phrase Retrieval:**  Look up the phrase corresponding to the `index` in the dictionary.
    *   **Output:** Output the retrieved phrase, followed by the `character`.  This is the decoded data.
    *   **Dictionary Update:** Add the retrieved phrase concatenated with the `character` to the dictionary, assigning it the next available index.

**Example: Decoding the tokens (0, A), (0, B), (1, A), (2, B), (0, C), (1, B), (6, B), (2, A)**

| Step | Token  | Index | Character | Dictionary Lookup | Output | Dictionary Update   | Dictionary                                    |
|------|--------|-------|-----------|-------------------|--------|--------------------|-----------------------------------------------|
| 1    | (0, A) | 0     | A         | ""                | A      | Add "A" at index 1 | {0: "", 1: "A"}                             |
| 2    | (0, B) | 0     | B         | ""                | B      | Add "B" at index 2 | {0: "", 1: "A", 2: "B"}                       |
| 3    | (1, A) | 1     | A         | "A"               | AA     | Add "AA" at index 3| {0: "", 1: "A", 2: "B", 3: "AA"}              |
| 4    | (2, B) | 2     | B         | "B"               | BB     | Add "BB" at index 4| {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB"}     |
| 5    | (0, C) | 0     | C         | ""                | C      | Add "C" at index 5 | {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB", 5: "C"}|
| 6    | (1, B) | 1     | B         | "A"               | AB     | Add "AB" at index 6 | {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB", 5: "C", 6: "AB"} |
| 7    | (6, B) | 6     | B         | "AB"              | ABB    | Add "ABB" at index 7| {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB", 5: "C", 6: "AB", 7: "ABB"} |
| 8    | (2, A) | 2     | A         | "B"               | BA     | Add "BA" at index 8| {0: "", 1: "A", 2: "B", 3: "AA", 4: "BB", 5: "C", 6: "AB", 7: "ABB", 8: "BA"} |

**Decoded Output:** ABAABBCABABBA (Original string)

**4. Advantages and Disadvantages of LZ78:**

**Advantages:**

*   **Simple Implementation:**  The algorithm is relatively easy to understand and implement.
*   **No prior knowledge required:** Does not require any pre-analysis of the input data.  It builds the dictionary dynamically.
*   **Effective for repetitive data:** Performs well on data with recurring patterns.
*   **Fast decoding:** Decoding is generally faster than encoding.

**Disadvantages:**

*   **Growing Dictionary:** The dictionary can grow large, potentially requiring significant memory. In practice, there are strategies to limit the size of the dictionary.
*   **Overhead:**  Each token includes an index, which can add overhead, especially for short sequences or data with little redundancy.
*   **Not Optimal:**  LZ78 is not always the most effective compression algorithm. Other algorithms, such as Lempel-Ziv-Welch (LZW), might achieve better compression ratios in certain scenarios.

**5. LZ78 vs. LZ77:**

| Feature           | LZ77                                    | LZ78                                  |
|-------------------|-----------------------------------------|---------------------------------------|
| **Dictionary**    | Sliding window of previously seen data | Explicit dictionary that grows dynamically |
| **Matching**      | Searches within the sliding window       | Searches within the dictionary        |
| **Token**         | (offset, length, next_char)             | (index, next_char)                    |
| **Memory Usage** | Limited by window size                  | Potentially unlimited (dictionary size) |
| **Complexity**   | More complex search within window      | Simpler dictionary lookup            |

**Key Differences:**

*   **Dictionary:** LZ77 uses a sliding window as its dictionary, while LZ78 uses a dynamically built explicit dictionary.
*   **Token Structure:** LZ77 tokens include an offset and length, referring back to the sliding window. LZ78 tokens include an index into the dictionary.

**Question 3:** What are the key differences between LZ77 and LZ78 regarding the dictionary?

**Answer:** LZ77 uses a sliding window as a dictionary containing recently seen characters, while LZ78 creates a dynamically growing, explicit dictionary of phrases.

**7. Important Points to Remember:**

*   LZ78 builds its dictionary incrementally during the encoding process.
*   The dictionary contains phrases, which are sequences of characters.
*   Tokens represent phrases using an index to the dictionary and the next character in the input.
*   Decoding reconstructs the dictionary in the same way as the encoding process.
*   LZ78 is a lossless compression algorithm.
