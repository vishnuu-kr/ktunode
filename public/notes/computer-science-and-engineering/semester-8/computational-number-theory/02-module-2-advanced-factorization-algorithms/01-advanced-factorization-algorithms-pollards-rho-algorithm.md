## Topic: Pollard's Rho Algorithm

### Introduction

Pollard's rho algorithm is a probabilistic integer factorization algorithm discovered by John L. Pollard in 1975. It is particularly effective for finding small factors of a large composite number. The algorithm's name comes from the Greek letter rho ($\rho$), which resembles the shape of the sequence of numbers generated by the algorithm. It is a **random walk** algorithm that aims to find a factor by exploiting the properties of cycles in sequences generated by a polynomial modulo the factor.

### 1. Underlying Principles of Pollard's Rho Algorithm

The core idea behind Pollard's rho algorithm is to find a non-trivial factor $p$ of a composite number $n$ by looking for a collision in a sequence of numbers generated modulo $p$. If we can find two numbers $x$ and $y$ in a sequence such that $x \equiv y \pmod{p}$ but $x \not\equiv y \pmod{n}$, then we know that $p$ divides $|x-y|$. Since $p$ is a factor of $n$, $\gcd(|x-y|, n)$ will likely reveal $p$.

**Key Idea:**

*   Generate a sequence of numbers $x_0, x_1, x_2, \ldots$ using a pseudo-random function $f(x)$ such that $x_{i+1} \equiv f(x_i) \pmod{n}$.
*   If we consider this sequence modulo a prime factor $p$ of $n$, i.e., $y_i \equiv x_i \pmod{p}$, then the sequence $y_0, y_1, y_2, \ldots$ will eventually become periodic.
*   The goal is to find $i \neq j$ such that $x_i \equiv x_j \pmod{p}$. This implies $p$ divides $|x_i - x_j|$.
*   The probability that $p$ divides $|x_i - x_j|$ is higher if $i$ and $j$ are close.

**Why "Rho"?**

The sequence of residues modulo $p$ will eventually enter a cycle. This pattern, when visualized, resembles the Greek letter $\rho$. The "tail" of the sequence leads into a "cycle."

```
... -> x_k -> x_{k+1} -> ... -> x_{m-1} -> x_m
                                     ^         |
                                     |         v
                                     ...       x_{k+1}
                                               ^
                                               |
                                               x_k
```

### 2. The Pseudo-Random Sequence Generator

A common choice for the pseudo-random function is a polynomial of degree 2, typically:

$f(x) = (x^2 + c) \pmod{n}$

where $c$ is a small constant (often 1) and $x_0$ is the starting value (often 2).

**Choosing $f(x)$:**

*   The function $f(x)$ should behave pseudo-randomly modulo any prime factor $p$ of $n$.
*   The polynomial $x^2 + c$ is a good choice because it's simple to compute and tends to generate sequences that exhibit good pseudo-random properties modulo $p$.
*   The value of $c$ should be chosen carefully. $c=1$ is a common starting point. If the algorithm fails for a particular $c$, try a different value.
*   The starting value $x_0$ is usually chosen to be small, like 2.

**Example:**

Let $n = 15$ and $f(x) = (x^2 + 1) \pmod{15}$. Let $x_0 = 2$.

*   $x_0 = 2$
*   $x_1 = (2^2 + 1) \pmod{15} = 5 \pmod{15} = 5$
*   $x_2 = (5^2 + 1) \pmod{15} = 26 \pmod{15} = 11$
*   $x_3 = (11^2 + 1) \pmod{15} = 122 \pmod{15} = 2$
*   $x_4 = (2^2 + 1) \pmod{15} = 5 \pmod{15} = 5$

The sequence modulo 15 is $2, 5, 11, 2, 5, 11, \ldots$. This sequence has entered a cycle.

Now consider the factors of 15: 3 and 5.

**Modulo 3:**

*   $x_0 \equiv 2 \pmod{3}$
*   $x_1 \equiv 5 \equiv 2 \pmod{3}$
*   $x_2 \equiv 11 \equiv 2 \pmod{3}$

The sequence modulo 3 is $2, 2, 2, \ldots$. The cycle length is 1.

**Modulo 5:**

*   $x_0 \equiv 2 \pmod{5}$
*   $x_1 \equiv 5 \equiv 0 \pmod{5}$
*   $x_2 \equiv 11 \equiv 1 \pmod{5}$
*   $x_3 \equiv 2 \pmod{5}$

The sequence modulo 5 is $2, 0, 1, 2, 0, 1, \ldots$. The cycle length is 3.

The cycle detection needs to happen when $x_i \equiv x_j \pmod{p}$ for a factor $p$.

### 3. Cycle Detection: Floyd's Cycle-Finding Algorithm (The Tortoise and the Hare)

Directly checking all pairs $(x_i, x_j)$ for equality modulo $p$ is impractical because we don't know $p$. Floyd's cycle-finding algorithm provides an efficient way to detect a cycle without knowing its length or starting point.

**The Algorithm:**

Maintain two pointers, a "tortoise" and a "hare," moving through the sequence at different speeds.

*   **Tortoise:** Moves one step at a time: $t_{i+1} = f(t_i) \pmod{n}$.
*   **Hare:** Moves two steps at a time: $h_{i+1} = f(f(h_i)) \pmod{n}$.

If there is a cycle, the hare will eventually "catch up" to the tortoise within the cycle. This means $t_i \equiv h_i \pmod{p}$ for some $i$.

**Finding the Factor:**

At each step, we compute $d = \gcd(|t_i - h_i|, n)$.

*   If $d = 1$, no common factor has been found yet. Continue.
*   If $1 < d < n$, we have found a non-trivial factor $d$ of $n$. This is the desired outcome.
*   If $d = n$, this indicates that the tortoise and hare have met at a point where $t_i \equiv h_i \pmod{n}$. This means they have both completed a full cycle and met at the same point modulo $n$. This often happens if the starting values are poor, the function $f(x)$ is not suitable, or if $n$ has a factor very close to $\sqrt{n}$. In this case, the algorithm fails for this particular $x_0$ and $c$, and we should try again with different parameters.

**Algorithm Steps:**

1.  Initialize $x = x_0$, $y = x_0$.
2.  Initialize $d = 1$.
3.  While $d = 1$:
    a.  Update tortoise: $x = f(x) \pmod{n}$.
    b.  Update hare: $y = f(f(y)) \pmod{n}$.
    c.  Calculate $d = \gcd(|x - y|, n)$.
4.  If $d = n$, the algorithm failed. Try again with a different $x_0$ or $c$.
5.  If $1 < d < n$, then $d$ is a factor of $n$.

**Example (Continuing with $n=15$, $f(x) = x^2+1 \pmod{15}$):**

Let $x_0 = 2$.

| Step | Tortoise ($x$) | Hare ($y$) | $x^2+1 \pmod{15}$ | $f(f(y)) \pmod{15}$ | $|x-y|$ | $\gcd(|x-y|, 15)$ |
| :--- | :------------- | :--------- | :---------------- | :------------------ | :------ | :---------------- |
| 0    | 2              | 2          | -                 | -                   | -       | 1                 |
| 1    | 5              | $f(f(2)) = f(5) = 26 \equiv 11 \pmod{15}$ | 5     | 11                  | $|5-11|=6$ | $\gcd(6, 15) = 3$ |

We found a factor $d=3$. The algorithm terminates successfully.

**Optimization: Batching GCD Computations**

Calculating GCD at every step can be computationally expensive. A common optimization is to accumulate the product of $|x - y|$ values modulo $n$ and compute the GCD only periodically.

Let $P = 1$. In each step:
1.  $x = f(x) \pmod{n}$
2.  $y = f(f(y)) \pmod{n}$
3.  $P = (P \times |x - y|) \pmod{n}$
4.  If it's time to check GCD (e.g., every $k$ steps), calculate $d = \gcd(P, n)$.
    *   If $d > 1$ and $d < n$, we found a factor. If $d=1$, reset $P=1$ and continue.
    *   If $d = n$, it means one of the factors $|x-y|$ was a multiple of $n$, or we accumulated too many factors and lost the original small difference. In this case, we might need to backtrack or restart.

This optimization is effective because $\gcd(a \cdot b, n) = \gcd(a, n) \cdot \gcd(b, n)$ if $\gcd(a, n)$ and $\gcd(b, n)$ are coprime. More generally, $\gcd(ab, n)$ can reveal factors of $n$ that are factors of $a$ or $b$.

### 4. Expected Running Time

Let $n$ be a composite number and $p$ be its smallest prime factor. Pollard's rho algorithm is expected to find $p$ in roughly $O(\sqrt{p} \log p)$ steps.

*   **Finding the cycle:** The expected length of the sequence before it enters a cycle (the "tail") is about $\sqrt{\pi p}/2$. The expected length of the cycle is also around $\sqrt{\pi p}/2$.
*   **Collision detection:** Floyd's algorithm finds a collision within a cycle of length $L$ in at most $L$ steps.
*   **Probability of success:** The probability that a specific step $i$ satisfies $x_i \equiv x_j \pmod{p}$ for some $j<i$ is roughly $1/p$.

The expected number of steps to find a factor $p$ is proportional to $\sqrt{p}$. If $n$ has a small prime factor $p$, Pollard's rho algorithm is very efficient. If all prime factors of $n$ are large (close to $\sqrt{n}$), then the algorithm's performance degrades, becoming similar to trial division with large primes.

**Complexity:**

The complexity is dominated by the $\gcd$ computations. Each step involves a polynomial evaluation (which is fast) and a $\gcd$. The expected number of steps is $O(\sqrt{p})$. A $\gcd$ operation takes $O(\log n)$ time.

Therefore, the expected running time is $O(\sqrt{p} \log n)$.

**Comparison with other algorithms:**

*   **Trial Division:** $O(\sqrt{n})$. Pollard's rho is better if $p \ll n$.
*   **Fermat's Factorization Method:** $O(n^{1/4})$. Pollard's rho is better if $p$ is small. Fermat's method is good for numbers $n$ that are products of two primes close to $\sqrt{n}$.
*   **Quadratic Sieve (QS) / Number Field Sieve (NFS):** These are sub-exponential time algorithms and are much faster for very large $n$ with large prime factors. Pollard's rho is a good choice for finding small factors of large numbers.

### 5. Implementation of Pollard's Rho Algorithm

```python
import math
import random

def gcd(a, b):
    """Computes the greatest common divisor of a and b."""
    while b:
        a, b = b, a % b
    return a

def pollards_rho(n):
    """
    Pollard's Rho algorithm for integer factorization.
    Finds a non-trivial factor of n.
    """
    if n % 2 == 0:
        return 2
    if n % 3 == 0:
        return 3

    # Function f(x) = (x^2 + c) mod n
    def f(x, c, mod):
        return (x * x + c) % mod

    x = random.randint(2, n - 1) # Start with a random value
    y = x
    c = random.randint(1, n - 1) # Start with a random constant for f(x)
    d = 1

    # Tortoise and Hare cycle detection
    while d == 1:
        x = f(x, c, n)          # Tortoise moves one step
        y = f(f(y, c, n), c, n) # Hare moves two steps
        d = gcd(abs(x - y), n)

        if d == n: # Failed, try again with different parameters
            # print(f"Failure detected (d=n). Retrying with new parameters...")
            return pollards_rho(n) # Recursive call to retry

    return d # Found a factor

# Example Usage:
# n = 8051 # Example from Wikipedia
# factor = pollards_rho(n)
# print(f"A factor of {n} is {factor}")
# print(f"The other factor is {n // factor}")

# n = 10403 # Another example
# factor = pollards_rho(n)
# print(f"A factor of {n} is {factor}")
# print(f"The other factor is {n // factor}")
```

**Considerations for implementation:**

*   **Handling $d=n$:** The algorithm can fail if $d=n$. This usually means the tortoise and hare met at the same point modulo $n$. When this happens, restart the algorithm with a different starting value for $x_0$ or a different constant $c$.
*   **Primality Test:** Before running Pollard's rho, it's good practice to check if $n$ is prime using a probabilistic primality test (like Miller-Rabin). If $n$ is prime, factorization is not possible.
*   **Efficiency for small factors:** Pollard's rho is most efficient when $n$ has small prime factors. For large numbers with large prime factors, other algorithms are preferred.
*   **The `random` module:** Ensure `random` is imported for choosing initial values.

### 6. Comparing Pollard's Rho Algorithm with Other Factorization Methods

| Algorithm           | Best Case   | Average Case | Worst Case | Notes                                                               |
| :------------------ | :---------- | :----------- | :--------- | :------------------------------------------------------------------ |
| Trial Division      | $O(\sqrt{p})$ | $O(\sqrt{n})$ | $O(\sqrt{n})$ | Simple, good for very small factors.                                |
| Fermat's Method     | $O(n^{1/4})$ | $O(n^{1/4})$ | $O(n^{1/4})$ | Good for $n$ with factors close to $\sqrt{n}$.                       |
| **Pollard's Rho**   | $O(\sqrt{p})$ | $O(\sqrt{p})$ | $O(\sqrt{n})$ | Probabilistic, excellent for finding small factors.                 |
| Pollard's p-1     | $O(\sqrt{p})$ | $O(\sqrt{p})$ | $O(\sqrt{n})$ | Works well if $p-1$ has only small prime factors.                   |
| Quadratic Sieve   | $O(e^{\sqrt{\ln n \ln \ln n}})$ | $O(e^{\sqrt{\ln n \ln \ln n}})$ | -          | Sub-exponential, better for numbers up to 100 digits.             |
| Number Field Sieve | $O(e^{(c + o(1))(\ln n)^{1/3}(\ln \ln n)^{2/3}})$ | -            | -          | The fastest known for very large numbers.                           |

**Pollard's Rho Strengths:**

*   **Simple to implement:** Compared to QS and NFS, it's significantly easier to code.
*   **Effective for small factors:** Its $O(\sqrt{p})$ complexity makes it very fast if $n$ has a small prime factor $p$.
*   **Probabilistic:** While not deterministic, it's highly likely to find a factor if one exists.

**Pollard's Rho Weaknesses:**

*   **Not suitable for large factors:** If all prime factors of $n$ are large, its performance approaches that of trial division.
*   **Can fail:** The failure case ($d=n$) requires re-running with different parameters.

### Key Points to Remember

*   Pollard's rho algorithm is a **probabilistic factorization algorithm** designed to find **small factors** of a composite number $n$.
*   It relies on finding a collision in a pseudo-random sequence modulo a prime factor $p$ of $n$.
*   The sequence is generated by a function like $f(x) = (x^2 + c) \pmod{n}$.
*   **Floyd's cycle-finding algorithm** (tortoise and hare) is used to detect these collisions efficiently.
*   The expected running time is approximately $O(\sqrt{p})$, where $p$ is the smallest prime factor of $n$.
*   The algorithm can fail if the tortoise and hare meet modulo $n$ ($d=n$), in which case it needs to be restarted with different parameters.
*   It's a good choice for finding small factors of large numbers, but less effective if all prime factors are large.
