## 1. Rationale for SHA-3 Development and Limitations of SHA-1 and SHA-2

*   **Need for a new standard:** While SHA-1 and SHA-2 were widely adopted, theoretical vulnerabilities and successful attacks on SHA-1 raised concerns about their long-term security. The cryptographic community recognized the importance of diversifying cryptographic primitives to mitigate risks associated with single algorithm compromises.

*   **SHA-1 Vulnerabilities:**  SHA-1 was found to be vulnerable to collision attacks. A collision occurs when two different inputs produce the same hash value.  A practical collision attack on SHA-1 was demonstrated in 2017.

*   **SHA-2 Limitations:**  While SHA-2 remains relatively secure, its design is closely related to SHA-1, raising concerns that advances in cryptanalysis could eventually expose vulnerabilities.  It was considered prudent to develop a fundamentally different algorithm.

*   **NIST competition:** The National Institute of Standards and Technology (NIST) launched a competition to select a new cryptographic hash algorithm to complement SHA-2.  The goal was to provide a backup option should weaknesses be discovered in SHA-2.

*   **SHA-3 as a complement, not a replacement:** SHA-3 is designed as a backup and complement to SHA-2, not a complete replacement. Both are still used depending on specific security requirements and deployment contexts.

*   **Focus on algorithmic diversity:**  SHA-3 uses a different design paradigm (sponge construction) compared to the Merkle-Damgård construction used in SHA-1 and SHA-2. This algorithmic diversity strengthens the overall cryptographic landscape.

## 2. The Keccak Algorithm

*   **Keccak as the foundation:** SHA-3 is based on the Keccak algorithm, designed by Guido Bertoni, Joan Daemen, Michael Peeters, and Gilles Van Assche.

*   **Sponge Construction:** Keccak uses a novel construction called the "sponge function."  This is fundamentally different from the Merkle-Damgård construction used in SHA-1 and SHA-2.

*   **State:** The core of Keccak operates on a *state*, which is a 3-dimensional array of bits. The state is represented as a 5 × 5 × w array, where *w* is the word size (1, 2, 4, 8, 16, 32, or 64 bits). The total state size is b = 25w bits.

*   **Parameters:** Key parameters include:
    *   `b`: the width of the state (also called *capacity*)
    *   `r`: the bitrate (part of the state processed during the absorbing phase)
    *   `c`: the capacity (part of the state that contributes to security)
    *   `f`: the permutation function (the core of the Keccak algorithm)

    The relationship is:  `b = r + c`

*   **Permutation Function (f):**  The permutation function `f` consists of a series of rounds. Each round consists of five steps (θ, ρ, π, χ, and ι), which perform bitwise operations on the state.  These steps are designed to provide confusion and diffusion, crucial for cryptographic security.

    *   **θ (Theta):**  Adds parity bits of columns to other columns.
    *   **ρ (Rho):**  Rotates each lane (row within a slice) by a different offset.
    *   **π (Pi):**  Permutes the lanes.
    *   **χ (Chi):**  A non-linear layer applying a simple Boolean function to each bit, based on the two neighboring bits in its row. This provides resistance against linear cryptanalysis.
    *   **ι (Iota):**  Adds a round constant to a lane.

## 3. Sponge Construction Principle

*   **Overview:** The sponge construction processes input data in two phases: *absorbing* and *squeezing*.

*   **Absorbing Phase:**
    1.  The input message is padded to be a multiple of the bitrate `r`.
    2.  The padded message is divided into blocks of size `r`.
    3.  The sponge state is initialized to all zeros.
    4.  For each block:
        *   The block is XORed with the first `r` bits of the state.
        *   The permutation function `f` is applied to the entire state `b`.

*   **Squeezing Phase:**
    1.  After absorbing all the input blocks, the squeezing phase begins.
    2.  As long as the desired output length has not been generated:
        *   The first `r` bits of the state are outputted as a block of the hash.
        *   The permutation function `f` is applied to the entire state `b`.

*   **Capacity and Security:** The capacity `c` determines the security level of the hash function.  A higher capacity provides greater resistance against attacks. Specifically, the security level is approximately `c/2` bits.  For example, if `c = 256`, the hash function provides approximately 128 bits of security.

*   **Key Advantage of Sponge Construction:**  It allows for variable output lengths, unlike traditional Merkle-Damgård constructions. This flexibility is a significant advantage.

## 4. SHA-3 Variants and Properties

*   **SHA-3 Standard:** The SHA-3 standard includes several variants with different output lengths:
    *   **SHA3-224:** Output length of 224 bits.
    *   **SHA3-256:** Output length of 256 bits.
    *   **SHA3-384:** Output length of 384 bits.
    *   **SHA3-512:** Output length of 512 bits.

*   **SHAKE (Extendable Output Functions):**  SHAKE functions are also part of the SHA-3 family.  They are *extendable output functions (XOFs)*, meaning their output length can be chosen arbitrarily.

    *   **SHAKE128(message, output_length):** Uses a capacity of 256 bits (security level of 128 bits).
    *   **SHAKE256(message, output_length):** Uses a capacity of 512 bits (security level of 256 bits).

*   **cSHAKE (Customizable SHAKE):** Allows for customization via a function name string 'N' and a customization string 'S'.  This adds domain separation, preventing attacks that exploit relationships between different hash function instances.  Used as `cSHAKE128(message, output_length, N, S)` and `cSHAKE256(message, output_length, N, S)`.

*   **Keccak-p Variants:** While SHA-3 is based on Keccak, the standardized functions use slightly different parameters than the original Keccak functions.  It is important to use the SHA-3 variants specified in the standard, not just any implementation of Keccak.

*   **Choosing the Right Variant:**
    *   Choose the SHA3-xxx variant that matches the desired output length.  Larger output lengths generally provide greater security, but also increase storage and bandwidth requirements.
    *   Use SHAKE functions when you need variable output lengths.
    *   Use cSHAKE when you need domain separation to prevent collision attacks across different applications.

## 5. Comparing SHA-3 with SHA-1 and SHA-2

| Feature          | SHA-1             | SHA-2                | SHA-3 (Keccak)           |
|-------------------|--------------------|-----------------------|----------------------------|
| Construction     | Merkle-Damgård     | Merkle-Damgård        | Sponge Construction         |
| Structure        | MD4-based          | MD4-based            | Radically different        |
| Status           | Broken, deprecated | Relatively secure   | Secure, NIST standard      |
| Output Lengths    | 160 bits           | 224, 256, 384, 512 bits | 224, 256, 384, 512, variable|
| Primary Use       | Previously widely used, now deprecated | Still widely used       | As a backup and complement |
| Vulnerabilities   | Collision attacks | Potential, but unproven  | Resistant to known attacks  |
| Internal State Size | 160 bits           | 256 or 512 bits       | Up to 1600 bits            |

*   **Key Differences:** SHA-3's sponge construction offers fundamentally different properties compared to the Merkle-Damgård construction used by SHA-1 and SHA-2.  This architectural difference is a key strength of SHA-3.

*   **Resistance to Attacks:** SHA-3 is designed to be resistant to attacks that exploit the structure of Merkle-Damgård based hash functions.

*   **Adoption:** While SHA-2 remains prevalent, SHA-3 is gaining wider adoption, especially in new systems and applications where stronger security guarantees are required.

## 6. Practical Applications of SHA-3

*   **Data Integrity:**  Verifying the integrity of data transmitted over a network or stored on a storage device.

*   **Password Storage:**  Hashing passwords before storing them to protect against data breaches.  Often combined with salting to further enhance security.

*   **Digital Signatures:**  Hashing documents before signing them with a private key.

*   **Message Authentication Codes (MACs):** Creating MACs using SHA-3 as the underlying hash function. HMAC-SHA3 provides data origin authentication and data integrity.

*   **Key Derivation Functions (KDFs):** Using SHA-3 as a building block for KDFs to derive cryptographic keys from a secret value.

*   **Random Number Generation:**  Seeding pseudo-random number generators (PRNGs) with SHA-3 outputs.

*   **Cryptocurrencies:**  Some cryptocurrencies utilize SHA-3 as part of their mining algorithms and block verification processes.

*   **Software Updates:**  Verifying the integrity of software updates to prevent the installation of malware.

**Example: Password Hashing**

```python
import hashlib

password = "MySecretPassword123"
salt = "RandomSaltValue" # Generate a unique salt for each password

# Concatenate the password and salt
password_with_salt = password + salt

# Hash the combined string using SHA3-256
hashed_password = hashlib.sha3_256(password_with_salt.encode('utf-8')).hexdigest()

print(f"Hashed Password: {hashed_password}")

# When verifying the password:
# 1. Retrieve the salt associated with the user's account.
# 2. Concatenate the entered password with the retrieved salt.
# 3. Hash the combined string using SHA3-256.
# 4. Compare the resulting hash with the stored hashed password.
```

## Practice Questions

1.  **Explain why SHA-3 was developed and what limitations existed in SHA-1 and SHA-2.**
    *   **Answer:**  SHA-3 was developed due to theoretical vulnerabilities and practical attacks on SHA-1, and the desire to diversify cryptographic algorithms as a safeguard against future weaknesses in SHA-2. SHA-1 was broken, and SHA-2 shares a similar design to SHA-1.

2.  **Describe the sponge construction and how it differs from the Merkle-Damgård construction.**
    *   **Answer:** The sponge construction has two phases: absorbing and squeezing. During the absorbing phase, input is XORed into the state and permuted. During squeezing, output is derived from the state after each permutation. It differs from Merkle-Damgård, which processes input in a sequential chaining manner and has a dedicated compression function.

3.  **What are the main SHA-3 variants, and what are their differences?**
    *   **Answer:** The main SHA-3 variants are SHA3-224, SHA3-256, SHA3-384, SHA3-512, SHAKE128, and SHAKE256. They differ in their output length and security levels.  SHAKE functions are extendable output functions (XOFs) that allow for variable output lengths.

4.  **Explain the purpose of the 'capacity' parameter in SHA-3, and how does it relate to the security level?**
    *   **Answer:**  The capacity parameter (c) determines the security level of SHA-3. A higher capacity provides greater resistance against attacks.  The security level is approximately c/2 bits.

5.  **Give an example of a practical application of SHA-3 and explain why it's suitable for that application.**
    *   **Answer:**  Password hashing. SHA-3 is suitable because it provides a strong and secure way to transform passwords into irreversible hashes, protecting them from being exposed in case of a data breach. It's also resistant to length extension attacks that affect some other hashing algorithms.

6.  **What are `cSHAKE` functions, and when would you use them?**
    *   **Answer:** `cSHAKE` functions are customizable SHAKE functions that allow for domain separation through function name 'N' and custom string 'S'. You would use them when you need to prevent collision attacks across different applications that might be using the same hash function.

## Important Points to Remember

*   SHA-3 is a complement to SHA-2, not a replacement.
*   SHA-3 uses the sponge construction, which is different from the Merkle-Damgård construction.
*   The capacity parameter determines the security level of SHA-3.
*   SHAKE functions provide extendable output lengths.
*   `cSHAKE` functions allow for domain separation through customizable strings.
*   Always use the standardized SHA-3 variants, not arbitrary implementations of Keccak.
