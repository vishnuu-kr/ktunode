# Compiler Design: Module 4 - Code Generation: Code Shape - Opportunities for Optimization

**Subject:** Compiler Design
**Module:** Module 4: Code Generation: Code Shape
**Topic:** Opportunities for Optimization
**Description:** Exploring optimization techniques that can be applied during or after code generation.
**Learning Outcomes:**

*   Identify common optimization opportunities arising from code shape.
*   Understand the principles behind various optimization techniques (e.g., constant folding, algebraic simplification, common subexpression elimination, dead code elimination).
*   Recognize the impact of code shape on the effectiveness of optimization.
*   Apply optimization techniques to simple code examples.
*   Discuss the trade-offs involved in applying different optimization techniques.

## 1. Introduction to Optimization in Code Generation

*   **Definition:** Optimization is the process of improving the code generated by a compiler to enhance its performance, reduce its size, or lower its power consumption (or a combination of these). It doesn't necessarily produce the *absolutely best* code, but rather code that is *better* than the unoptimized version.
*   **Why Optimize?**
    *   **Improved Performance:** Faster execution speed.
    *   **Reduced Resource Usage:** Smaller executable size, less memory consumption.
    *   **Lower Power Consumption:** Crucial for mobile and embedded devices.
*   **Optimization Levels:** Compilers often provide different optimization levels (e.g., `-O0`, `-O1`, `-O2`, `-O3` in GCC/Clang). Higher levels apply more aggressive optimizations, but may increase compilation time.

## 2. Code Shape and Optimization Opportunities

The "code shape" refers to the way intermediate code is generated and how it's structured before final code generation. Certain code shapes present specific optimization opportunities.

*   **Redundant Loads and Stores:**
    *   **Definition:** Instructions that load or store the same value multiple times in a short period without any intervening changes to the value.
    *   **Opportunity:** Eliminate redundant loads and stores.
    *   **Example:**
        ```assembly
        load R1, x  ; Load value of x into R1
        load R2, x  ; Redundant load of x into R2
        add R3, R1, R2
        ```
        **Optimized:**
        ```assembly
        load R1, x
        add R3, R1, R1
        ```
*   **Unnecessary Type Conversions:**
    *   **Definition:**  Implicit or explicit type conversions that are unnecessary for the correctness of the program.
    *   **Opportunity:** Eliminate redundant type conversions.
    *   **Example:**
        ```C
        int i = 10;
        float f = (float)i; // Explicit conversion
        int j = (int)f;     // Explicit conversion back (if f isn't used for fractional part)
        ```
        **Optimized (potentially):** If `f` is only used in contexts where `i` would have been sufficient and `f` wasn't modified to hold fractional parts, then `f` and `j` can be eliminated.

*   **Poor Register Allocation:**
    *   **Definition:**  Inefficient use of registers, leading to excessive spilling (storing register values to memory and reloading them later).
    *   **Opportunity:** Improve register allocation.
    *   **Example:** Consider a situation where a value is constantly being moved between register and memory. Careful analysis can identify the most heavily used variables and assign them to registers.
*   **Inefficient Addressing Modes:**
    *   **Definition:**  Using less efficient addressing modes when more efficient ones are available.
    *   **Opportunity:**  Use the most efficient addressing mode.
    *   **Example:** Instead of calculating an address with multiple instructions, use an indexing or offset addressing mode if the hardware supports it.

## 3. Common Optimization Techniques

*   **Constant Folding:**
    *   **Definition:** Evaluating constant expressions at compile time instead of runtime.
    *   **Example:**
        ```C
        int x = 2 + 3 * 4;
        ```
        **Optimized:**
        ```C
        int x = 14;
        ```
    *   **Implementation:** The compiler's constant expression evaluator performs the calculation and replaces the expression with its result.

*   **Algebraic Simplification:**
    *   **Definition:**  Applying algebraic identities to simplify expressions.
    *   **Examples:**
        *   `x + 0`  ->  `x`
        *   `x * 1`  ->  `x`
        *   `x * 2`  ->  `x + x` (can be further optimized to shift left in some cases)
        *   `x * 0` -> `0`

*   **Common Subexpression Elimination (CSE):**
    *   **Definition:** Identifying and eliminating redundant calculations of the same subexpression.
    *   **Example:**
        ```C
        int a = b + c;
        int d = b + c + e;
        ```
        **Optimized:**
        ```C
        int a = b + c;
        int d = a + e;
        ```
    *   **Implementation:**  Requires a data structure (e.g., a hash table) to track computed expressions and their values.
*   **Dead Code Elimination:**
    *   **Definition:** Removing code that has no effect on the program's output.  This includes unused variables, unreachable code, and expressions whose results are never used.
    *   **Examples:**
        *   **Unreachable Code:** Code after an unconditional `return` statement.
        *   **Unused Variable:** A variable that is assigned a value but never read.
        *   **Unused Expression:**  An expression whose result is calculated but never used.
    *   **Implementation:** Often relies on data flow analysis to determine variable liveness (whether a variable's value will be used later).
*   **Copy Propagation:**
    *   **Definition:** Replacing instances of a variable with the value assigned to it.
    *   **Example:**
        ```C
        x = y;
        z = x + 1;
        ```
        **Optimized:**
        ```C
        x = y;
        z = y + 1;
        ```
    *   **Benefits:**  Can simplify code and enable other optimizations, like constant folding or dead code elimination.

*   **Strength Reduction:**
    *   **Definition:** Replacing expensive operations with cheaper ones.
    *   **Examples:**
        *   `x * 2`  ->  `x << 1` (left shift)
        *   `x ^ 2` -> `x * x` (avoid exponentiation functions if possible)
        *   `i = i + 1`  -> `i++` (often compiled to a single increment instruction)

*   **Loop Unrolling:**
    *   **Definition:** Replicating the body of a loop multiple times to reduce the loop overhead.
    *   **Example:**
        ```C
        for (int i = 0; i < 3; i++) {
            a[i] = i * 2;
        }
        ```
        **Unrolled (partially):**
        ```C
        a[0] = 0 * 2;
        a[1] = 1 * 2;
        a[2] = 2 * 2;
        ```
    *   **Trade-offs:** Reduces loop overhead but increases code size.

*   **Function Inlining:**
    *   **Definition:** Replacing a function call with the body of the function itself.
    *   **Benefits:** Eliminates function call overhead, allows for further optimizations within the inlined code.
    *   **Trade-offs:** Increases code size, may increase compilation time.
*   **Register Allocation:** Carefully assigning variables to registers to minimize memory accesses (spilling/reloading).

## 4. Impact of Code Shape on Optimization

The way code is generated significantly affects the effectiveness of optimization.

*   **Straightforward Code Generation:** Producing simple, easy-to-understand intermediate code can make it easier for optimization passes to identify opportunities.  However, it may also miss some complex optimizations.

*   **Target-Specific Code Generation:**  Generating code tailored to the specific architecture can enable optimizations that wouldn't be possible on a more generic target.

*   **SSA (Static Single Assignment) Form:**  Converting the code to SSA form can simplify data flow analysis and make certain optimizations (like CSE and dead code elimination) more efficient.  In SSA, each variable is assigned a value only once.

## 5. Trade-offs in Optimization

*   **Compilation Time vs. Execution Time:**  More aggressive optimizations can significantly increase compilation time.  Finding the right balance is crucial.
*   **Code Size vs. Execution Time:** Some optimizations (e.g., loop unrolling, function inlining) increase code size while improving performance.
*   **Complexity:** Implementing complex optimization algorithms can be challenging and may introduce bugs.

## 6. Examples of Optimization in Action

Consider the following C code:

```c
int compute(int x, int y) {
    int a = x + y;
    int b = x + y;
    int c = a * 2;
    int d = 0;
    return c;
}
```

Let's see how different optimization techniques might apply:

1.  **Common Subexpression Elimination:** `a` and `b` are both `x + y`. CSE can eliminate the redundant calculation of `b`.
2.  **Constant Folding:** `a * 2` *could* be rewritten as `(x + y) * 2`, and might be further optimized (strength reduction) to something like `(x + y) << 1`.
3.  **Dead Code Elimination:** The variable `d` is assigned a value but never used, so it can be eliminated.

Optimized code (potentially):

```c
int compute(int x, int y) {
    int a = x + y;
    int c = a * 2; //or c = a << 1
    return c;
}
```

Or even further:

```c
int compute(int x, int y) {
    return (x + y) * 2; // or (x + y) << 1
}
```

## 7. Practice Questions and Exercises

1.  **Identify optimization opportunities:** Given the following code snippet, identify potential optimization opportunities and describe the optimization techniques that could be applied.

    ```c
    int foo(int a, int b) {
        int x = a + b;
        int y = a + b;
        int z = x * 1;
        int w = 0;
        return z;
    }
    ```

    **Answer:**
    *   **Common Subexpression Elimination:** `x` and `y` both calculate `a + b`. Eliminate the redundant calculation of `y`.
    *   **Algebraic Simplification:** `x * 1` can be simplified to `x`.
    *   **Dead Code Elimination:** `w` is assigned but never used, so it can be eliminated.

2.  **Apply constant folding:**  Optimize the following expression using constant folding: `int result = 10 + 5 * 2 - 3;`

    **Answer:** `int result = 17;` (10 + 10 - 3 = 17)

3.  **Rewrite the code snippet using optimization**:
    Given the code:

    ```c
    int calculate(int x) {
        int a = x * 2;
        int b = x * 2;
        int c = a + 0;
        return c;
    }
    ```
    Apply optimization strategies.

    **Answer:**
    ```c
    int calculate(int x) {
      return x * 2; // or return x << 1;
    }
    ```

## 8. Important Points to Remember

*   Optimization is a crucial part of the compilation process for improving code quality.
*   Many different optimization techniques exist, each with its own strengths and weaknesses.
*   The effectiveness of optimization depends on the code shape and the target architecture.
*   Optimization involves trade-offs between compilation time, execution time, and code size.
*   Understanding optimization techniques helps you write code that is more amenable to optimization and improves performance.
