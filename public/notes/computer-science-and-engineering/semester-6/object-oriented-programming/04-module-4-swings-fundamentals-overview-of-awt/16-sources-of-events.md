# Object-Oriented Programming: Module 4 - Swing Fundamentals (Overview of AWT)

## Topic: Sources of Events

### Learning Outcomes:

*   Understand the concept of event sources in GUI programming.
*   Identify common components that can act as event sources in AWT.
*   Explain the relationship between event sources and event listeners.
*   Differentiate between various types of events that can originate from different sources.

---

### 1. Introduction to Event Handling in GUI Programming

Graphical User Interface (GUI) applications are inherently interactive. Users interact with the application by performing actions such as clicking buttons, typing text, moving the mouse, or selecting menu items. These user actions generate *events*. Event handling is the mechanism by which GUI applications respond to these user interactions.

*   **Event:** An event is a signal that something has happened. In GUI programming, events typically represent user actions or system-generated occurrences.
*   **Event Handling:** The process of detecting and responding to events.

---

### 2. What is an Event Source?

An **event source** is a GUI component that generates an event. When a user interacts with a component, that component is responsible for creating and dispatching an event object.

*   **Definition:** An event source is any object that can register one or more listeners, and that notifies these listeners when an event of interest occurs.
*   **Role:** Event sources are the originators of events. They encapsulate the state and behavior that leads to event generation.

---

### 3. Common Event Sources in AWT (and by extension, Swing)

While Swing builds upon AWT, understanding AWT's foundational components is crucial. Many Swing components behave similarly to their AWT counterparts in terms of event generation.

Here are some common components that act as event sources:

#### 3.1. Buttons (`Button`)

*   **Description:** The most basic interactive element. Users click buttons to trigger actions.
*   **Events Generated:** Primarily `ActionEvent`.
*   **Example:** A "Submit" button on a form. Clicking it generates an `ActionEvent`.

#### 3.2. Checkboxes (`Checkbox`)

*   **Description:** Allows users to select or deselect an option.
*   **Events Generated:** Primarily `ItemEvent`. This event signals a change in the selected state of the checkbox.
*   **Example:** A checkbox labeled "Remember Me". When checked or unchecked, it generates an `ItemEvent`.

#### 3.3. Radio Buttons (`CheckboxGroup`)

*   **Description:** A group of checkboxes where only one can be selected at a time. The `CheckboxGroup` itself doesn't generate events, but individual `Checkbox` components within the group do.
*   **Events Generated:** `ItemEvent` for the individual `Checkbox` components when their selection state changes within the group.
*   **Example:** A group of radio buttons for selecting gender (Male, Female, Other). Selecting "Female" deselects "Male" and generates an `ItemEvent` for the "Female" checkbox.

#### 3.4. Text Fields (`TextField`)

*   **Description:** Allows users to input single-line text.
*   **Events Generated:**
    *   `ActionEvent`: Generated when the user presses the Enter key while the text field has focus.
    *   `TextEvent`: Generated when the text content of the field changes (e.g., as the user types). This is a more granular event.
*   **Example:** A search bar. Typing text generates `TextEvent`s, and pressing Enter generates an `ActionEvent`.

#### 3.5. Text Areas (`TextArea`)

*   **Description:** Allows users to input multi-line text.
*   **Events Generated:** Primarily `TextEvent`, as the content changes with user input. `ActionEvent` is not typically generated by `TextArea` when Enter is pressed, as Enter usually inserts a newline.
*   **Example:** A comment box. Typing comments generates `TextEvent`s.

#### 3.6. Lists (`List`)

*   **Description:** Displays a list of items, allowing single or multiple selections.
*   **Events Generated:**
    *   `ActionEvent`: Generated when the user double-clicks an item in the list (if multiple selection is allowed, or if single selection with Enter is configured).
    *   `ItemEvent`: Generated when an item's selection state changes (e.g., clicking to select or deselect an item).
*   **Example:** A list of files. Selecting a file generates an `ItemEvent`, double-clicking might generate an `ActionEvent` to open it.

#### 3.7. Scrollbars (`Scrollbar`)

*   **Description:** Allows users to select a value within a bounded range.
*   **Events Generated:** `AdjustmentEvent`. This event signals changes in the scrollbar's value, orientation, or type of adjustment.
*   **Example:** A volume slider. Moving the slider generates `AdjustmentEvent`s.

#### 3.8. Windows (`Frame`, `Dialog`)

*   **Description:** Top-level containers that can generate events related to their state.
*   **Events Generated:**
    *   `WindowEvent`: Generated for various window events like opening, closing, resizing, iconifying, deiconifying, etc.
*   **Example:** Closing a window generates a `WINDOW_CLOSING` `WindowEvent`.

#### 3.9. Menu Items (`MenuItem`, `CheckboxMenuItem`)

*   **Description:** Elements within a menu bar or popup menu.
*   **Events Generated:**
    *   `ActionEvent`: Generated when a regular `MenuItem` is clicked.
    *   `ItemEvent`: Generated when a `CheckboxMenuItem`'s selected state changes.
*   **Example:** A "File" -> "Open" menu item. Clicking "Open" generates an `ActionEvent`.

### 4. The Relationship: Event Sources and Event Listeners

Event handling in Java GUI involves a core pattern: the **Observer pattern**.

*   **Event Source:** The object that experiences an event and notifies its observers.
*   **Event Listener (or Event Handler):** An object that registers with an event source to be notified when a specific type of event occurs. Listeners implement specific listener interfaces.

**The Flow:**

1.  **Registration:** An event listener object registers itself with an event source using a `add<Event>Listener()` method (e.g., `button.addActionListener(myListener)`).
2.  **Event Generation:** The user interacts with the event source (e.g., clicks a button).
3.  **Event Object Creation:** The event source creates an event object that encapsulates details about the event (e.g., `ActionEvent`).
4.  **Notification:** The event source invokes the appropriate method on all registered listeners, passing the event object as an argument (e.g., `myListener.actionPerformed(event)`).
5.  **Response:** The listener's method executes the code to handle the event.

---

### 5. Key Concepts and Definitions Recap

*   **Event Source:** A GUI component that generates events.
*   **Event Listener:** An object that is registered with an event source and receives notifications when events occur.
*   **Event Object:** An object that carries information about the event that occurred.
*   **Listener Interface:** An interface that defines methods to handle specific types of events (e.g., `ActionListener`, `MouseListener`, `KeyListener`).
*   **Adapter Classes:** Convenience classes that provide default implementations for listener interfaces with multiple methods, allowing listeners to override only the methods they need. (While not strictly about *sources*, it's a related concept in event handling).

---

### 6. Differentiating Event Types from Sources

Different components are designed to generate different types of events, reflecting their specific functionality.

| Component           | Primary Event Types Generated                 | Event Object Type(s) | Description of Event                                       |
| :------------------ | :-------------------------------------------- | :------------------- | :--------------------------------------------------------- |
| `Button`            | Action                                        | `ActionEvent`        | Button click.                                              |
| `Checkbox`          | Item state change                             | `ItemEvent`          | Checkbox selected or deselected.                           |
| `TextField`         | Action, Text change                           | `ActionEvent`, `TextEvent` | Enter key pressed, text content modified.                  |
| `TextArea`          | Text change                                   | `TextEvent`          | Text content modified.                                     |
| `List`              | Action, Item state change                     | `ActionEvent`, `ItemEvent` | Item double-clicked, item selected/deselected.             |
| `Scrollbar`         | Adjustment                                    | `AdjustmentEvent`    | Scrollbar value, orientation, or type changed.           |
| `Window` (`Frame`, `Dialog`) | Window events (open, close, resize, etc.) | `WindowEvent`        | State changes of the window itself.                        |
| `MenuItem`          | Action                                        | `ActionEvent`        | Menu item clicked.                                         |
| `CheckboxMenuItem`  | Item state change                             | `ItemEvent`          | Checkbox menu item selected/deselected.                    |

---

### 7. Importance of Event Sources

Understanding event sources is fundamental for:

*   **Creating Interactive GUIs:** Knowing which components generate which events allows you to build responsive applications.
*   **Efficient Event Handling:** You can selectively register listeners only for the events and components that require a response, improving performance.
*   **Code Organization:** It helps in structuring your code to handle specific user interactions effectively.
*   **Debugging:** When an application doesn't behave as expected, identifying the event source and the generated event is often the first step in debugging.

### Practice Questions/Exercises

**Question 1:**
Which AWT component generates an `ActionEvent` when the user presses the Enter key while the component has focus?
A) `TextArea`
B) `Checkbox`
C) `TextField`
D) `Scrollbar`

**Question 2:**
What type of event is typically generated when a user checks or unchecks a `Checkbox`?
A) `ActionEvent`
B) `TextEvent`
C) `ItemEvent`
D) `MouseEvent`

**Question 3:**
If you want to respond to a user clicking a "Save" button, which component would you identify as the event source, and what listener interface would you typically implement?

**Question 4:**
True or False: A `List` component can generate both `ActionEvent` and `ItemEvent`.

**Question 5:**
Describe the role of a `MenuItem` as an event source.

---

### Answers

**Answer 1:**
C) `TextField`
*Explanation:* `TextField` generates an `ActionEvent` upon pressing Enter, while `TextArea` typically generates `TextEvent`s as text changes and does not use Enter for an ActionEvent.

**Answer 2:**
C) `ItemEvent`
*Explanation:* `ItemEvent` is specifically designed to signal changes in the selected state of items, such as checkboxes or list items.

**Answer 3:**
*   **Event Source:** The "Save" `Button` component.
*   **Listener Interface:** You would typically implement the `ActionListener` interface and its `actionPerformed()` method to handle the click event.

**Answer 4:**
True
*Explanation:* A `List` can generate an `ItemEvent` when an item's selection state changes (e.g., clicking to select/deselect) and an `ActionEvent` when an item is double-clicked (depending on the `List`'s configuration for multiple selections).

**Answer 5:**
A `MenuItem` is an event source because it represents an option within a menu that a user can select. When a user clicks on a `MenuItem`, it generates an `ActionEvent` to signal that the menu item has been triggered, allowing the application to perform a specific action associated with that menu item.

---

### Important Points to Remember:

*   **Every interactive GUI component that can trigger an action or state change is a potential event source.**
*   **The type of event generated is directly related to the component's purpose and user interaction.**
*   **Event handling follows a clear pattern: source generates, listener receives, and listener acts.**
*   **You must register a listener with the source using the appropriate `addXxxListener()` method.**
*   **The listener interface defines the methods that will be called when specific events occur.**
*   **Swing components largely follow the event model established by AWT, so understanding AWT event sources is foundational for Swing.**
