# Microprocessors and Embedded Systems Lab: Module 6 - DC Motor Control using PWM

This module focuses on controlling the direction and speed of a DC motor using Pulse Width Modulation (PWM) techniques with microcontrollers, primarily the 8051.

## Module 6: C Program for DC Motor Direction and Speed Control using PWM

### 1. Introduction to DC Motors and their Control

#### 1.1 DC Motors
*   **Definition:** A Direct Current (DC) motor is an electrical machine that converts electrical energy into mechanical energy. It operates on the principle of electromagnetic interaction, where a current-carrying conductor placed in a magnetic field experiences a force.
*   **Types:**
    *   Brushed DC motors (most common for simple applications)
    *   Brushless DC motors (more complex, higher efficiency)
*   **Basic Operation:** The stator (stationary part) provides a magnetic field, and the rotor (rotating part) carries windings. Current flowing through the rotor windings interacts with the stator's magnetic field, generating torque and causing rotation.

#### 1.2 Why PWM for DC Motor Control?
*   **Speed Control:** The speed of a DC motor is directly proportional to the average voltage applied to its terminals. By rapidly switching the voltage ON and OFF, we can control the average voltage. This is the essence of PWM.
*   **Efficiency:** PWM offers a more efficient way to control speed compared to varying resistance, as it avoids significant power dissipation in resistors.
*   **Direction Control:** In conjunction with an H-bridge circuit, PWM can be used to control the direction of rotation of a DC motor.

#### 1.3 Key Concepts
*   **Pulse Width Modulation (PWM):** A technique for generating an analog signal using a digital signal. It involves modulating the width of a digital pulse (varying the ON-time and OFF-time of a pulse train) while keeping the frequency constant.
*   **Duty Cycle:** The ratio of the ON-time of a pulse to its total period. It's usually expressed as a percentage.
    *   `Duty Cycle (%) = (ON Time / Period) * 100`
    *   A higher duty cycle means more "ON" time, resulting in a higher average voltage and thus higher motor speed.
*   **Frequency:** The number of pulses generated per second. For motor control, a suitable frequency is typically in the kHz range to ensure smooth operation and avoid audible noise.

### 2. Interfacing DC Motor with Microcontroller

#### 2.1 The Need for an Interface Circuit
*   **Current Drive Capability:** Microcontroller I/O pins have limited current sourcing/sinking capabilities. DC motors, especially under load, require much higher currents.
*   **Voltage Levels:** Microcontroller I/O pins operate at logic voltage levels (e.g., 5V or 3.3V), while motors might require higher voltages.
*   **Protection:** Driving a motor directly from a microcontroller can lead to damage due to back EMF (Electromotive Force) generated by the motor when it's switched off or changes speed.

#### 2.2 H-Bridge Circuit
*   **Definition:** An H-bridge is an electronic circuit that enables a voltage to be applied across a load (in this case, a DC motor) in either direction. It consists of four switches (typically MOSFETs or BJTs) arranged in an "H" configuration.
*   **How it Works:**
    *   **Forward Rotation:** Activating two diagonally opposite switches allows current to flow through the motor in one direction.
    *   **Reverse Rotation:** Activating the other two diagonally opposite switches reverses the direction of current flow through the motor.
    *   **Braking:** Activating both switches on one side (or all switches) shorts the motor terminals, causing it to brake rapidly.
    *   **Coast:** When all switches are open, the motor is free to coast.
*   **Common Implementation:** Using NPN and PNP transistors or N-channel and P-channel MOSFETs. Often, integrated H-bridge driver ICs (like the L293D or L298N) are used for convenience and protection.

#### 2.3 Interfacing with an 8051 Microcontroller
*   **PWM Generation:** The 8051 microcontroller has built-in hardware timers that can be configured to generate PWM signals. Timer 0 or Timer 1 are commonly used for this purpose.
*   **Direction Control:** Two digital output pins from the 8051 are used to control the enable pins of the H-bridge driver IC or directly drive the base/gate of transistors in a discrete H-bridge. These pins determine which pair of switches in the H-bridge is activated.

### 3. 8051 Timer Configuration for PWM

#### 3.1 Timer Modes
The 8051 has two timers, Timer 0 and Timer 1, each capable of operating in several modes. For PWM generation, **Mode 2 (8-bit auto-reload)** is most suitable.

*   **Mode 2:**
    *   **TLx (Timer Low byte):** Acts as an 8-bit up-counter. When it overflows, it automatically reloads a value from the **THx (Timer High byte)**.
    *   **THx:** Stores the reload value.
    *   **TCON Register:** Contains control bits for timers (TRx for start/stop, TFx for overflow flag).
    *   **TMOD Register:** Configures the operating mode of Timer 0 and Timer 1.

#### 3.2 Generating PWM using Timer 0 (Mode 2 Example)
To generate PWM using Timer 0 in Mode 2, we need to:

1.  **Configure Timer 0:** Set the appropriate bits in the `TMOD` register for Timer 0 to operate in Mode 2 (M1=0, M0=1).
2.  **Set PWM Frequency:** The frequency of the PWM signal depends on the timer's reload value (`TH0`) and the system's oscillator frequency.
    *   **Timer Clock:** The 8051's timers are typically clocked by `fosc / 12`, where `fosc` is the oscillator frequency.
    *   **Period of PWM:** The PWM period is determined by the timer's overflow. In Mode 2, the timer counts from the `TH0` value up to `FFh` and then overflows.
        *   `Number of counts = 256 - TH0` (assuming `TH0` holds the reload value)
        *   `Timer Period = (Number of counts) * (12 / fosc)`
    *   **PWM Frequency (f_pwm) = 1 / Timer Period**
    *   **f_pwm = fosc / (12 * (256 - TH0))**
    *   To achieve a desired PWM frequency, we can calculate the required `TH0` value:
        *   **TH0 = 256 - (fosc / (12 * f_pwm))**

3.  **Control Duty Cycle:** The duty cycle is controlled by the value loaded into `TL0` when the timer is running.
    *   **How it works:** The timer is started. It counts from `TL0` up to `FFh`. When it overflows, the `TF0` flag is set, and `TL0` is reloaded from `TH0`. The PWM output is typically toggled when the timer overflows.
    *   **Simpler Approach (using external hardware or specific microcontroller features):** Some microcontrollers have dedicated PWM modules. For the 8051, we often use an interrupt-driven approach or simpler logic.
    *   **PWM Output Pin:** For basic 8051, a timer output pin (like `P1.0` if connected to Timer 0) can be used, or we can toggle a general-purpose pin within the timer interrupt service routine.

#### 3.3 Using a Timer Interrupt for PWM (Common 8051 Approach)
This is a flexible way to generate PWM with specific duty cycles.

#### 3.4 Recommended approach: Timer 0 Mode 2 with Interrupts for Duty Cycle Control

*   **Goal:** Generate a PWM signal with a fixed frequency and variable duty cycle.
*   **Setup:**
    *   `fosc` = system clock frequency (e.g., 11.0592 MHz).
    *   Timer clock = `fosc / 12`.
    *   **Desired PWM Frequency** (e.g., 1 kHz).
    *   **Desired PWM Period** = 1 / PWM Frequency (e.g., 1 ms).
    *   **Number of timer ticks for the period** = PWM Period / Timer Tick Period = `(1 / PWM_Freq) / (12 / fosc)` = `(fosc) / (12 * PWM_Freq)`.
    *   Let's use `fosc = 12MHz`. Timer clock = 1MHz. PWM Frequency = 1kHz. Period = 1ms.
    *   Number of timer ticks for period = `12MHz / (12 * 1kHz) = 12,000,000 / 12,000 = 1000` ticks.

*   **Using Timer 0 in Mode 2 (8-bit auto-reload):**
    *   `TMOD = 0x20;` (Timer 0, Mode 2)
    *   `ET0 = 1; EA = 1;` (Enable Timer 0 interrupt and global interrupts)
    *   **The key is to set `TH0` such that the timer overflow rate matches the PWM frequency.**
    *   Number of counts in Mode 2 = `256 - TH0`.
    *   We want `256 - TH0` to be a value that, when multiplied by the timer tick period, gives the PWM period.
    *   **This is where it gets tricky for precise frequencies with 8-bit auto-reload alone.** A common practice is to use `TH0` to set a base frequency and then use the ISR to manage the duty cycle.

*   **Interrupt Service Routine (ISR) Strategy:**
    1.  **Define a `period_counts` value:** This is the number of timer ticks for the desired PWM period.
    2.  **Define `duty_cycle_counts`:** This is the number of timer ticks for the ON time.
    3.  **Set `TH0` to generate the frequency:** The overflow rate of Timer 0 determines the interrupt frequency. Let's set `TH0` such that it overflows at the desired PWM frequency. If we want 1kHz, we need the timer to overflow every 1ms. With `fosc=12MHz`, timer clock=1MHz. We need 1000 timer ticks.
        *   We can't directly set `TH0` for 1000 ticks in Mode 2 (max counts = 256).
        *   **This means we will use the ISR to manage both the period and the duty cycle.**

*   **Revised ISR Strategy:**
    *   **Global variables:**
        *   `volatile unsigned int timer_count;` // Counts down to zero for ON time
        *   `volatile unsigned char pwm_state;` // 0 for OFF, 1 for ON
        *   `volatile unsigned char duty_cycle_setting;` // 0-100
    *   **Initialization Function:**
        *   `TMOD = 0x20;` // Timer 0, Mode 2
        *   `TH0 = 0xFE;` // Reload value for Timer 0. If fosc=12MHz, timer clock=1MHz.
                        // Overflow happens every (256-0xFE) * 1us = 2 * 1us = 2us.
                        // This sets a base frequency of 500kHz. This is too fast.
        *   **Let's use `TH0` to set the *period*.**
        *   **Correct `TH0` calculation for desired frequency:**
            *   Let `fosc = 12MHz`. Timer clock = 1MHz.
            *   Desired PWM Frequency = 1kHz. Period = 1ms.
            *   We need to know how many timer ticks correspond to the period. `1ms / 1us = 1000` ticks.
            *   This requires a 10-bit counter, or two 8-bit timers, or using interrupts extensively.
            *   **Simpler approach using Timer 0 Mode 1 (16-bit):**
                *   `TMOD = 0x01;`
                *   Set `TH0` and `TL0` to a value that results in the desired PWM period.
                *   `Total Counts = (fosc) / (12 * PWM_Freq)`
                *   `Counts = 1000` for 1kHz with `fosc=12MHz`.
                *   `TH0 = (65536 - 1000) >> 8;`
                *   `TL0 = (65536 - 1000) & 0xFF;`
                *   `TR0 = 1;`
                *   **In ISR:** Toggle the PWM pin. Reload `TH0` and `TL0` after the ON time. This becomes complex.

    *   **Standard 8051 PWM Technique (using Timer 0 Mode 2 for frequency, and ISR for duty cycle):**
        1.  **Set `TH0` for the interrupt rate:** Let's aim for an interrupt rate that's a multiple of our desired PWM frequency. A common practice is to have the interrupt frequency match the PWM frequency.
            *   Let `fosc = 11.0592MHz`. Timer clock = 921.6 KHz.
            *   Desired PWM Frequency = 1kHz. Period = 1ms.
            *   **We need the timer to overflow every 1ms.**
            *   Counts needed = `1ms / (1 / 921.6 KHz) = 921.6`. Again, not directly for 8-bit.
            *   **Let's use Timer 1 for generating the PWM *period*, and Timer 0 for *duty cycle* within that period.** This is getting complicated.

        *   **Simplest Practical 8051 PWM:**
            *   Use Timer 0, Mode 2.
            *   Set `TH0` to control the *frequency*.
            *   In the Timer 0 ISR:
                *   Toggle the PWM output pin.
                *   Calculate the new value for `TL0` based on the desired duty cycle.
                *   `TR0 = 0;` // Stop timer briefly
                *   `TL0 = TH0 - duty_value;` // This sets the ON time. The timer will count from this value up to FFh.
                *   `TR0 = 1;` // Restart timer
                *   **`TH0` MUST be set such that `256 - TH0` corresponds to the total period counts.**

        *   **Example with `fosc = 12MHz`:**
            *   Timer clock = 1MHz. Timer tick = 1us.
            *   Let's aim for PWM Frequency = 1kHz. Period = 1ms.
            *   **The number of timer ticks for the period is 1000.**
            *   This requires a 10-bit counter. We can simulate this by using the ISR.
            *   **Set `TH0` for the period.** If `TH0 = 0x00` (or `0xFF` if we count down), the timer overflows every `256 * 1us = 256us`. This is too short.
            *   **The most common way is to use Timer 0 to generate interrupts at the desired PWM frequency and manage the duty cycle by controlling the ON-time duration within the ISR.**
            *   **Let's set `TH0` to control the frequency.** If `fosc = 12MHz`, timer clock = 1MHz.
                *   To get an interrupt every `X` microseconds, `TH0 = 256 - X`.
                *   We want an interrupt every 1ms (for 1kHz PWM).
                *   So, `TH0 = 256 - 1000`. This is impossible for 8-bit.

            *   **Let's use Timer 0 for the period.**
                *   `TMOD = 0x20;` // Timer 0, Mode 2

                *   `FREQ_RELOAD = 256 - (fosc / (12 * PWM_Freq))` -- This formula is incorrect for Mode 2 directly generating the PWM period itself.

            *   **Correct Approach: Timer 0 Mode 2 for Timer Overflow Rate, ISR for Duty Cycle Control:**
                *   `fosc = 12MHz`. Timer clock = 1MHz.
                *   Desired PWM Frequency = 1kHz. Period = 1ms.
                *   We need the timer to generate an interrupt every 1ms.
                *   Number of timer ticks for 1ms = 1000.
                *   **We will use the timer's count to define the ON time, and the time until the next overflow to define the OFF time.**
                *   `TMOD = 0x20;` // Timer 0, Mode 2
                *   `TR0 = 1;` // Start timer
                *   `ET0 = 1; EA = 1;` // Enable interrupts
                *   **In ISR:**
                    *   `volatile int on_counts = 500;` // Example: 50% duty cycle requires 0.5ms ON time
                    *   `volatile int off_counts = 500;` // Example: 50% duty cycle requires 0.5ms OFF time
                    *   `static bit pwm_pin_state = 0;`
                    *   If `pwm_pin_state == 0` (pin is LOW, need to turn HIGH):
                        *   Set `P1.0 = 1;`
                        *   `pwm_pin_state = 1;`
                        *   `TL0 = 256 - on_counts;` // Set timer for ON duration
                    *   Else (`pwm_pin_state == 1`, pin is HIGH, need to turn LOW):
                        *   Set `P1.0 = 0;`
                        *   `pwm_pin_state = 0;`
                        *   `TL0 = 256 - off_counts;` // Set timer for OFF duration
                    *   `TR0 = 1;` // Restart timer (auto-reload from TH0 will happen on overflow if TH0 is set)

                *   **Let's set `TH0` such that `256 - TH0` contributes to the period.**
                *   If `fosc = 12MHz`, timer clock = 1MHz.
                *   **The total period is `on_counts + off_counts`. Let this be `TOTAL_COUNTS`.**
                *   We want `TOTAL_COUNTS = 1000` (for 1kHz).
                *   **We need to use two counters or a 16-bit timer for this.**

            *   **Best practice for 8051 with Timer 0 Mode 2:**
                *   **Set `TH0` to control the total period:**
                    *   `fosc = 12MHz`, Timer Clock = 1MHz.
                    *   `PWM_Freq = 1kHz`, Period = 1ms.
                    *   Number of ticks for period = 1000.
                    *   We cannot achieve 1000 ticks directly with 8-bit auto-reload.
                    *   **Let's use Timer 0 to generate an interrupt every `N` ticks, where `N` is a value we can set with `TH0`.**
                    *   Set `TH0 = 256 - (ticks_for_period)`.
                    *   This implies `ticks_for_period` must be less than or equal to 256.
                    *   For `fosc=12MHz`, Max period = 256us (Frequency ≈ 3.9kHz).
                    *   So, if our desired PWM frequency is <= 3.9kHz, we can use Timer 0 Mode 2.
                    *   **Example:** PWM Frequency = 3.9kHz. Period = 256us.
                        *   `TH0 = 256 - 256 = 0x00`.
                        *   Timer overflows every 256us.
                        *   **In ISR:**
                            *   `static unsigned int on_counts = 128;` // 50% duty cycle
                            *   `static unsigned char pwm_state = 0;`
                            *   If `pwm_state == 0`:
                                *   `P1.0 = 1;`
                                *   `pwm_state = 1;`
                                *   `TL0 = 256 - on_counts;` // Timer will count for `on_counts` us
                            *   Else:
                                *   `P1.0 = 0;`
                                *   `pwm_state = 0;`
                                *   `TL0 = TH0;` // Reset TL0 to TH0 (which is 0x00), timer will count for 256us
                                                    // THIS IS WRONG. TL0 reloads from TH0 automatically.
                                                    // We need to control the OFF time by setting TL0 *after* the ON time.
                                                    // The problem is that the reload value TH0 is fixed for frequency.

                *   **Final Recommended Method (using Timer 0 Mode 2 and ISR):**
                    1.  **Define Global Variables:**
                        ```c
                        volatile unsigned char duty_cycle_value; // 0-255 for duty cycle
                        volatile unsigned int timer_period_counts; // Number of timer ticks for the entire PWM period
                        volatile unsigned char pwm_output_state; // 0: LOW, 1: HIGH
                        ```

                        *   `ET0 = 1; EA = 1;` // Enable Timer 0 interrupt and global interrupts
                        *   `duty_cycle_value = 128;` // Default to 50% duty cycle
                        *   `fosc = 12000000;`

                        *   `timer_period_counts = (fosc / 12) / PWM_FREQUENCY;` // Counts needed for the period. This will be > 256 if freq is low.
                        *   **Let's use TH0 to define the frequency and the ISR to manage the duty cycle precisely.**
                        *   **Calculate `TH0` for the desired PWM Frequency.**
                        *   `fosc = 12MHz`, Timer Clock = 1MHz.
                        *   Desired PWM Frequency = 1kHz. Period = 1ms.
                        *   **We need `256 - TH0` timer ticks for the *OFF* time, and the timer should be reloaded with `TH0` at the end of the ON time.**
                        *   **This implies the PWM signal should be HIGH for `256 - TH0` counts and LOW for `TH0` counts.** This is inverted PWM.
                        *   **Let's re-evaluate the standard technique:**
                            *   Set `TH0` to control the **period**.
                            *   `fosc = 12MHz`, Timer Clock = 1MHz.
                            *   PWM Frequency = 1kHz. Period = 1ms.
                            *   Number of ticks for period = 1000.
                            *   **We will use the ISR to count the required number of ticks for ON and OFF states.**
                            *   `TMOD = 0x20;` // Timer 0, Mode 2
                            *   `TH0 = 0x00;` // Set TH0 for maximum count in the timer. This is still problematic.

                        *   **Alternative: Timer 0 in Mode 1 (16-bit):**
                            *   `TMOD = 0x01;`
                            *   `TR0 = 1;`
                            *   `ET0 = 1; EA = 1;`
                            *   **ISR:**
                                *   `static unsigned char on_time_ticks = 500;` // Example duty cycle
                                *   `static unsigned char off_time_ticks = 500;`
                                *   `static bit pwm_pin_state = 0;`
                                *   If `pwm_pin_state == 0`: // Was LOW, now HIGH
                                    *   `P1.0 = 1;`
                                    *   `pwm_pin_state = 1;`
                                    *   `TH0 = 0xFF - (on_time_ticks >> 8);`
                                    *   `TL0 = 0xFF - (on_time_ticks & 0xFF);`
                                *   Else: // Was HIGH, now LOW
                                    *   `P1.0 = 0;`
                                    *   `pwm_pin_state = 0;`
                                    *   `TH0 = 0xFF - (off_time_ticks >> 8);`
                                    *   `TL0 = 0xFF - (off_time_ticks & 0xFF);`

                                *   **This approach requires careful calculation of the reload values based on desired ON/OFF times.**
                                *   **For `fosc=12MHz`, timer tick=1us. Let ON=0.5ms, OFF=0.5ms.**
                                *   `on_time_ticks = 500`, `off_time_ticks = 500`.
                                *   For ON time:
                                    *   `TH0 = 0xFF - (500 >> 8);` // 500 is 0x01F4. >> 8 is 1. `0xFF - 1 = 0xFE`.
                                    *   `TL0 = 0xFF - (500 & 0xFF);` // 500 & 0xFF is 244 (0xF4). `0xFF - 0xF4 = 0x0B`.
                                    *   So, reload TH0=0xFE, TL0=0x0B. Timer counts from this to 0xFFFF.
                                    *   Total counts = `0xFFFF - 0xFE0B + 1 = 0x01F4 + 1 = 501`. This is close to 500.
                                    *   **Correct Reload for Timer Mode 1 (16-bit count):**
                                        *   `CountValue = TargetTicks`.
                                        *   `THx = (65536 - CountValue) >> 8;`
                                        *   `TLx = (65536 - CountValue) & 0xFF;`
                                        *   For ON=500 ticks: `TH0 = (65536 - 500) >> 8 = 65036 >> 8 = 254 (0xFE)`
                                        *   `TL0 = (65536 - 500) & 0xFF = 65036 & 0xFF = 180 (0xB4)`.
                                        *   So, reload with `TH0=0xFE`, `TL0=0xB4`.
                                        *   For OFF=500 ticks: Same reload values.

                    3.  **ISR (`timer0_isr`):**
                        *   Implement the toggling logic and timer reload for ON/OFF states.

#### 3.5 Controlling Direction with H-Bridge
*   **H-Bridge Inputs:** Typically require two control signals (e.g., `IN1`, `IN2`) to control direction.
*   **Control Logic:**
    *   **Forward:** `IN1 = 1`, `IN2 = 0`
    *   **Reverse:** `IN1 = 0`, `IN2 = 1`
    *   **Brake/Coast:** `IN1 = 0`, `IN2 = 0` (or `IN1 = 1`, `IN2 = 1` for brake, depending on the driver IC)
*   **Connection to 8051:** Connect two general-purpose I/O pins from the 8051 to the control inputs of the H-bridge driver.

#### 4.2 Timer Initialization Function (using Timer 0, Mode 1)
```c
void timer0_init() {
    TMOD = 0x01; // Timer 0, Mode 1 (16-bit timer)
    // Set initial reload values for the PWM period
    TH0 = (65536 - PWM_PERIOD_TICKS) >> 8;
    TL0 = (65536 - PWM_PERIOD_TICKS) & 0xFF;

    ET0 = 1;     // Enable Timer 0 interrupt
    EA = 1;      // Enable global interrupts
    TR0 = 1;     // Start Timer 0
}
```

#### 4.3 PWM and Direction Control Functions

```c
unsigned char duty_cycle = 0; // Global variable for duty cycle (0-100%)
unsigned char pwm_state = 0;  // 0: LOW, 1: HIGH
unsigned int on_time_ticks;
unsigned int off_time_ticks;

void set_motor_speed(unsigned char speed_percentage) {
    if (speed_percentage > 100) speed_percentage = 100; // Cap at 100%
    duty_cycle = speed_percentage;

    // Calculate ON and OFF times in timer ticks
    // on_time_ticks = (PWM_PERIOD_TICKS * duty_cycle) / 100;
    // off_time_ticks = PWM_PERIOD_TICKS - on_time_ticks;

    // Calculate precise ticks, avoiding overflow issues with division
    on_time_ticks = (unsigned long)PWM_PERIOD_TICKS * duty_cycle / 100;
    off_time_ticks = PWM_PERIOD_TICKS - on_time_ticks;
}

void set_motor_direction(unsigned char direction) {
    if (direction == FORWARD) {
        DIR_PIN1 = 1;
        DIR_PIN2 = 0;
    } else if (direction == REVERSE) {
        DIR_PIN1 = 0;
        DIR_PIN2 = 1;
    } else { // STOP
        DIR_PIN1 = 0;
        DIR_PIN2 = 0; // or 1 for braking, depending on H-bridge
    }
}
```

#### 4.4 Timer Interrupt Service Routine (ISR)

```c
void timer0_isr() interrupt 1 {
    // Timer 0 ISR (vector address 000Bh)

    // Reload timer for the next period
    // This is crucial for maintaining the PWM frequency
    TH0 = (65536 - PWM_PERIOD_TICKS) >> 8;
    TL0 = (65536 - PWM_PERIOD_TICKS) & 0xFF;

    // Control PWM output based on duty cycle
    if (pwm_state == 0) { // Pin is currently LOW, transition to HIGH
        if (on_time_ticks > 0) {
            // Set PWM pin HIGH
            PWM_PIN = 1;
            pwm_state = 1;
            // Reload timer for the ON time duration
            TH0 = (65536 - on_time_ticks) >> 8;
            TL0 = (65536 - on_time_ticks) & 0xFF;
        } else {
            // If on_time_ticks is 0, keep it LOW for the entire period
            PWM_PIN = 0;
            pwm_state = 0; // Stay LOW
            // Reload timer for the full OFF time (which is the full period in this case)
            // This will be handled by the next interrupt if on_time_ticks is 0.
            // Or, we can explicitly set it for the full period if needed.
        }
    } else { // Pin is currently HIGH, transition to LOW
        if (off_time_ticks > 0) {
            // Set PWM pin LOW
            PWM_PIN = 0;
            pwm_state = 0;
            // Reload timer for the OFF time duration
            TH0 = (65536 - off_time_ticks) >> 8;
            TL0 = (65536 - off_time_ticks) & 0xFF;
        } else {
            // If off_time_ticks is 0, keep it HIGH for the entire period
            PWM_PIN = 1;
            pwm_state = 1; // Stay HIGH
            // Reload timer for the full ON time (which is the full period in this case)
            // This will be handled by the next interrupt if off_time_ticks is 0.
        }
    }
}
```

### 6. Practice Questions and Exercises

**Q1. What is PWM and why is it preferred for DC motor speed control?**

**Answer:** PWM (Pulse Width Modulation) is a technique to create an analog output from a digital signal by varying the duty cycle of a pulse train. It's preferred for DC motor speed control because it allows for efficient speed variation by controlling the average voltage applied to the motor. Unlike resistive control, PWM minimizes power loss in the control circuit, leading to higher efficiency.

**Q2. Explain the role of an H-bridge circuit in DC motor control.**

**Answer:** An H-bridge circuit is essential for DC motor control as it allows for the reversal of current flow through the motor, thereby controlling its direction of rotation. It typically consists of four switches that can be controlled by the microcontroller. By switching different pairs of transistors ON, the motor can be made to rotate forward, reverse, brake, or coast.

**Q3. How can the 8051 microcontroller generate a PWM signal? Describe two common methods.**

**Answer:** The 8051 can generate PWM signals using:
1.  **Hardware PWM:** Some microcontrollers (though not standard 8051) have dedicated PWM modules.
2.  **Software PWM (using Timers and Interrupts):** This is the common method for the 8051. It involves:
    *   Configuring a hardware timer (e.g., Timer 0 or Timer 1) to generate periodic interrupts.
    *   Using the Timer Mode 2 (8-bit auto-reload) or Mode 1 (16-bit) to control the interrupt frequency.
    *   In the Timer Interrupt Service Routine (ISR), the output pin is toggled. The duration for which the pin remains HIGH (ON time) and LOW (OFF time) is controlled by calculating and reloading the timer with appropriate values, thereby adjusting the duty cycle.

**Q4. If the 8051's oscillator frequency (`fosc`) is 11.0592 MHz, and we want to generate a PWM signal with a frequency of 500 Hz using Timer 0 in Mode 1 (16-bit), what should be the reload values for `TH0` and `TL0`?**

**Answer:**
*   `fosc = 11.0592 MHz`
*   Timer Clock = `fosc / 12 = 11.0592 MHz / 12 = 921.6 KHz`
*   Timer Tick Period = `1 / 921.6 KHz ≈ 1.085 µs`
*   Desired PWM Frequency = `500 Hz`
*   PWM Period = `1 / 500 Hz = 2 ms`
*   Number of Timer Ticks for Period = `PWM Period / Timer Tick Period = 2 ms / 1.085 µs ≈ 1843.2`
*   Let's use the closest integer: `1843` ticks for the period.
*   Reload value for 16-bit timer = `65536 - Number of Ticks`
*   Reload Value = `65536 - 1843 = 63693`
*   `TH0` = `63693 >> 8 = 248` (Decimal) = `0xF8` (Hex)
*   `TL0` = `63693 & 0xFF = 197` (Decimal) = `0xC5` (Hex)

**Q5. Write a C code snippet to set the 8051's Timer 0 to Mode 2 for PWM generation.**

**Answer:**
```c
TMOD = 0x20; // Timer 0, Mode 2 (8-bit auto-reload)
// TH0 will store the reload value, TL0 will count.
// TR0 = 1; to start the timer.
```

### 7. Important Points to Remember

*   **H-Bridge Driver ICs:** Using ICs like L293D or L298N simplifies H-bridge implementation and provides protection.
*   **Back EMF:** Always include a flyback diode (or a protection circuit within the driver IC) across the motor terminals to safely dissipate the back EMF generated when the motor is switched off or its speed changes.
*   **Timer Selection:** For PWM generation, Timer 0 or Timer 1 can be used. Mode 1 (16-bit timer) is generally more flexible for precise frequency control, especially if the required period is large. Mode 2 is good for generating regular interrupts at a specific rate.
*   **Interrupt Priority:** If using multiple interrupts, understand the 8051's interrupt priority scheme.
*   **Duty Cycle Range:** The duty cycle can range from 0% (motor off) to 100% (motor at full speed).
*   **Dynamic Control:** The speed and direction can be updated dynamically by calling the respective functions (`set_motor_speed()`, `set_motor_direction()`) with new values.
*   **Power Supply:** Ensure the motor power supply is adequate for the motor's requirements.
*   **Component Selection:** Choose transistors or driver ICs that can handle the motor's voltage and current.
