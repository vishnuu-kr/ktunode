# MICROPROCESSORS AND EMBEDDED SYSTEMS - Module 2: Stack and Subroutines

## Topic: Interrupts

This module delves into a crucial aspect of microprocessor operation: **Interrupts**. Understanding interrupts is vital for building responsive and efficient embedded systems, allowing microprocessors to react to external events without constant polling.

---

### 1. Introduction to Interrupts

**Definition:** An interrupt is a signal to the microprocessor, generated by hardware or software, which tells the processor to stop its current task and attend to something else. It's a mechanism that allows external devices or internal events to temporarily halt the normal program execution and transfer control to a special routine called an Interrupt Service Routine (ISR) or Interrupt Handler.

**Purpose:**
*   **Responsiveness:** Enables the microprocessor to respond to events in real-time, such as button presses, sensor readings, or communication data arrival.
*   **Efficiency:** Avoids the need for constant polling of devices, which consumes valuable CPU cycles. The CPU can continue its main task until an interrupt occurs.
*   **Asynchronous Event Handling:** Allows the system to handle events that are not synchronized with the main program flow.

**Analogy:** Imagine you are reading a book (main task). Suddenly, the doorbell rings (interrupt). You pause your reading, go to the door, attend to the visitor, and then return to your book from where you left off.

### 2. Types of Interrupts

Interrupts can be broadly categorized based on their source and handling:

#### 2.1 Hardware Interrupts

These are generated by external hardware devices.

*   **Maskable Interrupts:**
    *   **Definition:** These interrupts can be enabled or disabled (masked) by the programmer through software instructions.
    *   **Mechanism:** The microprocessor has an interrupt mask register or control bits that allow it to ignore certain maskable interrupts.
    *   **Examples:**
        *   **INTR (Interrupt Request):** A general-purpose maskable interrupt line on many microprocessors (like 8085).
        *   **Timer Interrupts:** Generated by an internal timer when a specific time interval has elapsed.
        *   **I/O Device Interrupts:** Generated by peripherals like keyboards, serial communication interfaces, disk controllers, etc.
    *   **Reference (Ram, B):** Chapter on Interrupts in "Fundamentals of Microprocessor and Micro controllers" discusses the INTR pin and its handling in detail for 8085.
    *   **Reference (Gaonkar, R.):** Chapter on Interrupts in "Microprocessor, Architecture, Programming and Applications" provides a comprehensive overview of hardware interrupts and their vectoring.

*   **Non-Maskable Interrupts (NMI):**
    *   **Definition:** These interrupts cannot be disabled by software. They are typically reserved for critical events that require immediate attention.
    *   **Mechanism:** They have a dedicated interrupt pin on the microprocessor that is always active.
    *   **Examples:**
        *   **Power Failure:** A signal indicating an imminent power loss, allowing the system to save critical data.
        *   **System Errors:** Unrecoverable hardware errors.
    *   **Importance:** Essential for system stability and data integrity.

#### 2.2 Software Interrupts

These are initiated by executing a specific instruction within the program.

*   **Mechanism:** A special instruction (e.g., `RST n` in 8085) is executed, which triggers an interrupt sequence.
*   **Purpose:**
    *   **System Calls:** Used to request services from the operating system or BIOS.
    *   **Error Handling:** Triggering an interrupt upon encountering an unrecoverable error condition in software.
    *   **Debugging:** Inserting breakpoints by using software interrupt instructions.
*   **Example (8085):**
    *   `RST 0` to `RST 7` instructions generate interrupts that vector to specific memory locations.
    *   `RST 5.5`, `RST 6.5`, `RST 7.5` are special interrupts in 8085.
*   **Reference (Ram, B):** Discusses software interrupts like `RST` instructions and their vector addresses.

### 3. Interrupt Handling Mechanism

When an interrupt occurs, the microprocessor follows a specific sequence of actions:

1.  **Interrupt Signal Detection:** The microprocessor detects the interrupt signal on its interrupt pin(s) or through an interrupt instruction.
2.  **Interrupt Acknowledgment:** The microprocessor typically acknowledges the interrupt. For hardware interrupts, this might involve sending an interrupt acknowledge signal to the interrupting device.
3.  **Current State Saving:** The microprocessor saves the current state of the CPU to the stack. This usually includes:
    *   **Program Counter (PC):** The address of the instruction to be executed next.
    *   **Flags Register:** The status of various arithmetic and logical operations.
    *   **Other Register Contents:** In some architectures, general-purpose registers might also be saved.
    *   **Why save to stack?** The stack is a LIFO (Last-In, First-Out) data structure, which is ideal for storing and restoring the context of interrupted tasks. This ensures that when the ISR finishes, the interrupted program can resume exactly where it left off.
4.  **Disabling Interrupts (Optional/Conditional):** To prevent further interrupts from disrupting the current ISR, the microprocessor might automatically disable further interrupts (or at least mask maskable interrupts).
5.  **Vectoring to ISR:** The microprocessor determines the address of the Interrupt Service Routine (ISR). This can be done in several ways:
    *   **Vectored Interrupts:** The interrupting device provides the microprocessor with a vector address (or an interrupt type number that can be translated to an address). Each interrupt source has a dedicated memory location that stores the ISR's starting address.
    *   **Polled Interrupts:** The microprocessor queries the interrupting devices to determine which one generated the interrupt. This is less efficient but simpler to implement.
6.  **Executing the ISR:** The microprocessor fetches and executes the instructions of the ISR.
    *   **ISR Function:** The ISR performs the necessary actions to service the interrupt request (e.g., read data from a buffer, update a display).
    *   **Re-enabling Interrupts:** Within the ISR, the programmer may choose to re-enable interrupts (especially lower-priority ones) to ensure system responsiveness to other events.
7.  **Restoring Context:** Upon completion of the ISR, the microprocessor restores the saved CPU state from the stack. This includes popping the saved PC and flags register.
8.  **Resuming Execution:** The microprocessor resumes execution of the interrupted program from the instruction that was about to be executed.

### 4. Interrupt Vector Table (IVT)

**Definition:** The Interrupt Vector Table (IVT) is a data structure (an array or table) stored in a specific memory region (usually the beginning of memory) that contains the starting addresses of the Interrupt Service Routines (ISRs) for various interrupt sources.

**Purpose:** When an interrupt occurs, the microprocessor uses the interrupt vector (an index or address) to look up the corresponding ISR's starting address in the IVT.

**Example (8085):**
The 8085 has specific interrupt pins with fixed vector addresses:
*   **TRAP:** 0024H (Non-maskable, highest priority)
*   **RST 7.5:** 003C H
*   **RST 6.5:** 0034 H
*   **RST 5.5:** 002CH
*   **INTR:** Requires an external device to provide an instruction (like `RST n` or `CALL address`) to vector to the ISR.

**Important Point:** The addresses in the IVT are typically hardcoded or initialized by the system firmware.

### 5. Interrupt Priority

When multiple interrupts occur simultaneously or while another interrupt is being serviced, the microprocessor needs a mechanism to decide which interrupt to handle first. This is managed through interrupt priority.

*   **Priority Levels:** Interrupt sources are assigned priority levels. Higher priority interrupts are serviced before lower priority ones.
*   **Preemptive vs. Non-Preemptive:**
    *   **Preemptive:** If a higher-priority interrupt occurs while a lower-priority ISR is executing, the lower-priority ISR can be interrupted, and the higher-priority ISR executed. This is the most common and desirable behavior for responsiveness.
    *   **Non-Preemptive:** Once an ISR starts executing, it will complete its execution without being interrupted by any other interrupt, regardless of priority.
*   **Interrupt Masking:** Maskable interrupts can be selectively disabled to manage priorities. For example, a low-priority ISR might mask all lower-priority interrupts to ensure its own completion.
*   **Example (8085 Priority):**
    *   TRAP (highest priority)
    *   RST 7.5
    *   RST 6.5
    *   RST 5.5
    *   INTR (lowest priority, can be made maskable or unmaskable by the `SIM` instruction).

### 6. Enabling and Disabling Interrupts

Microprocessors provide instructions to control the interrupt system.

*   **Enabling Interrupts:**
    *   **`EI` (Enable Interrupts):** This instruction enables maskable interrupts. For 8085, it sets the Interrupt Enable (IE) flag.
    *   **`SIM` (Set Interrupt Mask):** This instruction is used in the 8085 to configure the maskable interrupts (RST 7.5, RST 6.5, RST 5.5) and to enable/disable serial data output.
*   **Disabling Interrupts:**
    *   **`DI` (Disable Interrupts):** This instruction disables all maskable interrupts. For 8085, it clears the Interrupt Enable (IE) flag.
    *   **`RIM` (Read Interrupt Mask):** This instruction reads the status of the interrupt mask and serial data input from the `SIM` instruction.

**Important Point:** It is crucial to manage interrupt enabling and disabling carefully to avoid race conditions or missed interrupts. Often, interrupts are disabled before critical operations and re-enabled afterward.

### 7. Arduino and Interrupts

Arduino boards, based on microcontrollers like the ATmega series, also heavily utilize interrupts for efficient event handling.

*   **Arduino Uno (ATmega328P):**
    *   Has dedicated **Interrupt Pins**: Digital Pin 2 and Digital Pin 3 are typically connected to external interrupt request pins (INT0 and INT1) on the ATmega328P.
    *   **Interrupt Triggers:** Interrupts can be triggered by:
        *   **LOW:** When the pin is low.
        *   **CHANGE:** When the pin changes state (HIGH to LOW or LOW to HIGH).
        *   **RISING:** When the pin goes from LOW to HIGH.
        *   **FALLING:** When the pin goes from HIGH to LOW.
*   **Arduino `attachInterrupt()` Function:**
    *   This function is used to attach an ISR to a specific interrupt pin.
    *   **Syntax:** `attachInterrupt(digitalPinToInterrupt(pin), ISR_function, mode);`
        *   `digitalPinToInterrupt(pin)`: Converts the digital pin number to the corresponding interrupt number.
        *   `ISR_function`: The name of the function to be executed when the interrupt occurs.
        *   `mode`: Specifies the trigger condition (LOW, CHANGE, RISING, FALLING).
*   **ISR Considerations in Arduino:**
    *   **Short and Fast:** ISRs should be as short and fast as possible to minimize disruption to the main program flow.
    *   **No `delay()` or Blocking Functions:** Avoid using functions like `delay()`, `serial.print()`, or any other function that might block execution within an ISR.
    *   **`volatile` Keyword:** Variables accessed by both the main program and an ISR should be declared as `volatile` to ensure the compiler always reads their most up-to-date value.
*   **Reference (Margolis, M.):** The "Arduino Cookbook" provides practical examples and explanations of using interrupts with Arduino, including the `attachInterrupt()` function.
*   **Reference (Baichtal, J.):** "Arduino for beginners" also covers basic interrupt usage with simple projects.
*   **Reference (Pajankar, A.):** "Arduino Made Simple" offers clear introductions to interrupt concepts and their implementation.
*   **Reference (Monk, S.):** "Programming Arduino Next Steps" delves deeper into advanced interrupt techniques.

### 9. Key Concepts and Definitions to Remember

*   **Interrupt:** A signal to pause current execution and attend to an event.
*   **ISR (Interrupt Service Routine):** A dedicated routine to handle an interrupt.
*   **Maskable Interrupts:** Can be enabled/disabled by software.
*   **Non-Maskable Interrupts (NMI):** Cannot be disabled by software (critical events).
*   **Vector Table (IVT):** Table storing ISR addresses.
*   **Interrupt Priority:** Hierarchy for servicing multiple interrupts.
*   **Stack:** Used to save/restore CPU state during an interrupt.
*   **`EI` / `DI`:** Enable/Disable maskable interrupts.
*   **`SIM` / `RIM` (8085):** Set/Read Interrupt Mask, control serial I/O.
*   **`attachInterrupt()` (Arduino):** Function to link an ISR to a pin.
*   **`volatile` (C/C++):** Keyword for variables shared between ISRs and main code.
*   **Preemptive vs. Non-preemptive:** Whether an ISR can be interrupted by a higher-priority interrupt.

1.  **8085 Assembly Language:**
    Write an 8085 assembly language program snippet that:
    a.  Disables interrupts.
    b.  Initializes the stack pointer.
    c.  Enables interrupts.
    d.  Assume an ISR for `RST 5.5` is located at address `2000H`. What would the initial IVT entry look like in memory?
    e.  Write a small ISR for `RST 5.5` that toggles an LED connected to port `80H` (assuming appropriate bit manipulation).

    *   **Answer Hint:**
        *   Disable: `DI`
        *   Initialize SP: `LXI SP, XXXXH` (e.g., `LXI SP, 3000H`)
        *   Enable: `EI`
        *   IVT for RST 5.5: At `002CH`, store the address `2000H` as `00 20`. This involves `LXI H, 2000H` and `SHLD 002CH`.
        *   ISR: Save registers, toggle LED, restore registers, `RETI`.

2.  **Arduino C++:**
    Write an Arduino sketch that uses an interrupt to count the number of times a button connected to Digital Pin 2 is pressed. The count should be displayed on the Serial Monitor. The interrupt should be triggered on the rising edge of the button press.

    *   **Answer Hint:**
        ```cpp
        volatile unsigned long buttonPressCount = 0; // Use volatile

        void setup() {
          Serial.begin(9600);
          pinMode(2, INPUT_PULLUP); // Button connected to Pin 2, use internal pull-up
          attachInterrupt(digitalPinToInterrupt(2), incrementCounter, RISING); // Attach ISR
        }

        void loop() {
          Serial.print("Button Pressed: ");
          Serial.println(buttonPressCount);
          delay(100); // Small delay to avoid flooding the serial monitor
        }

        void incrementCounter() {
          buttonPressCount++; // ISR function
        }
        ```

3.  **Conceptual Question:**
    Describe a scenario in an embedded system (e.g., a washing machine control) where interrupts would be essential. What events might trigger interrupts, and what would be the typical ISR for each?

    *   **Answer Hint:**
        *   **Events:** Door latch sensor (door opened/closed), water level sensor (water reached required level), motor speed feedback (motor stalled), timer expiration.
        *   **ISRs:**
            *   Door Latch: Start filling water if door is closed and start button pressed.
            *   Water Level: Stop filling water, start agitation.
            *   Motor Stall: Stop motor, signal error.
            *   Timer Expired: Proceed to next cycle phase (drain, spin).

### 11. Important Points to Remember

*   Interrupts are crucial for **real-time responsiveness** in embedded systems.
*   Always save the processor's **context** (PC, flags) before executing an ISR.
*   **Restore the context** after the ISR finishes to allow seamless resumption of the interrupted program.
*   Keep ISRs **short and efficient**. Avoid blocking operations within an ISR.
*   Use the `volatile` keyword for variables accessed by both the main code and ISRs.
*   Understand the interrupt priority scheme of your processor to manage concurrent interrupt requests.
*   Master the specific instructions (`EI`, `DI`, `SIM`, `RIM` for 8085) and functions (`attachInterrupt()` for Arduino) related to interrupt control.
*   The stack is the **backbone of context saving** during interrupts.
