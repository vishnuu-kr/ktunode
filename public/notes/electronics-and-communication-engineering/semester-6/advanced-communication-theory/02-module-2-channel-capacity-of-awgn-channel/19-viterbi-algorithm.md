### 1. Introduction to the Viterbi Algorithm

The Viterbi algorithm is a dynamic programming algorithm used for finding the most likely sequence of hidden states in a hidden Markov model (HMM). In the context of digital communications, it is primarily used for **maximum likelihood decoding of convolutional codes**.

**Key Concept:** Convolutional codes are widely used for error correction in digital communication systems due to their simplicity and effectiveness. The Viterbi algorithm provides an efficient way to decode these codes, finding the most probable transmitted sequence given the received noisy sequence.

**Importance:** For a given received sequence, there could be multiple possible transmitted sequences that could have resulted in it, especially in the presence of noise. The Viterbi algorithm systematically searches through all possible transmitted sequences and identifies the one that is "closest" to the received sequence in terms of Hamming distance (or a similar metric).

### 2. Convolutional Codes and their Trellis Representation

Before diving into the Viterbi algorithm, it's crucial to understand convolutional codes and their graphical representation.

**2.1 Convolutional Codes:**

*   **Definition:** Convolutional codes are defined by a memory element (shift registers) and linear feedforward logic. The output bits are a convolution of the input data stream and the generator polynomials.
*   **Parameters:**
    *   **Constraint Length (K):** The number of bits that affect the current output. It determines the "memory" of the encoder.
    *   **Code Rate (k/n):** The ratio of the number of information bits ($k$) to the number of coded bits ($n$) per block of input.
    *   **Generator Polynomials:** Represent the connections from the shift register stages to the modulo-2 adders that produce the output bits.
*   **Encoding Process:**
    *   Input bits are shifted into a series of shift registers.
    *   The output bits are generated by modulo-2 addition of specific shift register states, determined by the generator polynomials.

**Example:** A rate-1/2 convolutional encoder with constraint length $K=3$.
*   The encoder has $K-1=2$ shift registers.
*   Generator polynomials: $g^{(1)} = [1, 1, 1]$ (octal 7) and $g^{(2)} = [1, 0, 1]$ (octal 5).
*   Input: $d_i$
*   Output bits: $c_i^{(1)}$ and $c_i^{(2)}$ where $c_i^{(j)} = \sum_{l=0}^{K-1} d_{i-l} \cdot g_l^{(j)} \pmod{2}$.

**2.2 Trellis Diagram:**

*   **Purpose:** The trellis diagram provides a state-transition representation of a convolutional encoder. It visualizes all possible paths through the encoder's states over time.
*   **States:** The states of the encoder are determined by the contents of the shift registers. For a code with constraint length $K$, there are $2^{K-1}$ states.
*   **Transitions:** Each time a new information bit arrives, the encoder transitions from one state to another. Each transition is associated with the output coded bits.
*   **Structure:** The trellis is a time-unrolled representation of the encoder's state machine.
    *   **Nodes:** Represent the states of the encoder.
    *   **Branches:** Represent transitions between states, labeled with the output coded bits.
    *   **Time:** The diagram progresses in discrete time steps, corresponding to the arrival of each input bit.

**Example (Continuing the rate-1/2, K=3 encoder):**
*   Number of states: $2^{K-1} = 2^{3-1} = 2^2 = 4$ states.
*   States are represented by the contents of the two shift registers: $s_1 s_0$.
*   The states are: 00, 01, 10, 11.

| Current State ($s_1 s_0$) | Input Bit ($d_i$) | Next State ($s'_1 s'_0$) | Output ($c_i^{(1)} c_i^{(2)}$) | Generator $g^{(1)}$ | Generator $g^{(2)}$ |

| 00                        | 0                 | 00                        | 00                            | [1,1,1]             | [1,0,1]             |

**Important Point:** The trellis diagram is fundamental to understanding how the Viterbi algorithm operates, as it systematically explores all possible transmitted sequences.

### 3. The Viterbi Algorithm: Step-by-Step

The Viterbi algorithm is a **dynamic programming** approach that finds the most likely path through the trellis for a given received sequence. It operates in three main steps:

1.  **Initialization:** For the first time step, initialize the path metrics for each state.
2.  **Recursion (or Iteration):** For each subsequent time step, calculate the path metrics for all states by considering all incoming branches and selecting the path with the minimum metric.
3.  **Termination:** After processing all time steps, identify the state with the minimum path metric and trace back through the stored decisions to reconstruct the most likely transmitted sequence.

**3.1 Path Metric:**

*   **Definition:** The path metric quantifies the "closeness" of a particular path through the trellis to the received noisy sequence.
*   **Common Metrics:**
    *   **Hamming Distance:** For uncoded or hard-decision decoding. It's the number of positions at which two sequences differ.
    *   **Euclidean Distance (or Squared Euclidean Distance):** For soft-decision decoding, especially in AWGN channels. It's calculated as the sum of squared differences between the received symbol and the ideal symbol for each bit.
    *   **Log-Likelihood Ratio (LLR):** A more sophisticated metric for soft-decision decoding, which directly relates to the probability of a bit being 0 or 1.

**For AWGN Channel (Soft Decision Decoding), the squared Euclidean distance is commonly used:**
Let $\mathbf{r} = [r_1, r_2, \dots, r_n]$ be the received sequence of real numbers (e.g., after matched filtering), and let $\mathbf{c} = [c_1, c_2, \dots, c_n]$ be the ideal coded sequence of real numbers (e.g., +1 for '1', -1 for '0'). The squared Euclidean distance is $\sum_{i=1}^n (r_i - c_i)^2$.
Minimizing $\sum (r_i - c_i)^2$ is equivalent to maximizing the correlation with the ideal signal, which is related to the likelihood.

**3.2 Algorithm Steps in Detail:**

*   **Initialization (t=0):**
    *   For the initial state (usually state '00...' which represents all zeros in the shift registers), the path metric is set to 0.
    *   For all other states, the path metric is set to infinity.
    *   Store the path leading to each state (initially empty or pointing to the initial state).

*   **Recursion (for t = 1, 2, ...):**
    *   For each state $j$ at time $t$:
        *   Consider all incoming branches from states $i$ at time $t-1$. Each incoming branch corresponds to a specific input bit ($d_t$) and produces a specific coded bit sequence ($\mathbf{c}_t$).
        *   For each incoming branch from state $i$ to state $j$:
            *   Calculate the **branch metric ($\lambda_{ij}$)**: This is the distance (e.g., squared Euclidean distance) between the received coded symbols $\mathbf{r}_t$ and the ideal coded symbols $\mathbf{c}_t$ corresponding to that transition.
            *   Calculate the **path metric to state j via state i**: This is the path metric of state $i$ at time $t-1$ plus the branch metric $\lambda_{ij}$.
        *   **Select the minimum:** For state $j$ at time $t$, compare the path metrics arriving from all possible predecessor states $i$.
        *   **Update path metric:** Set the path metric of state $j$ at time $t$ to the minimum of these values.
        *   **Store survivor path:** Record which predecessor state $i$ yielded this minimum path metric. This decision defines the "survivor path" to state $j$ at time $t$.

*   **Termination (at the end of the received sequence, time T):**
    *   **Find the best state:** Identify the state at time $T$ with the minimum overall path metric.
    *   **Traceback:** Starting from this best state, follow the stored survivor path decisions backward in time. Each decision at each time step tells you the input bit that led to that state from the previous state. This reconstructs the most likely transmitted sequence.

**Important Point:** The Viterbi algorithm efficiently prunes away unlikely paths by always keeping track of only the "best" path to each state at each time step. This is what makes it a practical decoder.

### 4. Viterbi Algorithm Example (Soft-Decision Decoding)

Let's consider a simplified scenario with a rate-1/2, $K=3$ convolutional encoder. We'll use squared Euclidean distance as the path metric.

**Encoder Recap:**
*   States: 00, 01, 10, 11
*   Transitions and Outputs (as shown in section 2.2)

**Received Sequence (after matched filtering and sampling):**
Assume the transmitted sequence was `10110`.
The encoder outputs might be:
`11` (for input 1)
`00` (for input 0)
`11` (for input 1)
`01` (for input 1)
`00` (for input 0)

So, ideal transmitted coded sequence is: `11 00 11 01 00` (pairs of bits)

Due to AWGN, let's say the received sequence is: `1.2 0.9 | -0.3 0.1 | 1.0 1.3 | 0.2 -0.8 | -0.1 -0.2`

We need to decode this 10-bit received sequence. The trellis will have 5 time steps.

**Initialization (t=0):**
*   State 00: Path Metric (PM) = 0. Path: []
*   State 01: PM = $\infty$. Path: []
*   State 10: PM = $\infty$. Path: []
*   State 11: PM = $\infty$. Path: []

**Time Step 1 (Input: $d_1=1$, Received: $r_1=1.2, r_2=0.9$):**
*   **From State 00 (PM=0):**
    *   Input 1: Next State 10, Ideal Output `11`.
        *   Branch Metric $\lambda_{00 \to 10} = (1.2 - 1)^2 + (0.9 - 1)^2 = 0.2^2 + (-0.1)^2 = 0.04 + 0.01 = 0.05$.
        *   Path Metric to 10: $0 + 0.05 = 0.05$. Path: [1]
    *   Input 0: Next State 00, Ideal Output `00`.
        *   Branch Metric $\lambda_{00 \to 00} = (1.2 - 0)^2 + (0.9 - 0)^2 = 1.44 + 0.81 = 2.25$.
        *   Path Metric to 00: $0 + 2.25 = 2.25$. Path: [0]

*   **Update States:**
    *   State 00: PM = 2.25 (via 0). Path: [0]
    *   State 01: PM = $\infty$.
    *   State 10: PM = 0.05 (via 1). Path: [1]
    *   State 11: PM = $\infty$.

**Time Step 2 (Input: $d_2=0$, Received: $r_3=-0.3, r_4=0.1$):**
*   **From State 00 (PM=2.25):**
    *   Input 0: Next State 00, Ideal Output `00`.
        *   $\lambda_{00 \to 00} = (-0.3 - 0)^2 + (0.1 - 0)^2 = 0.09 + 0.01 = 0.10$.
        *   Path Metric to 00: $2.25 + 0.10 = 2.35$. Path: [0, 0]
    *   Input 1: Next State 10, Ideal Output `11`.
        *   $\lambda_{00 \to 10} = (-0.3 - 1)^2 + (0.1 - 1)^2 = (-1.3)^2 + (-0.9)^2 = 1.69 + 0.81 = 2.50$.
        *   Path Metric to 10: $2.25 + 2.50 = 4.75$. Path: [0, 1]

*   **From State 01 (PM=$\infty$):** (No need to calculate as PM is infinite)

*   **From State 10 (PM=0.05):**
    *   Input 0: Next State 01, Ideal Output `00`.
        *   $\lambda_{10 \to 01} = (-0.3 - 0)^2 + (0.1 - 0)^2 = 0.09 + 0.01 = 0.10$.
        *   Path Metric to 01: $0.05 + 0.10 = 0.15$. Path: [1, 0]
    *   Input 1: Next State 11, Ideal Output `11`.
        *   $\lambda_{10 \to 11} = (-0.3 - 1)^2 + (0.1 - 1)^2 = (-1.3)^2 + (-0.9)^2 = 1.69 + 0.81 = 2.50$.
        *   Path Metric to 11: $0.05 + 2.50 = 2.55$. Path: [1, 1]

*   **From State 11 (PM=$\infty$):** (No need to calculate)

*   **Update States (Selecting Minimums):**
    *   State 00: PM = 2.35 (via 0). Path: [0, 0]
    *   State 01: PM = 0.15 (via 0). Path: [1, 0]
    *   State 10: PM = 4.75 (via 0). Path: [0, 1] (Note: This is the minimum path to state 10 at t=2)
    *   State 11: PM = 2.55 (via 1). Path: [1, 1]

**(Continue this process for all time steps)**

**Time Step 3 (Input: $d_3=1$, Received: $r_5=1.0, r_6=1.3$):**
*   ... (Calculations omitted for brevity)

**Time Step 4 (Input: $d_4=1$, Received: $r_7=0.2, r_8=-0.8$):**
*   ...

**Time Step 5 (Input: $d_5=0$, Received: $r_9=-0.1, r_{10}=-0.2$):**
*   ...

**Termination (After processing all received bits):**
Let's assume (hypothetically) after all steps, the path metrics are:
*   State 00: PM = 5.2
*   State 01: PM = 4.8
*   State 10: PM = 6.1
*   State 11: PM = 5.0

The state with the minimum path metric is State 01 (PM=4.8). Now, we traceback from State 01 at t=5.

*   **t=5, State 01:** Suppose this state was reached from State 00 with input 0. Path: `...0`
*   **t=4, State 00:** Suppose this state was reached from State 01 with input 1. Path: `...10`
*   **t=3, State 01:** Suppose this state was reached from State 10 with input 0. Path: `...010`
*   **t=2, State 10:** Suppose this state was reached from State 00 with input 1. Path: `...1010`
*   **t=1, State 00:** Suppose this state was reached from State 00 with input 0. Path: `01010`

**Most likely transmitted sequence: `01010`**

**Important Points:**
*   The number of states grows exponentially with $K$.
*   The complexity of the Viterbi algorithm is proportional to $2^{K-1} \times N$ (where $N$ is the number of received bits). For practical purposes, $K$ is usually limited to around 7-9.
*   Soft-decision decoding (using LLR or similar metrics) generally provides better performance than hard-decision decoding.

### 5. Advantages and Disadvantages of the Viterbi Algorithm

**Advantages:**

*   **Optimal for Convolutional Codes:** It is the maximum likelihood sequence estimator for convolutional codes, meaning it finds the most probable transmitted sequence.
*   **Efficient Implementation:** Despite the potentially large number of states, its dynamic programming nature makes it computationally feasible for moderate constraint lengths.
*   **Hardware Implementation:** It can be efficiently implemented in hardware (e.g., ASICs, FPGAs) for real-time decoding in communication systems.
*   **Adaptable Metrics:** Can be used with different metrics (Hamming, Euclidean, LLR) depending on the channel and decoding strategy.

**Disadvantages:**

*   **Complexity Growth:** The computational complexity and memory requirements increase exponentially with constraint length $K$. This limits its applicability to larger $K$.
*   **Not Optimal for All Codes:** It is specifically designed for convolutional codes. Other decoding algorithms (like BCJR) are used for other types of codes (e.g., turbo codes, LDPC codes).
*   **No Direct Bit Information:** The Viterbi algorithm outputs a sequence of bits. It doesn't directly provide reliability information for individual bits, unlike the BCJR algorithm.

**References:**

*   **Lin & Costello, Error Control Coding:** Discusses performance comparisons and limitations.
*   **Goldsmith, Wireless Communications:** Provides a good overview of the trade-offs.

### 6. Viterbi Algorithm in the Context of AWGN Channel Capacity

While the Viterbi algorithm itself doesn't directly calculate channel capacity, it is a crucial component in systems designed to operate close to the Shannon capacity of the AWGN channel.

*   **Approaching Capacity:** Convolutional codes, when decoded by the Viterbi algorithm, can achieve error rates very close to the theoretical limits imposed by the AWGN channel, especially for moderate signal-to-noise ratios (SNR).
*   **Performance Gain:** The error correction capability of convolutional codes, combined with the Viterbi decoder, provides a significant performance gain (coding gain) compared to uncoded systems. This gain allows for lower transmit power or higher data rates for a given error probability.
*   **System Design:** Understanding the Viterbi algorithm is essential for designing practical wireless communication systems that aim to utilize the AWGN channel capacity effectively. The choice of code rate, constraint length, and modulation scheme are all influenced by the capabilities and limitations of the Viterbi decoder.

**References:**

*   **Cover & Thomas, Elements of Information Theory:** Provides the theoretical foundation for channel capacity and how coding can approach it. (Chapter 11, Channel Capacity and Coding)
*   **Goldsmith, Wireless Communications:** Discusses the role of coding in achieving capacity in AWGN and fading channels.

### 7. Practice Questions and Answers

**Question 1:** What is the primary application of the Viterbi algorithm in digital communications?
    a) Modulation demodulation
    b) Equalization
    c) Maximum likelihood decoding of convolutional codes
    d) Source coding

**Answer 1:** c) Maximum likelihood decoding of convolutional codes

**Question 2:** The constraint length ($K$) of a convolutional encoder determines:
    a) The code rate
    b) The number of output bits per input bit
    c) The memory of the encoder (number of shift registers = $K-1$)
    d) The generator polynomials

**Answer 2:** c) The memory of the encoder (number of shift registers = $K-1$)

**Question 3:** In the Viterbi algorithm, what is typically minimized when using soft-decision decoding in an AWGN channel?
    a) Hamming distance
    b) Path length
    c) Squared Euclidean distance
    d) Signal-to-noise ratio

**Answer 3:** c) Squared Euclidean distance

**Question 4:** If a convolutional encoder has a constraint length $K=4$, how many states does it have?
    a) 3
    b) 4
    c) 8
    d) 16

**Answer 4:** c) 8 ($2^{K-1} = 2^{4-1} = 2^3 = 8$)

**Question 5:** (Conceptual) Briefly explain why the Viterbi algorithm is considered a "greedy" or "dynamic programming" approach.

**Answer 5:** The Viterbi algorithm is a dynamic programming approach because at each step (time instance), it makes the locally optimal choice (selecting the path with the minimum metric to reach each state) without considering the global future consequences. By storing and updating the "survivor path" to each state, it effectively prunes away less likely paths, ensuring that the overall most likely path is eventually found by the end of the trellis. This "best path so far" principle is characteristic of dynamic programming.

### 8. Important Points to Remember

*   **Viterbi is for Convolutional Codes:** Its core purpose is decoding these specific types of codes.
*   **Trellis Diagram is Key:** Understanding the state transitions and branch outputs is essential for grasping the algorithm.
*   **Path Metric:** The choice of metric (Hamming vs. Euclidean) is crucial and depends on the decoding type (hard vs. soft). For AWGN, squared Euclidean distance is common for soft-decision.
*   **Dynamic Programming:** The algorithm efficiently finds the most likely path by making optimal decisions at each step.
*   **Complexity:** Grows exponentially with constraint length ($2^{K-1}$ states), limiting practical $K$.
*   **Approaching Capacity:** Viterbi-decoded convolutional codes are vital for practical systems aiming to utilize AWGN channel capacity.
