# CODING THEORY: Module 4 - Review on Convolutional Codes

## Topic: Construction

This module provides a review of convolutional codes, focusing on their construction. We will delve into the fundamental principles that govern the design of these codes, enabling efficient error detection and correction.

### Learning Outcomes:

*   Understand the basic structure and operation of convolutional encoders.
*   Learn different methods for constructing convolutional codes.
*   Analyze the properties and performance of convolutional codes.
*   Apply knowledge of convolutional codes to practical scenarios.

### Key Concepts and Definitions:

*   **Convolutional Code:** A type of error-correcting code in which each codeword bit is a function of an unlimited number of message bits. This is achieved by using a finite-length shift register and modulo-2 adders.
*   **Encoder:** The circuit that generates the codeword from the message sequence.
*   **Constraint Length (K):** The number of bits in the shift register of the convolutional encoder. This parameter dictates the memory of the encoder.
*   **Code Rate (r):** The ratio of the number of message bits to the number of encoded bits per time unit. For a convolutional code, $r = k/n$, where $k$ is the number of bits entering the shift register at each time step, and $n$ is the number of output bits generated at each time step.
*   **Generator Polynomials:** Polynomials that define the connections of the shift register to the modulo-2 adders in the encoder. These are crucial for constructing and understanding the code's properties.
*   **State Diagram:** A graphical representation of the encoder's operation, showing the transitions between different states based on the input bits.
*   **Trellis Diagram:** An expanded version of the state diagram that unfolds over time, illustrating the complete encoding process for a sequence of input bits.
*   **Free Distance ($d_{free}$):** The minimum Hamming distance between the all-zero codeword and any other valid codeword. This is a key performance metric for convolutional codes.

### 1. Basic Structure of a Convolutional Encoder

A convolutional encoder typically consists of:

*   **Shift Register:** A series of $K-1$ memory elements (flip-flops) that store the incoming message bits.
*   **Modulo-2 Adders (XOR Gates):** Used to combine bits from different stages of the shift register to generate the output bits.
*   **Connections:** The connections from the shift register stages to the adders determine the generator polynomials and thus the code itself.

**Illustration:**

Consider a simple convolutional encoder with constraint length $K=3$ and code rate $r=1/2$ (meaning 1 message bit input, 2 codeword bits output).

Let the message sequence be $m_1, m_2, m_3, \dots$.
The shift register stores the current input bit and the previous $K-1$ bits.
Let the contents of the shift register at time $i$ be $(m_i, m_{i-1}, m_{i-2})$.

**Encoder Structure:**

*   **Output 1 ($y_{1i}$):** Generated by combining specific bits from the shift register.
*   **Output 2 ($y_{2i}$):** Generated by combining other specific bits from the shift register.

**Example:**

Let's define the generator polynomials for this example:
*   $g^{(1)}(D) = 1 + D + D^2$
*   $g^{(2)}(D) = 1 + D^2$

The output bits at time $i$ can be represented as:
$y_{1i} = m_i \oplus m_{i-1} \oplus m_{i-2}$
$y_{2i} = m_i \oplus m_{i-2}$

In terms of delay elements (D):
$Y_1(D) = G^{(1)}(D) M(D) = (1 + D + D^2) M(D)$
$Y_2(D) = G^{(2)}(D) M(D) = (1 + D^2) M(D)$

The overall codeword polynomial is $Y(D) = [Y_1(D), Y_2(D)]$.

**Important Note:** The exponents of $D$ in the generator polynomial correspond to the taps on the shift register. A tap on the first stage corresponds to $D^0=1$, the second stage to $D^1$, and so on. The highest power of $D$ in the polynomial is $K-1$.

### 2. Construction Methods for Convolutional Codes

The primary method for constructing convolutional codes involves defining their generator polynomials. The choice of these polynomials significantly impacts the code's performance, particularly its free distance.

#### 2.1 Generator Polynomials

Generator polynomials are defined over the finite field $GF(2)$. For a code with rate $k/n$, there will be $n$ generator polynomials, $g^{(1)}(D), g^{(2)}(D), \dots, g^{(n)}(D)$. Each polynomial $g^{(j)}(D)$ is a polynomial in $D$ of degree at most $K-1$.

The output sequence of the $j$-th output branch is given by:
$Y_j(D) = G^{(j)}(D) M(D)$, where $G^{(j)}(D) = \sum_{l=0}^{K-1} g^{(j)}_l D^l$ and $g^{(j)}_l \in \{0, 1\}$.

**Example (Continuing from above):**
For $K=3$, $r=1/2$, $g^{(1)}(D) = 1 + D + D^2$ and $g^{(2)}(D) = 1 + D^2$.
The encoder has $K-1 = 2$ memory elements.

Let the input message sequence be $1011$.
Initial state of the shift register is assumed to be all zeros $(0, 0)$.

| Time (i) | Input ($m_i$) | Shift Register (before input) | Shift Register (after input) | $y_{1i} = m_i \oplus m_{i-1} \oplus m_{i-2}$ | $y_{2i} = m_i \oplus m_{i-2}$ | Output ($y_{1i}y_{2i}$) |
| :------- | :------------ | :---------------------------- | :--------------------------- | :------------------------------------------ | :---------------------------------------- | :------------------------ |
| 0        | 0 (initial)   | (0, 0)                        | (0, 0)                       | 0                                           | 0                                         | 00                        |
| 1        | 1             | (0, 0)                        | (1, 0)                       | $1 \oplus 0 \oplus 0 = 1$                   | $1 \oplus 0 = 1$                          | 11                        |
| 2        | 0             | (1, 0)                        | (0, 1)                       | $0 \oplus 1 \oplus 0 = 1$                   | $0 \oplus 1 = 1$                          | 11                        |
| 3        | 1             | (0, 1)                        | (1, 0)                       | $1 \oplus 0 \oplus 1 = 0$                   | $1 \oplus 0 = 1$                          | 01                        |
| 4        | 1             | (1, 0)                        | (1, 1)                       | $1 \oplus 1 \oplus 0 = 0$                   | $1 \oplus 1 = 0$                          | 00                        |

The encoded output sequence for the message $1011$ is $00 \, 11 \, 11 \, 01 \, 00$.

#### 2.2 State Diagrams

The state of the encoder is determined by the contents of the shift register. For a constraint length $K$ and $k$ input bits at each step, there are $2^{K-1}$ possible states (assuming $k=1$ for simplicity of illustration).

**Example (K=3, r=1/2):**
Constraint length $K=3$. Number of memory elements is $K-1=2$.
The states are represented by the contents of the shift register: $(m_{i-1}, m_{i-2})$.
Possible states: 00, 01, 10, 11.

*   **State 00:** Shift register contains $(0, 0)$.
*   **State 01:** Shift register contains $(0, 1)$.
*   **State 10:** Shift register contains $(1, 0)$.
*   **State 11:** Shift register contains $(1, 1)$.

**Transitions:**

From a given state, if the input is 0, the new state is formed by shifting the current state and adding a 0 at the most significant bit position. If the input is 1, a 1 is added.

Let's use the previous encoder ($g^{(1)}(D) = 1 + D + D^2$, $g^{(2)}(D) = 1 + D^2$) to illustrate state transitions.
Output bits: $y_1 = m \oplus m_{prev} \oplus m_{prev2}$, $y_2 = m \oplus m_{prev2}$

| Current State $(m_{i-1}, m_{i-2})$ | Input ($m_i$) | Next State $(m_i, m_{i-1})$ | Output ($y_{1i}y_{2i}$) |
| :--------------------------------- | :------------ | :-------------------------- | :------------------------ |
| 00                                 | 0             | 00                          | $0 \oplus 0 \oplus 0 = 0$, $0 \oplus 0 = 0 \implies 00$ |
| 00                                 | 1             | 10                          | $1 \oplus 0 \oplus 0 = 1$, $1 \oplus 0 = 1 \implies 11$ |
| 01                                 | 0             | 00                          | $0 \oplus 0 \oplus 1 = 1$, $0 \oplus 1 = 1 \implies 11$ |
| 01                                 | 1             | 10                          | $1 \oplus 0 \oplus 1 = 0$, $1 \oplus 1 = 0 \implies 00$ |
| 10                                 | 0             | 01                          | $0 \oplus 1 \oplus 0 = 1$, $0 \oplus 0 = 0 \implies 10$ |
| 10                                 | 1             | 11                          | $1 \oplus 1 \oplus 0 = 0$, $1 \oplus 0 = 1 \implies 01$ |
| 11                                 | 0             | 01                          | $0 \oplus 1 \oplus 1 = 0$, $0 \oplus 1 = 1 \implies 01$ |
| 11                                 | 1             | 11                          | $1 \oplus 1 \oplus 1 = 1$, $1 \oplus 1 = 0 \implies 10$ |

#### 2.3 Trellis Diagrams

A trellis diagram is formed by "unrolling" the state diagram over time. It explicitly shows all possible paths through the states for a given sequence of input bits.

**Example (K=3, r=1/2, for message 10):**
States: 00, 01, 10, 11.

*   **Time 0:** Start in state 00 (initial state).
    *   Input 0: Output 00, transition to state 00. Path: $00_{00 \to 00}$
    *   Input 1: Output 11, transition to state 10. Path: $11_{00 \to 10}$
*   **Time 1:**
    *   From state 00:
        *   Input 0: Output 00, transition to state 00. Path: $00_{00 \to 00}$
        *   Input 1: Output 11, transition to state 10. Path: $11_{00 \to 10}$
    *   From state 10:
        *   Input 0: Output 10, transition to state 01. Path: $10_{10 \to 01}$
        *   Input 1: Output 01, transition to state 11. Path: $01_{10 \to 11}$

If the message is $10$:
Time 0: Input 1 from state 00 -> Output 11, move to state 10.
Time 1: Input 0 from state 10 -> Output 10, move to state 01.

The encoded sequence for message $10$ is $1110$.

#### 2.4 Properties and Performance Metrics

The quality of a convolutional code is determined by its free distance.

*   **Free Distance ($d_{free}$):** The minimum Hamming distance between the all-zero codeword and any other non-zero codeword.
    *   A larger $d_{free}$ generally implies better error-correcting capability.
    *   Calculating $d_{free}$ involves examining all possible paths in the trellis diagram and finding the path with the minimum Hamming weight for the encoded output.

**Example (K=3, r=1/2, $g^{(1)}(D) = 1 + D + D^2$, $g^{(2)}(D) = 1 + D^2$):**
Let's look for the minimum weight codeword.
If message is $00\dots0$, codeword is $0000\dots0$.
If message is $1$, codeword is $11$. Hamming weight is 2.
If message is $01$, codeword is $1110$. Hamming weight is 3.
If message is $11$, codeword is $0110$. Hamming weight is 2.

From the state diagram transitions, we can find paths that diverge from the all-zero path and re-converge. The length of the information sequence and the encoder structure determine the minimum weight. For this code, it can be shown that $d_{free} = 5$. (This requires a more detailed analysis of the trellis).

#### 2.5 Construction of Good Convolutional Codes

The goal is to construct codes with a good free distance for a given constraint length and code rate. Tables of optimal convolutional codes for various $K$ and $n$ are available in literature.

**Key considerations for construction:**

*   **Maximizing $d_{free}$:** This is the primary objective.
*   **Minimizing $d_{free}/n$:** Ratio of free distance to the number of output bits per symbol.
*   **Structure of generator polynomials:**
    *   **Octal representation:** Generator polynomials are often represented in octal form (e.g., $11_8$ for $1+D$). For $r=1/2$, two polynomials are needed. A common notation is $(g^{(1)}_{octal}, g^{(2)}_{octal})$.
    *   **Example:** For $K=3$, $g^{(1)}(D) = 1+D+D^2 \rightarrow 110_2 = 6_8$. $g^{(2)}(D) = 1+D^2 \rightarrow 101_2 = 5_8$. So, this code can be denoted as $(6, 5)_8$.
    *   **Important Properties of Generator Polynomials for Good Codes:**
        *   Each generator polynomial should have a weight (number of non-zero terms) of at least 3 for $r=1/2$ codes.
        *   The distance between any two generator polynomials should be at least 3.
        *   The grandfathering condition: $G^{(i)}(D)$ should divide $D^m - 1$ for some $m$.

**(CO4: Use algebraic techniques to construct efficient codes with reduced structural complexity (Knowledge Level: K3))** - The choice of generator polynomials and their properties are algebraic techniques to design codes.

**Tables of Optimal Codes:**
For practical purposes, instead of deriving optimal codes from scratch, engineers often refer to tables that list the best known convolutional codes for specific $K$ and $r$. These tables are based on extensive computer search.

**Example from Lin & Costello, 2nd Ed. (Table 5.1):**
For $K=3$, $r=1/2$:
The code with $g^{(1)}(D) = 1+D+D^2$ and $g^{(2)}(D) = 1+D^2$ (octal (6,5)) has $d_{free}=5$.
The code with $g^{(1)}(D) = 1+D+D^2$ and $g^{(2)}(D) = 1+D+D^2$ (octal (6,6)) has $d_{free}=4$. Clearly, (6,5) is better.

#### 2.6 Rate-k/n Convolutional Codes

For $r = k/n$, the encoder has $k$ input bits entering at each time step, and $n$ output bits are generated. The encoder will have $K-1$ memory elements to store the $k \times (K-1)$ previous input bits.

**Encoder Structure:**
The $k$ input bits are fed into $k$ separate shift registers (or a combined shift register structure), and $n$ sets of modulo-2 adders combine bits from these registers to produce $n$ output streams.

**Generator Matrix:**
For rate-$k/n$ codes, the generator function is represented by a $k \times n$ generator matrix, where each entry is a polynomial in $D$.
$G(D) = \begin{pmatrix}
G^{(1)}(D) \\
\vdots \\
G^{(k)}(D)
\end{pmatrix}$ is not quite right for the multi-input case.
The correct representation is a $k \times n$ matrix of polynomials:
$G(D) = \begin{pmatrix}
G_{11}(D) & G_{12}(D) & \dots & G_{1n}(D) \\
G_{21}(D) & G_{22}(D) & \dots & G_{2n}(D) \\
\vdots & \vdots & \ddots & \vdots \\
G_{k1}(D) & G_{k2}(D) & \dots & G_{kn}(D)
\end{pmatrix}$

The output codeword polynomial vector $Y(D) = [Y_1(D), \dots, Y_n(D)]$ is given by:
$Y(D) = M(D) G(D)$, where $M(D) = [m_1(D), \dots, m_k(D)]$ is the input message polynomial vector.

### 3. Construction and Implementation Considerations

*   **Systematic Convolutional Codes:** In systematic codes, the input message bits appear directly in the output codeword. For convolutional codes, this means $k$ of the $n$ output branches are directly the input bits. This can simplify decoding in some cases.
*   **Puncturing:** To achieve higher code rates or to adapt a code to different channel conditions, the systematic encoder output can be "punctured" by skipping some output bits. This means removing some bits from the encoded stream according to a specific pattern.
    *   Example: For a rate 1/2 code, we transmit $y_1y_2$. To get a rate 3/4 code from this, we could transmit $y_1y_2y_1y_2y_1y_2$ and puncture it to $y_1y_2y_1y_2$ (omitting every third bit of each stream, or some other pattern).
    *   Puncturing is a common technique to generate rate-$1/r$ codes from a mother code with a lower rate.

### Summary of Important Points:

*   Convolutional codes are defined by their **constraint length ($K$)** and **code rate ($k/n$)**.
*   The encoder structure is characterized by a **shift register** and **modulo-2 adders**.
*   **Generator polynomials** are the algebraic basis for constructing convolutional codes and are crucial for their performance.
*   The **state diagram** and **trellis diagram** visualize the encoder's operation and are fundamental for decoding.
*   **Free distance ($d_{free}$)** is the primary performance metric, indicating error-correcting capability.
*   Optimal codes are often found through extensive **computer search** and listed in tables.
*   **Puncturing** is a technique used to achieve higher code rates from existing convolutional codes.

**Question 2:**
What is the significance of the free distance ($d_{free}$) of a convolutional code? How is it related to error detection and correction?

**Answer 2:**
The **free distance ($d_{free}$)** is the minimum Hamming distance between the all-zero codeword and any other valid codeword generated by the convolutional encoder.

*   **Error Detection:** A code with minimum distance $d_{min}$ can detect up to $d_{min}-1$ errors. For convolutional codes, $d_{free}$ determines the maximum number of errors that can be reliably detected. If $d_{free}$ errors occur, the decoder is likely to produce an incorrect output.
*   **Error Correction:** A code with minimum distance $d_{min}$ can correct up to $\lfloor (d_{min}-1)/2 \rfloor$ errors. Therefore, a convolutional code with free distance $d_{free}$ can correct up to $\lfloor (d_{free}-1)/2 \rfloor$ errors. A larger $d_{free}$ directly translates to a higher capability of correcting errors in the received sequence.

**Question 3:**
Explain the concept of **puncturing** in convolutional codes and why it is used.

**Answer 3:**
**Puncturing** is a technique used to increase the code rate of an existing convolutional code. It involves selectively deleting or "skipping" certain coded bits from the output of a lower-rate encoder to produce a higher-rate code.

*   **Mechanism:** A puncturing pattern (a sequence of 0s and 1s) is used to decide which bits to transmit. A '1' in the pattern indicates that the corresponding coded bit is transmitted, while a '0' means it is deleted.
*   **Purpose:**
    1.  **Achieving Higher Code Rates:** A single, good low-rate convolutional code (e.g., rate 1/2) can be used to generate a family of higher-rate codes (e.g., rate 2/3, 3/4, 5/6) by applying different puncturing patterns. This offers flexibility in adapting to varying channel conditions and bandwidth constraints.
    2.  **Reducing Bandwidth:** By transmitting fewer bits, higher code rates are achieved, leading to more efficient use of the communication channel bandwidth.
*   **Trade-off:** While puncturing increases the code rate, it typically reduces the free distance and thus the error-correcting capability of the code compared to the original rate-1/2 code. The design of the puncturing pattern is crucial to minimize this performance degradation.

**(CO6: Illustrate modern error correcting codes like Turbo codes, LDOC code and polar codes (Knowledge Level: K2))** - Puncturing is a fundamental technique that connects basic convolutional codes to more advanced coding schemes.

### Important Points to Remember:

*   The constraint length $K$ is a primary parameter affecting the complexity and performance of convolutional codes.
*   The choice of generator polynomials is critical. Optimal codes maximize $d_{free}$ for a given $K$ and $r$.
*   Always ensure the shift register is initialized to a known state (usually all zeros) or that the decoding algorithm can handle unknown initial states.
*   Understanding the trellis diagram is key to implementing decoding algorithms like the Viterbi algorithm.
*   Convolutional codes are well-suited for applications requiring continuous data streams and moderate complexity.
