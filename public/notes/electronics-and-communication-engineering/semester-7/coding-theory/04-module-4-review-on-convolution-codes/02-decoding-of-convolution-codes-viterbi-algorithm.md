# Module 4: Review on Convolutional Codes - Decoding of Convolutional Codes – Viterbi Algorithm

## 1. Introduction to Convolutional Codes

Convolutional codes are a type of error-correcting code that are widely used in digital communication systems. Unlike block codes, which operate on blocks of data independently, convolutional codes operate on a continuous stream of data. This means that the encoded output at any given time depends not only on the current input bits but also on a finite number of previous input bits. This property gives convolutional codes their "memory."

### Key Concepts:

*   **Encoder:** A finite-state machine that takes an input data stream and produces a coded output stream.
*   **Constraint Length (K):** The number of bits that affect the output at any given time. This includes the current input bit and the previous $K-1$ input bits stored in the shift register.
*   **Generator Polynomials:** Polynomials that define the linear feedback shift register (LFSR) connections in the encoder. For a rate $k/n$ convolutional code, there are $n$ generator polynomials.
*   **Rate (k/n):** The ratio of the number of input bits ($k$) to the number of output bits ($n$) per symbol.
*   **State Diagram:** A graphical representation of the encoder's transitions between states based on the input bits.
*   **Trellis Diagram:** An unwrapped state diagram that illustrates the evolution of the encoder's states over time. This is crucial for understanding Viterbi decoding.
*   **Branch Metric:** The measure of error between the received sequence and the possible transmitted sequences for a given transition in the trellis.

### Important Points to Remember:

*   Convolutional codes have memory, meaning the output depends on past inputs.
*   The constraint length $K$ is a key parameter determining the complexity and performance of the code.
*   Generator polynomials define the encoder's structure.

## 2. The Viterbi Algorithm: A Maximum Likelihood Decoding Approach

The Viterbi algorithm is a maximum likelihood (ML) decoding algorithm for convolutional codes. It finds the most likely transmitted sequence given the received, potentially noisy, sequence. It does this by efficiently searching the trellis diagram for the path that minimizes the total accumulated error (distance).

### Key Concepts:

*   **Maximum Likelihood (ML) Decoding:** The goal is to find the transmitted codeword that is closest to the received codeword in terms of a specific distance measure (usually the Hamming distance or Euclidean distance).
*   **Trellis Diagram Revisited:** The Viterbi algorithm operates on the trellis diagram. The trellis has $2^{K-1}$ states, and for each state, there are two possible transitions corresponding to an input bit of '0' or '1'.
*   **Path:** A sequence of transitions through the trellis, representing a possible transmitted codeword.
*   **Path Metric:** The accumulated error along a path. This is typically the sum of the branch metrics for each transition in the path.
*   **Survivor Path:** At each stage (time interval) in the trellis, the Viterbi algorithm keeps track of the path with the minimum path metric for each state. This path is called the survivor path.
*   **Traceback:** After the algorithm has processed the entire received sequence, the survivor path for the final state is used to reconstruct the most likely transmitted message. This is done by tracing back through the stored pointers.

### Algorithm Steps:

The Viterbi algorithm operates in stages, processing the received sequence bit by bit (or symbol by symbol). At each stage $t$:

1.  **Initialization (t=0):**
    *   The path metric for the initial state (state 00...0) is set to 0.
    *   The path metrics for all other states are set to infinity.

2.  **Calculation of Branch Metrics (for each possible transition):**
    *   For each state $s_{i}$ at time $t-1$, and for each possible input bit ($0$ or $1$), calculate the branch metric.
    *   The branch metric measures the "distance" between the received symbols (at time $t$) and the output symbols generated by the encoder for that specific transition.
    *   Commonly used metrics:
        *   **Hamming Distance:** For hard decision decoding.
        *   **Euclidean Distance (or Squared Euclidean Distance):** For soft decision decoding. This is generally preferred as it provides better performance.

3.  **Calculation of Path Metrics (for each state at time $t$):**
    *   For each state $s_{j}$ at time $t$, there will be two incoming transitions from states at time $t-1$.
    *   Calculate the path metric for each incoming transition by adding the branch metric to the path metric of the preceding state at time $t-1$.
    *   **Compare and Select (Maximum Likelihood):** For each state $s_{j}$, select the incoming transition that results in the minimum path metric. Store this minimum path metric as the path metric for state $s_{j}$ at time $t$.
    *   **Store Survivor Pointers:** Along with the minimum path metric, store a pointer indicating which previous state and input bit led to this minimum metric. This pointer is crucial for the traceback phase.

4.  **Traceback (after processing the entire received sequence):**
    *   Start from the final state at the end of the trellis (typically state 00...0 for properly terminated codes).
    *   Follow the stored pointers backward from stage to stage. Each pointer reveals the input bit that led to that state's survivor path.
    *   The sequence of input bits traced back is the decoded message.

### Example: Rate 1/2, K=3 Convolutional Code

Let's consider a simple rate 1/2 convolutional code with generator polynomials $g_1 = 1+x$ and $g_2 = 1+x+x^2$. The constraint length $K=3$.

**Encoder Structure:**
The encoder has a shift register of length $K-1 = 2$. The states are determined by the contents of the shift register. For $K=3$, there are $2^{K-1} = 2^2 = 4$ states: 00, 01, 10, 11.

*   **State Representation:** State is represented by the contents of the shift register (e.g., `s1 s0`).
*   **Output Calculation:**
    *   $y_1 = \text{input} \oplus s_0$ (using generator polynomial $1+x$)
    *   $y_2 = \text{input} \oplus s_0 \oplus s_1$ (using generator polynomial $1+x+x^2$)

**Trellis Diagram (Conceptual):**

*   **States:** 00, 01, 10, 11
*   **Transitions:** From each state, two transitions occur: one for input '0' and one for input '1'.
    *   If input is '0': $s_1$ becomes $s_0$, $s_0$ becomes '0'.
    *   If input is '1': $s_1$ becomes $s_0$, $s_0$ becomes '1'.

**Let's trace the encoder for input message `101`:**

| Time (t) | Input | Shift Register (s1 s0) (Before) | Output (y1 y2) | Shift Register (s1 s0) (After) | State (After) |
| :------- | :---- | :------------------------------ | :------------- | :----------------------------- | :------------ |
| 0        | 1     | 00                              | 1 (1$\oplus$0), 1 (1$\oplus$0$\oplus$0) | 01                             | 01            |
| 1        | 0     | 01                              | 0 (0$\oplus$0), 1 (0$\oplus$0$\oplus$1) | 10                             | 10            |
| 2        | 1     | 10                              | 0 (1$\oplus$1), 0 (1$\oplus$1$\oplus$0) | 01                             | 01            |

**Received Sequence:** Let's assume the transmitted sequence was `110100` and due to noise, the received sequence is `100100`.

**Viterbi Decoding:**

We will use Hamming distance for simplicity in this example (hard decision decoding).

**Stage 0 (Initialization):**
*   State 00: Path Metric = 0. Pointer: None.
*   State 01: Path Metric = $\infty$.
*   State 10: Path Metric = $\infty$.
*   State 11: Path Metric = $\infty$.

**Stage 1 (Processing first received bits `10`):**

*   **From State 00:**
    *   Input '0': Next state 00. Encoder output `00`. Received `10`. Branch Metric: HD(`10`, `00`) = 2. Path Metric = 0 (prev metric) + 2 = 2. Pointer: (State 00, Input 0).
    *   Input '1': Next state 01. Encoder output `11`. Received `10`. Branch Metric: HD(`10`, `11`) = 1. Path Metric = 0 (prev metric) + 1 = 1. Pointer: (State 00, Input 1).

*   **Update State Metrics at Stage 1:**
    *   State 00: Metric = 2 (from input '0'). Survivor Path: 0.
    *   State 01: Metric = 1 (from input '1'). Survivor Path: 1.
    *   State 10: Metric = $\infty$.
    *   State 11: Metric = $\infty$.

**Stage 2 (Processing next received bits `01`):**

*   **From State 00 (Metric 2):**
    *   Input '0': Next state 00. Encoder output `00`. Received `01`. Branch Metric: HD(`01`, `00`) = 1. Path Metric = 2 + 1 = 3. Pointer: (State 00, Input 0).
    *   Input '1': Next state 01. Encoder output `11`. Received `01`. Branch Metric: HD(`01`, `11`) = 1. Path Metric = 2 + 1 = 3. Pointer: (State 00, Input 1).

*   **From State 01 (Metric 1):**
    *   Input '0': Next state 10. Encoder output `01`. Received `01`. Branch Metric: HD(`01`, `01`) = 0. Path Metric = 1 + 0 = 1. Pointer: (State 01, Input 0).
    *   Input '1': Next state 11. Encoder output `10`. Received `01`. Branch Metric: HD(`01`, `10`) = 2. Path Metric = 1 + 2 = 3. Pointer: (State 01, Input 1).

*   **Update State Metrics at Stage 2:**
    *   State 00: Metric = 3 (from input '0'). Survivor Path: 0.
    *   State 01: Metric = 3 (from input '1'). Survivor Path: 1.
    *   State 10: Metric = 1 (from input '0'). Survivor Path: 0.
    *   State 11: Metric = 3 (from input '1'). Survivor Path: 1.

**Stage 3 (Processing next received bits `00`):**

*   **From State 00 (Metric 3):**
    *   Input '0': Next state 00. Encoder output `00`. Received `00`. Branch Metric: HD(`00`, `00`) = 0. Path Metric = 3 + 0 = 3. Pointer: (State 00, Input 0).
    *   Input '1': Next state 01. Encoder output `11`. Received `00`. Branch Metric: HD(`00`, `11`) = 2. Path Metric = 3 + 2 = 5. Pointer: (State 00, Input 1).

*   **From State 01 (Metric 3):**
    *   Input '0': Next state 10. Encoder output `01`. Received `00`. Branch Metric: HD(`00`, `01`) = 1. Path Metric = 3 + 1 = 4. Pointer: (State 01, Input 0).
    *   Input '1': Next state 11. Encoder output `10`. Received `00`. Branch Metric: HD(`00`, `10`) = 1. Path Metric = 3 + 1 = 4. Pointer: (State 01, Input 1).

*   **From State 10 (Metric 1):**
    *   Input '0': Next state 01. Encoder output `00`. Received `00`. Branch Metric: HD(`00`, `00`) = 0. Path Metric = 1 + 0 = 1. Pointer: (State 10, Input 0).
    *   Input '1': Next state 11. Encoder output `11`. Received `00`. Branch Metric: HD(`00`, `11`) = 2. Path Metric = 1 + 2 = 3. Pointer: (State 10, Input 1).

*   **From State 11 (Metric 3):**
    *   Input '0': Next state 11. Encoder output `00`. Received `00`. Branch Metric: HD(`00`, `00`) = 0. Path Metric = 3 + 0 = 3. Pointer: (State 11, Input 0).
    *   Input '1': Next state 10. Encoder output `11`. Received `00`. Branch Metric: HD(`00`, `11`) = 2. Path Metric = 3 + 2 = 5. Pointer: (State 11, Input 1).

*   **Update State Metrics at Stage 3:**
    *   State 00: Metric = 3 (from input '0'). Survivor Path: 0.
    *   State 01: Metric = 1 (from input '0'). Survivor Path: 0.
    *   State 10: Metric = 3 (from input '1'). Survivor Path: 1.
    *   State 11: Metric = 3 (from input '0'). Survivor Path: 0.

**Traceback (assuming the encoder terminated in state 00):**

The Viterbi algorithm typically works on a finite block of data, and the encoder is often terminated by flushing the shift register with zeros, forcing the encoder back to the all-zero state. For our example, let's assume we are looking for the most likely path ending in state 00.

*   **End of Trellis (e.g., after last bit):** The minimum path metric ending in state 00 is 3. This path came from State 00 at the previous stage with input '0'.
    *   Decoded bit: 0. Pointer to (State 00, Input 0) at Stage 2.

*   **Stage 2:** The survivor path for state 00 at Stage 2 had a metric of 3 and came from State 00 at Stage 1 with input '0'.
    *   Decoded bit: 0. Pointer to (State 00, Input 0) at Stage 1.

*   **Stage 1:** The survivor path for state 00 at Stage 1 had a metric of 2 and came from State 00 at Stage 0 with input '0'.
    *   Decoded bit: 0. Pointer to (State 00, Input 0) at Stage 0.

*   **Stage 0:** Started in state 00.

**Decoded Message (Traceback from end state):** 000. This is not ideal because our original message was 101. This highlights the importance of proper termination and understanding the structure. In a real scenario, we would track the survivor paths more carefully.

**Correction to Traceback Example (focusing on the path with the overall minimum metric):**

If we consider the overall minimum path metric at the end of the trellis across all states, it might lead us to the correct path. Let's re-examine the metrics at Stage 3:
*   State 00: 3
*   State 01: 1
*   State 10: 3
*   State 11: 3

The minimum metric is 1, ending in state 01. Let's trace back from there.

*   **End of Trellis (State 01, Metric 1):** Came from State 10 at Stage 2 with input '0'.
    *   Decoded bit: 0. Pointer to (State 10, Input 0) at Stage 2.

*   **Stage 2 (State 10, Metric 1):** Came from State 01 at Stage 1 with input '0'.
    *   Decoded bit: 0. Pointer to (State 01, Input 0) at Stage 1.

*   **Stage 1 (State 01, Metric 1):** Came from State 00 at Stage 0 with input '1'.
    *   Decoded bit: 1. Pointer to (State 00, Input 1) at Stage 0.

*   **Stage 0:** Started in state 00.

**Decoded Message (Traceback): 100**. This is closer to the original `101`. The discrepancies are due to the assumed received sequence and the simplified Hamming distance metric.

### Soft-Decision Decoding:

*   Instead of hard decisions (0 or 1), soft decisions use analog values (e.g., voltage levels) of the received signal.
*   The branch metric is typically the squared Euclidean distance between the received symbol and the ideal transmitted symbol.
    *   For binary antipodal signaling: $d^2 = (r - s)^2$, where $r$ is the received symbol and $s$ is the transmitted symbol.
*   Soft-decision decoding generally offers about 2-3 dB improvement in signal-to-noise ratio (SNR) compared to hard-decision decoding.

### Important Points to Remember:

*   Viterbi algorithm finds the ML path in the trellis.
*   It's a dynamic programming algorithm, using the principle of optimality.
*   The key steps are branch metric calculation, path metric calculation, and traceback.
*   Soft-decision decoding provides better performance than hard-decision decoding.
*   The complexity of the Viterbi algorithm is proportional to $2^{K-1} \times n$, where $K$ is the constraint length and $n$ is the number of output bits per symbol. This can become computationally expensive for large $K$.

## 3. Decoding Performance and Complexity

### Performance:

*   **Free Distance ($d_{free}$):** The minimum Hamming distance between the all-zero codeword and any other valid codeword. A larger free distance generally leads to better error correction capabilities.
*   **Error Probability:** The probability of decoding an incorrect message. The performance of convolutional codes is often analyzed by looking at their error probability versus SNR.
*   **Impact of Constraint Length (K):** Increasing $K$ generally improves the error correction performance but also increases the complexity.

### Complexity:

*   **State Complexity:** The number of states in the trellis is $2^{K-1}$.
*   **Add-Compare-Select (ACS) Operations:** The core of the Viterbi algorithm involves $2^{K-1} \times n$ ACS operations per stage.
*   **Memory Requirements:** Storing the survivor paths requires memory proportional to the number of states and the length of the decoded sequence.
*   **Free Distance vs. Constraint Length:** While increasing $K$ helps, the most significant gains are often seen for smaller values of $K$. The structure of the generator polynomials also plays a crucial role in determining $d_{free}$.

## 4. Termination of Convolutional Codes

For block-based processing, it's common to terminate convolutional codes by appending a sequence of zeros to the input message. This forces the encoder's shift register to return to the all-zero state at the end of the transmission. This has two main benefits:

1.  **Ensures a Known End State:** This simplifies the traceback process in Viterbi decoding, as the decoder knows the expected final state.
2.  **Reduces the Likelihood of Errors Propagating Beyond the Message Block:** The termination sequence effectively "cleans up" the encoder's memory.

The number of termination bits required is equal to the constraint length minus one ($K-1$).

**Question 2:**
What is the primary advantage of using soft-decision decoding with the Viterbi algorithm compared to hard-decision decoding?

**Answer 2:**
The primary advantage of soft-decision decoding is its **superior error correction performance**. By using the analog values of the received signal (rather than just their binary interpretation), soft-decision decoding provides more information to the decoder. This leads to a lower bit error rate (BER) for a given signal-to-noise ratio (SNR), typically offering a gain of 2-3 dB. This improvement is achieved because the decoder can better distinguish between signals that are close to the decision boundary.
