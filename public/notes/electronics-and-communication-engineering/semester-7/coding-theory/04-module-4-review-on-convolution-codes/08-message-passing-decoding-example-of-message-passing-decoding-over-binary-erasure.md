# CODING THEORY: Module 4 - Review on Convolutional Codes

## Topic: Message Passing Decoding

### Learning Outcomes:
* Understand the principles of message passing decoding algorithms.
* Apply message passing decoding to convolutional codes.
* Analyze the performance of message passing decoding on binary erasure channels.

### Key Concepts and Definitions:

*   **Convolutional Codes:** Codes generated by a finite-state machine. They have memory, meaning the current output depends not only on the current input but also on previous inputs.
    *   **Code Rate (k/n):** The ratio of message bits to transmitted bits.
    *   **Constraint Length (K):** The number of bits that influence the current output. Often defined as the memory length + 1.
    *   **Generator Polynomials:** Polynomials that define the convolutional encoder.
    *   **Trellis Diagram:** A graphical representation of the state transitions of a convolutional encoder over time. Essential for decoding.

*   **Message Passing Decoding:** A class of decoding algorithms that operate on a graphical representation of the code (often a trellis or a factor graph). Information is passed between nodes in the graph, refining estimates of the transmitted bits until a likely codeword is found.
    *   **Belief Propagation (BP):** A general message passing algorithm for graphical models. It aims to compute the marginal probability distribution of each variable.
    *   **Sum-Product Algorithm:** A variant of Belief Propagation often used for decoding codes. It computes sums of products of probabilities.
    *   **Factor Graph:** A bipartite graph representing a function as a product of simpler functions (factors). For codes, the factor graph represents the code's parity check equations or generator matrix structure.

*   **Binary Erasure Channel (BEC):** A communication channel where each transmitted bit is either received correctly (with probability 1-ε) or erased (with probability ε). Erasures are known to the decoder.

### Principles of Message Passing Decoding:

Message passing decoding algorithms, like the Sum-Product algorithm, work by iteratively exchanging "messages" between nodes in a graphical model. For convolutional codes, this typically involves passing messages along the edges of the trellis diagram.

1.  **Graphical Representation:** The convolutional code is represented as a trellis diagram or a factor graph. Each node in the graph represents a variable (e.g., transmitted bits, state transitions), and edges represent the relationships (constraints) between these variables.

2.  **Initialization:**
    *   **Extrinsic Information:** Initial messages are often initialized based on the received symbols (soft or hard decisions). For a BEC, if a bit is erased, the decoder has no information, so the initial message might reflect a uniform distribution. If it's received correctly, the message reflects the certainty of that received bit.
    *   **Prior Probabilities:** The decoder might incorporate prior probabilities of the transmitted bits if known (e.g., uniform prior for all bits).

3.  **Message Passing Iterations:**
    *   **Variable Nodes to Factor Nodes (or Constraint Nodes):** A variable node sends a message to its neighboring factor nodes. This message typically represents the decoder's current belief about the value of that variable, conditioned on all other information it has received so far.
    *   **Factor Nodes to Variable Nodes:** A factor node receives messages from all its neighboring variable nodes. It then computes a new message to send back to each variable node. This new message incorporates the information from all other neighbors, effectively "summing out" the variables it's responsible for. This is where the "sum-product" comes in – it involves summing over possible values and multiplying probabilities.

4.  **Convergence:** The process repeats for a fixed number of iterations or until the messages stabilize, indicating that the beliefs have converged.

5.  **Final Decision:** After convergence, the decoder makes a final decision on each transmitted bit by examining the marginal probability distribution (or a related metric) at each variable node.

### Message Passing Decoding for Convolutional Codes:

For convolutional codes, the trellis diagram is the natural structure for message passing. The Sum-Product algorithm can be applied directly to the trellis.

*   **States:** The states of the trellis represent the memory of the encoder.
*   **Branches:** Each branch in the trellis represents a state transition caused by an input bit, producing an output codeword.
*   **Edges:** The edges of the trellis connect nodes in consecutive time steps. Messages are passed along these edges.

**Types of Messages:**

*   **Forward Messages ($\alpha_t(s)$):** These messages represent the probability (or log-likelihood ratio) of being in state $s$ at time $t$, given the received symbols up to time $t$. These are passed forward in time.
*   **Backward Messages ($\beta_t(s)$):** These messages represent the probability (or log-likelihood ratio) of reaching the end of the codeword from state $s$ at time $t$, given the received symbols from time $t+1$ onwards. These are passed backward in time.

The Viterbi algorithm can be viewed as a hard-decision, greedy version of message passing where only the most likely path is tracked. Message passing (like the BCJR algorithm, which is equivalent to Sum-Product on the trellis) computes the maximum a posteriori (MAP) probability for each bit.

### Example: Message Passing Decoding over Binary Erasure Channels (BEC)

Let's consider a simple convolutional code and a BEC.

**Scenario:**

*   **Code:** A simple rate 1/2 convolutional code with generator polynomials $g^{(1)} = 1+D$ and $g^{(2)} = 1+D+D^2$.
*   **Encoder State:** The encoder has 2 states ($S_0, S_1$), determined by the current value of the memory bit (last input bit).
    *   State $S_0$: Memory bit is 0.
    *   State $S_1$: Memory bit is 1.
*   **Trellis Diagram:**
    *   From $S_0$:
        *   Input 0: Output (0, 0), next state $S_0$.
        *   Input 1: Output (1, 1), next state $S_1$.
    *   From $S_1$:
        *   Input 0: Output (1, 1), next state $S_0$.
        *   Input 1: Output (0, 0), next state $S_1$.

*   **Channel:** Binary Erasure Channel with erasure probability $\epsilon$.

**Received Sequence:** Let the transmitted sequence be $d = [0, 1, 0]$.
*   **Input 0:** Encoder state $S_0$. Output: $(c^{(1)}_0, c^{(2)}_0) = (0, 0)$. Next state: $S_0$.
*   **Input 1:** Encoder state $S_0$. Output: $(c^{(1)}_1, c^{(2)}_1) = (1, 1)$. Next state: $S_1$.
*   **Input 0:** Encoder state $S_1$. Output: $(c^{(1)}_2, c^{(2)}_2) = (1, 1)$. Next state: $S_0$.
*   **Transmitted Codeword:** $(c^{(1)}, c^{(2)}) = ([0, 1, 1], [0, 1, 1])$.

**Received Symbols (Assume received symbols $y^{(1)}$ and $y^{(2)}$):**
Let's say the received symbols are:
*   $y^{(1)} = [0, \text{E}, 1]$ (E denotes erasure)
*   $y^{(2)} = [\text{E}, 1, 1]$

**Message Passing Decoding (Sum-Product on Trellis):**

The Sum-Product algorithm can be implemented using forward and backward messages, or directly on a factor graph representation of the trellis. For simplicity, let's conceptualize the message passing.

**Initialization:**

*   **For received bits:**
    *   If $y_t^{(j)} = 0$: Initial message $\approx \infty$ (log-likelihood ratio - LLR) favoring 0.
    *   If $y_t^{(j)} = 1$: Initial message $\approx -\infty$ LLR favoring 1.
*   **For erased bits:**
    *   If $y_t^{(j)} = \text{E}$: Initial message = 0 (no information, uniform belief).

Let's use probabilities for illustration, though LLRs are more common in practice.

**Time $t=0$:**
*   Input $d_0 = 0$.
*   Encoder state $S_0$.
*   Outputs: $(c^{(1)}_0, c^{(2)}_0) = (0, 0)$.
*   Received: $y^{(1)}_0 = 0$, $y^{(2)}_0 = \text{E}$.

**Messages at $t=0$:**
*   For $c^{(1)}_0$: Received 0. Message from channel $\approx P(c^{(1)}_0=0)=1$.
*   For $c^{(2)}_0$: Received E. Message from channel $\approx P(c^{(2)}_0)=0.5$ for both 0 and 1.

**Trellis Structure at $t=0$:**

| From State | Input | Output ($c^{(1)}, c^{(2)}$) | To State |
| :--------- | :---- | :----------------------- | :------- |
| $S_0$      | 0     | (0, 0)                   | $S_0$    |

**Message Passing:**

The decoder needs to determine the input bits ($d_0, d_1, d_2$). The process involves propagating beliefs about states and transmitted bits.

**Simplified View for BEC:**

In a BEC, message passing can be visualized as passing beliefs about *which branches were transmitted*. If a bit is erased, the decoder doesn't know which of the two possible branches was taken. If a bit is received correctly, it strongly favors the branch that produced that bit.

Let's use the Sum-Product algorithm framework. We can define messages passed on the edges of the trellis.

**Messages ($m_{t \to t+1}$ for bits, $m_{s \to s'}$ for state transitions):**

Consider the first input bit $d_0$. It starts at $S_0$.
*   Input $d_0=0$: Output $(c^{(1)}_0, c^{(2)}_0) = (0,0)$. Goes to $S_0$.
    *   Received $y^{(1)}_0 = 0$. This is consistent with $c^{(1)}_0=0$.
    *   Received $y^{(2)}_0 = \text{E}$. This provides no information about $c^{(2)}_0$.

The decoder has to decide if $d_0=0$ was transmitted.

Let's use Belief Propagation on a factor graph. The factor graph for a convolutional code represents the relationships defined by the generator polynomials.

For $g^{(1)} = 1+D$ and $g^{(2)} = 1+D+D^2$:
The output bits are:
$c^{(1)}_t = d_t \oplus d_{t-1}$
$c^{(2)}_t = d_t \oplus d_{t-1} \oplus d_{t-2}$

We have received symbols $y^{(1)}$ and $y^{(2)}$. The decoder wants to find the most likely sequence of $d_t$.

**Example walkthrough (conceptual for BEC):**

*   **Time $t=0$:** Input $d_0$. Starts at $S_0$.
    *   Assume $d_0=0$. Output $(0,0)$. Next state $S_0$.
    *   Received $y^{(1)}_0 = 0$ (consistent), $y^{(2)}_0 = \text{E}$ (erasure).
    *   Belief about $d_0=0$ increases due to $y^{(1)}_0=0$. The erasure $y^{(2)}_0$ doesn't help much.

*   **Time $t=1$:** Input $d_1$.
    *   If $d_0=0$, encoder was in $S_0$.
        *   Assume $d_1=1$. Output $(1,1)$. Next state $S_1$.
        *   Received $y^{(1)}_1 = \text{E}$, $y^{(2)}_1 = 1$.
        *   $c^{(1)}_1$ is related to $d_1 \oplus d_0$. If $d_1=1, d_0=0$, then $c^{(1)}_1 = 1$. Received E. No info.
        *   $c^{(2)}_1$ is related to $d_1 \oplus d_0 \oplus d_{-1}$. If $d_1=1, d_0=0$, then $c^{(2)}_1 = 1 \oplus 0 \oplus d_{-1} = 1 \oplus d_{-1}$. Received 1. So $1 \oplus d_{-1} = 1 \implies d_{-1}=0$.
        *   This helps infer the *previous* state's input, which is $d_0$. If $d_{-1}=0$, it confirms $d_0=0$ was the correct input to transition to $S_0$.

    *   If $d_0=1$ (hypothetical), encoder was in $S_1$.
        *   Assume $d_1=0$. Output $(1,1)$. Next state $S_0$.
        *   Received $y^{(1)}_1 = \text{E}$, $y^{(2)}_1 = 1$.
        *   $c^{(1)}_1$ is related to $d_1 \oplus d_0$. If $d_1=0, d_0=1$, then $c^{(1)}_1 = 1$. Received E. No info.
        *   $c^{(2)}_1$ is related to $d_1 \oplus d_0 \oplus d_{-1}$. If $d_1=0, d_0=1$, then $c^{(2)}_1 = 0 \oplus 1 \oplus d_{-1} = 1 \oplus d_{-1}$. Received 1. So $1 \oplus d_{-1} = 1 \implies d_{-1}=0$.
        *   This suggests $d_0=0$, contradicting our hypothetical $d_0=1$.

**Message Passing Iterations on Trellis (Conceptual):**

Let's trace the beliefs about the transmitted bits. We'll use LLRs, denoted as $\lambda$. $\lambda > 0$ favors 0, $\lambda < 0$ favors 1.
LLR from received symbol $y$: $\lambda(y) = \log \frac{P(y|0)}{P(y|1)}$.
For BEC:
*   $y=0$: $\lambda(0) = \log \frac{1-\epsilon}{ \epsilon} \approx \infty$ (if $\epsilon < 0.5$)
*   $y=1$: $\lambda(1) = \log \frac{\epsilon}{1-\epsilon} \approx -\infty$ (if $\epsilon < 0.5$)
*   $y=E$: $\lambda(E) = \log \frac{0.5}{0.5} = 0$ (no information)

**Messages passed:**
Messages are functions of the received symbols and previous messages. The Sum-Product rule on a trellis typically involves:
$m_{t \to t+1}^{(j)}(state_{t+1}) = \sum_{state_t} \sum_{d_t} P(y_t^{(1)}, y_t^{(2)}, d_t | state_t, state_{t+1}) \cdot m_{t-1 \to t}^{(j)}(state_t)$

In LLR form:
$\lambda_{t \to t+1}(state_{t+1}) = \text{LLR}(\text{contribution from } y_t \text{ and } m_{t-1 \to t}) + \lambda_{t-1 \to t}(state_t)$

The exact implementation is detailed in textbooks like Lin & Costello.

**Let's focus on the impact of BEC:**

*   **Erasures weaken the messages:** When a received symbol is an erasure, the contribution to the LLR is 0, meaning it doesn't help differentiate between hypotheses.
*   **Iterative Refinement:** Message passing allows information from later received symbols (that are not erased) to "correct" early beliefs that were weakened by erasures.

**Example Trace with LLRs (Simplified):**

Received sequence for $(c^{(1)}, c^{(2)})$ = ([0, E, 1], [E, 1, 1])

*   **Bit $c^{(1)}_0=0$:** Received $y^{(1)}_0 = 0$. Strong LLR $\lambda_0 \approx \infty$ for 0.
*   **Bit $c^{(2)}_0=E$:** Received $y^{(2)}_0 = E$. LLR $\lambda_0 = 0$.
*   **Bit $c^{(1)}_1=E$:** Received $y^{(1)}_1 = E$. LLR $\lambda_1 = 0$.
*   **Bit $c^{(2)}_1=1$:** Received $y^{(2)}_1 = 1$. Strong LLR $\lambda_1 \approx -\infty$ for 1.
*   **Bit $c^{(1)}_2=1$:** Received $y^{(1)}_2 = 1$. Strong LLR $\lambda_2 \approx -\infty$ for 1.
*   **Bit $c^{(2)}_2=1$:** Received $y^{(2)}_2 = 1$. Strong LLR $\lambda_2 \approx -\infty$ for 1.

**Decoding $d_0$:**
*   $d_0=0$ implies $(c^{(1)}_0, c^{(2)}_0) = (0,0)$.
    *   This path is consistent with $y^{(1)}_0 = 0$.
    *   It is not contradicted by $y^{(2)}_0 = \text{E}$.
*   $d_0=1$ (hypothetical) implies $(c^{(1)}_0, c^{(2)}_0) = (1,1)$.
    *   This path is inconsistent with $y^{(1)}_0 = 0$.

So, the initial belief strongly favors $d_0=0$.

**Decoding $d_1$:**
*   We know $d_0=0$ (from previous step).
*   If $d_1=0$: $(c^{(1)}_1, c^{(2)}_1) = (0,0)$.
    *   Contradicts $y^{(2)}_1 = 1$.
    *   Consistent with $y^{(1)}_1 = \text{E}$.
*   If $d_1=1$: $(c^{(1)}_1, c^{(2)}_1) = (1,1)$.
    *   Consistent with $y^{(2)}_1 = 1$.
    *   Consistent with $y^{(1)}_1 = \text{E}$.

The received $y^{(2)}_1=1$ strongly favors the path where $c^{(2)}_1=1$. This means $d_1=1$ is favored.

**Decoding $d_2$:**
*   We know $d_0=0$ and $d_1=1$.
*   Encoder state before $d_2$: From $S_0$ with input $d_1=1$ goes to $S_1$.
*   If $d_2=0$: $(c^{(1)}_2, c^{(2)}_2) = (1,1)$.
    *   Contradicts $y^{(1)}_2 = 1$ (it should be 0 if $d_2=0$). Oh wait, $c^{(1)}_t = d_t \oplus d_{t-1}$.
    *   $c^{(1)}_2 = d_2 \oplus d_1$. With $d_1=1$, if $d_2=0$, $c^{(1)}_2=0$. Received $y^{(1)}_2=1$. Contradicts.
    *   $c^{(2)}_2 = d_2 \oplus d_1 \oplus d_0$. With $d_0=0, d_1=1$, if $d_2=0$, $c^{(2)}_2=0 \oplus 1 \oplus 0 = 1$. Received $y^{(2)}_2=1$. Consistent.
*   If $d_2=1$: $(c^{(1)}_2, c^{(2)}_2) = (0,0)$.
    *   $c^{(1)}_2 = d_2 \oplus d_1$. With $d_1=1$, if $d_2=1$, $c^{(1)}_2=1 \oplus 1 = 0$. Received $y^{(1)}_2=1$. Contradicts.
    *   $c^{(2)}_2 = d_2 \oplus d_1 \oplus d_0$. With $d_0=0, d_1=1$, if $d_2=1$, $c^{(2)}_2=1 \oplus 1 \oplus 0 = 0$. Received $y^{(2)}_2=1$. Contradicts.

Hold on, the state transition logic was:
*   From $S_0$, Input 0 $\to$ Output (0, 0), Next State $S_0$.
*   From $S_0$, Input 1 $\to$ Output (1, 1), Next State $S_1$.
*   From $S_1$, Input 0 $\to$ Output (1, 1), Next State $S_0$.
*   From $S_1$, Input 1 $\to$ Output (0, 0), Next State $S_1$.

Let's retrace with the correct outputs:

Transmitted codeword: $(c^{(1)}, c^{(2)}) = ([0, 1, 1], [0, 1, 1])$ for inputs $d = [0, 1, 0]$.

Received symbols: $y^{(1)} = [0, \text{E}, 1]$, $y^{(2)} = [\text{E}, 1, 1]$

**Decoding $d_0$:**
*   Initial state $S_0$.
*   If $d_0=0$: Output $(0,0)$. Next state $S_0$.
    *   $c^{(1)}_0=0$: Received $y^{(1)}_0=0$. Consistent.
    *   $c^{(2)}_0=0$: Received $y^{(2)}_0=\text{E}$. No info.
*   If $d_0=1$: Output $(1,1)$. Next state $S_1$.
    *   $c^{(1)}_0=1$: Received $y^{(1)}_0=0$. Contradicts.
    *   $c^{(2)}_0=1$: Received $y^{(2)}_0=\text{E}$. No info.

Strong evidence for $d_0=0$.

**Decoding $d_1$:**
*   From $d_0=0$, current state is $S_0$.
*   If $d_1=0$: Output $(0,0)$. Next state $S_0$.
    *   $c^{(1)}_1=0$: Received $y^{(1)}_1=\text{E}$. No info.
    *   $c^{(2)}_1=0$: Received $y^{(2)}_1=1$. Contradicts.
*   If $d_1=1$: Output $(1,1)$. Next state $S_1$.
    *   $c^{(1)}_1=1$: Received $y^{(1)}_1=\text{E}$. No info.
    *   $c^{(2)}_1=1$: Received $y^{(2)}_1=1$. Consistent.

Strong evidence for $d_1=1$.

**Decoding $d_2$:**
*   From $d_1=1$, current state is $S_1$.
*   If $d_2=0$: Output $(1,1)$. Next state $S_0$.
    *   $c^{(1)}_2=1$: Received $y^{(1)}_2=1$. Consistent.
    *   $c^{(2)}_2=1$: Received $y^{(2)}_2=1$. Consistent.
*   If $d_2=1$: Output $(0,0)$. Next state $S_1$.
    *   $c^{(1)}_2=0$: Received $y^{(1)}_2=1$. Contradicts.
    *   $c^{(2)}_2=0$: Received $y^{(2)}_2=1$. Contradicts.

Strong evidence for $d_2=0$.

**Decoded Input Sequence:** $[0, 1, 0]$. This matches the transmitted sequence.

This simplified trace highlights how the non-erased symbols provide strong evidence, while erasures leave ambiguity that is resolved by passing information through the trellis. The Sum-Product algorithm systematically combines these pieces of information.

### Practice Questions/Exercises:

1.  **Conceptual:** Explain why message passing decoding is generally considered more powerful than Viterbi decoding for soft-decision decoding.
    *   **Answer:** Viterbi is a maximum-likelihood (ML) decoder for hard decisions, or uses maximum probability path selection. Message passing (like BCJR/Sum-Product) computes the *a posteriori probability* (APP) of each individual bit, making it a true MAP decoder for individual bits. This allows it to leverage soft information more effectively and often achieve better performance, especially at low signal-to-noise ratios.

        *   Constraint length $K = 3$ (highest power of D in generators is 2, $K = \text{degree} + 1$).

3.  **BEC Decoding:** Consider the same rate 1/2 code with $g^{(1)} = 1+D$, $g^{(2)} = 1+D+D^2$. Transmitted codeword is $([0,1,1], [0,1,1])$. Received symbols are $y^{(1)} = [0, \text{E}, 1]$, $y^{(2)} = [1, 1, 1]$.
    Trace the likely decoded input sequence using message passing principles on the BEC. What is the decoded sequence?
    *   **Transmitted inputs:** $d=[0, 1, 0]$
    *   **Encoder outputs:** $(c^{(1)}, c^{(2)}) = ([0,1,1], [0,1,1])$
    *   **Received symbols:** $y^{(1)} = [0, \text{E}, 1]$, $y^{(2)} = [1, 1, 1]$

    *   **$d_0$:** Initial state $S_0$.
        *   If $d_0=0$: output $(0,0)$. Next state $S_0$.
            *   $c^{(1)}_0=0$: received $y^{(1)}_0=0$. Consistent.
            *   $c^{(2)}_0=0$: received $y^{(2)}_0=1$. Contradicts.
        *   If $d_0=1$: output $(1,1)$. Next state $S_1$.
            *   $c^{(1)}_0=1$: received $y^{(1)}_0=0$. Contradicts.
            *   $c^{(2)}_0=1$: received $y^{(2)}_0=1$. Consistent.
        *   The evidence for $d_0=1$ is stronger due to the contradiction on $c^{(2)}_0$ for $d_0=0$. *However*, the original example trace had $y^{(2)}_0=E$, not 1. Let's use the problem's $y^{(2)} = [1, 1, 1]$:
            *   If $d_0=0 \implies (0,0)$: $y^{(1)}_0=0$ ok, $y^{(2)}_0=1$ BAD for 0.
            *   If $d_0=1 \implies (1,1)$: $y^{(1)}_0=0$ BAD for 1, $y^{(2)}_0=1$ ok for 1.
            Both have one contradiction and one consistency. The messages would be weaker.

    Let's revisit the original example's received symbols as it was more illustrative:
    $y^{(1)} = [0, \text{E}, 1]$, $y^{(2)} = [\text{E}, 1, 1]$
    This yielded $[0, 1, 0]$ correctly.

    Let's re-analyze Question 3: $y^{(1)} = [0, \text{E}, 1]$, $y^{(2)} = [1, 1, 1]$
    *   **$d_0$:** (Start at $S_0$)
        *   $d_0=0 \implies (0,0)$. $y^{(1)}_0=0$ (ok), $y^{(2)}_0=1$ (contradicts 0).
        *   $d_0=1 \implies (1,1)$. $y^{(1)}_0=0$ (contradicts 1), $y^{(2)}_0=1$ (ok for 1).
        *   Both have one strike. The initial evidence is weak. The decoder must rely on later bits.

    *   **$d_1$:** (From $S_0$ if $d_0=0$; from $S_1$ if $d_0=1$)
        *   Case 1: Assume $d_0=0$ (state $S_0$).
            *   $d_1=0 \implies (0,0)$. $y^{(1)}_1=\text{E}$ (no info), $y^{(2)}_1=1$ (contradicts 0).
            *   $d_1=1 \implies (1,1)$. $y^{(1)}_1=\text{E}$ (no info), $y^{(2)}_1=1$ (ok for 1).
            *   This case favors $d_1=1$.
        *   Case 2: Assume $d_0=1$ (state $S_1$).
            *   $d_1=0 \implies (1,1)$. $y^{(1)}_1=\text{E}$ (no info), $y^{(2)}_1=1$ (ok for 1).
            *   $d_1=1 \implies (0,0)$. $y^{(1)}_1=\text{E}$ (no info), $y^{(2)}_1=1$ (contradicts 0).
            *   This case favors $d_1=0$.

    *   **$d_2$:** (Depends on state after $d_1$)
        *   If $d_0=0, d_1=1$ (state $S_1$).
            *   $d_2=0 \implies (1,1)$. $y^{(1)}_2=1$ (ok), $y^{(2)}_2=1$ (ok). Both consistent.
            *   $d_2=1 \implies (0,0)$. $y^{(1)}_2=1$ (contradicts 0), $y^{(2)}_2=1$ (contradicts 0). Both contradict.
            *   Strongly favors $d_2=0$.
        *   If $d_0=1, d_1=0$ (state $S_0$).
            *   $d_2=0 \implies (0,0)$. $y^{(1)}_2=1$ (contradicts 0), $y^{(2)}_2=1$ (contradicts 0). Both contradict.
            *   $d_2=1 \implies (1,1)$. $y^{(1)}_2=1$ (ok), $y^{(2)}_2=1$ (ok). Both consistent.
            *   Strongly favors $d_2=1$.

    **Combining evidence:**
    *   Path 1: $d=[0,1,0]$. Total evidence: $d_0$ weak, $d_1=1$ favored, $d_2=0$ favored.
    *   Path 2: $d=[1,0,1]$. Total evidence: $d_0$ weak, $d_1=0$ favored, $d_2=1$ favored.

    The messages passed from $d_2$'s evaluation back to $d_1$ and then to $d_0$ will resolve the initial ambiguity. The $y^{(1)}_2=1$ and $y^{(2)}_2=1$ bits are strong indicators.
    If $d=[0,1,0]$: $(c^{(1)}, c^{(2)}) = ([0,1,1], [0,1,1])$. Received $y^{(1)}=[0,E,1]$, $y^{(2)}=[1,1,1]$.
    *   $c^{(1)}_0=0$ vs $y^{(1)}_0=0$ (ok)
    *   $c^{(2)}_0=0$ vs $y^{(2)}_0=1$ (BAD)
    *   $c^{(1)}_1=1$ vs $y^{(1)}_1=E$ (neutral)
    *   $c^{(2)}_1=1$ vs $y^{(2)}_1=1$ (ok)
    *   $c^{(1)}_2=1$ vs $y^{(1)}_2=1$ (ok)
    *   $c^{(2)}_2=1$ vs $y^{(2)}_2=1$ (ok)
    This path has 1 BAD, 3 OK, 1 Neutral.

    If $d=[1,0,1]$: $(c^{(1)}, c^{(2)}) = ([1,0,0], [1,1,0])$. Received $y^{(1)}=[0,E,1]$, $y^{(2)}=[1,1,1]$.
    *   $c^{(1)}_0=1$ vs $y^{(1)}_0=0$ (BAD)
    *   $c^{(2)}_0=1$ vs $y^{(2)}_0=1$ (ok)
    *   $c^{(1)}_1=0$ vs $y^{(1)}_1=E$ (neutral)
    *   $c^{(2)}_1=1$ vs $y^{(2)}_1=1$ (ok)
    *   $c^{(1)}_2=0$ vs $y^{(1)}_2=1$ (BAD)
    *   $c^{(2)}_2=0$ vs $y^{(2)}_2=1$ (BAD)
    This path has 3 BAD, 2 OK, 1 Neutral.

    The message passing will overwhelmingly favor $[0,1,0]$.
    **Decoded sequence:** $[0, 1, 0]$.

### Important Points to Remember:

*   **Graphical Structure:** Message passing relies on representing the code as a graph (trellis or factor graph).
*   **Iterative Process:** Information is exchanged iteratively between nodes to refine estimates.
*   **Soft Information:** Message passing algorithms are particularly effective when provided with soft information from the channel, though they can operate on hard decisions as well.
*   **BEC Behavior:** In a BEC, erasures create uncertainty. Message passing uses the reliable received bits to infer the erased ones by exploiting the code's structure and constraints.
*   **Convergence:** The iterative nature allows for convergence to accurate estimates, making it suitable for codes where brute-force ML decoding is infeasible (like Turbo codes or LDPC codes, though this module focuses on convolutional codes).
*   **Relation to Viterbi:** Viterbi can be seen as a simplified, greedy message passing that only keeps the most likely path, discarding information about other paths. Message passing (Sum-Product) considers all paths simultaneously.

### Alignment with Course Outcomes:

*   **CO1, CO2, CO6:** Understanding message passing provides insight into the mechanisms behind modern iterative decoding schemes (like Turbo, LDPC, Polar) which are mentioned in CO6. The principles also reinforce the error detection/correction capabilities of codes (CO2).
*   **CO5:** Message passing decoding is a direct method for applying convolutional codes for error detection and correction, offering a more sophisticated approach than simpler methods.
*   **CO3, CO4:** While CO3 and CO4 focus on block codes, the iterative nature of message passing is a fundamental concept that underpins efficient decoding strategies for many code types. The general principles of exchanging information to satisfy constraints are shared.
