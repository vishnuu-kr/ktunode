# Microcontrollers: Module 4 - Serial Communication in 8051

This module delves into the essential topic of serial communication within the 8051 microcontroller. While the module title might suggest a focus on timers, this particular topic expands on the capabilities of the 8051 by exploring its built-in serial port functionalities. Understanding serial communication is crucial for interfacing the 8051 with various external devices and for building sophisticated embedded systems.

---

## 1. Introduction to Serial Communication

Serial communication is a method of transmitting data one bit at a time, sequentially, over a single communication line. This contrasts with parallel communication, where multiple bits are transmitted simultaneously over multiple lines.

**Key Concepts:**

*   **Asynchronous vs. Synchronous:**
    *   **Asynchronous:** Data is transmitted without a separate clock signal. The sender and receiver agree on a transmission rate (baud rate) and use start and stop bits to frame each character. This is the most common method for microcontrollers like the 8051.
    *   **Synchronous:** Data is transmitted with a separate clock signal that synchronizes both the sender and receiver. This allows for higher data transfer rates but requires more complex circuitry.
*   **Baud Rate:** The number of signal changes (bits) per second. It dictates the speed of serial communication.
*   **Data Framing:** The process of adding extra bits to a data byte to facilitate error detection and synchronization during asynchronous communication. This typically includes:
    *   **Start Bit:** A logic LOW bit to signal the beginning of a data byte.
    *   **Data Bits:** The actual bits of the data byte (usually 5 to 8 bits).
    *   **Parity Bit (Optional):** A bit used for error checking (even or odd parity).
    *   **Stop Bit(s):** One or two logic HIGH bits to signal the end of a data byte.

## 2. Serial Communication Modes in 8051

The 8051 microcontroller supports four distinct serial communication modes, controlled by the **Serial Port Control Register (SCON)**.

**Key Concepts:**

*   **SCON Register (Special Function Register - SFR):** This register plays a pivotal role in configuring the serial port's operation.

    | Bit | Symbol | Description                                          |
    | :-- | :----- | :--------------------------------------------------- |
    | 7   | SM0    | Serial Port Mode bit 0                               |
    | 6   | SM1    | Serial Port Mode bit 1                               |
    | 5   | SM2    | Enables/Disables the SM2 bit for multiprocessor mode |
    | 4   | REN    | Receive Enable bit                                   |
    | 3   | TB8    | Transmit Bit 8                                       |
    | 2   | RB8    | Receive Bit 8                                        |
    | 1   | TI     | Transmit Interrupt Flag                              |
    | 0   | RI     | Receive Interrupt Flag                               |

*   **Mode 0:**
    *   **Description:** Shift register mode. Data is transmitted and received serially via the RXD pin. The TXD pin acts as a clock output.
    *   **Baud Rate:** Fixed at Fosc / 12.
    *   **Data Format:** 8 bits of data, LSB first. No start/stop bits are generated by hardware, but they are often added externally.
    *   **SCON Configuration:** SM0 = 0, SM1 = 0.
    *   **Use Case:** Primarily used for communication with devices that require a synchronous serial clock.

*   **Mode 1:**
    *   **Description:** 8-bit UART mode. Data is transmitted and received serially via the RXD pin. TXD pin is used for transmission.
    *   **Baud Rate:** Variable, programmable using the Timer 1 overflow.
    *   **Data Format:** 10 bits: 1 start bit, 8 data bits (LSB first), 1 stop bit.
    *   **SCON Configuration:** SM0 = 0, SM1 = 1.
    *   **Use Case:** Most common mode for general-purpose serial communication with devices like PCs, modems, and other microcontrollers.

*   **Mode 2:**
    *   **Description:** 9-bit UART mode. Similar to Mode 1, but allows for an additional bit (either for parity or as a ninth data bit).
    *   **Baud Rate:** Fixed at either Fosc / 32 (when Timer 1 is not used) or Fosc / 64 (when Timer 1 is used to generate the baud rate).
    *   **Data Format:** 11 bits: 1 start bit, 8 data bits, 1 stop bit, and the 9th bit is either the TB8 (transmit) or RB8 (receive) bit.
    *   **SCON Configuration:** SM0 = 1, SM1 = 0.
    *   **Use Case:** Useful for multiprocessor communication where one processor can address others using the 9th bit as an address indicator.

*   **Mode 3:**
    *   **Description:** 9-bit UART mode with variable baud rate. Similar to Mode 2 but the baud rate is controlled by Timer 1.
    *   **Baud Rate:** Variable, programmable using the Timer 1 overflow.
    *   **Data Format:** 10 bits: 1 start bit, 8 data bits, 1 stop bit, and the 9th bit is either the TB8 (transmit) or RB8 (receive) bit.
    *   **SCON Configuration:** SM0 = 1, SM1 = 1.
    *   **Use Case:** Also used for multiprocessor communication, offering flexibility in baud rate control.

**Important Point to Remember:**
The baud rate in modes 1 and 3 is determined by Timer 1. The **PCON (Power Control Register)** register's SMOD bit can be used to double the baud rate in these modes.

## 3. RS-232 Pin Configuration and Connection

RS-232 is a widely used standard for serial communication, defining the electrical characteristics and pin functions for connecting serial devices.

**Key Concepts:**

*   **RS-232 Standard:** Defines voltage levels, signaling rates, connectors, and wiring for serial communication.
    *   **Voltage Levels:**
        *   Logic HIGH (binary 1): -3V to -15V
        *   Logic LOW (binary 0): +3V to +15V
    *   This is the inverse of TTL (Transistor-Transistor Logic) levels used by microcontrollers. Therefore, a level converter (like the MAX232) is typically required to interface the 8051's TTL serial signals with RS-232 devices.

*   **DB-9 Connector (Commonly Used):**
    *   **Pin 1 (CD - Carrier Detect):** Indicates that a connection with a remote modem exists.
    *   **Pin 2 (RXD - Receive Data):** Receives serial data from the other device.
    *   **Pin 3 (TXD - Transmit Data):** Transmits serial data to the other device.
    *   **Pin 4 (DTR - Data Terminal Ready):** Signals that the terminal is ready to communicate.
    *   **Pin 5 (GND - Signal Ground):** Common ground reference for both devices.
    *   **Pin 6 (DSR - Data Set Ready):** Signals that the modem or data set is ready.
    *   **Pin 7 (RTS - Request To Send):** Indicates that the terminal wants to send data.
    *   **Pin 8 (CTS - Clear To Send):** Indicates that the terminal is ready to receive data.
    *   **Pin 9 (RI - Ring Indicator):** Indicates an incoming call from a modem.

*   **8051 Serial Pins:**
    *   **TXD (Pin 1 of Port 3):** Transmits serial data.
    *   **RXD (Pin 0 of Port 3):** Receives serial data.

*   **Connection between 8051 and PC (using a MAX232 level converter):**
    *   8051 TXD (P3.1) -> MAX232 TXD -> DB-9 TXD (Pin 3)
    *   8051 RXD (P3.0) -> MAX232 RXD -> DB-9 RXD (Pin 2)
    *   8051 GND -> MAX232 GND -> DB-9 GND (Pin 5)
    *   The MAX232 handles the conversion between TTL and RS-232 voltage levels.

## 4. Serial Port Programming in 8051

Programming the serial port involves configuring the SCON register, setting the baud rate, and then using instructions to transmit and receive data.

### 4.1. Transmitting Data

To transmit a byte of data:

1.  **Load the data:** Place the byte to be transmitted into the **Serial Buffer Register (SBUF)**. `SBUF` is a dual-purpose register that acts as both a transmit and receive buffer.
2.  **Set the transmit interrupt flag (TI):** The `TI` flag in the SCON register is automatically set to 1 by the hardware when the transmission of a character is complete. The program must clear this flag to allow the next transmission.
3.  **Wait for transmission completion:** The program typically polls the `TI` flag. When `TI` becomes 1, it indicates that the buffer is empty and ready for the next byte.
4.  **Clear TI:** After detecting `TI` as 1, clear it to 0 to prepare for the next transmission.

**Example (Assembly Language):**

```assembly
MOV SBUF, #'A'      ; Load the character 'A' into the transmit buffer
WAIT_TX:
    JNB TI, WAIT_TX ; Wait until TI flag is set (transmission complete)
    CLR TI          ; Clear the TI flag for the next transmission
```

**Important Points to Remember:**
*   The `TI` flag must be cleared in software after each transmission.
*   The `REN` bit in SCON must be set to enable the serial port for reception, even if only transmitting.

### 4.2. Receiving Data

To receive a byte of data:

1.  **Enable reception:** Set the **Receive Enable (REN)** bit in the SCON register to 1.
2.  **Wait for a start bit:** The hardware automatically detects the start bit.
3.  **Receive data bits:** The 8 data bits are shifted into the SBUF register.
4.  **Receive stop bit:** The stop bit is detected, and the **Receive Interrupt Flag (RI)** in the SCON register is automatically set to 1.
5.  **Retrieve data:** Once `RI` is set, the received byte can be read from the SBUF register.
6.  **Clear RI:** The `RI` flag must be cleared in software to allow the reception of the next byte.

**Example (Assembly Language):**

```assembly
WAIT_RX:
    JNB RI, WAIT_RX ; Wait until RI flag is set (reception complete)
    MOV A, SBUF     ; Move the received byte from SBUF to Accumulator A
    CLR RI          ; Clear the RI flag for the next reception
```

**Important Points to Remember:**
*   The `REN` bit in SCON must be set for reception.
*   The `RI` flag must be cleared in software after each reception.
*   The serial port can transmit and receive simultaneously (full-duplex) if both `TI` and `RI` are handled appropriately.

### 4.3. Baud Rate Generation

The baud rate in modes 1 and 3 is controlled by Timer 1.

1.  **Configure Timer 1:** Set Timer 1 to operate in **Mode 2 (8-bit auto-reload)**.
2.  **Load the TL1 register:** The TL1 register is loaded with a value that, when incremented by the timer clock, will cause an overflow at the desired baud rate.
3.  **Set the TH1 register:** The TH1 register is also loaded with the same auto-reload value.
4.  **Enable Timer 1:** Start Timer 1 by setting the TR1 bit in the TCON register.
5.  **Set the SMOD bit (Optional):** If the baud rate needs to be doubled, set the SMOD bit in the PCON register.

**Baud Rate Calculation for Mode 1 (using Timer 1):**

*   `Baud Rate = (Fosc / 32) / (256 - TH1)` (if SMOD = 0 in PCON)
*   `Baud Rate = (Fosc / 16) / (256 - TH1)` (if SMOD = 1 in PCON)

**Calculating TH1 Value:**

*   `TH1 = 256 - (Fosc / (32 * Baud Rate))` (for SMOD=0)
*   `TH1 = 256 - (Fosc / (16 * Baud Rate))` (for SMOD=1)

**Example:** For Fosc = 11.0592 MHz and a desired baud rate of 9600 bps:

*   **With SMOD=0:**
    *   `TH1 = 256 - (11059200 / (32 * 9600))`
    *   `TH1 = 256 - (11059200 / 307200)`
    *   `TH1 = 256 - 36`
    *   `TH1 = 220` (decimal) or `0xDC` (hexadecimal)

*   **With SMOD=1:**
    *   `TH1 = 256 - (11059200 / (16 * 9600))`
    *   `TH1 = 256 - (11059200 / 153600)`
    *   `TH1 = 256 - 72`
    *   `TH1 = 184` (decimal) or `0xB8` (hexadecimal)

## 5. Interrupt-Driven Serial Communication

Instead of polling the `TI` and `RI` flags, interrupts can be used for more efficient serial communication.

**Key Concepts:**

*   **Enable Serial Interrupts:**
    *   Set the `ES` (Serial Interrupt Enable) bit in the **IE (Interrupt Enable) register**.
    *   Enable global interrupts by setting the `EA` (Global Interrupt Enable) bit in the IE register.
*   **Interrupt Service Routines (ISRs):** When a serial event occurs (transmission complete or reception complete), the 8051 jumps to the serial ISR.
    *   **For Transmission:** The ISR should clear `TI` and load the next byte into `SBUF`.
    *   **For Reception:** The ISR should read the received byte from `SBUF`, process it, and then clear `RI`.
*   **Buffer Management:** For continuous data flow, a buffer can be used in the ISR to store received data or queue data for transmission.

**Example (Conceptual Assembly):**

```assembly
; Main program
    MOV TMOD, #20H   ; Timer 1 in Mode 2 for baud rate
    MOV TH1, #220    ; Load TH1 for 9600 baud (example)
    SETB TR1         ; Start Timer 1
    SETB SM1         ; Mode 1
    SETB SM0         ; Mode 1
    SETB REN         ; Enable reception
    SETB ES          ; Enable serial interrupts
    SETB EA          ; Enable global interrupts

    ; ... other program initialization ...

    SJMP $ ; Infinite loop

; Serial ISR
SERIAL_ISR:
    PUSH ACC       ; Save accumulator
    PUSH PSW       ; Save program status word

    JNB RI, RX_HANDLING ; Check if receive interrupt occurred
    CLR RI           ; Clear RI flag
    MOV A, SBUF      ; Read received data
    ; ... process received data ...
    SJMP ISR_EXIT

RX_HANDLING:
    JNB TI, ISR_EXIT ; Check if transmit interrupt occurred
    CLR TI           ; Clear TI flag
    ; ... load next byte to transmit into SBUF ...

ISR_EXIT:
    POP PSW        ; Restore PSW
    POP ACC        ; Restore accumulator
    RETI           ; Return from interrupt
```

## 6. Protocols and Multiprocessor Communication

While basic serial communication involves point-to-point communication, more complex protocols exist for managing multiple devices.

**Key Concepts:**

*   **UART (Universal Asynchronous Receiver/Transmitter):** The hardware component within the 8051 responsible for serial communication.
*   **Protocols:** Sets of rules that govern how data is exchanged between devices. Examples include:
    *   **Modbus:** A serial communication protocol used for industrial automation.
    *   **ASCII:** American Standard Code for Information Interchange, used for representing text characters.
*   **Multiprocessor Communication:**
    *   Involves multiple microcontrollers communicating with each other over a single serial line.
    *   **Mode 2 and Mode 3** are crucial for this, using the 9th bit (TB8/RB8) to distinguish between data and address information.
    *   **SM2 Bit:** When set, `SM2` in SCON allows the 8051 to receive data only when the 9th bit is HIGH (typically indicating an address). When `SM2` is cleared, all received data is accepted, regardless of the 9th bit.

**How Multiprocessor Communication Works (using Mode 2/3):**

1.  **Addressing:** When one processor wants to send data to another, it first sends an "address frame" where the 9th bit (TB8) is set to 1. The data bytes that follow will have the 9th bit set to 0.
2.  **Reception:** Each receiving processor constantly monitors the serial line.
    *   If `SM2` is cleared, all data is received. The software must then check if the 9th bit indicates an address or data.
    *   If `SM2` is set, only frames with the 9th bit as HIGH (address frames) will set the RI flag. The software then reads the 9th bit. If it matches the processor's own address, it sets `SM2` to 0 to receive the subsequent data bytes. After receiving the data, it might set `SM2` back to 1 to ignore subsequent data addressed to others.

## 7. Key Concepts & Points to Remember

*   **Serial vs. Parallel:** Serial transmits one bit at a time, parallel transmits multiple bits simultaneously.
*   **SCON Register:** Controls the serial port's operating mode, baud rate, and interrupt flags.
*   **Modes 0-3:** Different configurations of the serial port offering varying data formats and baud rate control.
    *   **Mode 0:** Shift Register (Fosc/12)
    *   **Mode 1:** 8-bit UART (Variable Baud Rate via Timer 1)
    *   **Mode 2:** 9-bit UART (Fixed Baud Rate: Fosc/32 or Fosc/64)
    *   **Mode 3:** 9-bit UART (Variable Baud Rate via Timer 1)
*   **TXD and RXD:** The physical pins on Port 3 for serial transmission and reception.
*   **RS-232:** A standard requiring voltage level conversion (e.g., MAX232) for interfacing with PCs.
*   **SBUF Register:** Holds the data byte being transmitted or received.
*   **TI and RI Flags:** Indicate transmission completion and reception completion, respectively. They must be cleared in software.
*   **Baud Rate:** Speed of serial communication. Determined by Fosc and Timer 1 configuration (and SMOD bit).
*   **Interrupt-Driven Serial Communication:** More efficient than polling, using `ES` and the serial ISR.
*   **Multiprocessor Communication:** Uses the 9th bit and the `SM2` bit for addressing.

## 9. Answers to Practice Questions

1.  **Serial:** Transmits data one bit at a time sequentially over a single line. **Parallel:** Transmits multiple bits simultaneously over multiple lines.
2.  Mode 0, Mode 1, Mode 2, Mode 3.
3.  SCON (Serial Port Control Register).
4.  TXD (Port 3, Pin 1) for transmission and RXD (Port 3, Pin 0) for reception.

5.  **Exercise: Transmitting a String (Assembly)**

    ```assembly
    ORG 0000H
    MOV TMOD, #20H       ; Timer 1 in Mode 2 (8-bit auto-reload)
    MOV TH1, #220        ; For 9600 baud @ 11.0592MHz Fosc (example)
    SETB TR1             ; Start Timer 1

    MOV SCON, #50H       ; Mode 1, enable REN, clear TI/RI

    ACALL TRANSMIT_STRING

    SJMP $               ; Infinite loop

    TRANSMIT_STRING:
        MOV DPTR, #MESSAGE  ; Point DPTR to the message
        MOV R0, #0          ; Index for string characters

    TX_LOOP:
        MOV A, [DPTR+R0]    ; Get character from message
        CMP A, #0           ; Check for null terminator
        JE TX_DONE          ; If null, exit
        MOV SBUF, A         ; Load character into SBUF
    TX_WAIT:
        JNB TI, TX_WAIT     ; Wait until transmission complete
        CLR TI              ; Clear TI flag
        INC R0              ; Move to next character
        SJMP TX_LOOP

    TX_DONE:
        RET

    MESSAGE: DB 'Hello World!', 0 ; Null-terminated string

    END
    ```

6.  **Exercise: Receiving and Echoing Characters (Assembly)**

    ```assembly
    ORG 0000H
    MOV TMOD, #20H       ; Timer 1 in Mode 2 (8-bit auto-reload)
    MOV TH1, #220        ; For 9600 baud @ 11.0592MHz Fosc (example)
    SETB TR1             ; Start Timer 1

    MOV SCON, #50H       ; Mode 1, enable REN, clear TI/RI

    SJMP $               ; Infinite loop

    ; No explicit ISR in polling example, but shows the core logic:
    ; To do this with interrupts, you'd enable ES, EA and use the SERIAL_ISR from Section 4.3

    RX_TX_LOOP:
        JNB RI, RX_TX_LOOP ; Wait until RI is set (character received)
        MOV A, SBUF         ; Read received character from SBUF
        MOV SBUF, A         ; Load character back into SBUF for transmission
        CLR RI              ; Clear RI flag

        ; Wait for transmission of echoed character to complete
    TX_WAIT:
        JNB TI, TX_WAIT
        CLR TI
        SJMP RX_TX_LOOP     ; Loop back to wait for next character

    END
    ```

7.  **Exercise: Baud Rate Calculation**
    Given: Fosc = 12 MHz, Baud Rate = 2400 bps, Mode 1, SMOD = 0.

    *   Formula: `TH1 = 256 - (Fosc / (32 * Baud Rate))`
    *   `TH1 = 256 - (12,000,000 / (32 * 2400))`
    *   `TH1 = 256 - (12,000,000 / 76,800)`
    *   `TH1 = 256 - 156.25`
    *   Since TH1 must be an integer, this calculation shows that 2400 bps with a 12 MHz crystal and SMOD=0 is not perfectly achievable. A common practice is to use crystals like 11.0592 MHz or 18.432 MHz, which are specifically designed to facilitate standard baud rates.

    *   **If we used 11.0592 MHz Fosc:**
        *   `TH1 = 256 - (11,059,200 / (32 * 2400))`
        *   `TH1 = 256 - (11,059,200 / 76,800)`
        *   `TH1 = 256 - 144`
        *   `TH1 = 112` (decimal) or `0x70` (hexadecimal)

8.  **Design Challenge Outline:**

    *   **Hardware Connection:**
        1.  Connect the 8051's TXD pin (P3.1) to the RX input of a MAX232 level converter.
        2.  Connect the 8051's RXD pin (P3.0) to the TX output of the MAX232.
        3.  Connect the 8051's GND to the MAX232's GND and the PC's GND.
        4.  Connect the MAX232's RS-232 TXD pin to the PC's RXD pin (DB-9 Pin 2).
        5.  Connect the MAX232's RS-232 RXD pin to the PC's TXD pin (DB-9 Pin 3).
        6.  Ensure the MAX232 is correctly powered (typically 5V from the 8051 board).
        7.  Connect a sensor (e.g., temperature sensor via ADC) to the 8051's ADC input.

    *   **Software Logic:**
        1.  **Initialization:**
            *   Configure Timer 1 for auto-reload mode (Mode 2) to generate the desired baud rate (e.g., 9600 bps). Calculate and load the appropriate value into TH1.
            *   Configure SCON register for Mode 1 (SM0=0, SM1=1), enable reception (REN=1), and clear interrupt flags.
            *   Enable global interrupts (EA=1) and serial interrupts (ES=1) if using interrupt-driven communication.
        2.  **Main Loop:**
            *   **Read Sensor:** Periodically read the sensor value (e.g., using ADC).
            *   **Format Data:** Convert the sensor reading into a human-readable format (e.g., ASCII string).
            *   **Transmit Data:**
                *   If polling: Load the first character into SBUF, wait for TI, clear TI, repeat for all characters.
                *   If interrupt-driven: Place the first character in SBUF, and the ISR will handle subsequent transmissions.
            *   **Delay:** Implement a delay mechanism to wait for approximately 5 seconds before the next reading and transmission. This can be done using timers or nested loops.

    *   **Considerations:**
        *   Error handling for sensor readings.
        *   Buffering for continuous data flow.
        *   Choice between polling and interrupt-driven serial communication for efficiency.
