### 2. Introduction to Races in Sequential Circuits

**What is a Race Condition?**

A race condition occurs in a sequential circuit when the final state of the circuit depends on the order in which certain state variables change. This is particularly problematic in asynchronous sequential circuits and can also affect synchronous circuits if not handled properly.

**Key Concepts:**

*   **State Variables (Flip-flops/Latches):** The memory elements of a sequential circuit that store the current state.
*   **Transition:** The change of state in response to input signals and the clock (in synchronous circuits).
*   **Propagation Delay:** The finite time it takes for a logic gate to respond to a change in its input and produce a stable output.
*   **Glitches/Spurious Outputs:** Temporary, incorrect logic levels that can occur during transitions due to differences in propagation delays.

**Why are Races a Concern in ASM Charts?**

ASM charts are a graphical representation of the behavior of sequential circuits, describing states, transitions, and outputs. When realizing an ASM chart with hardware, particularly with flip-flops and combinatorial logic, race conditions can lead to:

*   **Incorrect State Transitions:** The circuit might enter an unintended state because the state variables do not update simultaneously.
*   **Unpredictable Behavior:** The output or the next state can vary from one clock cycle to another, making the circuit unreliable.

### 3. Types of Races

While the core concept of a race is about the timing of state variable changes, in the context of ASM chart realization, we primarily encounter races related to the *combinational logic* that determines the next state and outputs.

#### 3.1. Static Race

A static race occurs when a state variable is supposed to remain unchanged during a state transition, but due to glitches or timing variations, it momentarily flickers to the opposite state before settling back to its intended value.

**Example:** Suppose a state variable `Y` is intended to remain `0` in the next state. However, due to different propagation delays in the combinational logic producing `Y`, it momentarily transitions to `1` and then back to `0`. If another part of the circuit samples `Y` during this transient `1` state, it might interpret the state incorrectly.

**Impact on ASM:** In an ASM chart, if a transition depends on a state variable that experiences a static race, the circuit might behave erratically if the sampling point for the next state decision coincides with the glitch.

#### 3.2. Dynamic Race

A dynamic race occurs when a state variable is supposed to change from `0` to `1` (or `1` to `0`) during a state transition, but due to differences in propagation delays, it passes through intermediate states (e.g., `0` to `1` to `0` or `1` to `0` to `1`) before settling to its final correct state.

**Example:** If a state variable `Y` is supposed to change from `0` to `1`, but due to propagation delays, the signals controlling its change cause it to go `0` -> `1` -> `0` -> `1`. If another state variable or output logic depends on the intermediate `0` state, an incorrect decision could be made.

**Impact on ASM:** This is particularly dangerous in synchronous circuits where flip-flops are triggered by the clock edge. If a dynamic race causes a state variable to change multiple times within the setup or hold time window of the next clock edge, the flip-flop might capture an intermediate, incorrect value, leading to an entirely wrong next state.

### 4. Races in ASM Chart Realization

When translating an ASM chart into hardware, the state variables are typically implemented using flip-flops. The next-state logic and output logic are implemented using combinational circuits.

**How Races Arise During Realization:**

1.  **Multiple Inputs to a Flip-flop:** The input to a flip-flop (D input) is usually generated by combinational logic. If this combinational logic has different propagation delays for signals that affect the D input, it can lead to races.
2.  **Feedback Paths:** Sequential circuits inherently have feedback. The output of a flip-flop feeds back into the combinational logic to determine the next state. If the combinational logic takes too long to settle, it can cause issues with the next clock edge.
3.  **Shared Inputs:** If multiple state variables receive inputs from a common combinational logic block, the delay variations in this block can cause races.

**Consider an ASM Chart with:**

*   **States:** Represented by state registers (flip-flops).
*   **Transitions:** Determined by input conditions and the current state.
*   **Outputs:** Associated with states or transitions.

The critical path for determining the *next state* is from the output of the current flip-flops, through the combinational next-state logic, to the input of the flip-flops for the next clock cycle. Races occur when this path does not settle to a stable value before the arrival of the next clock edge (for synchronous circuits) or when intermediate stable states are reached that are not part of the intended transition (for asynchronous circuits).

**Textbook References:**

*   **Givone (2002):** Discusses races in the context of asynchronous sequential circuits, emphasizing the role of propagation delays and the potential for unintended state changes. Chapter 9, "Analysis of Asynchronous Sequential Circuits," would be relevant.
*   **Mano & Ciletti (2018):** Covers state minimization and state assignment, which are crucial for avoiding races. They often discuss races in the context of state table reduction and the potential for glitches. Chapters 7 and 8 are relevant.
*   **Wakerly (2008):** Provides a comprehensive treatment of sequential circuit design, including potential problems like races and hazards. Chapter 7, "State-Machine Design," and Chapter 8, "Sequential Circuit Design Hazards," are highly relevant.

### 5. Detecting and Preventing Races in ASM Realization

The primary goal is to ensure that the combinational logic producing the next state and outputs settles to a stable value before the next clock edge.

#### 5.1. Race Detection (Analysis Phase)

*   **Timing Analysis:** This involves calculating the maximum and minimum propagation delays through all logic paths. If the total delay in a feedback path is such that an incorrect signal can propagate and affect a flip-flop before the next clock edge, a race is likely.
*   **State Table Analysis:** For state assignments, examine the state table. If multiple transitions depend on inputs that are generated from the same flip-flop outputs but have different delay paths, it can indicate a potential race.

#### 5.2. Race Prevention (Design Phase)

The most effective methods for preventing races are employed during the design and state assignment phase.

1.  **State Assignment:**
    *   **Choosing a State Assignment:** The binary codes assigned to each state can significantly impact the likelihood of races. State assignments that minimize the number of bit changes between transitions are often preferred.
    *   **Using Assignments that Avoid Critical Races:** Certain state assignment strategies, like **unique next-state assignments**, aim to ensure that no two states have the same next state for the same input, thereby preventing races from causing unintended state transitions.
    *   **Givone (2002)** and **Wakerly (2008)** discuss various state assignment techniques to avoid races and hazards.

2.  **Hazard-Free Logic Design:**
    *   **Static and Dynamic Hazards:** Just like in combinational circuits, hazards can occur in the logic producing the flip-flop inputs. These hazards need to be eliminated.
    *   **Using Karnaugh Maps (K-maps) or Quine-McCluskey:** These tools can be used to derive minimal sum-of-products (SOP) or product-of-sums (POS) expressions. However, these minimal forms are not always hazard-free.
    *   **Covering Glitches:** Adding redundant terms to the K-map can eliminate static hazards. For dynamic hazards, ensuring that a variable changing from 0 to 1 (or vice versa) involves a single, direct transition without intermediate logic level changes is crucial. This often requires specific SOP or POS implementations.
    *   **Mano & Ciletti (2018)** extensively covers hazard detection and elimination in combinational logic, which is directly applicable to the next-state and output logic derived from an ASM chart. Chapter 8 on hazards is key.

3.  **Using Flip-flops with Robust Timing Characteristics:**
    *   **Master-Slave Flip-flops:** These are inherently more robust against races than edge-triggered flip-flops because they sample the input during one clock phase and output during another, effectively isolating the input logic from the clock edge.
    *   **Level-Sensitive Latches:** While not always used for state registers, latches can be part of the design. Understanding their behavior with regard to races is important.

4.  **Synchronizing Logic:**
    *   **Adding Synchronizers:** In systems with multiple clock domains or when dealing with asynchronous inputs, synchronizers (often a chain of flip-flops) are used to ensure that external signals are properly registered within the system's clock domain, mitigating race-like effects from external timing variations.

5.  **Choosing Appropriate Clock Speed:**
    *   If the combinational logic is too slow to settle, a slower clock frequency can be used. However, this is often not a preferred solution as it limits performance. The goal is to design the logic to be fast enough for the intended clock speed.

### 6. Example: A Simple ASM Chart and Potential Race Scenario

Consider a simple Mealy machine described by an ASM chart:

**ASM Chart Snippet:**

*   **State S0:**
    *   Input `X = 0`: Output `Y = 0`, Transition to S0.
    *   Input `X = 1`: Output `Y = 1`, Transition to S1.
*   **State S1:**
    *   Input `X = 0`: Output `Y = 0`, Transition to S0.
    *   Input `X = 1`: Output `Y = 1`, Transition to S1.

Let's say we assign state `S0` to binary `00` and `S1` to binary `01`.
Let the state variables be `Q1Q0`. So, `S0 = 00`, `S1 = 01`.

**Next State Logic (D inputs to flip-flops):**

Assuming we use JK flip-flops and set J=K for toggling or direct D input. Let's simplify and assume D flip-flops.
The current state is `Q1Q0`. The input is `X`.

*   **Next state of Q0 (D0):**
    *   From `S0 (00)` with `X=0`: Next state `0`.
    *   From `S0 (00)` with `X=1`: Next state `1`.
    *   From `S1 (01)` with `X=0`: Next state `0`.
    *   From `S1 (01)` with `X=1`: Next state `1`.

    This simplifies to: `D0 = X`

*   **Next state of Q1 (D1):**
    *   From `S0 (00)` with `X=0`: Next state `0`.
    *   From `S0 (00)` with `X=1`: Next state `0`.
    *   From `S1 (01)` with `X=0`: Next state `0`.
    *   From `S1 (01)` with `X=1`: Next state `0`.

    This simplifies to: `D1 = 0` (The state variable `Q1` never changes).

**Output Logic (Y):**

*   **Y:**
    *   In `S0 (00)` with `X=0`: Output `0`.
    *   In `S0 (00)` with `X=1`: Output `1`.
    *   In `S1 (01)` with `X=0`: Output `0`.
    *   In `S1 (01)` with `X=1`: Output `1`.

    This simplifies to: `Y = X`

**Potential Race Scenario:**

In this very simple example, the next state logic is trivial (`D0 = X`, `D1 = 0`). However, consider a more complex ASM where:

*   State `S2` is assigned `10`.
*   From `S0 (00)`, if `X=1`, we go to `S2 (10)`.
*   So, if `Q1Q0 = 00` and `X=1`, then `D1` should become `1` and `D0` should become `0`.

Let's say the logic for `D1` is complex and involves several gates.
Suppose `D1` is generated by: `D1 = (Q0 AND X) OR (Q1 AND X)`

*   Current state: `Q1Q0 = 00`, `X = 0`. `D1 = (0 AND 0) OR (0 AND 0) = 0`.
*   Input changes: `X` changes to `1`.
*   Desired next state: `Q1Q0` should become `10` (if `X=1` transitions to a state with `Q1=1`).

If the combinational logic for `D1` has varying delays:
*   Perhaps the `Q0 AND X` term settles to `1` first (when `Q0` is `0` and `X` becomes `1`).
*   Then the `Q1 AND X` term settles to `0` (when `Q1` is `0` and `X` becomes `1`).
*   The OR gate combines them.

If there's a glitch in `Q0` (e.g., due to a race within the `Q0` logic itself, if it were more complex) or if the input `X` is not perfectly synchronized, the `D1` signal might momentarily take on an incorrect value before settling.

**Wakerly (2008)** emphasizes that state assignment plays a vital role. If we had assigned `S0 = 00` and `S1 = 10`, then the transition from `S0` to `S1` would require both `Q1` and `Q0` to change. If the combinational logic for `D1` and `D0` are not carefully designed to avoid races (e.g., due to propagation delays), this could lead to a dynamic race.

### 7. Practice Questions and Exercises

**Question 1:**
Define a "race condition" in the context of sequential circuit design. What are the main types of races?
*   **Answer:** A race condition occurs when the final state of a sequential circuit depends on the order in which state variables change due to unequal propagation delays. The main types are static races (where a state variable should not change but momentarily does) and dynamic races (where a state variable changes multiple times before settling).

**Question 2:**
Explain how races can manifest when realizing an ASM chart into hardware using flip-flops and combinational logic.
*   **Answer:** Races arise from propagation delays in the combinational logic that generates the next-state signals for the flip-flops. If this logic does not settle to a stable value before the next clock edge (in synchronous circuits), or if it settles to unintended intermediate states, a race condition occurs, leading to incorrect state transitions.

**Question 3:**
Consider a state assignment for an ASM where a state variable `Q` is supposed to remain `0`. However, the combinational logic producing the `D` input for the flip-flop implementing `Q` has a glitch, causing `D` to momentarily go to `1` and then back to `0`. What type of race is this, and what could be a consequence?
*   **Answer:** This is a **static race**. A consequence could be that if the clock edge arrives during the momentary `1` glitch, the flip-flop might incorrectly update its state.

**Question 4 (Design Exercise):**
Design the combinational logic for the `D` input of a flip-flop based on the following requirements:
*   Current state: `Q`
*   Input: `X`
*   Next state (`D`): `D = Q' + X`
    *   If `Q=0, X=0`, `D = 0' + 0 = 1`.
    *   If `Q=0, X=1`, `D = 0' + 1 = 1`.
    *   If `Q=1, X=0`, `D = 1' + 0 = 0`.
    *   If `Q=1, X=1`, `D = 1' + 1 = 1`.
    The resulting truth table for `D` is `D = Q' + X`.

    Now, consider implementing `D = Q' + X` using a Sum-of-Products (SOP) form derived directly from a K-map. Show how to implement it to avoid static hazards.

*   **Answer:**
    The K-map for `D` with input `Q` (assume `X` is the other variable):

    ```
       X=0 | X=1
    Q=0 ---|----
       1   | 1
    Q=1 ---|----
       0   | 1
    ```

    The minimal SOP is `D = Q' + QX`.
    *   `Q'` covers `(Q=0, X=0)` and `(Q=0, X=1)`.
    *   `QX` covers `(Q=1, X=1)`.

    Let's check for hazards:
    *   Transition from `(Q=0, X=0)` to `(Q=0, X=1)`: `Q` remains `0`. `D` should stay `1`.
        *   `Q'` goes from `1` to `1`.
        *   `QX` goes from `0` to `0`.
        *   `D = 1 + 0 = 1`. This is stable. No static hazard here.

    *   Transition from `(Q=0, X=1)` to `(Q=1, X=1)`: `X` remains `1`. `D` should go from `1` to `1`.
        *   `Q'` goes from `1` to `0`.
        *   `QX` goes from `0` to `1`.
        *   `D = Q' + QX`.
        *   During transition, `Q'` becomes `0`. If `QX` has not yet become `1` due to delays, `D` could momentarily be `0 + 0 = 0`. This is a **static-1 hazard**.

    To eliminate this static hazard, we need to add a redundant term to cover the `(Q=0, X=1)` square that is shared by `Q'` and `QX`. The redundant term covering this transition is `Q'X`.

    Hazard-free SOP: `D = Q' + QX + Q'X` (Notice `Q'X` is repeated, which is fine in logic).
    Alternatively, `D = Q' + QX`. The correct way to eliminate the hazard from `D = Q' + QX` is to add the term that covers the transition where the hazard occurs. The hazard occurs when `Q` changes from `0` to `1` while `X=1`. The input values for this transition are `(Q=0, X=1)`. The implicant covering this is `Q'X`. So, `D = Q' + QX + Q'X`.
    We can simplify this: `D = Q' + X(Q + Q') = Q' + X(1) = Q' + X`.
    Let's re-examine the K-map and the transitions.
    The problem occurs when `Q` transitions from `0` to `1` while `X` is `1`.
    The input term `Q'` covers the cells `(Q=0, X=0)` and `(Q=0, X=1)`.
    The input term `QX` covers the cell `(Q=1, X=1)`.
    When `X=1`, we have `D = Q' + Q`. If `Q=0`, `D = 1 + 0 = 1`. If `Q=1`, `D = 0 + 1 = 1`. This logic should be stable.

    The hazard arises if the implementation of `Q'` and `QX` have different delays, and the OR gate is slow.
    Consider the path for `Q'`: `Q` -> NOT gate -> `Q'`.
    Consider the path for `QX`: `Q` -> AND gate with `X` -> `QX`.
    If `Q` changes from `0` to `1`, `Q'` becomes `0`. If `QX` (which is `1 * 1 = 1` when `Q=1, X=1`) is slower to respond than `Q'`, then `D = Q' + QX` could momentarily become `0 + 0 = 0`.

    The way to fix this is to add a covering term for the transition from `(Q=0, X=1)` to `(Q=1, X=1)`. This transition is covered by the term `X`. However, `X` alone doesn't cover the required states. The specific term needed to cover the hazard at `(Q=0, X=1)` is `Q'X`.
    So, the hazard-free expression is `D = Q' + QX + Q'X`.
    This simplifies to `D = (Q' + Q'X) + QX = Q'(1+X) + QX = Q' + QX`. This is the same minimal form, which indicates the minimal form might not be hazard-free.

    Let's re-draw the K-map and identify the redundant implicant needed:
    ```
       X=0 | X=1
    Q=0 ---|----
       1*  | 1*+ |  (* = covered by Q')
    Q=1 ---|----
       0   | 1+  |  (+ = covered by QX)
    ```
    The hazard occurs at `(Q=0, X=1)`. Both `Q'` and `QX` cover this cell.
    The transition is from `Q=0` to `Q=1` when `X=1`.
    We need a term that covers `(Q=0, X=1)` and `(Q=1, X=1)`. This term is `X`.
    So, a hazard-free implementation would be `D = Q' + QX + X`.
    This simplifies to `D = Q' + X(Q+1) = Q' + X`.
    Wait, the original function is `D = Q' + X`. Let's verify the K-map for this:
    ```
       X=0 | X=1
    Q=0 ---|----
       1   | 1
    Q=1 ---|----
       0   | 1
    ```
    The minimal SOP is indeed `D = Q' + X`.
    Let's re-analyze the transition that causes the hazard:
    From state `(Q=0, X=1)` to `(Q=1, X=1)`.
    Here, `Q` changes from `0` to `1`.
    Let's assume the implementation of `D = Q' + X`.
    If we implement `Q'` using an inverter and `X` directly, and then OR them.
    The path for `Q'`: `Q` -> Inverter -> `Q'`.
    The path for `X`: `X` directly.
    The OR gate combines `Q'` and `X`.
    When `Q` changes from `0` to `1` (and `X=1`):
    *   `Q'` changes from `1` to `0`.
    *   `X` remains `1`.
    *   `D = Q' + X`.
    If the inverter for `Q'` has a propagation delay, `Q'` will transition from `1` to `0`. During this transition, if the OR gate is slow to update, it might read `Q'=0` and `X=1` but still output `0` momentarily if the `1` from `X` is not yet fully processed, or if the `Q'` signal becoming `0` causes a temporary dip.

    The correct method to remove a static-1 hazard from an SOP expression is to **encompass the pair of adjacent 1s in the K-map that are not covered by any single prime implicant by adding a redundant implicant that covers them.**
    In our K-map:
    ```
       X=0 | X=1
    Q=0 ---|----
       1*  | 1*+ |  (* = covered by Q')
    Q=1 ---|----
       0   | 1+  |  (+ = covered by QX)
    ```
    The pair of 1s at `(Q=0, X=1)` and `(Q=1, X=1)` is adjacent.
    The prime implicant `Q'` covers `(Q=0, X=0)` and `(Q=0, X=1)`.
    The prime implicant `QX` covers `(Q=1, X=1)`.
    The transition from `(Q=0, X=1)` to `(Q=1, X=1)` involves the changing variable `Q`. We need an implicant that covers both these cells. This implicant is `X`.
    So, the hazard-free expression is `D = Q' + QX + X`.
    This simplifies to `D = Q' + X`.

    **Conclusion for Question 4:** The minimal SOP expression `D = Q' + QX` *is not* hazard-free for the transition from `(Q=0, X=1)` to `(Q=1, X=1)`. The hazard-free expression is `D = Q' + QX + Q'X`, which simplifies to `D = Q' + X`. The *implementation* of `D = Q' + X` needs care. If `Q'` and `X` are implemented separately and ORed, a static hazard could occur if the delays are not managed. Using a more robust implementation or ensuring the gate delays are consistent is key. For example, using a hazard-free SOP form obtained by adding redundant terms. `D = Q' + X` derived from `D = Q'(X + X') + X(Q + Q') = Q'X + Q'X' + XQ + XQ'`.
    This implies the expression `D = Q' + X` itself is hazard-free if implemented correctly. The issue is often in how the AND/OR gates are combined from the K-map. The example for hazard removal usually involves adding a redundant group.

    **Correct approach for Q4:**
    The minimal SOP is `D = Q' + QX`.
    The transition causing a static-1 hazard is between `(Q=0, X=1)` and `(Q=1, X=1)`.
    We need to add a redundant term that covers both these cells. This term is `X`.
    So, the hazard-free SOP is `D = Q' + QX + X`.
    This simplifies to `D = Q' + X`.
    If the original problem statement implied that `D = Q' + X` was the function, and we were to derive an SOP implementation from a K-map that might have hazards, then the minimal SOP for `D = Q' + X` is indeed `D = Q' + X`. However, the *implementation* of `D = Q' + X` using basic gates might still exhibit hazards if the gates have significant and mismatched delays. For example, if `Q'` is implemented as `NOT(Q)` and `X` is used directly, and then ORed. The transition where `Q` goes from `0` to `1` (with `X=1`) makes `Q'` go from `1` to `0`. If the OR gate is slow, it might briefly see `0` from `Q'` and `1` from `X` but still output `0`. The addition of the `Q'X` term ensures that even if `Q'` is momentarily `0`, the `Q'X` term (which is `0` in this specific transition) is complemented by the `X` term.

    The standard way to eliminate static hazards is to add redundant terms to the SOP form derived from the K-map until all essential transitions are covered by at least two implicants.
    For `D = Q' + QX`:
    The transition from `(0,1)` to `(1,1)` requires coverage. `Q'` covers `(0,0)` and `(0,1)`. `QX` covers `(1,1)`.
    The missing coverage for the transition is a term covering `(0,1)` and `(1,1)`. This term is `X`.
    So, the hazard-free form is `D = Q' + QX + X`. This simplifies to `D = Q' + X`.

    Therefore, the minimal form `D = Q' + X` IS hazard-free. The exercise tests the understanding of how to identify transitions that could cause hazards and how to add redundant terms to cover them.

### 8. Important Points to Remember

*   **Races are timing-dependent phenomena.** They are caused by unequal propagation delays in combinational logic paths.
*   **Static races** occur when a state variable should not change but momentarily does.
*   **Dynamic races** occur when a state variable changes multiple times before settling.
*   **State assignment** is critical for preventing races in sequential circuits derived from ASM charts.
*   **Hazard-free logic design** for next-state and output logic is essential.
*   **Master-slave flip-flops** offer better protection against certain types of races compared to simple edge-triggered flip-flops.
*   **Timing analysis** is required to confirm the absence of races in a design.
