## ADVANCED COMMUNICATION THEORY: Module 1 - Entropy

### Topic: Average Length of Source Code

**Learning Outcomes Covered:**

*   Understand the concept of the average length of a source code and its significance in data compression.
*   Relate the average length of a source code to the entropy of the source.
*   Analyze the optimality of different coding schemes in achieving minimum average length.

**Key Concepts and Definitions:**

*   **Source:** A system that generates a sequence of symbols from a finite alphabet.
*   **Alphabet ($\mathcal{X}$):** The set of all possible symbols that a source can generate.
*   **Probability Distribution ($P(x)$):** The probability of each symbol $x \in \mathcal{X}$ occurring.
*   **Symbol:** An individual unit of information generated by the source.
*   **Code:** A mapping from the source alphabet to a set of codewords (sequences of bits).
*   **Codeword:** A sequence of bits representing a source symbol.
*   **Length of a Codeword ($l(x)$):** The number of bits in the codeword assigned to symbol $x$.
*   **Source Code:** A set of codewords assigned to the symbols of a source alphabet.
*   **Average Length of a Source Code ($L$):** The expected length of the codewords used to represent the source symbols, weighted by their probabilities.

**1. Understanding Average Length of Source Code**

The primary goal of source coding is to represent the information generated by a source using as few bits as possible, without losing information. This is achieved by assigning shorter codewords to more frequent symbols and longer codewords to less frequent symbols. The **average length of a source code** quantifies the efficiency of this representation.

**Definition:**
The average length $L$ of a source code for a source with alphabet $\mathcal{X} = \{x_1, x_2, \dots, x_m\}$ and probability distribution $P(x_i)$ for each symbol $x_i$, where $l(x_i)$ is the length of the codeword assigned to $x_i$, is given by:

$L = \sum_{i=1}^{m} P(x_i) l(x_i)$

This is essentially the expected value of the codeword lengths.

**Example:**
Consider a source that generates symbols {A, B, C} with the following probabilities:
$P(A) = 0.5$, $P(B) = 0.25$, $P(C) = 0.25$.

Let's consider two different source codes:

**Code 1:**
*   A: 0 (length $l(A)=1$)
*   B: 10 (length $l(B)=2$)
*   C: 11 (length $l(C)=2$)

Average Length $L_1 = P(A)l(A) + P(B)l(B) + P(C)l(C)$
$L_1 = (0.5 \times 1) + (0.25 \times 2) + (0.25 \times 2)$
$L_1 = 0.5 + 0.5 + 0.5 = 1.5$ bits/symbol

**Code 2:**
*   A: 00 (length $l(A)=2$)
*   B: 01 (length $l(B)=2$)
*   C: 1 (length $l(C)=1$)

Average Length $L_2 = P(A)l(A) + P(B)l(B) + P(C)l(C)$
$L_2 = (0.5 \times 2) + (0.25 \times 2) + (0.25 \times 1)$
$L_2 = 1.0 + 0.5 + 0.25 = 1.75$ bits/symbol

In this example, Code 1 is more efficient as it has a lower average length.

**2. Relation to Entropy**

The **entropy** of a source, denoted by $H(X)$, is a measure of the average information content per symbol. It represents the theoretical lower bound on the average number of bits per symbol required to represent the source.

**Definition (Revisited):**
For a discrete memoryless source (DMS) with alphabet $\mathcal{X} = \{x_1, x_2, \dots, x_m\}$ and probability distribution $P(x_i)$, the entropy is given by:

$H(X) = -\sum_{i=1}^{m} P(x_i) \log_b P(x_i)$

where $b$ is the base of the logarithm (typically 2 for bits).

**Shannon's Source Coding Theorem (First Theorem):**
This fundamental theorem states that for any discrete memoryless source, the average length $L$ of any uniquely decodable code is bounded below by the entropy of the source. Specifically, it is possible to construct a uniquely decodable code with an average length $L$ such that:

$H(X) \le L < H(X) + 1$ (for binary codes, $b=2$)

This theorem has profound implications:

*   **Lower Bound:** The entropy $H(X)$ sets a fundamental limit on how much compression is possible. We cannot achieve an average length less than the entropy.
*   **Achievability:** It is possible to get arbitrarily close to this entropy limit with efficient coding schemes.

**Key Insight:** To minimize the average length $L$, we should ideally assign codeword lengths $l(x_i)$ such that $l(x_i) \approx -\log_2 P(x_i)$. This is because $L = \sum P(x_i) l(x_i)$. If we set $l(x_i) = -\log_2 P(x_i)$, then $L = \sum P(x_i) (-\log_2 P(x_i)) = H(X)$. However, codeword lengths must be integers, so this exact relationship is generally not achievable.

**3. Optimal Coding Schemes**

The goal is to design codes that approach the entropy limit. Two prominent coding schemes that achieve this are:

**a) Shannon-Fano Coding:**

*   **Procedure:**
    1.  List the symbols in descending order of probability.
    2.  Divide the list into two sub-lists such that the sum of probabilities in each sub-list is as close as possible.
    3.  Assign a '0' to the first half and a '1' to the second half.
    4.  Recursively apply steps 2 and 3 to each sub-list until each sub-list contains only one symbol.
*   **Average Length:** Generally good, but not always optimal.
*   **Textbook Reference:** Goldsmith, Chapter 3 (Source Coding); Cover & Thomas, Chapter 5 (Source Coding)

**Example (Shannon-Fano):**
Source: {A: 0.4, B: 0.3, C: 0.2, D: 0.1}

1.  Sorted probabilities: {A: 0.4, B: 0.3, C: 0.2, D: 0.1}
2.  Split: {A: 0.4, B: 0.3} | {C: 0.2, D: 0.1} (Sum of probs: 0.7 vs 0.3) - *This isn't the best split. We want sums to be as close as possible.*
    Let's try: {A: 0.4, B: 0.3} | {C: 0.2, D: 0.1} -> Sums: 0.7 and 0.3. Not ideal.
    Consider the cumulative probabilities: 0.4, 0.7, 0.9, 1.0. We want to split around 0.5.
    Split 1: {A: 0.4, B: 0.3} | {C: 0.2, D: 0.1} -> Sums: 0.7 and 0.3.
    Split 2: {A: 0.4} | {B: 0.3, C: 0.2, D: 0.1} -> Sums: 0.4 and 0.6. This is better.

Let's use the split that aims for equal probability sums:
Split: {A: 0.4, B: 0.3} | {C: 0.2, D: 0.1} -> Probability sums are 0.7 and 0.3.
A better split might be to divide the total probability sum (1.0) in half (0.5).
List: (A, 0.4), (B, 0.3), (C, 0.2), (D, 0.1)
Cumulative: 0.4, 0.7, 0.9, 1.0
Target split point is around 0.5.
First group: A (0.4). Remaining sum = 0.6. We need to split between A and B.
Group 1: {A, B} (sum 0.7) ; Group 2: {C, D} (sum 0.3) - Not balanced.

Let's try dividing the probability mass as evenly as possible:
1.  A (0.4)
2.  B (0.3)
3.  C (0.2)
4.  D (0.1)

Split 1: {A, B} vs {C, D}. Sums: 0.7 vs 0.3.
Assign '0' to the first group, '1' to the second:
A: 0...
B: 0...
C: 1...
D: 1...

Now, recursively split:
For {A, B}: A (0.4), B (0.3). Split between them.
A: 00 (length 2)
B: 01 (length 2)

For {C, D}: C (0.2), D (0.1). Split between them.
C: 10 (length 2)
D: 11 (length 2)

Code: {A: 00, B: 01, C: 10, D: 11}
Average Length $L_{SF} = (0.4 \times 2) + (0.3 \times 2) + (0.2 \times 2) + (0.1 \times 2) = 0.8 + 0.6 + 0.4 + 0.2 = 2.0$ bits/symbol.

Entropy: $H(X) = -(0.4 \log_2 0.4 + 0.3 \log_2 0.3 + 0.2 \log_2 0.2 + 0.1 \log_2 0.1)$
$H(X) \approx -(0.4 \times -1.32) - (0.3 \times -1.74) - (0.2 \times -2.32) - (0.1 \times -3.32)$
$H(X) \approx 0.53 + 0.52 + 0.46 + 0.33 \approx 1.84$ bits/symbol.
$L_{SF} = 2.0$, which is $H(X) + 0.16$. It's reasonably close.

**b) Huffman Coding:**

*   **Procedure:** This is a greedy algorithm guaranteed to produce an optimal prefix code (a code where no codeword is a prefix of another codeword), minimizing the average length.
    1.  Create a leaf node for each symbol, with its probability as its weight.
    2.  Combine the two nodes with the lowest probabilities into a new parent node. The probability of the parent node is the sum of the probabilities of its children.
    3.  Assign a '0' to the edge leading to one child (e.g., left) and a '1' to the edge leading to the other child (e.g., right).
    4.  Repeat steps 2 and 3 until only one node (the root) remains.
    5.  The codeword for each symbol is the sequence of 0s and 1s from the root to its leaf node.
*   **Average Length:** Achieves the minimum possible average length for any uniquely decodable code, and thus is very close to the entropy.
*   **Textbook Reference:** Goldsmith, Chapter 3 (Source Coding); Cover & Thomas, Chapter 5 (Source Coding); Rappaport, Chapter 3 (Digital Transmission of Information)

**Example (Huffman Coding):**
Source: {A: 0.4, B: 0.3, C: 0.2, D: 0.1} (Same as before)

1.  Initial nodes: (A, 0.4), (B, 0.3), (C, 0.2), (D, 0.1)
2.  Combine C and D (lowest probabilities): Node CD (0.3) with children C (0.2) and D (0.1).
    Nodes: (A, 0.4), (B, 0.3), (CD, 0.3)
3.  Combine B and CD (lowest probabilities): Node BCD (0.6) with children B (0.3) and CD (0.3).
    Nodes: (A, 0.4), (BCD, 0.6)
4.  Combine A and BCD: Root Node ABCD (1.0) with children A (0.4) and BCD (0.6).

Let's assign 0 to the left child and 1 to the right child consistently (or vice-versa, it doesn't affect optimality, just the specific codewords). Conventionally, lower probability goes left (0), higher goes right (1).

Tree structure:

        ABCD (1.0)
       /       \
      A (0.4)   BCD (0.6)
                /      \
               B (0.3)  CD (0.3)
                       /     \
                      C (0.2) D (0.1)

Let's re-assign labels for clarity (0 left, 1 right):

        ABCD (1.0)
       /       \
      A (0.4)  BCD (0.6) --- 1
     / \
    0   1

    BCD (0.6)
   /      \
  B (0.3)  CD (0.3) --- 1
 / \
0   1

  CD (0.3)
 /     \
C (0.2) D (0.1) --- 1
/     \
0     1

So, the codewords are:
*   A: 0 (length $l(A)=1$)
*   B: 10 (length $l(B)=2$)
*   C: 110 (length $l(C)=3$)
*   D: 111 (length $l(D)=3$)

Average Length $L_{Huffman} = P(A)l(A) + P(B)l(B) + P(C)l(C) + P(D)l(D)$
$L_{Huffman} = (0.4 \times 1) + (0.3 \times 2) + (0.2 \times 3) + (0.1 \times 3)$
$L_{Huffman} = 0.4 + 0.6 + 0.6 + 0.3 = 1.9$ bits/symbol.

Comparing this to the entropy $H(X) \approx 1.84$:
$L_{Huffman} = 1.9$, which is $H(X) + 0.06$. This is very close to the entropy limit, demonstrating the optimality of Huffman coding.

**Comparison of Shannon-Fano and Huffman:**
In this specific example, Huffman coding ($L=1.9$) is better than the Shannon-Fano code we constructed ($L=2.0$). Huffman coding is guaranteed to produce the optimal prefix code in terms of average length.

**Important Points to Remember:**

*   The **average length** of a source code is a crucial metric for evaluating its compression efficiency.
*   The **entropy** of a source represents the theoretical minimum achievable average length.
*   **Shannon's Source Coding Theorem** establishes the fundamental relationship: $H(X) \le L < H(X) + 1$.
*   **Huffman coding** is a practical and optimal algorithm for constructing prefix codes that achieve the minimum average length for a given source.
*   The goal is to match codeword lengths to the negative logarithm of symbol probabilities ($l(x_i) \approx -\log_2 P(x_i)$) to minimize average length.
*   Source coding is a fundamental step in digital communication and data compression.

### Practice Questions and Exercises

**Question 1:**
A discrete memoryless source has an alphabet $\mathcal{X} = \{a, b, c\}$ with probabilities $P(a) = 0.5$, $P(b) = 0.3$, and $P(c) = 0.2$.
Consider the following two binary codes:
*   Code 1: $a \rightarrow 0$, $b \rightarrow 10$, $c \rightarrow 11$
*   Code 2: $a \rightarrow 00$, $b \rightarrow 01$, $c \rightarrow 1$

Calculate the average length of Code 1 and Code 2. Which code is more efficient?

**Answer 1:**
*   **Average Length of Code 1:**
    $L_1 = P(a)l(a) + P(b)l(b) + P(c)l(c)$
    $L_1 = (0.5 \times 1) + (0.3 \times 2) + (0.2 \times 2)$
    $L_1 = 0.5 + 0.6 + 0.4 = 1.5$ bits/symbol

*   **Average Length of Code 2:**
    $L_2 = P(a)l(a) + P(b)l(b) + P(c)l(c)$
    $L_2 = (0.5 \times 2) + (0.3 \times 2) + (0.2 \times 1)$
    $L_2 = 1.0 + 0.6 + 0.2 = 1.8$ bits/symbol

Code 1 is more efficient as it has a lower average length (1.5 bits/symbol vs 1.8 bits/symbol).

**Question 2:**
Calculate the entropy of the source in Question 1. How does the entropy compare to the average lengths of the codes?

**Answer 2:**
Entropy $H(X) = -\sum_{i=1}^{m} P(x_i) \log_2 P(x_i)$
$H(X) = -(0.5 \log_2 0.5 + 0.3 \log_2 0.3 + 0.2 \log_2 0.2)$
$H(X) = -(0.5 \times -1) - (0.3 \times -1.737) - (0.2 \times -2.322)$
$H(X) = 0.5 + 0.5211 + 0.4644 \approx 1.4855$ bits/symbol.

Comparing entropy to the code lengths:
*   $H(X) \approx 1.4855$ bits/symbol
*   $L_1 = 1.5$ bits/symbol
*   $L_2 = 1.8$ bits/symbol

The entropy (1.4855) is indeed less than both average lengths. Code 1 (1.5) is very close to the entropy, confirming Shannon's theorem ($H(X) \le L$). Code 2 is less efficient and further from the entropy limit.
