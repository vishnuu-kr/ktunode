## Topic: Source Coding

*   Understand the practical considerations and challenges in implementing source coding schemes.

### Key Concepts and Definitions:

**Source Coding:** The process of converting data from a source into a compressed form for efficient storage and transmission. The goal is to represent the information with fewer bits without significant loss of quality (lossless compression) or with acceptable loss (lossy compression).

**Entropy (H(X)):** A measure of the average amount of information or uncertainty associated with a random variable. It quantifies the minimum average number of bits required to represent each symbol from a source.
*   **Formula:** $H(X) = -\sum_{i=1}^{n} p(x_i) \log_b p(x_i)$, where $p(x_i)$ is the probability of the $i$-th symbol and $b$ is the base of the logarithm (usually 2 for bits).
*   **Significance:** Entropy provides the theoretical lower bound on the average codeword length achievable by any lossless compression scheme. (Aligns with CO1)

**Source Alphabet:** The set of all possible symbols that can be generated by a source.

**Code:** A mapping from the source alphabet to a set of codewords (sequences of bits).

**Codeword:** A sequence of bits representing a source symbol.

**Prefix Code (or Instantaneous Code):** A code where no codeword is a prefix of another codeword. This property allows for unambiguous decoding without delimiters.

**Average Codeword Length (L):** The expected length of a codeword, calculated as $L = \sum_{i=1}^{n} p(x_i) l(c_i)$, where $l(c_i)$ is the length of the codeword for symbol $x_i$.

**Lossless Compression:** Compression where the original data can be perfectly reconstructed from the compressed data.

**Lossy Compression:** Compression where some information is lost during the compression process, resulting in a reconstruction that is an approximation of the original data.

---

### 1. The Source Coding Theorem (Shannon's First Theorem)

*   **Statement:** For a discrete memoryless source (DMS) with entropy $H(X)$, it is possible to losslessly compress the source output such that the average codeword length $L$ satisfies $H(X) \le L < H(X) + 1$.
*   **Implication:** This theorem establishes that entropy represents the fundamental limit of lossless data compression. No lossless compression scheme can achieve an average codeword length less than the source's entropy. (Aligns with CO2)
*   **Textbook Reference:** **Elements of Information Theory by Thomas & Cover** extensively covers the proof and implications of the Source Coding Theorem.

---

### 2. Principles of Source Coding

The primary goal is to assign shorter codewords to more frequent symbols and longer codewords to less frequent symbols, thereby minimizing the average codeword length.

*   **Huffman Coding:**
    *   A widely used algorithm for constructing optimal prefix codes.
    *   **Algorithm:**
        1.  Create a leaf node for each symbol with its probability.
        2.  Repeatedly combine the two nodes with the lowest probabilities into a new parent node whose probability is the sum of the children's probabilities.
        3.  Assign '0' to the edge connecting to one child and '1' to the edge connecting to the other.
        4.  Continue this process until only one root node remains.
        5.  The codeword for a symbol is the sequence of bits along the path from the root to the symbol's leaf node.
    *   **Property:** Huffman coding generates an optimal prefix code, meaning it achieves the minimum possible average codeword length among all prefix codes for a given source.
    *   **Example:** Consider a source with symbols {A, B, C, D} and probabilities P(A)=0.5, P(B)=0.25, P(C)=0.125, P(D)=0.125.
        *   **Entropy Calculation:**
            $H(X) = -(0.5 \log_2 0.5 + 0.25 \log_2 0.25 + 0.125 \log_2 0.125 + 0.125 \log_2 0.125)$
            $H(X) = -(0.5 \times -1 + 0.25 \times -2 + 0.125 \times -3 + 0.125 \times -3)$
            $H(X) = -( -0.5 - 0.5 - 0.375 - 0.375 ) = 1.75$ bits/symbol.
        *   **Huffman Coding Steps:**
            1.  Nodes: (A, 0.5), (B, 0.25), (C, 0.125), (D, 0.125)
            2.  Combine C and D: (CD, 0.25)
            3.  Nodes: (A, 0.5), (B, 0.25), (CD, 0.25)
            4.  Combine B and CD: (BCD, 0.5)
            5.  Nodes: (A, 0.5), (BCD, 0.5)
            6.  Combine A and BCD: (ABCD, 1.0)
        *   **Codewords:**
            *   A: 0 (length 1)
            *   B: 10 (length 2)
            *   C: 110 (length 3)
            *   D: 111 (length 3)
        *   **Average Codeword Length:**
            $L = (0.5 \times 1) + (0.25 \times 2) + (0.125 \times 3) + (0.125 \times 3)$
            $L = 0.5 + 0.5 + 0.375 + 0.375 = 1.75$ bits/symbol.
            This matches the entropy, demonstrating optimality for prefix codes. (Aligns with CO2)

*   **Shannon-Fano Coding:**
    *   Another method for constructing prefix codes, generally less optimal than Huffman coding.
    *   **Algorithm:**
        1.  Sort symbols by probability in descending order.
        2.  Divide the list into two sublists such that the sum of probabilities in each sublist is as close as possible to 0.5.
        3.  Assign '0' to the first sublist and '1' to the second sublist.
        4.  Recursively apply the process to each sublist.
    *   **Comparison to Huffman:** While it aims to assign shorter codes to higher probability symbols, it doesn't guarantee optimality in the same way as Huffman coding.
    *   **Textbook Reference:** **Elements of Information Theory by Thomas & Cover** and **Digital Communication Systems by Simon Haykin** discuss Shannon-Fano coding.

*   **Arithmetic Coding:**
    *   A more advanced and often more efficient compression technique than Huffman coding, especially for skewed probability distributions.
    *   **Principle:** Represents an entire message (sequence of symbols) as a single fraction within the interval [0, 1). As more symbols are processed, the interval representing the remaining possibilities becomes smaller and smaller.
    *   **Advantage:** Can achieve average codeword lengths closer to the theoretical entropy, even for very small alphabets or when the probabilities don't lend themselves well to Huffman coding's binary tree structure. It can effectively assign fractional bits per symbol.
    *   **Disadvantage:** Computationally more complex than Huffman coding.
    *   **Textbook Reference:** **Elements of Information Theory by Thomas & Cover** provides a detailed treatment of arithmetic coding.

### 3. Types of Source Coding Schemes

*   **Lossless Source Coding:**
    *   **Goal:** Perfect reconstruction of the original data.
    *   **Examples:** Huffman coding, Arithmetic coding, LZW (Lempel-Ziv-Welch).
    *   **Application:** Text files, executable programs, medical images, where any loss of information is unacceptable.

*   **Lossy Source Coding:**
    *   **Goal:** Achieve higher compression ratios by discarding some information that is deemed perceptually less important.
    *   **Metrics for Quality:** Mean Squared Error (MSE), Peak Signal-to-Noise Ratio (PSNR), perceptual metrics.
    *   **Examples:** JPEG (for images), MP3 (for audio), MPEG (for video).
    *   **Key Techniques:** Quantization, Transform coding (e.g., Discrete Cosine Transform - DCT), Predictive coding.
    *   **Application:** Multimedia content where some fidelity loss is tolerable for significant compression gains.
    *   **Textbook Reference:** While not the primary focus of this module, concepts of lossy compression are touched upon in the context of signal processing for communication systems in books like **Wireless Communications by Andrea Goldsmith** and **Communication Systems by Simon Haykin**, particularly when discussing modulation and signal representation.

---

### 4. Practical Considerations in Source Coding

*   **Adaptivity:** Real-world data sources may have changing statistical properties. Adaptive coding schemes adjust their parameters (e.g., codeword lengths) in real-time to maintain compression efficiency.
*   **Complexity:** The computational cost of encoding and decoding is a crucial factor, especially for real-time applications.
*   **Memory Requirements:** Storing probability tables or code trees can require significant memory.
*   **Error Resilience:** If the compressed data is transmitted over a noisy channel, errors in the compressed stream can lead to significant degradation in the reconstructed data. This is where error-correction coding (channel coding) becomes important.
*   **Textbook Reference:** Discussion on adaptive coding might be found in more specialized texts or research papers. General communication system books like **Wireless Communications by Theodore S. Rappaport** might allude to the need for efficient data representation but not detail adaptive source coding algorithms.

---

### Important Points to Remember:

*   **Entropy is the bedrock of source coding.** It defines the ultimate compression limit for lossless coding.
*   **Prefix codes** are essential for unambiguous decoding.
*   **Huffman coding** is optimal for prefix codes and widely used.
*   **Arithmetic coding** offers better compression ratios but is more complex.
*   **Lossless vs. Lossy compression** depends on the application's tolerance for data degradation.
*   Source coding aims to remove **statistical redundancy** in the data.

### Practice Questions and Exercises:

**Question 1 (CO1, K2):** Define entropy and explain its significance in the context of data compression.
**Answer:** Entropy ($H(X)$) is a measure of the average uncertainty or information content of a random variable. In data compression, it represents the theoretical minimum average number of bits required to represent each symbol from a source without loss of information. A higher entropy indicates more randomness and less compressibility.

**Question 2 (CO2, K3):** A discrete memoryless source has the following symbol probabilities: P(A) = 0.6, P(B) = 0.2, P(C) = 0.1, P(D) = 0.1.
    a) Calculate the entropy of the source.
    b) Construct a Huffman code for this source.
    c) Calculate the average codeword length for the Huffman code.
    d) Is the average codeword length greater than or equal to the entropy? Explain why.

**Answer:**
    a) **Entropy Calculation:**
        $H(X) = -(0.6 \log_2 0.6 + 0.2 \log_2 0.2 + 0.1 \log_2 0.1 + 0.1 \log_2 0.1)$
        $H(X) \approx -(0.6 \times -0.737 + 0.2 \times -2.322 + 0.1 \times -3.322 + 0.1 \times -3.322)$
        $H(X) \approx -(-0.4422 - 0.4644 - 0.3322 - 0.3322) \approx 1.571$ bits/symbol.

    b) **Huffman Code Construction:**
        1.  Nodes: (A, 0.6), (B, 0.2), (C, 0.1), (D, 0.1)
        2.  Combine C and D: (CD, 0.2)
        3.  Nodes: (A, 0.6), (B, 0.2), (CD, 0.2)
        4.  Combine B and CD: (BCD, 0.4)
        5.  Nodes: (A, 0.6), (BCD, 0.4)
        6.  Combine A and BCD: (ABCD, 1.0)

        Codewords:
        *   A: 0 (length 1)
        *   B: 10 (length 2)
        *   C: 110 (length 3)
        *   D: 111 (length 3)

    c) **Average Codeword Length:**
        $L = (0.6 \times 1) + (0.2 \times 2) + (0.1 \times 3) + (0.1 \times 3)$
        $L = 0.6 + 0.4 + 0.3 + 0.3 = 1.6$ bits/symbol.

    d) Yes, the average codeword length (1.6 bits/symbol) is greater than the entropy (approx. 1.571 bits/symbol). This is expected due to the Source Coding Theorem ($H(X) \le L < H(X) + 1$). The difference is small because Huffman coding is an optimal prefix code and the probabilities are relatively well-suited for it. The difference exists because we are restricted to integer code lengths, whereas entropy can be a fractional value.

**Question 3 (CO2, K2):** Explain the advantage of using arithmetic coding over Huffman coding in certain scenarios.
**Answer:** Arithmetic coding can achieve average codeword lengths closer to the theoretical entropy, especially when the source has a small alphabet or very skewed probability distributions. This is because it encodes an entire message as a single fraction, allowing it to assign effectively fractional bits per symbol, something Huffman coding (which requires integer code lengths) cannot do as precisely.
