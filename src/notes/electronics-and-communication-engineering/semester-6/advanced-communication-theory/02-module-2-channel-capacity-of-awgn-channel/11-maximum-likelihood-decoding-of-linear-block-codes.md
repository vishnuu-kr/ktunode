## Topic: Maximum Likelihood Decoding of Linear Block Codes

### 1. Introduction to Decoding and Linear Block Codes

**Concept:** In digital communication systems, information is transmitted as a sequence of bits. Errors can occur during transmission due to noise and interference, corrupting the original data. Error control coding is employed to detect and correct these errors at the receiver. Linear block codes are a fundamental class of error-correcting codes characterized by their linear structure, which simplifies the encoding and decoding processes.

**Key Concepts:**

*   **Code Word:** A block of bits transmitted over the channel. It consists of message bits and parity bits.
*   **Block Code:** A code where a block of $k$ message bits is mapped to a block of $n$ code bits. The **code rate** is defined as $R = k/n$.
*   **Linear Block Code:** A block code where the sum (modulo-2) of any two code words is also a code word. This property makes them mathematically tractable.
*   **Generator Matrix ($G$):** An $k \times n$ matrix that defines a linear block code. Any valid code word $c$ can be generated by multiplying the message vector $m$ (of length $k$) by the generator matrix: $c = mG$.
*   **Parity Check Matrix ($H$):** An $(n-k) \times n$ matrix that defines a linear block code. A vector $c$ is a valid code word if and only if $cH^T = 0$, where $H^T$ is the transpose of $H$.
*   **Syndrome:** For a received vector $y$, the syndrome $s$ is calculated as $s = yH^T$. If $s = 0$, the received vector is likely a valid code word. If $s \neq 0$, an error has occurred.

### 2. The Additive White Gaussian Noise (AWGN) Channel

**Concept:** The AWGN channel is a fundamental model for communication channels where the primary source of error is additive, random noise that is uniformly distributed across all frequencies and has a Gaussian probability distribution.

**Key Concepts:**

*   **Channel Model:** A transmitted signal $x$ is corrupted by additive noise $z$ to produce a received signal $y$. For a linear block code, the transmitted signal is a vector of bits. When these bits are modulated and transmitted, they are represented as symbols. For simplicity, we often consider the effect of the AWGN channel on these symbols.
*   **Probability Density Function (PDF) of Noise:** The noise $z$ is modeled as a random variable with a Gaussian distribution and zero mean, $z \sim \mathcal{N}(0, \sigma^2)$, where $\sigma^2$ is the noise variance.
*   **Signal-to-Noise Ratio (SNR):** A measure of the strength of the transmitted signal relative to the strength of the noise. It significantly impacts the error rate of the communication system. The SNR can be expressed as $E_b/N_0$, where $E_b$ is the energy per bit and $N_0$ is the power spectral density of the noise.

While this topic focuses on block codes, understanding the AWGN channel is crucial for analyzing their performance, which is a precursor to understanding fading channels.

### 3. Maximum Likelihood (ML) Decoding

**Concept:** Maximum Likelihood decoding is an optimal decoding strategy that aims to find the transmitted code word that is "most likely" to have been received, given the received noisy signal. It minimizes the probability of error.

**Key Concept:**

*   **Likelihood Function:** For a received vector $y$, the likelihood function $P(y | c)$ represents the probability of observing $y$ given that code word $c$ was transmitted. For the AWGN channel, this likelihood function is related to the Euclidean distance between the received vector and the transmitted code word.

**The ML Decoding Rule:**

Given a received vector $y$, the ML decoder chooses the code word $\hat{c}$ from the set of all possible code words $\mathcal{C}$ that maximizes the likelihood function $P(y | c)$:

$$ \hat{c} = \arg \max_{c \in \mathcal{C}} P(y | c) $$

For the AWGN channel, the probability of receiving $y$ given $c$ is given by a Gaussian distribution with mean $c$ and variance $\sigma^2$. Maximizing $P(y | c)$ is equivalent to minimizing the squared Euclidean distance between $y$ and $c$:

$$ \hat{c} = \arg \min_{c \in \mathcal{C}} \|y - c\|^2 $$

**Explanation:**

Imagine the set of all possible code words as points in an $n$-dimensional space. The received vector $y$ is also a point in this space, but it's corrupted by noise, so it's unlikely to be exactly one of the code word points. The ML decoder calculates the distance from $y$ to every valid code word. The code word closest to $y$ in terms of Euclidean distance is declared as the transmitted code word.

**Example:**

Consider a simple linear block code with $n=3$ and $k=1$. Let the generator matrix be $G = [1 \ 0 \ 0]$. The possible message bits are $m=0$ and $m=1$. The corresponding code words are:
*   $m=0 \implies c = 0 \cdot [1 \ 0 \ 0] = [0 \ 0 \ 0]$
*   $m=1 \implies c = 1 \cdot [1 \ 0 \ 0] = [1 \ 0 \ 0]$

The code consists of two code words: $c_0 = [0 \ 0 \ 0]$ and $c_1 = [1 \ 0 \ 0]$.

Suppose the received vector is $y = [0.8 \ -0.1 \ 0.2]$.

We need to calculate the squared Euclidean distance from $y$ to each code word:

*   Distance to $c_0$: $\|y - c_0\|^2 = \|[0.8 \ -0.1 \ 0.2] - [0 \ 0 \ 0]\|^2 = (0.8)^2 + (-0.1)^2 + (0.2)^2 = 0.64 + 0.01 + 0.04 = 0.69$
*   Distance to $c_1$: $\|y - c_1\|^2 = \|[0.8 \ -0.1 \ 0.2] - [1 \ 0 \ 0]\|^2 = (0.8 - 1)^2 + (-0.1 - 0)^2 + (0.2 - 0)^2 = (-0.2)^2 + (-0.1)^2 + (0.2)^2 = 0.04 + 0.01 + 0.04 = 0.09$

Since the distance to $c_1$ (0.09) is smaller than the distance to $c_0$ (0.69), the ML decoder chooses $\hat{c} = c_1 = [1 \ 0 \ 0]$ as the transmitted code word.

### 4. Hard-Decision vs. Soft-Decision Decoding

**Concept:** The way the received signal is processed before decoding leads to different types of decoding: hard-decision and soft-decision.

**Key Concepts:**

*   **Hard-Decision Decoding:** The received analog signal is first converted into a binary symbol (0 or 1) using a threshold detector. This binary symbol is then passed to the decoder. The decoder operates on these hard bits.
    *   **Pros:** Simpler receiver implementation.
    *   **Cons:** Information about the reliability of the received bit is lost during the quantization process.
*   **Soft-Decision Decoding:** The received analog signal is not quantized to binary digits. Instead, a metric (e.g., the actual received analog value, or a quantized version with multiple bits) that indicates the likelihood of the bit being a 0 or 1 is passed to the decoder. The decoder uses this information to make a more informed decision.
    *   **Pros:** More robust, significantly better performance, especially at low SNR.
    *   **Cons:** More complex receiver implementation.

**ML Decoding and Decision Types:**

*   **ML Hard-Decision Decoding:** The decoder operates on the binary output of a hard-decision device. It compares the received binary vector with all possible code words and chooses the one with the minimum Hamming distance.
    *   **Hamming Distance:** The number of positions at which two code words of the same length differ.
    *   **ML Rule (Hard-Decision):** $\hat{c} = \arg \min_{c \in \mathcal{C}} d_H(y_{bin}, c)$, where $y_{bin}$ is the hard-decoded received binary vector and $d_H$ is the Hamming distance.

*   **ML Soft-Decision Decoding:** The decoder operates on the analog or quantized analog values. It directly minimizes the Euclidean distance between the received vector and the code words, as described in Section 3.

**Example (Continuing from Section 3):**

Let's assume the received signal after matched filtering (before thresholding) was $y_{analog} = [0.8 \ -0.1 \ 0.2]$.

*   **Hard-Decision:** If we use a threshold of 0.5, the received binary vector is $y_{bin} = [1 \ 0 \ 0]$ (assuming 0.8 > 0.5, -0.1 < 0.5, 0.2 < 0.5).
    *   Hamming distance to $c_0 = [0 \ 0 \ 0]$: $d_H([1 \ 0 \ 0], [0 \ 0 \ 0]) = 1$.
    *   Hamming distance to $c_1 = [1 \ 0 \ 0]$: $d_H([1 \ 0 \ 0], [1 \ 0 \ 0]) = 0$.
    *   The minimum Hamming distance is 0 to $c_1$. So, $\hat{c} = [1 \ 0 \ 0]$. In this case, hard-decision decoding yields the correct result.

*   **Soft-Decision:** As calculated in Section 3, minimizing the Euclidean distance leads to $\hat{c} = [1 \ 0 \ 0]$ because $\|y_{analog} - c_1\|^2 < \|y_{analog} - c_0\|^2$.

**Important Point to Remember:** Soft-decision decoding is always better than or equal to hard-decision decoding in terms of error probability. The performance gain can be up to 2-3 dB in SNR.

### 5. Syndrome Decoding and the Viterbi Algorithm (Brief Mention for Context)

**Concept:** While ML decoding is optimal, its direct implementation (calculating distances to all code words) can be computationally intensive, especially for large codes. Syndrome decoding and algorithms like the Viterbi algorithm offer more efficient ways to perform decoding.

**Key Concepts:**

*   **Syndrome Decoding:** This technique uses the parity check matrix $H$ to identify the error pattern. If a received vector $y$ is written as $y = c + e$ (where $c$ is a valid code word and $e$ is the error vector), then the syndrome is $s = yH^T = (c + e)H^T = cH^T + eH^T$. Since $cH^T = 0$ for a valid code word, $s = eH^T$. The decoder calculates the syndrome $s$ and looks up the corresponding error pattern $e$ in a pre-computed table. The corrected code word is then $c_{corr} = y + e$. This is typically used for linear block codes and is efficient if the number of possible error patterns is manageable.

*   **Viterbi Algorithm:** This algorithm is used for decoding convolutional codes, which are another important class of error-correcting codes. It's a maximum likelihood sequence estimation algorithm that efficiently finds the most likely sequence of transmitted symbols by working through a trellis diagram of the code. It's highly parallelizable and widely used.

**Important Point to Remember:** For linear block codes, the direct ML approach (minimum Euclidean distance) is conceptually important. For practical implementation and efficiency, especially for codes with a large number of code words, more structured decoding algorithms like syndrome decoding (for block codes) or the Viterbi algorithm (for convolutional codes) are preferred.

### 6. Practical Considerations and Complexity

**Concept:** The choice of a decoding algorithm depends heavily on the desired performance, the complexity of the code, and the computational resources available at the receiver.

**Key Concepts:**

*   **Computational Complexity:** The number of operations (additions, multiplications, comparisons) required by the decoder. ML decoding, in its brute-force form, has exponential complexity with respect to the code length $n$.
*   **Error Rate Performance:** The probability of decoding error versus SNR. ML decoding provides the best possible error rate performance.
*   **Code Design:** The structure of the linear block code (e.g., Hamming codes, BCH codes, Reed-Solomon codes) significantly impacts the complexity of ML decoding and its performance.

**Important Point to Remember:** There is a fundamental trade-off between decoding complexity and error correction performance. ML decoding offers optimal performance but at the highest complexity. Practical systems often employ decoding algorithms that strike a balance between these two factors.

**Question 2:**
Explain the core principle behind Maximum Likelihood (ML) decoding in the context of an AWGN channel. Why is it considered optimal?

**Answer 2:**
The core principle of Maximum Likelihood (ML) decoding on an AWGN channel is to choose the transmitted code word that is "most likely" to have produced the received noisy signal. Mathematically, given a received vector $y$, the ML decoder selects the code word $\hat{c}$ from the set of all possible code words $\mathcal{C}$ that maximizes the conditional probability $P(y|c)$.

For an AWGN channel, the received signal $y$ is related to the transmitted code word $c$ by $y = c + z$, where $z$ is Gaussian noise. The probability density function of $y$ given $c$ is a Gaussian distribution with mean $c$ and variance $\sigma^2$. Maximizing this probability density function is equivalent to minimizing the squared Euclidean distance between the received vector $y$ and the transmitted code word $c$:

$$ \hat{c} = \arg \min_{c \in \mathcal{C}} \|y - c\|^2 $$

ML decoding is considered optimal because it minimizes the probability of error at the output of the decoder. By choosing the code word that is closest in Euclidean distance to the received noisy vector, it makes the decision that is statistically most likely to be correct, regardless of the SNR. This is the fundamental criterion for an optimal detector in a probabilistic setting.

**Question 3:**
What is the main difference between hard-decision and soft-decision decoding, and which one generally offers better performance?

**Answer 3:**
The main difference lies in the information available to the decoder.

*   **Hard-Decision Decoding:** The receiver first quantizes the analog received signal into binary bits (0s and 1s) using a threshold detector. The decoder then operates on these binary bits, typically by minimizing the Hamming distance between the received binary vector and the valid code words. This process loses information about the reliability of each received bit.

*   **Soft-Decision Decoding:** The receiver does not quantize the analog signal to hard bits. Instead, it provides the decoder with a metric that indicates the likelihood of each bit being a 0 or 1. This metric can be the actual analog value, a quantized analog value (e.g., 3 bits per symbol), or a log-likelihood ratio (LLR). The decoder uses this likelihood information to make a more informed decision, typically by minimizing the Euclidean distance.

**Soft-decision decoding generally offers better performance** than hard-decision decoding. By retaining information about the reliability of each received bit, soft-decision decoders can make more accurate decisions, especially at low signal-to-noise ratios (SNRs). The performance gain can be significant, often on the order of 2-3 dB in SNR.

### 8. Important Points to Remember

*   **ML Decoding is Optimal:** It minimizes the probability of error by choosing the code word closest to the received signal in Euclidean distance.
*   **AWGN Channel:** For AWGN, maximizing likelihood is equivalent to minimizing squared Euclidean distance.
*   **Hard vs. Soft Decision:** Soft-decision decoding is always superior to hard-decision decoding in terms of error performance because it preserves more information about the received signal.
*   **Complexity:** Direct ML decoding can be computationally complex, leading to the use of more efficient algorithms in practice.
*   **Syndrome Decoding:** An efficient method for linear block codes that utilizes the parity check matrix to identify error patterns.
*   **Hamming Distance:** Used in hard-decision ML decoding; it measures the number of differing bits.
*   **Euclidean Distance:** Used in soft-decision ML decoding; it measures the geometric distance in the signal space.
