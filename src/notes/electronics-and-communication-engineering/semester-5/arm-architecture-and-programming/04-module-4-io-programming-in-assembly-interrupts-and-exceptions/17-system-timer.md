# ARM Architecture and Programming: Module 4 - I/O Programming in Assembly: Interrupts and Exceptions

## Topic: System Timer

### 1. Introduction to System Timers

System timers are fundamental hardware components in embedded systems, providing the ability to measure time, generate periodic interrupts, and trigger events at precise intervals. In the context of ARM Cortex-M processors, the **SysTick timer** is a dedicated, simple, yet powerful 24-bit down-counting timer, primarily intended for use by the operating system or for general-purpose timing applications.

**Key Concepts:**

*   **Timer:** A hardware circuit that counts up or down at a set frequency.
*   **Periodic Interrupt:** An interrupt that occurs at regular intervals.
*   **Time Measurement:** Using a timer to determine the duration of an event.
*   **Delay Generation:** Using a timer to pause program execution for a specific duration.

*   (Implicitly) Understand how timers can be integrated with interrupt mechanisms.

### 2. The ARM Cortex-M SysTick Timer

The SysTick timer is a core component of the ARM Cortex-M architecture. It's a 24-bit down-counter that can be configured to generate a **System Exception** (specifically, a SysTick exception) when it reaches zero. This exception can be used to implement a periodic interrupt, often for tasks like operating system tick management or general-purpose timing.

**Key Concepts:**

*   **24-bit Down-Counter:** Counts from a loaded value down to zero.
*   **Reload Value:** The value that is loaded into the counter when it reaches zero (or when the timer is enabled, depending on configuration).
*   **System Exception (SysTick Exception):** A specific type of exception generated by the SysTick timer.
*   **System Clock:** The SysTick timer can be clocked by either the processor's internal clock or an external clock source.

**SysTick Timer Registers (as described in Yiu):**

The SysTick timer primarily interacts with the following registers within the NVIC (Nested Vectored Interrupt Controller) and System Control Block:

*   **SysTick Control and Status Register (STCTRL):**
    *   **ENABLE (Bit 0):** Enables/disables the SysTick counter.
    *   **TICKINT (Bit 1):** Enables/disables the SysTick exception request when the COUNTFLAG is asserted.
    *   **CLKSOURCE (Bit 2):** Selects the clock source for the SysTick counter (processor clock or external clock).
    *   **COUNTFLAG (Bit 16):** Indicates whether the counter has been counted to zero since the last read of this register. It's a read-only bit.

*   **SysTick Reload Value Register (STRELOAD):**
    *   This 24-bit register holds the value to be reloaded into the SysTick counter when it reaches zero. The reload value determines the period of the timer.
    *   **IMPORTANT:** Loading a value of 0x000000 into STRELOAD causes the SysTick exception to be generated every 2^24 clock cycles.

*   **SysTick Current Value Register (STCURRENT):**
    *   This 24-bit read-only register holds the current value of the down-counting timer.

*   **SysTick Calibration Register (STCALIB):**
    *   This register provides calibration information, often indicating the value needed to achieve a 10ms interval. It can also indicate if the clock source is reliable.
    *   **NOREF (Bit 31):** If set, the SysTick exception is not generated when the counter is zero (i.e., when TICKINT is cleared).
    *   **SKEW (Bit 30):** Indicates if the 10ms calibration value is accurate.
    *   **TENMS (Bits 23-0):** The reload value for the SysTick timer to achieve a 10ms interval with the processor clock.

**How it Works:**

1.  **Configuration:** The STRELOAD register is loaded with the desired reload value. The STCTRL register is configured: `ENABLE` is set to 1 to start the timer, `TICKINT` is set to 1 to enable the SysTick exception, and `CLKSOURCE` is set to 1 to use the processor clock (common).
2.  **Counting:** The SysTick timer starts counting down from the `STRELOAD` value at each clock cycle.
3.  **Exception Generation:** When the counter reaches zero, the `COUNTFLAG` bit in STCTRL is set to 1. If `TICKINT` is also set to 1, a SysTick exception request is signaled to the NVIC.
4.  **Interrupt Handling:** The NVIC prioritizes and services the SysTick exception. The processor then executes the corresponding SysTick interrupt service routine (ISR).
5.  **Reload:** The `STRELOAD` value is automatically reloaded into the counter when it reaches zero, and the counting process repeats.

**Example:**

Let's say the processor clock is 16 MHz (16,000,000 Hz). If we want a SysTick interrupt every 1 ms:

*   Clock period = 1 / 16,000,000 s = 62.5 ns.
*   Number of clock cycles for 1 ms = 1 ms / 62.5 ns = 0.001 s / 0.0000000625 s = 16,000 cycles.
*   Therefore, we would load `STRELOAD` with 16,000 (0x3E80 in hex).

If we want an interrupt every 10 ms (as suggested by the `TENMS` field in `STCALIB`), and `TENMS` is 16000, then the clock frequency is indeed 16 MHz.

### 3. Programming the SysTick Timer in Assembly

Programming the SysTick timer in assembly involves directly manipulating the control registers.

**Key Concepts:**

*   **Memory-Mapped Registers:** SysTick registers are memory-mapped, meaning they are accessed like memory locations.
*   **LDR (Load Register) and STR (Store Register):** Assembly instructions used to read from and write to memory locations (and therefore registers).
*   **Bit Manipulation:** Using bitwise instructions (e.g., `ORR`, `BIC`) to modify specific bits within registers.

**Assembly Code Example (Conceptual - Specific addresses might vary slightly by MCU):**

Let's assume the SysTick base address is `0xE000E010`.

*   `STCTRL` address: `0xE000E010`
*   `STRELOAD` address: `0xE000E014`
*   `STCURRENT` address: `0xE000E018`

```assembly
    .syntax unified        @ Use unified syntax
    .thumb                 @ Use Thumb instruction set

    .equ STCTRL, 0xE000E010  @ SysTick Control and Status Register
    .equ STRELOAD, 0xE000E014 @ SysTick Reload Value Register
    .equ STCURRENT, 0xE000E018 @ SysTick Current Value Register

    .global SysTick_Init
    .global SysTick_Handler  @ If handling the interrupt here

SysTick_Init:
    @ Disable SysTick timer momentarily to configure
    LDR R0, =STCTRL
    MOV R1, #0              @ Value to disable (clear ENABLE, TICKINT, CLKSOURCE)
    STR R1, [R0]            @ Write 0 to STCTRL

    @ Load the reload value (e.g., for a 16MHz clock, 1ms interrupt)
    @ 16,000,000 Hz / 1000 Hz = 16,000 cycles for 1ms
    LDR R0, =STRELOAD
    MOV R1, #16000          @ Reload value for 1ms at 16MHz
    STR R1, [R0]            @ Write reload value

    @ Configure STCTRL:
    @ Bit 0: ENABLE = 1 (Enable the SysTick counter)
    @ Bit 1: TICKINT = 1 (Enable SysTick exception request)
    @ Bit 2: CLKSOURCE = 1 (Use processor clock)
    @ Other bits are 0 by default or not relevant for basic enable

    LDR R0, =STCTRL
    MOV R1, #0x07           @ Bits 0, 1, 2 set to 1: ENABLE, TICKINT, CLKSOURCE
    STR R1, [R0]            @ Write to STCTRL to enable and set configuration

    BX LR                   @ Return from initialization

SysTick_Handler:
    @ SysTick Interrupt Service Routine (ISR)
    @ This is where your periodic code will run.
    @ For demonstration, let's just toggle an LED or increment a counter.

    @ Save registers used by the handler (if any)
    PUSH {R0-R2, LR}        @ Example: Save registers

    @ --- Your periodic code here ---
    @ Example: Increment a counter
    LDR R1, =tick_counter
    LDR R2, [R1]
    ADD R2, R2, #1
    STR R2, [R1]
    @ --- End of periodic code ---

    @ Clear the SysTick exception by reading STCTRL
    @ The COUNTFLAG bit (bit 16) is automatically cleared on read
    LDR R0, =STCTRL
    LDR R1, [R0]            @ Read STCTRL to clear the pending interrupt

    @ Restore registers
    POP {R0-R2, LR}

    BX LR                   @ Return from exception

    .data
    tick_counter: .word 0   @ A variable to count ticks

```

**Explanation of the Assembly Code:**

1.  **`.equ` Directives:** Define symbolic names for register addresses for readability.
2.  **`SysTick_Init` Function:**
    *   **Disable Timer:** The timer is first disabled by writing 0 to `STCTRL`. This is crucial to avoid unexpected behavior during configuration.
    *   **Load Reload Value:** The desired reload value (e.g., 16000 for 1ms) is loaded into `STRELOAD`.
    *   **Configure and Enable:** The `STCTRL` register is configured.
        *   `0x01` (Bit 0): Enables the counter.
        *   `0x02` (Bit 1): Enables the SysTick exception.
        *   `0x04` (Bit 2): Selects the processor clock.
        *   `0x07` combines these bits.
    *   **`BX LR`:** Returns from the initialization function.
3.  **`SysTick_Handler` Function:**
    *   **`PUSH`:** Saves any registers used within the ISR to the stack to preserve their original state.
    *   **Periodic Code:** This is the core of your time-critical operations. It could involve updating sensor readings, controlling actuators, or managing task scheduling.
    *   **Clear Interrupt:** Reading from the `STCTRL` register automatically clears the `COUNTFLAG` bit, which signals to the NVIC that the SysTick interrupt has been serviced.
    *   **`POP`:** Restores the saved registers from the stack.
    *   **`BX LR`:** Returns from the interrupt handler.
4.  **`.data` Section:** Declares a global variable `tick_counter` to demonstrate that the handler is executing.

**Important Points to Remember:**

*   **NVIC Configuration:** While the SysTick timer generates the exception, the **NVIC** must be configured to enable and set the priority for the SysTick exception. This is typically done through the `NVIC_ISER` (Interrupt Set-Enable Register) and `NVIC_IPR` (Interrupt Priority Register) series, not directly shown in the SysTick code itself.
*   **Reload Value:** The reload value is `MAX_VALUE - desired_interval`. If you want `N` cycles, you load `2^24 - N` (if the timer counts down from `2^24`). However, the common practice is to load `N` and have the timer count from `N` down to 1, generating the interrupt on the transition from 1 to 0. The Cortex-M Technical Reference Manual clarifies that the reload value is loaded when the counter is zero, and the count starts from the loaded value. So, loading `X` will result in `X` cycles.
*   **Clock Source:** Ensure the `CLKSOURCE` bit in `STCTRL` is set correctly based on your system's clock configuration. Using the processor clock (AHB clock) is most common.
*   **Interrupt Priority:** The SysTick exception has a fixed priority level by default, but it can be configured in the NVIC.

### 4. Using the SysTick Timer for Delays and Timing

The SysTick timer is ideal for creating precise software delays and for periodic tasks.

**Key Concepts:**

*   **Software Delay:** Pausing program execution for a specified duration.
*   **Polling:** Continuously checking a flag or status bit for a condition to become true.
*   **Event Timing:** Measuring the time between two events.

**Example 1: Creating a Fixed Delay (Polling Method)**

This method uses the SysTick timer to count down, and the main program polls the `COUNTFLAG` to determine when the delay has elapsed. This is less efficient than using interrupts because it consumes CPU cycles.

```assembly
    .syntax unified
    .thumb

    .equ STCTRL, 0xE000E010
    .equ STRELOAD, 0xE000E014
    .equ STCURRENT, 0xE000E018

    .global DelayMs

DelayMs:
    @ R0 = desired delay in milliseconds

    @ 1. Get the processor clock frequency (assuming it's known or configured elsewhere)
    @ For simplicity, let's assume 16MHz, so 16000 cycles per ms.
    @ In a real system, you'd read this or have it defined.
    MOV R2, #16000          @ Cycles per millisecond (for 16MHz clock)
    MUL R1, R0, R2          @ R1 = total cycles for delay (R0 * R2)

    @ If R1 is 0, the delay is effectively 0 or too large to represent
    CMP R1, #0
    BEQ .exit_delay

    @ 2. Configure SysTick for counting down without interrupt
    LDR R3, =STCTRL
    MOV R4, #0x04           @ CLKSOURCE = 1 (processor clock), TICKINT = 0, ENABLE = 0
    STR R4, [R3]            @ Disable timer and ensure no interrupt

    @ 3. Load the reload value
    LDR R3, =STRELOAD
    STR R1, [R3]            @ Load the calculated delay cycles

    @ 4. Enable the SysTick timer
    MOV R4, #0x05           @ ENABLE = 1, CLKSOURCE = 1 (TICKINT is 0)
    STR R4, [R3]            @ Enable the timer with reload value

    @ 5. Wait for the COUNTFLAG to be set (polling)
.wait_loop:
    LDR R3, =STCTRL         @ Point to STCTRL
    LDR R4, [R3]            @ Read STCTRL
    AND R4, R4, #0x00010000 @ Isolate the COUNTFLAG (bit 16)
    CMP R4, #0
    BNE .delay_done         @ If COUNTFLAG is set (non-zero), exit loop

    B .wait_loop            @ Continue waiting

.delay_done:
    @ 6. Disable the timer and clear the flag
    LDR R3, =STCTRL
    MOV R4, #0              @ Disable the timer completely
    STR R4, [R3]            @ Write 0 to STCTRL

.exit_delay:
    BX LR                   @ Return

```

**Explanation of DelayMs:**

1.  **Calculate Cycles:** The input `R0` (milliseconds) is multiplied by the cycles per millisecond (`R2`) to get the total number of clock cycles for the delay.
2.  **Configure for Polling:** `STCTRL` is configured with `CLKSOURCE=1` (processor clock) and `TICKINT=0` (no interrupt). The timer is initially disabled.
3.  **Load Reload:** The calculated delay in cycles is loaded into `STRELOAD`.
4.  **Enable Timer:** The timer is enabled by setting `ENABLE=1` in `STCTRL`.
5.  **Polling Loop:** The code repeatedly reads `STCTRL` and checks the `COUNTFLAG` (bit 16). When `COUNTFLAG` becomes 1, it means the timer has counted down to zero.
6.  **Disable and Exit:** The timer is disabled, and the function returns.

**Example 2: Using SysTick Interrupt for Periodic Task Execution**

This is the preferred method for many applications as it allows the CPU to perform other tasks while waiting for the timer to expire.

```assembly
    .syntax unified
    .thumb

    .equ STCTRL, 0xE000E010
    .equ STRELOAD, 0xE000E014
    .equ STCURRENT, 0xE000E018

    .equ NVIC_ST_ENABLE, 0xE000E100  @ SysTick exception enable in NVIC (simplified address)
    .equ NVIC_ST_PRIORITY, 0xE000E180 @ SysTick exception priority in NVIC (simplified address)

    .global main
    .global SysTick_Handler

main:
    @ Configure SysTick for periodic interrupt (e.g., 10ms)
    @ Assume 16MHz clock: 16,000,000 / 100 = 160,000 cycles for 10ms
    LDR R0, =STRELOAD
    MOV R1, #160000         @ Reload value for 10ms
    STR R1, [R0]

    LDR R0, =STCTRL
    MOV R1, #0x07           @ ENABLE, TICKINT, CLKSOURCE = 1
    STR R1, [R0]

    @ Configure NVIC for SysTick interrupt (if needed, often default priority is fine)
    @ For a real MCU, you'd use specific NVIC register addresses.
    @ Example: Setting priority to 1 (lower number is higher priority)
    @ LDR R0, =NVIC_ST_PRIORITY
    @ MOV R1, #0x20         @ Assuming priority field is bits 7-5, value 1 (0x20 = 1 << 5)
    @ STR R1, [R0]

    @ Enable SysTick IRQ in NVIC (usually handled by startup file or OS)
    @ LDR R0, =NVIC_ST_ENABLE
    @ MOV R1, #1            @ Enable SysTick IRQ (bit 15 typically)
    @ STR R1, [R0]

    @ Main loop
.main_loop:
    @ Do other tasks here
    WFI                     @ Wait For Interrupt - saves power until an interrupt occurs
    B .main_loop

SysTick_Handler:
    PUSH {R0, LR}           @ Save registers used

    @ --- Code to execute every 10ms ---
    @ Example: Toggle an LED, update a timer variable
    LDR R0, =led_state
    LDR R1, [R0]
    EOR R1, R1, #1          @ Toggle the state
    STR R1, [R0]
    @ --- End of periodic code ---

    POP {R0, LR}            @ Restore registers
    BX LR                   @ Return from exception

    .data
    led_state: .word 0      @ Variable to represent an LED state

```

**Explanation of Periodic Task Example:**

1.  **SysTick Initialization:** Configures the SysTick timer to generate an interrupt at the desired interval (e.g., 10ms).
2.  **NVIC Configuration (Implicit):** Assumes the SysTick interrupt is enabled in the NVIC and has an appropriate priority.
3.  **Main Loop:** The `main` loop continuously executes.
4.  **`WFI` (Wait For Interrupt):** This instruction puts the processor into a low-power state until the next interrupt occurs, saving energy.
5.  **`SysTick_Handler`:** When the SysTick timer generates an interrupt, this handler is executed, performing the time-critical task.

### 5. Practice Questions and Answers

**Question 1:**

What is the primary purpose of the SysTick timer in ARM Cortex-M processors?

**Answer:**
The primary purpose of the SysTick timer is to provide a simple, standardized way to generate periodic system interrupts (SysTick exceptions) and to implement software delays or timing measurements. It's often used by operating systems for task scheduling (tick timer) and by applications for general timing needs.

**Question 2:**

Which register controls the enabling/disabling and clock source selection for the SysTick timer?
a) STRELOAD
b) STCURRENT
c) STCTRL
d) STCALIB

**Answer:**
c) STCTRL (SysTick Control and Status Register)

**Question 3:**

If a Cortex-M processor is running at 72 MHz, and you want the SysTick timer to generate an interrupt every 5 milliseconds, what value should you load into the `STRELOAD` register? Show your calculation.

**Answer:**
*   Processor Clock Frequency = 72 MHz = 72,000,000 Hz
*   Desired Interval = 5 ms = 0.005 seconds
*   Number of clock cycles for the interval = Clock Frequency \* Desired Interval
*   Cycles = 72,000,000 Hz \* 0.005 s = 360,000 cycles

Therefore, you should load `STRELOAD` with `360000` (decimal) or `0x057E40` (hexadecimal).

**Question 4:**

What is the difference between configuring the SysTick timer to generate an interrupt and configuring it to simply count down for a polling-based delay? What are the advantages of the interrupt-driven approach?

**Answer:**
*   **Interrupt-Driven:** `TICKINT` bit in `STCTRL` is set to 1. When the timer reaches zero, it triggers a SysTick exception, and the processor vectors to the `SysTick_Handler` ISR. The main program can continue executing other tasks or enter a low-power state (`WFI`).
*   **Polling-Based:** `TICKINT` bit in `STCTRL` is set to 0. The main program continuously checks the `COUNTFLAG` bit in `STCTRL` until it is set, indicating the timer has expired.

**Advantages of the Interrupt-Driven Approach:**

*   **Efficiency:** The CPU is not tied up constantly checking the timer flag. It can perform other useful work or conserve power.
*   **Responsiveness:** The system can react to other events as soon as they occur, rather than waiting for a polling loop to complete.
*   **Task Scheduling:** Essential for operating systems to manage and switch between different tasks based on time slices.

**Question 5:**

Consider the following assembly snippet for SysTick configuration. What is wrong with this initialization if the goal is to get a periodic interrupt every 1ms on a 16MHz system?

```assembly
    .equ STCTRL, 0xE000E010
    .equ STRELOAD, 0xE000E014

    LDR R0, =STRELOAD
    MOV R1, #1000           @ Reload value for 1ms (assuming 16MHz)
    STR R1, [R0]

    LDR R0, =STCTRL
    MOV R1, #0x05           @ ENABLE, CLKSOURCE = 1, TICKINT = 0
    STR R1, [R0]
```

**Answer:**
The error is in the `STCTRL` configuration. The `TICKINT` bit (Bit 1) is set to `0`, which means the SysTick exception request is **disabled**. To get a periodic interrupt, `TICKINT` must be set to `1`. The `R1` value should be `0x07` (`0x01` for ENABLE + `0x02` for TICKINT + `0x04` for CLKSOURCE).

### 6. Important Points to Remember

*   The SysTick timer is a 24-bit down-counter.
*   It can generate a SysTick exception (interrupt) when it reaches zero if configured to do so (`TICKINT` bit in `STCTRL`).
*   The reload value (`STRELOAD`) determines the period. A reload value of `N` means `N` clock cycles.
*   The `STCALIB` register provides calibration information, particularly for a 10ms interval.
*   Always disable the SysTick timer before reconfiguring its reload value or other settings.
*   For interrupt-driven timing, ensure the SysTick interrupt is enabled in the NVIC and has an appropriate priority.
*   The `WFI` (Wait For Interrupt) instruction is crucial for power efficiency when using interrupt-driven timing.
*   When implementing a polling-based delay, the `COUNTFLAG` bit in `STCTRL` is used to detect timer expiration.
*   The exact memory addresses of SysTick registers might vary slightly between different ARM Cortex-M microcontroller families, but the register names and bit fields are generally consistent. Always refer to the specific MCU's datasheet or reference manual.
