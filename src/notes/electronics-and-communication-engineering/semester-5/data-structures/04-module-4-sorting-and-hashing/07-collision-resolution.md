# Data Structures: Module 4 - Sorting and Hashing

## Topic: Collision Resolution

---

### **1. Introduction to Hashing and Collisions**

*   **Hashing:** A technique used to map keys (e.g., employee IDs, names) to indices in an array (hash table). The goal is to achieve average $O(1)$ time complexity for insertion, deletion, and search operations.
*   **Hash Function ($h(k)$):** A function that takes a key $k$ and computes an index in the hash table. A good hash function distributes keys uniformly across the table.
*   **Collision:** Occurs when two or more different keys map to the same index in the hash table. This is inevitable if the number of possible keys is greater than the size of the hash table.

**Why are collisions a problem?**

If collisions are not handled properly, the benefits of $O(1)$ average access time are lost, and performance can degrade significantly, potentially to $O(n)$ in the worst case (similar to a linked list).

---

### **2. Types of Collision Resolution Techniques**

When a collision occurs, we need a strategy to find an alternative location for the key that caused the collision or to locate the key when searching. The two primary categories of collision resolution techniques are:

*   **Separate Chaining (Open Hashing)**
*   **Open Addressing (Closed Hashing)**

---

### **3. Separate Chaining (Open Hashing)**

*   **Concept:** Each slot in the hash table points to a linked list (or another data structure like a dynamic array or a balanced binary search tree) containing all keys that hash to that slot.
*   **How it works:**
    *   **Insertion:** When a key $k$ is inserted, compute $h(k)$. Traverse the linked list at $h(k)$. If $k$ is not already present, insert it (usually at the head for simplicity).
    *   **Search:** Compute $h(k)$. Traverse the linked list at $h(k)$ to find the key.
    *   **Deletion:** Compute $h(k)$. Traverse the linked list at $h(k)$ and remove the key if found.
*   **Data Structure:** The hash table itself is an array, and each element of the array is a pointer to the head of a linked list.

**Example:**

Let's say we have a hash table of size 10 and the hash function is $h(k) = k \pmod{10}$.
Keys to insert: 12, 22, 35, 42, 55, 67, 88, 91

| Index | Linked List             |
| :---- | :---------------------- |
| 0     |                         |
| 1     | 91 ->                   |
| 2     | 12 -> 22 -> 42 ->       |
| 3     |                         |
| 4     |                         |
| 5     | 35 -> 55 ->             |
| 6     |                         |
| 7     | 67 ->                   |
| 8     | 88 ->                   |
| 9     |                         |

**Analysis:**

*   **Advantages:**
    *   Simple to implement.
    *   The hash table never truly "fills up" as long as memory is available for linked list nodes.
    *   Performance degrades gracefully as the load factor increases.
*   **Disadvantages:**
    *   Requires extra space for the linked list nodes.
    *   Access time can degrade to $O(n)$ in the worst case if all keys hash to the same slot and the linked list becomes very long.
*   **Load Factor ($\alpha$):** Defined as the ratio of the number of keys ($n$) to the table size ($m$): $\alpha = n/m$.
    *   For Separate Chaining, the average length of a linked list is $\alpha$.
    *   Average time complexity for search, insertion, and deletion is $O(1 + \alpha)$.

**Textbook References:**

*   **Horowitz, Sahni, Anderson-Freed:** Discusses separate chaining as a primary method for handling collisions, often using linked lists. (Chapter 7)
*   **Samanta:** Explains separate chaining with an emphasis on its practical implementation using arrays of pointers to linked lists. (Chapter 6)
*   **Gilberg & Forouzan:** Provides clear pseudocode and C implementations for separate chaining. (Chapter 9)

### **4. Open Addressing (Closed Hashing)**

*   **Concept:** All keys are stored directly within the hash table array itself. When a collision occurs, we probe for an alternative empty slot in the table according to a specific probing sequence.
*   **Probing Sequence:** A sequence of indices generated by a probing function when a collision occurs. If $h(k)$ is occupied, we try $h(k, 1), h(k, 2), h(k, 3), \ldots$, where $h(k, i)$ is the $i$-th probe.
*   **Types of Open Addressing:**

#### **4.1. Linear Probing**

*   **Probing Sequence:** $h(k, i) = (h(k) + i) \pmod{m}$, for $i = 0, 1, 2, \ldots, m-1$.
    *   This means if the initial slot $h(k)$ is occupied, we try the next slot, then the next, and so on, wrapping around the table if necessary.
*   **Insertion:** Compute $h(k)$. If the slot is empty, insert the key. If occupied, try $(h(k) + 1) \pmod{m}$, then $(h(k) + 2) \pmod{m}$, until an empty slot is found.
*   **Search:** Compute $h(k)$. If the key is found, return it. If the slot is empty, the key is not in the table. If the slot contains a different key, continue probing using the same sequence until the key is found or an empty slot is encountered.
*   **Deletion:** This is tricky with linear probing. If we simply remove a key from a slot, it might break the search chain for other keys that collided and were placed after it. A common solution is to use a special "deleted" marker instead of truly removing the key.
    *   **"Deleted" Marker:** When deleting a key, mark its slot as "deleted." During search, treat a "deleted" slot as occupied and continue probing. During insertion, a "deleted" slot can be reused.

**Example (Linear Probing):**

Table size $m=10$, $h(k) = k \pmod{10}$.
Keys: 12, 22, 35, 42, 55, 67, 88, 91

1.  **Insert 12:** $h(12) = 2$. Slot 2 is empty. Table: `[_, _, 12, _, _, _, _, _, _, _]`
2.  **Insert 22:** $h(22) = 2$. Slot 2 is occupied by 12. Probe $(2+1)\pmod{10} = 3$. Slot 3 is empty. Table: `[_, _, 12, 22, _, _, _, _, _, _]`
3.  **Insert 35:** $h(35) = 5$. Slot 5 is empty. Table: `[_, _, 12, 22, _, 35, _, _, _, _]`
4.  **Insert 42:** $h(42) = 2$. Slot 2 occupied (12). Probe $(2+1)\pmod{10} = 3$. Slot 3 occupied (22). Probe $(2+2)\pmod{10} = 4$. Slot 4 is empty. Table: `[_, _, 12, 22, 42, 35, _, _, _, _]`
5.  **Insert 55:** $h(55) = 5$. Slot 5 occupied (35). Probe $(5+1)\pmod{10} = 6$. Slot 6 is empty. Table: `[_, _, 12, 22, 42, 35, 55, _, _, _]`
6.  **Insert 67:** $h(67) = 7$. Slot 7 is empty. Table: `[_, _, 12, 22, 42, 35, 55, 67, _, _]`
7.  **Insert 88:** $h(88) = 8$. Slot 8 is empty. Table: `[_, _, 12, 22, 42, 35, 55, 67, 88, _]`
8.  **Insert 91:** $h(91) = 1$. Slot 1 is empty. Table: `[_, 91, 12, 22, 42, 35, 55, 67, 88, _]`

**Problem with Linear Probing: Primary Clustering**

When a collision occurs, the cluster of occupied slots tends to grow. If a new key hashes into any part of a cluster, it will be placed at the end of the cluster, making the cluster even longer. This leads to long probe sequences and degrades performance.

**Analysis (Linear Probing):**

*   **Load Factor ($\alpha$):** For open addressing, $\alpha = n/m$ and $\alpha < 1$.
*   **Performance:** In the worst case, can be $O(n)$. Average performance depends on clustering.
    *   Average successful search: approximately $\frac{1}{2}(1 + \frac{1}{1-\alpha})$ probes.
    *   Average unsuccessful search: approximately $\frac{1}{2}(1 + \frac{1}{(1-\alpha)^2})$ probes.
    *   As $\alpha$ approaches 1, performance degrades sharply. It's recommended to keep $\alpha \le 0.5$.

**Textbook References:**

*   **Horowitz, Sahni, Anderson-Freed:** Explains linear probing and its issues with clustering. (Chapter 7)
*   **Samanta:** Details the mechanism of linear probing, including the deletion problem. (Chapter 6)
*   **Gilberg & Forouzan:** Provides C code for linear probing with a "deleted" marker. (Chapter 9)

#### **4.2. Quadratic Probing**

*   **Probing Sequence:** $h(k, i) = (h(k) + c_1 i + c_2 i^2) \pmod{m}$, for $i = 0, 1, 2, \ldots, m-1$.
    *   Commonly, $c_1 = 0$ and $c_2 = 1$, resulting in $h(k, i) = (h(k) + i^2) \pmod{m}$.
    *   This sequence probes slots further away from the initial hash location.
*   **How it works:** Similar to linear probing, but the step size increases quadratically, helping to alleviate primary clustering.
*   **Insertion/Search/Deletion:** Follows the same logic as linear probing but uses the quadratic probe sequence. Deletion still requires a "deleted" marker.

**Example (Quadratic Probing, $h(k, i) = (h(k) + i^2) \pmod{10}$):**

Table size $m=10$, $h(k) = k \pmod{10}$.
Keys: 12, 22, 35, 42, 55, 67, 88, 91

1.  **Insert 12:** $h(12) = 2$. Slot 2 empty. Table: `[_, _, 12, _, _, _, _, _, _, _]`
2.  **Insert 22:** $h(22) = 2$. Slot 2 occupied (12). Probe $(2+1^2)\pmod{10} = 3$. Slot 3 empty. Table: `[_, _, 12, 22, _, _, _, _, _, _]`
3.  **Insert 35:** $h(35) = 5$. Slot 5 empty. Table: `[_, _, 12, 22, _, 35, _, _, _, _]`
4.  **Insert 42:** $h(42) = 2$. Slot 2 occupied (12). Probe $(2+1^2)\pmod{10} = 3$. Slot 3 occupied (22). Probe $(2+2^2)\pmod{10} = (2+4)\pmod{10} = 6$. Slot 6 empty. Table: `[_, _, 12, 22, _, 35, 42, _, _, _]`
5.  **Insert 55:** $h(55) = 5$. Slot 5 occupied (35). Probe $(5+1^2)\pmod{10} = 6$. Slot 6 occupied (42). Probe $(5+2^2)\pmod{10} = (5+4)\pmod{10} = 9$. Slot 9 empty. Table: `[_, _, 12, 22, _, 35, 42, _, _, 55]`

**Problem with Quadratic Probing: Secondary Clustering**

While quadratic probing resolves primary clustering, it suffers from secondary clustering. If two keys hash to the same initial slot $h(k)$, they will follow the *exact same* probe sequence.

**Analysis (Quadratic Probing):**

*   **Advantages:** Reduces primary clustering compared to linear probing.
*   **Disadvantages:** Suffers from secondary clustering.
*   **Guaranteed Insertion:** To ensure that an insertion always finds an empty slot if one exists, the table size $m$ should be a prime number, and the load factor $\alpha$ should be at most 0.5. This guarantees that at least half of the table slots will be probed.

**Textbook References:**

*   **Horowitz, Sahni, Anderson-Freed:** Discusses quadratic probing and its relation to clustering. (Chapter 7)
*   **Samanta:** Explains the probing sequence and the conditions for guaranteed insertion. (Chapter 6)

#### **4.3. Double Hashing**

*   **Probing Sequence:** $h(k, i) = (h_1(k) + i \cdot h_2(k)) \pmod{m}$, for $i = 0, 1, 2, \ldots, m-1$.
    *   $h_1(k)$ is the primary hash function.
    *   $h_2(k)$ is a secondary hash function, which must be carefully chosen.
*   **How it works:** The step size ($h_2(k)$) is determined by the key itself. This drastically reduces both primary and secondary clustering because keys that hash to the same initial slot will likely have different $h_2(k)$ values, leading to different probe sequences.
*   **Insertion/Search/Deletion:** Follows the same logic as other open addressing methods but uses the double hashing probe sequence. Deletion requires a "deleted" marker.

**Requirements for $h_2(k)$:**

1.  $h_2(k)$ should never return 0. If $h_2(k)=0$, the probe sequence becomes constant: $h_1(k), h_1(k), \ldots$, and no other slots are probed.
2.  $h_2(k)$ should be relatively prime to the table size $m$. This ensures that all $m$ slots are eventually probed if necessary. A common way to achieve this is to choose $m$ to be a prime number and ensure $1 \le h_2(k) < m$.
    *   A typical choice for $h_2(k)$ is $h_2(k) = R - (k \pmod{R})$, where $R$ is a prime number smaller than $m$.

**Example (Double Hashing):**

Table size $m=11$ (a prime).
$h_1(k) = k \pmod{11}$
$h_2(k) = 7 - (k \pmod{7})$

Keys: 12, 22, 35, 42, 55, 67, 88, 91

1.  **Insert 12:**
    *   $h_1(12) = 12 \pmod{11} = 1$. Slot 1 empty.
    *   Table: `[_, 12, _, _, _, _, _, _, _, _, _]`
2.  **Insert 22:**
    *   $h_1(22) = 22 \pmod{11} = 0$. Slot 0 empty.
    *   Table: `[22, 12, _, _, _, _, _, _, _, _, _]`
3.  **Insert 35:**
    *   $h_1(35) = 35 \pmod{11} = 2$. Slot 2 empty.
    *   Table: `[22, 12, 35, _, _, _, _, _, _, _, _]`
4.  **Insert 42:**
    *   $h_1(42) = 42 \pmod{11} = 9$. Slot 9 empty.
    *   Table: `[22, 12, 35, _, _, _, _, _, _, 42, _]`
5.  **Insert 55:**
    *   $h_1(55) = 55 \pmod{11} = 0$. Slot 0 occupied (22).
    *   $h_2(55) = 7 - (55 \pmod{7}) = 7 - 6 = 1$.
    *   Probe 1: $(h_1(55) + 1 \cdot h_2(55)) \pmod{11} = (0 + 1 \cdot 1) \pmod{11} = 1$. Slot 1 occupied (12).
    *   Probe 2: $(h_1(55) + 2 \cdot h_2(55)) \pmod{11} = (0 + 2 \cdot 1) \pmod{11} = 2$. Slot 2 occupied (35).
    *   Probe 3: $(h_1(55) + 3 \cdot h_2(55)) \pmod{11} = (0 + 3 \cdot 1) \pmod{11} = 3$. Slot 3 empty.
    *   Table: `[22, 12, 35, 55, _, _, _, _, _, 42, _]`
6.  **Insert 67:**
    *   $h_1(67) = 67 \pmod{11} = 1$. Slot 1 occupied (12).
    *   $h_2(67) = 7 - (67 \pmod{7}) = 7 - 4 = 3$.
    *   Probe 1: $(h_1(67) + 1 \cdot h_2(67)) \pmod{11} = (1 + 1 \cdot 3) \pmod{11} = 4$. Slot 4 empty.
    *   Table: `[22, 12, 35, 55, 67, _, _, _, _, 42, _]`
7.  **Insert 88:**
    *   $h_1(88) = 88 \pmod{11} = 0$. Slot 0 occupied (22).
    *   $h_2(88) = 7 - (88 \pmod{7}) = 7 - 4 = 3$.
    *   Probe 1: $(h_1(88) + 1 \cdot h_2(88)) \pmod{11} = (0 + 1 \cdot 3) \pmod{11} = 3$. Slot 3 occupied (55).
    *   Probe 2: $(h_1(88) + 2 \cdot h_2(88)) \pmod{11} = (0 + 2 \cdot 3) \pmod{11} = 6$. Slot 6 empty.
    *   Table: `[22, 12, 35, 55, 67, _, 88, _, _, 42, _]`
8.  **Insert 91:**
    *   $h_1(91) = 91 \pmod{11} = 3$. Slot 3 occupied (55).
    *   $h_2(91) = 7 - (91 \pmod{7}) = 7 - 0 = 7$.
    *   Probe 1: $(h_1(91) + 1 \cdot h_2(91)) \pmod{11} = (3 + 1 \cdot 7) \pmod{11} = 10$. Slot 10 empty.
    *   Table: `[22, 12, 35, 55, 67, _, 88, _, _, 42, 91]`

**Analysis (Double Hashing):**

*   **Advantages:** Generally provides the best performance among open addressing methods due to minimal clustering.
*   **Disadvantages:** Requires designing two good hash functions, which can be complex. Performance is still sensitive to the load factor and the quality of hash functions.
*   **Performance:** Close to ideal $O(1)$ on average for both successful and unsuccessful searches, provided the hash functions are well-chosen and the load factor is reasonable.

**Textbook References:**

*   **Horowitz, Sahni, Anderson-Freed:** Introduces double hashing as a method to combat clustering. (Chapter 7)
*   **Samanta:** Provides a detailed explanation of double hashing and the criteria for selecting the secondary hash function. (Chapter 6)
*   **Aho, Hopcroft, Ullman:** Discusses various collision resolution strategies, including double hashing, from a theoretical perspective. (Chapter 5)

### **5. Choosing a Hash Function and Table Size**

*   **Hash Function Properties:**
    *   **Deterministic:** Always produces the same output for the same input.
    *   **Uniform Distribution:** Distributes keys evenly across the table to minimize collisions.
    *   **Efficiency:** Computes quickly.
    *   **Key Range:** Should handle the range of keys encountered.
*   **Common Hash Functions:**
    *   **Division Method:** $h(k) = k \pmod{m}$. Simple and effective if $m$ is chosen carefully.
    *   **Multiplication Method:** $h(k) = \lfloor m(kA \pmod{1}) \rfloor$, where $A$ is a constant between 0 and 1 (e.g., Knuth's suggestion $A \approx (\sqrt{5}-1)/2$).
    *   **Universal Hashing:** A family of hash functions from which one is chosen randomly. Provides theoretical guarantees against worst-case inputs.
*   **Table Size ($m$):**
    *   **Prime Numbers:** Using a prime number for $m$ is often beneficial, especially with the division method and double hashing, as it helps in distributing keys more evenly and in ensuring that probe sequences cover more slots.
    *   **Load Factor ($\alpha$):** Keep $\alpha$ reasonably low. For open addressing, $\alpha \le 0.5$ is a good rule of thumb. For separate chaining, $\alpha \approx 1$ is usually acceptable.
    *   **Resizing:** If the load factor becomes too high, the hash table can be resized (typically doubled and a new prime size chosen) and all existing elements rehashed into the new table. This is an expensive operation but maintains good performance.

**Answer 2:**

The primary advantage of Double Hashing is that it **minimizes both primary and secondary clustering**.
*   **Linear Probing:** Suffers from primary clustering, where contiguous blocks of occupied cells form and grow, leading to long probe sequences.
*   **Quadratic Probing:** Eliminates primary clustering but suffers from secondary clustering, where keys that hash to the same initial location follow the same probe sequence.
*   **Double Hashing:** Uses a secondary hash function to determine the step size for probing. This means keys that hash to the same initial location will likely have different step sizes, resulting in different probe sequences. This significantly reduces clustering and leads to a more uniform distribution of probes, approaching the ideal $O(1)$ performance more closely.

**Answer 3:**

The "deleted" marker concept is used in **open addressing** collision resolution techniques (like linear probing, quadratic probing, and double hashing) to handle deletions.

*   **Why it's necessary:** When a key is deleted, if its slot is simply marked as empty, it can break the probe sequence for other keys that were inserted later and collided with the deleted key's original hash location. A search for these later keys might stop prematurely at the now-empty slot, incorrectly concluding the key is not present.
*   **Implications:**
    *   **Search:** When searching for a key, a "deleted" slot is treated as if it were occupied. The search continues probing until the key is found or an truly empty slot is encountered.
    *   **Insertion:** A "deleted" slot can be treated as an empty slot. An insertion operation can overwrite a "deleted" marker with the new key, effectively reusing the space.

This mechanism ensures the integrity of search operations while allowing for the reuse of slots that previously held deleted elements. However, over time, a table with many deletions and insertions might contain many "deleted" markers, which can still slow down searches slightly, though less so than a full cluster.

### **8. Important Points to Remember**

*   **Collisions are unavoidable** in hashing if the number of possible keys exceeds the table size.
*   **Collision resolution techniques** are crucial for maintaining the efficiency of hash tables.
*   **Separate Chaining** uses auxiliary data structures (like linked lists) at each table slot. Performance is $O(1 + \alpha)$.
*   **Open Addressing** stores all keys within the table array, probing for empty slots on collision. Performance depends heavily on the load factor and clustering.
*   **Primary Clustering** (Linear Probing): Clusters of occupied cells grow, increasing probe lengths.
*   **Secondary Clustering** (Quadratic Probing): Keys hashing to the same initial slot follow the same probe sequence.
*   **Double Hashing** minimizes clustering by using a key-dependent step size, offering the best performance among open addressing methods.
*   **Load Factor ($\alpha$)** is critical: keep it low for open addressing ($\le 0.5$ recommended) and manage it for separate chaining.
*   **Table size ($m$)** should ideally be a prime number, especially for the division method and double hashing.
*   **Deletion in Open Addressing** requires a special "deleted" marker to maintain search path integrity.
*   **Choosing a good hash function** is paramount for uniform distribution and efficiency.
