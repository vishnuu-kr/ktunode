## Module 4: Advanced Features of Java - Event Handling in Swings

This module delves into the core of interactive Java applications by exploring **Event Handling in Swings**. Understanding how to respond to user actions is crucial for creating dynamic and user-friendly graphical interfaces.

**Course Outcomes Addressed:**

*   **CO4 (K3):** Identify and utilize various Swing controls, components, and containers. (While this module focuses on event handling, it builds upon the knowledge of Swing components acquired previously.)

**1. Introduction to Event Handling**

Event handling is the mechanism by which a program responds to user interactions or other occurrences within the system. In GUI programming, events are typically generated by user actions such as mouse clicks, key presses, or window manipulations.

*   **What is an Event?**
    An **event** is a signal to the program that something has happened. In Swing, events are objects that represent these occurrences.
    *   *Example:* Clicking a button, typing in a text field, closing a window.

*   **What is Event Handling?**
    **Event handling** is the process of detecting and responding to these events. It involves identifying the source of the event and executing specific code (an event handler) to manage the event.

*   **Event-Driven Programming:**
    GUI applications are often characterized by **event-driven programming**. This means the program's flow is determined by events. Instead of executing a predefined sequence of operations, the program waits for events to occur and then responds accordingly.

**2. The Java Event Handling Model**

Java's event handling model is based on the **Delegation Event Model**. This model involves three key participants:

*   **Event Source:** The component that generates the event.
    *   *Example:* A `JButton`, a `JTextField`.

*   **Event Listener:** An object that "listens" for specific types of events from an event source. It contains the methods that will be executed when an event occurs.

*   **Event Object:** An object that encapsulates information about the event that occurred. This object is passed to the event listener's methods.
    *   *Example:* `ActionEvent`, `MouseEvent`, `KeyEvent`.

**Important Point:** The event listener receives the event and takes the appropriate action. The event source "delegates" the responsibility of handling the event to the listener.

**3. Event Classes and Interfaces**

Swing provides a rich set of event classes and interfaces within the `java.awt.event` and `javax.swing.event` packages.

*   **`java.awt.event.ActionEvent`:**
    *   Represents an action event, typically generated by clicking a button, selecting a menu item, or pressing the Enter key in a text field.
    *   Key methods:
        *   `getSource()`: Returns the object that generated the event.
        *   `getActionCommand()`: Returns the string command associated with the event (e.g., the text on a button).

*   **`java.awt.event.MouseEvent`:**
    *   Represents mouse events like clicks, movements, and drags.
    *   Key methods:
        *   `getX()`, `getY()`: Returns the x and y coordinates of the mouse event relative to the component.
        *   `getClickCount()`: Returns the number of mouse clicks.
        *   `getButton()`: Returns which mouse button was pressed (e.g., `MouseEvent.BUTTON1`).

*   **`java.awt.event.KeyEvent`:**
    *   Represents keyboard events like key presses and releases.
    *   Key methods:
        *   `getKeyCode()`: Returns the numeric code of the key pressed.
        *   `getKeyChar()`: Returns the character representation of the key.
        *   `isShiftDown()`, `isControlDown()`: Check if modifier keys are pressed.

*   **`java.awt.event.WindowAdapter` and `java.awt.event.WindowEvent`:**
    *   Used for handling window events (e.g., opening, closing, activating).
    *   `WindowAdapter` is an abstract class providing default implementations for all `WindowListener` methods, making it convenient to override only the methods you need.

**4. Implementing Event Listeners**

There are several ways to implement event listeners in Swing:

*   **Using a Separate Class (Inner Class or Standalone):**
    You can create a separate class that implements the appropriate listener interface.

    ```java
    import javax.swing.*;
    import java.awt.event.*;
    import java.awt.*;

    // Standalone listener class
    class MyButtonListener implements ActionListener {
        @Override
        public void actionPerformed(ActionEvent e) {
            System.out.println("Button clicked!");
        }
    }

    public class EventHandlingExample1 extends JFrame implements ActionListener { // Implementing ActionListener directly

        JButton button;

        public EventHandlingExample1() {
            setTitle("Event Handling Example 1");
            setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            setSize(300, 200);
            setLayout(new FlowLayout());

            button = new JButton("Click Me");
            button.addActionListener(this); // 'this' refers to the JFrame which is also an ActionListener

            add(button);
            setVisible(true);
        }

        @Override
        public void actionPerformed(ActionEvent e) {
            System.out.println("Button clicked from JFrame!");
        }

        public static void main(String[] args) {
            new EventHandlingExample1();
        }
    }
    ```

    *   **Advantages:** Good for complex event handling logic, promotes code organization.
    *   **Disadvantages:** Can lead to a proliferation of small classes.

*   **Using an Inner Class:**
    An inner class is defined within another class. It has access to the outer class's members.

    ```java
    import javax.swing.*;
    import java.awt.event.*;
    import java.awt.*;

    public class EventHandlingExample2 extends JFrame {

        JButton button;

        public EventHandlingExample2() {
            setTitle("Event Handling Example 2");
            setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            setSize(300, 200);
            setLayout(new FlowLayout());

            button = new JButton("Click Me");
            button.addActionListener(new ButtonHandler()); // Inner class as listener

            add(button);
            setVisible(true);
        }

        // Inner class implementation
        class ButtonHandler implements ActionListener {
            @Override
            public void actionPerformed(ActionEvent e) {
                System.out.println("Button clicked from inner class!");
            }
        }

        public static void main(String[] args) {
            new EventHandlingExample2();
        }
    }
    ```

    *   **Advantages:** Tightly couples the listener to the component it serves, can access outer class members directly.
    *   **Disadvantages:** Can increase the complexity of the outer class if too many inner classes are used.

*   **Using an Anonymous Inner Class:**
    This is a concise way to create a listener inline, often used for simple event handlers.

    ```java
    import javax.swing.*;
    import java.awt.event.*;
    import java.awt.*;

    public class EventHandlingExample3 extends JFrame {

        JButton button;

        public EventHandlingExample3() {
            setTitle("Event Handling Example 3");
            setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            setSize(300, 200);
            setLayout(new FlowLayout());

            button = new JButton("Click Me");
            button.addActionListener(new ActionListener() { // Anonymous inner class
                @Override
                public void actionPerformed(ActionEvent e) {
                    System.out.println("Button clicked from anonymous inner class!");
                }
            });

            add(button);
            setVisible(true);
        }

        public static void main(String[] args) {
            new EventHandlingExample3();
        }
    }
    ```

    *   **Advantages:** Very concise for simple event handling, keeps the listener code close to where it's registered.
    *   **Disadvantages:** Can become unreadable for complex logic.

*   **Using Lambda Expressions (Java 8 and later):**
    For functional interfaces (interfaces with a single abstract method), lambda expressions provide an even more concise syntax. `ActionListener` is a functional interface.

    ```java
    import javax.swing.*;
    import java.awt.event.*;
    import java.awt.*;

    public class EventHandlingExample4 extends JFrame {

        JButton button;

        public EventHandlingExample4() {
            setTitle("Event Handling Example 4");
            setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            setSize(300, 200);
            setLayout(new FlowLayout());

            button = new JButton("Click Me");
            button.addActionListener(e -> System.out.println("Button clicked from lambda expression!")); // Lambda expression

            add(button);
            setVisible(true);
        }

        public static void main(String[] args) {
            new EventHandlingExample4();
        }
    }
    ```

    *   **Advantages:** Extremely concise, modern Java approach, highly readable for simple actions.
    *   **Disadvantages:** Only applicable to functional interfaces.

**5. Registering Event Listeners**

To make an event handler work, you must **register** the listener with the event source. This is done using methods like `addActionListener()`, `addMouseListener()`, etc., provided by the Swing components.

*   **Syntax:** `eventSource.add<EventType>Listener(eventListener);`
    *   `eventSource`: The component generating the event (e.g., `button`, `textField`).
    *   `add<EventType>Listener()`: The method to register the listener.
    *   `eventListener`: The object implementing the listener interface.

**6. Event Adapters**

Many listener interfaces have multiple methods. If you only need to handle one or two specific events, implementing the entire interface can be cumbersome. **Event adapter classes** provide default implementations for all methods in a listener interface. You can then extend an adapter class and override only the methods you need.

*   **Example: `WindowAdapter`**
    The `WindowListener` interface has seven methods. To handle only window closing, you can extend `WindowAdapter` and override `windowClosing()`.

    ```java
    import javax.swing.*;
    import java.awt.event.*;
    import java.awt.*;

    public class EventHandlingExample5 extends JFrame {

        public EventHandlingExample5() {
            setTitle("Event Handling Example 5");
            setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE); // Prevent default close operation
            setSize(300, 200);
            setLayout(new FlowLayout());

            // Anonymous inner class extending WindowAdapter
            addWindowListener(new WindowAdapter() {
                @Override
                public void windowClosing(WindowEvent e) {
                    System.out.println("Window is closing!");
                    // Perform cleanup or save data before exiting
                    System.exit(0);
                }
            });

            setVisible(true);
        }

        public static void main(String[] args) {
            new EventHandlingExample5();
        }
    }
    ```

**7. Handling Different Event Types**

*   **`ActionListener`:** For actions like button clicks, menu selections.
*   **`MouseListener`:** For mouse events (press, release, enter, exit, click).
    *   `mouseClicked(MouseEvent e)`
    *   `mousePressed(MouseEvent e)`
    *   `mouseReleased(MouseEvent e)`
    *   `mouseEntered(MouseEvent e)`
    *   `mouseExited(MouseEvent e)`
*   **`MouseMotionListener`:** For mouse movement (drag, move).
    *   `mouseDragged(MouseEvent e)`
    *   `mouseMoved(MouseEvent e)`
*   **`KeyListener`:** For keyboard events (press, release, type).
    *   `keyPressed(KeyEvent e)`
    *   `keyReleased(KeyEvent e)`
    *   `keyTyped(KeyEvent e)`
*   **`ItemListener`:** For changes in item selection (e.g., checkboxes, list items).
    *   `itemStateChanged(ItemEvent e)`
*   **`TextListener`:** For changes in text fields.
    *   `textValueChanged(TextEvent e)`

**8. Event Propagation and Filtering (Advanced Concept)**

While not explicitly detailed in basic Swing event handling, it's worth noting that events can propagate through the component hierarchy. For more advanced scenarios, Java provides mechanisms for event filtering, allowing you to intercept and process events before they reach their intended listeners. This is often handled through EventDispatchThread (EDT) considerations and custom event dispatching.

**Key Points to Remember:**

*   **Delegation Event Model:** Event Source, Event Listener, Event Object.
*   **Registering Listeners:** Use `add<EventType>Listener()` methods.
*   **Listener Interfaces:** Implement the appropriate interface (e.g., `ActionListener`, `MouseListener`).
*   **Event Adapters:** Useful for handling only a subset of events from an interface.
*   **Anonymous Inner Classes and Lambda Expressions:** Concise ways to implement simple listeners.
*   **Event Objects:** Carry information about the event (source, type, details).
*   **`java.awt.event` and `javax.swing.event`:** Packages containing event-related classes and interfaces.

**Practice Questions:**

1.  **Explain the three main components of Java's Delegation Event Model.**
    *   **Answer:**
        1.  **Event Source:** The component that generates the event.
        2.  **Event Listener:** An object that receives events from the source and contains the methods to handle them.
        3.  **Event Object:** An object that encapsulates information about the event.

2.  **What is the purpose of an `ActionListener` interface? Provide an example of a component that typically generates `ActionEvent`s.**
    *   **Answer:** The `ActionListener` interface is used to handle action events. A common component that generates `ActionEvent`s is a `JButton` when it is clicked.

3.  **Describe two different ways to implement an event listener in Java Swing, highlighting a key advantage of each.**
    *   **Answer:**
        *   **Anonymous Inner Class:** A concise way to implement a listener inline, ideal for simple event handlers.
        *   **Lambda Expression (Java 8+):** An even more concise syntax for functional interfaces, suitable for simple, single-method implementations.

4.  **How would you register a `MouseListener` with a `JPanel` named `myPanel`?**
    *   **Answer:**
        ```java
        myPanel.addMouseListener(new MouseAdapter() { // Using an anonymous inner class extending MouseAdapter
            @Override
            public void mouseClicked(MouseEvent e) {
                System.out.println("Panel clicked at: " + e.getX() + ", " + e.getY());
            }
        });
        ```

5.  **When would you use an `Event Adapter` class instead of implementing a listener interface directly?**
    *   **Answer:** You would use an event adapter class when you only need to handle a few specific events from an interface that has many methods. The adapter provides default implementations for all methods, allowing you to override only the ones you need, reducing boilerplate code.
