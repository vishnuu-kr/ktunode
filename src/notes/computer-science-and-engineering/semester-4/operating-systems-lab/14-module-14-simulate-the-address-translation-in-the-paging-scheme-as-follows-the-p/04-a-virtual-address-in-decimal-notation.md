# OPERATING SYSTEMS LAB - Module 14: Paging Simulation (Address Translation)

**Topic:** Simulate the address translation in the paging scheme. Program receives three command line arguments: virtual address (decimal).

**Learning Outcomes:**

*   Understand the concept of paging in operating systems.
*   Learn how virtual addresses are translated to physical addresses using page tables.
*   Implement a simple paging simulation program that takes a virtual address as input and translates it to a physical address.
*   Understand the role of command-line arguments in program execution.

## 1. Introduction to Paging

*   **Definition:** Paging is a memory management technique that divides both physical memory (RAM) and logical memory (process address space) into fixed-size blocks.
    *   **Frames:** Blocks of physical memory are called frames.
    *   **Pages:** Blocks of logical memory are called pages.
*   **Purpose:**
    *   Eliminates external fragmentation (contiguous memory allocation issues).
    *   Allows non-contiguous allocation of process memory.
    *   Supports virtual memory, allowing processes to execute even if their entire address space is not physically present in memory.

## 2. Key Concepts and Definitions

*   **Virtual Address (Logical Address):** The address generated by the CPU during program execution.  This is the address that the program "thinks" it's using.
*   **Physical Address:** The actual address in physical memory (RAM) where the data or instruction is stored.
*   **Page Table:** A data structure used by the operating system to translate virtual addresses to physical addresses.  Each process has its own page table.
*   **Page Number:** The higher-order bits of a virtual address, used as an index into the page table.
*   **Offset:** The lower-order bits of a virtual address, representing the displacement within the page/frame.  The offset remains the same during translation.
*   **Frame Number:** The entry in the page table corresponding to a given page number. This represents the physical frame number where the page is stored.
*   **Page Size:** The size of each page and frame, which is typically a power of 2 (e.g., 4KB).
*   **Translation Lookaside Buffer (TLB):** A cache that stores recent virtual-to-physical address translations to speed up the translation process. Not covered in this simple simulation.
*   **Page Fault:** An exception that occurs when the CPU tries to access a page that is not currently in physical memory.

## 3. Address Translation Process

1.  **Virtual Address Decomposition:**  The virtual address is divided into two parts: the page number and the offset.

2.  **Page Table Lookup:** The page number is used as an index into the page table. The entry at that index contains the corresponding frame number (if the page is valid and present in memory).

3.  **Address Calculation:** The frame number from the page table is combined with the offset from the virtual address to form the physical address.

   `Physical Address = (Frame Number << Offset Bits) + Offset`
   Where `Offset Bits = log2(Page Size)`

4.  **Page Fault Handling:** If the page table entry indicates that the page is not present in memory (invalid bit set, or page table entry points to disk), a page fault occurs.  The operating system then retrieves the page from secondary storage (e.g., disk) and loads it into a free frame in physical memory. The page table is updated, and the instruction that caused the page fault is re-executed.

## 4. Command-Line Arguments

*   **Purpose:** Allows passing information to a program when it is executed.
*   **Mechanism:** When a program is executed from the command line, the operating system passes the command-line arguments to the program as an array of strings.
*   **C/C++:**
    *   `int main(int argc, char *argv[])`
    *   `argc`: The number of command-line arguments (including the program name itself).
    *   `argv`: An array of strings, where `argv[0]` is the program name, `argv[1]` is the first argument, `argv[2]` is the second argument, and so on.

## 5. Simulation Implementation (Simplified Example in C)

**Assumptions:**

*   Fixed page size (e.g., 4KB = 4096 bytes).
*   Simplified page table representation (an array).
*   All pages are initially assumed to be present in memory (no page fault handling in this basic example).
*   Small number of pages/frames for illustration purposes.

```c
#include <stdio.h>
#include <stdlib.h>

// Define constants
#define PAGE_SIZE 4096   // 4KB page size
#define NUM_PAGES 16      // Number of virtual pages
#define NUM_FRAMES 8      // Number of physical frames

// Global Page Table (Simplified)
int page_table[NUM_PAGES];

// Function to initialize the page table
void initialize_page_table() {
    // Initialize with a simple mapping (e.g., page i maps to frame i % NUM_FRAMES)
    for (int i = 0; i < NUM_PAGES; i++) {
        page_table[i] = i % NUM_FRAMES; // Mapping virtual page to physical frame
    }
}

// Function to translate a virtual address to a physical address
unsigned int translate_address(unsigned int virtual_address) {
    // Extract the page number and offset
    unsigned int page_number = virtual_address / PAGE_SIZE;
    unsigned int offset = virtual_address % PAGE_SIZE;

    // Check if the page number is valid
    if (page_number >= NUM_PAGES) {
        printf("Error: Invalid virtual address (page number out of range).\n");
        return -1; // Indicate an error
    }

    // Get the frame number from the page table
    unsigned int frame_number = page_table[page_number];

    // Calculate the physical address
    unsigned int physical_address = (frame_number * PAGE_SIZE) + offset;

    return physical_address;
}

int main(int argc, char *argv[]) {
    // Check if the correct number of arguments is provided
    if (argc != 2) {
        printf("Usage: %s <virtual_address>\n", argv[0]);
        return 1; // Indicate an error
    }

    // Initialize the page table
    initialize_page_table();

    // Get the virtual address from the command-line argument
    unsigned int virtual_address = atoi(argv[1]);

    // Translate the virtual address
    unsigned int physical_address = translate_address(virtual_address);

    // Print the results
    if (physical_address != (unsigned int)-1) {
        printf("Virtual Address: %u\n", virtual_address);
        printf("Physical Address: %u\n", physical_address);
    }

    return 0;
}
```

**Explanation:**

1.  **Includes:**  Standard C libraries for input/output and string conversion.
2.  **Constants:** `PAGE_SIZE`, `NUM_PAGES`, `NUM_FRAMES` define the system parameters.
3.  **`page_table`:** A global array representing the page table.  In a real OS, this would be more complex and managed per process.  This simplified version just uses an integer array.
4.  **`initialize_page_table()`:**  Sets up a basic mapping between virtual pages and physical frames. The mapping here is intentionally simple for demonstration.  In a real system, the OS would manage this based on memory availability.
5.  **`translate_address()`:**
    *   Calculates the page number and offset from the virtual address.
    *   Checks if the page number is within valid bounds.
    *   Looks up the frame number in the `page_table`.
    *   Calculates the physical address by combining the frame number and offset.
    *   Includes basic error checking for invalid virtual addresses.
6.  **`main()`:**
    *   Handles command-line arguments.
    *   Converts the virtual address from a string to an unsigned integer using `atoi()`.
    *   Calls `translate_address()` to perform the translation.
    *   Prints the virtual and physical addresses (or an error message).

**Compilation and Execution:**

1.  Save the code as `paging_sim.c`.
2.  Compile: `gcc paging_sim.c -o paging_sim`
3.  Run: `./paging_sim 8192`  (where 8192 is the virtual address you want to translate)

**Important Notes:**

*   This is a *very* simplified simulation.  It lacks:
    *   Page fault handling.
    *   More realistic page table structures (e.g., with valid/invalid bits).
    *   Memory management (allocation/deallocation of frames).
    *   TLB.
*   Real-world operating systems implement paging in a much more sophisticated way.
*   The command-line argument `argv[1]` is a *string*.  You must convert it to an integer using `atoi()` or `strtol()` before using it as a numeric value.

## 6. Practice Questions/Exercises

1.  **Question:** What is the purpose of paging in an operating system?

    **Answer:** To eliminate external fragmentation, allow non-contiguous memory allocation, and support virtual memory.

2.  **Question:** Define virtual address and physical address.

    **Answer:** Virtual address is the address generated by the CPU, while the physical address is the actual location in physical memory.

3.  **Question:** What is a page table, and what is its role in address translation?

    **Answer:** A page table is a data structure that maps virtual pages to physical frames, enabling the translation of virtual addresses to physical addresses.

4.  **Question:** Given a virtual address of 10240 (decimal), a page size of 4096 bytes, and a page table entry that maps virtual page 2 to physical frame 5, what is the physical address?

    **Answer:**
    *   Page number = 10240 / 4096 = 2
    *   Offset = 10240 % 4096 = 2048
    *   Frame number = 5 (from the page table)
    *   Physical address = (5 * 4096) + 2048 = 20480 + 2048 = 22528

    *   Allow the user to specify the page size as a command-line argument.
