## Operating Systems Lab: Module 14 - Paging Simulation (Virtual Address Space Size)

**Objective:** Simulate address translation in the paging scheme, focusing on the impact of the virtual address space size.

**Learning Outcomes:**

*   Understand the paging memory management scheme.
*   Simulate address translation from virtual to physical addresses using paging.
*   Understand the relationship between the virtual address space size, page size, and number of page table entries.
*   Implement a program to accept the size of the virtual address space (in MB) as a command-line argument and perform preliminary calculations for address translation.
*   Identify and handle potential errors related to invalid inputs (e.g., non-numeric input, invalid virtual address space sizes).

**1. Key Concepts and Definitions:**

*   **Paging:** A memory management scheme that divides both physical memory (RAM) and virtual memory into fixed-size blocks called *frames* and *pages*, respectively.  Pages are stored in frames.
*   **Virtual Address Space:** The logical view of memory presented to a process. It's the range of addresses the program uses.  In this simulation, the size of the virtual address space is provided in megabytes (MB).
*   **Physical Address Space:** The actual range of physical memory addresses available in the system.
*   **Virtual Address:** The address generated by the CPU.
*   **Physical Address:** The actual address in RAM where the data is located.
*   **Page Table:** A data structure used by the operating system to store the mapping between virtual pages and physical frames. Each entry in the page table maps a single virtual page to its corresponding frame in physical memory (or indicates that the page is not currently in physical memory).
*   **Page Size:**  The fixed size of a page and a frame.  Common sizes are 4KB (2^12 bytes), 8KB, 16KB, etc. This is *critical* for address translation.
*   **Page Offset:** The portion of the virtual address that identifies the location of a byte within a page.  If the page size is 2^n bytes, the last 'n' bits of the virtual address form the page offset.
*   **Page Number (Virtual Page Number - VPN):** The portion of the virtual address that identifies the page. This is used as an index into the page table.
*   **Frame Number (Physical Frame Number - PFN):** The portion of the physical address that identifies the frame in physical memory where the page is stored.

**2. Address Translation with Paging:**

The basic process of translating a virtual address to a physical address involves the following steps:

1.  **Divide the virtual address:** The virtual address is divided into two parts: the page number (VPN) and the page offset.
2.  **Use the page number as an index:** The page number is used as an index into the page table.
3.  **Retrieve the frame number:** The page table entry corresponding to the page number contains the frame number (PFN).
4.  **Combine the frame number and page offset:**  The frame number is combined with the page offset to form the physical address.

**Example:**

Let's say we have:

*   Virtual Address: 0x12345678
*   Page Size: 4KB (4096 bytes or 2^12 bytes)

1.  **Virtual Address in Binary:** 00010010 00110100 01010110 01111000
2.  **Page Offset (last 12 bits):** 0110 01111000 (0x678)
3.  **Page Number (remaining bits):** 00010010 00110100 0101 (0x12345)
4.  **Assume Page Table Entry for Page 0x12345 contains Frame Number 0xABC:**
5.  **Physical Address:** (Frame Number << 12) | Page Offset  => (0xABC << 12) | 0x678 => 0xABC000 + 0x678 = 0xABC0678

**3. Relationship between Virtual Address Space, Page Size, and Page Table Size:**

*   **Virtual Address Space Size (V):** Determines the maximum address a process can use.  Given in MB (Megabytes).
*   **Page Size (P):** Affects internal fragmentation (smaller pages reduce fragmentation but increase page table size).
*   **Number of Pages (N):**  V / P.  This determines the number of entries required in the page table.
*   **Page Table Size (T):** N * Size of a Page Table Entry.  The size of a page table entry depends on how many bits are needed to represent a frame number (which is determined by the amount of physical memory available).

**Important Formulas:**

*   `Number of bits for Page Offset = log2(Page Size)` (Page size must be a power of 2)
*   `Number of bits for Page Number = Total bits in virtual address - Number of bits for Page Offset`
*   `Total bits in virtual address = log2(Virtual Address Space in Bytes)`
    *   Convert MB to bytes:  `Virtual Address Space in Bytes = Virtual Address Space in MB * 1024 * 1024`

**4. Implementing the Simulation:**

Your program should:

1.  **Accept the virtual address space size in MB as a command-line argument.**
2.  **Choose a suitable Page Size.** A common default is 4KB (4096 bytes). This can be hardcoded or optionally taken as an argument as well.
3.  **Calculate the number of bits required for the page offset.** `log2(Page Size)`
4.  **Calculate the virtual address space size in bytes.** `MB * 1024 * 1024`
5.  **Calculate the total number of bits in the virtual address.** `log2(Virtual Address Space in Bytes)`
6.  **Calculate the number of bits required for the page number (VPN).**
7.  **Calculate the number of pages.**  `Virtual Address Space in Bytes / Page Size`
8.  **Print all calculated values.** This allows you to verify your calculations.

**Example Code (Python):**

```python
import sys
import math

def simulate_paging(virtual_address_space_mb, page_size_kb=4): #default page size = 4KB
    """
    Simulates address translation in the paging scheme.

    Args:
        virtual_address_space_mb: Size of the virtual address space in MB.
        page_size_kb: Page size in KB (default 4KB).
    """

    try:
        virtual_address_space_mb = float(virtual_address_space_mb)
        page_size_kb = float(page_size_kb)

        if virtual_address_space_mb <= 0 or page_size_kb <= 0:
            raise ValueError("Virtual address space and page size must be positive values.")


        # Calculate sizes in bytes
        virtual_address_space_bytes = int(virtual_address_space_mb * 1024 * 1024)
        page_size_bytes = int(page_size_kb * 1024) # Convert KB to Bytes


        # Calculate bits needed for page offset
        page_offset_bits = int(math.log2(page_size_bytes))

        # Calculate total virtual address bits
        virtual_address_bits = int(math.log2(virtual_address_space_bytes))

        #Calculate the number of pages
        num_pages = int(virtual_address_space_bytes / page_size_bytes)

        # Calculate bits needed for page number
        page_number_bits = virtual_address_bits - page_offset_bits


        print(f"Virtual Address Space: {virtual_address_space_mb} MB")
        print(f"Page Size: {page_size_kb} KB")
        print(f"Virtual Address Space (bytes): {virtual_address_space_bytes}")
        print(f"Page Size (bytes): {page_size_bytes}")
        print(f"Bits for Page Offset: {page_offset_bits}")
        print(f"Total Virtual Address Bits: {virtual_address_bits}")
        print(f"Number of Pages: {num_pages}")
        print(f"Bits for Page Number: {page_number_bits}")

    except ValueError as e:
        print(f"Error: Invalid input. {e}")
    except OverflowError:
        print("Error: The virtual address space is too large to be represented by the system's integer type.")
    except Exception as e:
        print(f"An unexpected error occurred: {e}")


if __name__ == "__main__":
    if len(sys.argv) != 2:
        print("Usage: python paging_simulation.py <virtual_address_space_mb>")
        sys.exit(1)

    virtual_address_space_mb = sys.argv[1]
    simulate_paging(virtual_address_space_mb)

```

2.  Open your terminal or command prompt.
3.  Run the script with the virtual address space size as an argument:

**5. Error Handling:**

*   **Non-numeric input:** Use `try-except` blocks to handle cases where the command-line argument is not a number. Print an appropriate error message.
*   **Invalid virtual address space size:** Ensure the size is a positive number.  Consider also imposing a maximum size based on realistic system limitations. Raise a `ValueError` if the input is invalid.
*   **Zero page size:** The page size must be greater than zero.
*   **Overflow errors:** Very large virtual address spaces can cause overflow errors during calculations (especially when using `int`). Consider using larger integer types if necessary, or limiting the maximum virtual address space size.

**6. Practice Questions/Exercises:**

1.  **What is the purpose of paging?**
    *   **Answer:**  To allow processes to use more memory than is physically available (virtual memory), to enable memory sharing between processes, and to provide memory protection.

2.  **If the virtual address space is 128MB and the page size is 8KB, how many entries are needed in the page table?**
    *   **Answer:**
        *   128 MB = 128 * 1024 * 1024 = 134217728 bytes
        *   8 KB = 8 * 1024 = 8192 bytes
        *   Number of pages = 134217728 / 8192 = 16384 pages
        *   Therefore, 16384 entries are needed in the page table.

3.  **How is the page offset calculated from the virtual address?**
    *   **Answer:** The page offset is the lower *n* bits of the virtual address, where 2^*n* is equal to the page size in bytes.

4.  **What happens if a page is not present in physical memory?**
    *   **Answer:** A page fault occurs. The operating system must then retrieve the page from secondary storage (e.g., the hard drive) and load it into physical memory.

5.  **Modify the Python code to allow the user to specify the page size (in KB) as a second command line argument.**
    *   **Answer:** See modified code example above.

**7. Important Points to Remember:**

*   Paging allows for non-contiguous memory allocation.
*   The page table is a crucial component for address translation.
*   The size of the virtual address space is limited by the architecture of the CPU (number of address lines).
*   The choice of page size involves a trade-off between internal fragmentation and the size of the page table.
*   Address translation can be slow, so Translation Lookaside Buffers (TLBs) are used to cache recent translations.
