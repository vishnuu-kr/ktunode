## OPERATING SYSTEMS - Module 4: I/O System - Topic: Interrupts

These notes cover the topic of Interrupts within the I/O system of an Operating System, focusing on the key concepts, definitions, and practical examples.

**Learning Outcomes:**

*   Understand the purpose and function of interrupts in an operating system.
*   Differentiate between various types of interrupts.
*   Explain the interrupt handling mechanism, including the role of the interrupt vector table.
*   Describe the interrupt priority system and its importance.
*   Analyze the advantages and disadvantages of using interrupts.

**1. Introduction to Interrupts**

*   **Definition:** An interrupt is a signal to the processor emitted by hardware or software indicating an event that needs immediate attention.  It suspends the current process and transfers control to an interrupt handler (also known as an Interrupt Service Routine or ISR).

*   **Purpose:**
    *   **Improved CPU Utilization:** Allows the CPU to perform other tasks while waiting for I/O operations to complete.  Without interrupts, the CPU would have to constantly poll devices, wasting valuable processing time.
    *   **Real-time Response:** Enables the OS to respond quickly to external events, critical for real-time systems.
    *   **Efficient Resource Management:** Enables the OS to manage resources efficiently by allowing devices to signal when they are ready to transfer data or require service.

*   **Key Concepts:**
    *   **Interrupt Request (IRQ):**  A signal sent by a hardware device to the interrupt controller, requesting the CPU's attention.
    *   **Interrupt Controller:** A hardware component that manages interrupt requests and prioritizes them. Examples: APIC (Advanced Programmable Interrupt Controller), PIC (Programmable Interrupt Controller).
    *   **Interrupt Handler (ISR):** A specific routine (function) in the OS kernel that handles a particular type of interrupt.
    *   **Interrupt Vector Table (IVT):** A table that contains the addresses of the interrupt handlers.  The interrupt number (associated with the interrupt request) is used as an index into the IVT to find the corresponding handler's address.
    *   **Interrupt Masking:** Disabling certain interrupts to prevent them from interrupting the current process.  Typically used for critical sections of code or when handling higher-priority interrupts.

**2. Types of Interrupts**

*   **Hardware Interrupts (External Interrupts):** Generated by external hardware devices, such as:
    *   **I/O Interrupts:** Signaled by I/O devices (e.g., keyboard, mouse, disk drive, network card) when they are ready to transfer data or require service. Example:  A keyboard press triggering an interrupt to process the input.
    *   **Hardware Failure Interrupts:**  Signaled by hardware components when a failure occurs (e.g., memory error, power failure).
    *   **Timer Interrupts:** Generated by a timer at regular intervals. Used for time-sharing and scheduling processes.

*   **Software Interrupts (Internal Interrupts or Traps):**  Caused by software instructions, typically:
    *   **System Calls:**  A program requests services from the operating system kernel (e.g., file I/O, memory allocation). Example: Calling the `read()` system call to read data from a file.
    *   **Exceptions:** Errors or exceptional conditions during program execution (e.g., division by zero, invalid memory access).
        *   **Faults:** Errors that can be corrected (e.g., page fault). After handling, the interrupted instruction is re-executed.
        *   **Traps:** Intentional exceptions used for debugging or system calls. After handling, the next instruction after the trap is executed.
        *   **Aborts:** Severe errors that cannot be recovered from (e.g., hardware failure). The program is usually terminated.

**3. Interrupt Handling Mechanism**

1.  **Interrupt Request:**  An I/O device signals an interrupt request (IRQ) to the interrupt controller.
2.  **Interrupt Controller Handling:**
    *   The interrupt controller prioritizes the IRQs if multiple requests are received simultaneously.
    *   It signals the CPU via the interrupt pin.
3.  **CPU Response:**
    *   The CPU suspends execution of the current process after completing the current instruction.
    *   It saves the current program state (e.g., program counter, registers) onto the stack.
4.  **Interrupt Acknowledgement:** The CPU acknowledges the interrupt.
5.  **Interrupt Vector Lookup:**  The interrupt controller provides the interrupt number to the CPU. The CPU uses this number as an index into the Interrupt Vector Table (IVT) to find the address of the corresponding ISR.
6.  **Interrupt Handler Execution:**  The CPU jumps to and executes the ISR.  The ISR handles the event that triggered the interrupt.
7.  **Interrupt Return:**  After the ISR completes its task, it executes a return-from-interrupt instruction.
8.  **State Restoration:** The CPU restores the previously saved program state from the stack.
9.  **Resumption of Execution:**  The interrupted process resumes execution from the point where it was interrupted.

**Example:**

Imagine a user presses a key on the keyboard.

1.  The keyboard controller sends an IRQ to the interrupt controller.
2.  The interrupt controller signals the CPU.
3.  The CPU saves the current program state and acknowledges the interrupt.
4.  The interrupt controller provides the keyboard interrupt number.
5.  The CPU uses this number to look up the address of the keyboard ISR in the IVT.
6.  The CPU jumps to the keyboard ISR, which reads the key code from the keyboard buffer and stores it in the input buffer.
7.  The keyboard ISR signals the operating system that a key press has occurred.
8.  The ISR returns, and the CPU restores the previous program state.
9.  The interrupted program continues execution, now able to access the key press data.

**4. Interrupt Priority**

*   **Purpose:** To handle multiple interrupt requests efficiently, especially when different devices have different levels of urgency.

*   **Mechanism:** Interrupts are assigned priorities.  A higher-priority interrupt can interrupt a lower-priority interrupt handler. A lower-priority interrupt will be masked (delayed) until a higher-priority interrupt handler completes.

*   **Example:** A hardware failure interrupt (e.g., power loss) would typically have a higher priority than a keyboard interrupt.  This ensures that the system can respond to the critical failure immediately.

*   **Interrupt Masking (Disabling Interrupts):**  Used to prevent interrupts during critical sections of code or when handling high-priority interrupts.  Interrupts can be selectively masked using the interrupt mask register in the CPU.  Enabling interrupts allows pending interrupts to be processed.

**5. Advantages and Disadvantages of Interrupts**

*   **Advantages:**
    *   **Improved CPU Utilization:** The CPU can perform other tasks while waiting for I/O operations.
    *   **Real-time Responsiveness:** Enables the OS to react quickly to external events.
    *   **Efficiency:** More efficient use of system resources compared to polling.
    *   **Flexibility:** Allows the OS to handle a wide range of events from various devices.

*   **Disadvantages:**
    *   **Overhead:** Interrupt handling incurs overhead due to saving and restoring the program state.
    *   **Complexity:** Interrupt-driven systems can be more complex to design and debug.
    *   **Interrupt Latency:**  The time it takes to respond to an interrupt can vary, which can be problematic for real-time systems requiring predictable response times.  Factors influencing interrupt latency include interrupt priority, interrupt masking, and the length of other running ISRs.
    *   **Spurious Interrupts:**  Interrupts that occur for no apparent reason, which can consume system resources.

**6. Important Points to Remember:**

*   Interrupts are essential for modern operating systems, enabling efficient I/O handling and real-time responsiveness.
*   Understanding the interrupt handling mechanism, including the role of the IVT and interrupt priority, is crucial.
*   Interrupts can be both hardware-generated and software-generated.
*   While interrupts offer many advantages, they also introduce overhead and complexity.

**7. Practice Questions/Exercises:**

1.  **What is an interrupt, and why are interrupts important in operating systems?**
    *   **Answer:** An interrupt is a signal to the processor indicating an event that requires immediate attention. Interrupts are important because they improve CPU utilization, enable real-time responsiveness, and provide efficient resource management by allowing the CPU to do other tasks while I/O operations are in progress.

2.  **Differentiate between hardware and software interrupts. Provide examples of each.**
    *   **Answer:** Hardware interrupts are generated by external hardware devices (e.g., keyboard press, disk I/O). Software interrupts are generated by software instructions (e.g., system calls, exceptions like division by zero).

3.  **Explain the purpose of the Interrupt Vector Table (IVT).**
    *   **Answer:** The IVT is a table containing the addresses of interrupt handlers. The interrupt number is used as an index into the IVT to find the corresponding handler's address. This allows the OS to quickly locate the appropriate ISR for each interrupt.

4.  **What is interrupt masking, and why is it used?**
    *   **Answer:** Interrupt masking (or disabling interrupts) is the process of preventing certain interrupts from interrupting the current process. It is used during critical sections of code or when handling high-priority interrupts to prevent lower-priority interrupts from interfering.

5.  **Explain how interrupt priority works and why it's needed.**
    *   **Answer:** Interrupt priority assigns different priority levels to different interrupts. A higher-priority interrupt can interrupt a lower-priority interrupt handler, while a lower-priority interrupt is masked until a higher-priority interrupt handler completes. This is necessary to ensure that more important or time-critical events are handled first.
