## OPERATING SYSTEMS - Module 3: Memory Management - Virtual Memory - Paging: Introduction

**Learning Outcomes:**

*   Understand the concept of virtual memory and its advantages.
*   Explain the basic principles of paging.
*   Describe the address translation process in a paging system.
*   Identify the role and structure of page tables.
*   Differentiate between logical and physical addresses.
*   Understand basic performance considerations for paging.

**1. Introduction to Virtual Memory**

*   **Definition:** Virtual memory is a memory management technique that allows processes to execute even if they are not entirely loaded into physical memory (RAM). It separates logical memory as perceived by the process from the actual physical memory available.

*   **Key Concepts:**
    *   **Virtual Address Space:** The logical view of memory seen by a process. It is the set of all logical addresses a process can reference.
    *   **Physical Address Space:** The actual memory locations available in RAM.
    *   **Mapping:** The process of translating virtual addresses to physical addresses. This mapping is crucial for virtual memory to function.

*   **Advantages of Virtual Memory:**
    *   **Increased Degree of Multiprogramming:** Allows more processes to run concurrently because the total size of all running processes can exceed the physical memory available.
    *   **Larger Address Space:** Processes can have a virtual address space larger than the actual physical memory. This simplifies programming and allows for larger data structures.
    *   **Memory Protection:** Each process has its own virtual address space, preventing one process from interfering with the memory of another.  This promotes system stability and security.
    *   **Sharing:** Virtual memory allows multiple processes to share portions of their virtual address space, facilitating efficient inter-process communication and code reuse (e.g., shared libraries).
    *   **Reduced I/O:** Fewer I/O operations are required because only the necessary parts of a process are loaded into memory. This improves overall system performance.

*   **Example:** Imagine you have 4GB of RAM and want to run three applications, each requiring 2GB of memory. Without virtual memory, you wouldn't be able to run all three applications simultaneously. Virtual memory allows you to run all three applications because only the currently used portions of each application are loaded into RAM, while the rest resides on the hard drive (swap space).

**2. Basic Principles of Paging**

*   **Definition:** Paging is a virtual memory technique where both the logical address space of a process and the physical memory are divided into fixed-size blocks.

*   **Key Concepts:**
    *   **Pages:** Fixed-size blocks of the virtual address space.
    *   **Frames:** Fixed-size blocks of the physical memory (RAM).  The size of a page is equal to the size of a frame.
    *   **Page Table:** A data structure used to map virtual pages to physical frames.  Each process has its own page table (or a part of it in hierarchical paging).

*   **How Paging Works:**
    1.  The logical address space of each process is divided into pages.
    2.  The physical memory is divided into frames.
    3.  When a process needs to access a virtual address, the virtual address is divided into two parts: a page number and a page offset.
    4.  The page number is used as an index into the page table.
    5.  The page table entry (PTE) contains the frame number where the corresponding page is located in physical memory. If the page is not in memory (a page fault), the PTE will indicate that.
    6.  The frame number is combined with the page offset to form the physical address.
    7.  The physical address is then used to access the data in RAM.

*   **Example:** Let's say you have a page size of 4KB (4096 bytes). A virtual address of 10240 (decimal) would be divided as follows (assuming a simplified system):
    *   Page Number: 10240 / 4096 = 2 (integer division)
    *   Page Offset: 10240 % 4096 = 2048

    Now, the system consults the page table for process. Assuming the page table entry for page number 2 contains the frame number 5.

    *   Physical Address: (Frame Number * Frame Size) + Page Offset = (5 * 4096) + 2048 = 22528 (decimal)

**3. Address Translation in a Paging System**

*   **The Process:**  Address translation (also called address mapping) is the core mechanism of paging. It converts a virtual address generated by the CPU into a physical address used to access memory.

*   **Steps:**
    1.  **Virtual Address Decomposition:** The CPU generates a virtual address. This address is divided into two parts: the *page number* and the *page offset*.
    2.  **Page Table Lookup:**  The operating system (specifically, the memory management unit - MMU) uses the page number to look up the corresponding entry in the process's page table.
    3.  **Page Table Entry Retrieval:** The page table entry (PTE) contains information about the page, including:
        *   **Frame Number:**  The physical frame number where the page is located in memory.
        *   **Present/Absent Bit (Valid Bit):** Indicates whether the page is currently residing in physical memory. If the bit is set (e.g., to 1), the page is in memory. If the bit is clear (e.g., to 0), the page is not in memory, and a page fault will occur.
        *   **Protection Bits:**  Specify the access rights for the page (e.g., read-only, read-write, execute).
        *   **Modified/Dirty Bit:**  Indicates whether the page has been modified since it was loaded into memory.  This is important for page replacement algorithms.
    4.  **Page Fault Handling:** If the present/absent bit indicates that the page is not in memory (a page fault), the OS must:
        *   Find a free frame in memory.  If no frames are free, a page replacement algorithm is used to select a page to evict from memory.
        *   Load the required page from secondary storage (e.g., hard drive) into the chosen frame.
        *   Update the page table entry to reflect the new frame number and set the present/absent bit to 1.
        *   Restart the instruction that caused the page fault.
    5.  **Physical Address Construction:** If the page is in memory, the frame number from the PTE is combined with the page offset from the virtual address to create the physical address.
    6.  **Memory Access:** The CPU uses the physical address to access the desired data in RAM.

*   **Diagram:**

    ```
    +---------------------+       +-----------------+       +---------------------+
    | Virtual Address     | ----> | Page Table Lookup | ----> | Physical Address    |
    | (Page Number, Offset)|       | (Using MMU)      |       | (Frame Number, Offset)|
    +---------------------+       +-----------------+       +---------------------+
                              |       |
                              |       +---------------------+
                              |       | Page Table Entry    |
                              |       | (Frame Number,      |
                              |       |  Present/Absent bit, |
                              |       |  Protection bits, ...) |
                              |       +---------------------+
                              |
                              | If Page Absent (Page Fault) -> OS Page Fault Handler
    ```

**4. The Role and Structure of Page Tables**

*   **Role:** Page tables are the central data structure in a paging system. They are used to translate virtual addresses to physical addresses. They also provide information about the status and properties of each page.

*   **Structure:**
    *   A page table is essentially an array of page table entries (PTEs).
    *   The index into the array is the page number.
    *   Each PTE typically contains the following fields:
        *   **Frame Number:** The physical frame number where the page is located.
        *   **Present/Absent Bit (Valid Bit):** Indicates whether the page is in memory.
        *   **Protection Bits:** Control access to the page (e.g., read-only, read-write, execute).
        *   **Modified/Dirty Bit:** Indicates whether the page has been modified.
        *   **Reference Bit (Accessed Bit):** Indicates whether the page has been accessed recently (used by some page replacement algorithms).
        *   **Caching Disabled Bit:**  Indicates whether caching should be disabled for the page.

*   **Page Table Storage:**
    *   Page tables can be large, especially for processes with large virtual address spaces.
    *   Therefore, they are usually stored in physical memory.
    *   The address of the current process's page table is usually stored in a special CPU register called the **Page Table Base Register (PTBR)**.
    *   Accessing the page table for every memory access can be slow.  To mitigate this, a special hardware cache called the **Translation Lookaside Buffer (TLB)** is used to store recent virtual-to-physical address translations.

*   **Multi-Level Page Tables (Hierarchical Paging):** For large virtual address spaces, a single-level page table can become very large and consume a significant amount of memory. Multi-level page tables (e.g., two-level, three-level) are used to reduce the memory footprint of the page tables.  This approach divides the page table into multiple levels, where the first-level page table contains pointers to second-level page tables, and so on.

**5. Logical vs. Physical Addresses**

*   **Logical Address (Virtual Address):**
    *   Generated by the CPU.
    *   Consists of a page number and a page offset.
    *   Is the address that the programmer uses in their code.
    *   Independent of the physical memory layout.

*   **Physical Address:**
    *   The actual address in RAM where the data is stored.
    *   Consists of a frame number and a frame offset.
    *   Used by the memory controller to access the physical memory.

*   **Relationship:** The page table is the mechanism that bridges the gap between logical addresses and physical addresses.  The MMU performs the translation.

*   **Analogy:** Think of logical addresses as street addresses, and physical addresses as GPS coordinates. The page table is like a mapping service that converts street addresses to GPS coordinates.

**6. Basic Performance Considerations for Paging**

*   **Page Fault Rate:** The frequency with which page faults occur.  A high page fault rate can significantly degrade performance because it requires frequent access to secondary storage, which is much slower than RAM.
*   **Effective Access Time (EAT):** The average time it takes to access a memory location.  The EAT is affected by the page fault rate and the time it takes to handle a page fault.

*   **EAT Calculation (Simplified):**

    `EAT = (1 - p) * Memory Access Time + p * Page Fault Time`

    Where:
    *   `p` is the page fault rate (a value between 0 and 1).
    *   `Memory Access Time` is the time it takes to access memory directly (e.g., 100 ns).
    *   `Page Fault Time` is the time it takes to handle a page fault (e.g., 10 ms = 10,000,000 ns).  This includes the time to access the disk, update the page table, and restart the process.

*   **Impact of TLB:**  The TLB significantly reduces the EAT by caching frequently used page table entries.  If the page table entry is found in the TLB (a TLB hit), the address translation is much faster. If the entry is not in the TLB (a TLB miss), the page table must be accessed, which is slower.

*   **Strategies to Improve Performance:**
    *   **Increase RAM:** This reduces the likelihood of page faults.
    *   **Effective Page Replacement Algorithms:** Choosing good page replacement algorithms (e.g., LRU, FIFO, Optimal) can minimize the number of page faults.
    *   **Larger Page Sizes:** While larger page sizes can reduce the size of the page table, they can also lead to internal fragmentation (wasted space within a page).  The optimal page size depends on the application and the system.
    *   **Increase TLB Size:** A larger TLB can store more page table entries, leading to a higher TLB hit rate and faster address translation.
    *   **Prefetching:**  Anticipating the pages that a process will need and loading them into memory before they are actually requested can reduce the number of page faults.

**Important Points to Remember:**

*   Virtual memory provides a larger address space and allows processes to run even if they are not entirely in memory.
*   Paging divides both logical and physical memory into fixed-size blocks (pages and frames).
*   Page tables map virtual pages to physical frames.
*   The MMU performs address translation.
*   Page faults occur when a page is not present in physical memory.
*   The Translation Lookaside Buffer (TLB) is a cache that speeds up address translation.
*   Performance is significantly affected by page fault rate.

**Practice Questions/Exercises:**

1.  **Question:** Explain the difference between a logical address and a physical address.
    *   **Answer:** A logical address is generated by the CPU and is a virtual address seen by the process, composed of a page number and offset.  A physical address is the actual memory location in RAM, composed of a frame number and offset. The page table maps logical addresses to physical addresses.

2.  **Question:** What is a page fault, and how is it handled by the operating system?
    *   **Answer:** A page fault occurs when a process tries to access a page that is not currently in physical memory.  The OS handles it by finding a free frame (or evicting one using a page replacement algorithm), loading the required page from disk into the frame, updating the page table, and restarting the instruction that caused the fault.

3.  **Question:** What is the purpose of the present/absent bit (valid bit) in a page table entry?
    *   **Answer:** The present/absent bit indicates whether the corresponding page is currently residing in physical memory. If the bit is set, the page is in memory. If the bit is clear, the page is not in memory, and a page fault will occur.

4.  **Question:** If a system has a 32-bit virtual address space and a page size of 4KB, how many bits are used for the page number and the page offset?
    *   **Answer:** Page size = 4KB = 2^12 bytes.  Therefore, the page offset requires 12 bits. The remaining bits are used for the page number: 32 - 12 = 20 bits for the page number.

5.  **Question:** Why is the TLB important for performance in a paging system?
    *   **Answer:** The TLB is a cache that stores recently used virtual-to-physical address translations.  It significantly speeds up address translation because if the page table entry is found in the TLB (a TLB hit), the address translation can be performed quickly without accessing the slower page table in main memory.  A higher TLB hit rate reduces the effective access time.

6.  **Exercise:** Assume a system uses a page size of 8KB. Convert the following virtual addresses to page number and offset:
    *   a) 17408
    *   b) 32768
    *   c) 53248
    *   d) 78848

    **Answers:**
    *   a) 17408 / 8192 = 2, 17408 % 8192 = 1024 (Page Number: 2, Offset: 1024)
    *   b) 32768 / 8192 = 4, 32768 % 8192 = 0 (Page Number: 4, Offset: 0)
    *   c) 53248 / 8192 = 6, 53248 % 8192 = 3584 (Page Number: 6, Offset: 3584)
    *   d) 78848 / 8192 = 9, 78848 % 8192 = 5120 (Page Number: 9, Offset: 5120)
