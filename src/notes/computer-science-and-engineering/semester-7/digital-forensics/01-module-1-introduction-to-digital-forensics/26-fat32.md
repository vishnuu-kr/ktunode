### 1. Introduction to FAT File Systems

*   **Purpose:** File systems are responsible for organizing and managing data on storage devices (hard drives, USB drives, memory cards, etc.). They dictate how files are named, stored, accessed, and deleted.
*   **Evolution of FAT:**
    *   **FAT12:** Used in early floppy disks. Limited to small disk sizes and few files.
    *   **FAT16:** Introduced for larger hard drives. Still had limitations on file size and number of files.
    *   **FAT32:** Introduced with Windows 95 OSR2. Significantly increased storage capacity and file count. It became the de facto standard for many removable media for a long time.
    *   **ExFAT:** Developed by Microsoft to overcome FAT32's limitations, especially for flash drives and SD cards (larger file sizes, no 4GB file size limit).

#### Key Concepts & Definitions:

*   **File System:** A method and data structure that an operating system uses to control how data is stored and retrieved.
*   **Cluster:** The smallest unit of disk space allocation. A cluster is a group of contiguous sectors.
*   **Sector:** The smallest physical addressable unit on a storage device, typically 512 bytes.

### 2. Structure of FAT32

FAT32 is a file system that uses a table (the File Allocation Table) to keep track of which clusters are used for files and which are free.

#### Key Components:

*   **Boot Sector (Volume Boot Record - VBR):**
    *   Located at the **logical block address (LBA) 0** of the partition.
    *   Contains critical information about the file system, including:
        *   Jump instruction to the boot loader code.
        *   OEM ID (e.g., "MSWIN4.1" for FAT32).
        *   Bytes per sector.
        *   Sectors per cluster.
        *   Number of reserved sectors.
        *   Number of FATs (usually 2).
        *   Total sectors in the partition.
        *   Size of each FAT (in sectors).
        *   Root directory cluster number (always cluster 2 for FAT32).
        *   Disk drive number.
        *   Extended boot signature.
        *   Volume serial number.
        *   Volume label.
        *   File system type ("FAT32").
        *   Boot loader code.
        *   Bootstrap (end-of-sector mark).

*   **Reserved Sectors:**
    *   Contain the boot sector and potentially other reserved areas.
    *   The first reserved sector is always the VBR.

*   **File Allocation Table (FAT):**
    *   A table that tracks the status of each cluster on the disk.
    *   Each entry in the FAT corresponds to a cluster.
    *   Entries can indicate:
        *   **Free cluster:** Value 0x00000000 (represented as 0).
        *   **Reserved cluster:** Value 0xFFFFFFF0 - 0xFFFFFFF6 (used by the system).
        *   **Bad cluster:** Value 0xFFFFFFF7.
        *   **Last cluster of a file:** Value 0xFFFFFFF8 - 0xFFFFFFFE.
        *   **In use cluster:** A cluster number pointing to the next cluster in the file.
    *   FAT32 uses 32-bit entries for each cluster.
    *   There are typically **two copies of the FAT** for redundancy. The second copy is a backup.

*   **Root Directory (FAT32):**
    *   Unlike FAT12 and FAT16, the root directory in FAT32 is **not a fixed structure at a specific location**.
    *   It is stored as a **normal file** in a specific cluster allocated by the file system.
    *   The starting cluster for the root directory is stored in the boot sector.
    *   Each directory entry (file or subdirectory) is 32 bytes in size.

*   **Data Area:**
    *   The remaining space on the partition, divided into clusters.
    *   This is where the actual file data is stored.

#### Forensic Implications of FAT Structure:

*   **Cluster Chains:** Files are stored in clusters, and the FAT links these clusters together to form a chain for each file.
*   **File Deletion:** When a file is deleted, its directory entry is marked as deleted (the first character of the filename is replaced with `0xE5`), and the corresponding FAT entries are marked as free (set to 0). However, the actual data in the clusters remains on the disk until overwritten. This is a crucial aspect for file recovery.
*   **Data Remnants:** Even if a file is deleted and its clusters are reused, parts of the original file's data might still exist in unallocated clusters.
