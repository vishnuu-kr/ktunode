# Computer Vision: Module 4 - Segmentation and Object Detection

## Topic: Model Quality Metrics

This module focuses on evaluating the performance of models used for **Image Segmentation** and **Object Detection**. Understanding these metrics is crucial for choosing the right model, fine-tuning it, and comparing different approaches.

### 1. Fundamental Concepts of Segmentation and Object Detection Evaluation

*   **Goal:** To quantitatively assess how well a model performs its intended task (identifying and/or delineating objects within an image).
*   **Ground Truth:** The "correct" or human-annotated segmentation masks or bounding boxes for a dataset. This serves as the benchmark against which the model's predictions are compared.
*   **Predictions:** The output generated by the computer vision model (e.g., predicted segmentation masks, predicted bounding boxes with class labels and confidence scores).
*   **Comparison:** Metrics are derived by comparing the model's predictions against the ground truth. This involves understanding concepts like **True Positives (TP)**, **False Positives (FP)**, and **False Negatives (FN)**.

---

### 2. Differentiating Metrics for Segmentation vs. Object Detection

While some metrics are shared, their interpretation and application differ significantly:

*   **Segmentation Metrics:** Primarily focus on **pixel-level accuracy** and the **overlap** between predicted and ground truth masks. They are concerned with *how well the shape and boundaries of an object are delineated*.
*   **Object Detection Metrics:** Focus on both **localization accuracy** (how well the bounding box encloses the object) and **classification accuracy** (correctly identifying the object's class). They are concerned with *identifying the presence and location of objects*.

---

### 3. Common Segmentation Evaluation Metrics

Segmentation evaluates the accuracy of pixel-wise classification.

#### 3.1 Intersection over Union (IoU)

*   **Concept:** Measures the overlap between the predicted segmentation mask and the ground truth segmentation mask. It's a fundamental metric for assessing segmentation quality.
*   **Formula:**
    $$ \text{IoU} = \frac{\text{Area of Intersection}}{\text{Area of Union}} $$
    *   **Area of Intersection:** The number of pixels that are present in both the predicted mask and the ground truth mask.
    *   **Area of Union:** The total number of pixels present in either the predicted mask or the ground truth mask (or both).
*   **Range:** 0 to 1. Higher IoU indicates better overlap.
*   **Example:** Imagine a predicted mask of a cat and a ground truth mask of the same cat. IoU measures how much these two pixel sets overlap. A perfect overlap would give an IoU of 1.
*   **Important:** For binary segmentation (foreground/background), IoU is calculated for the foreground class.

#### 3.2 Pixel Accuracy

*   **Concept:** The ratio of correctly classified pixels to the total number of pixels.
*   **Formula:**
    $$ \text{Pixel Accuracy} = \frac{\text{Number of Correctly Classified Pixels}}{\text{Total Number of Pixels}} $$
    *   Correctly classified pixels include: True Positives (TP - foreground pixels correctly predicted as foreground) and True Negatives (TN - background pixels correctly predicted as background).
*   **Range:** 0 to 1. Higher accuracy is better.
*   **Caveat:** Can be misleading in datasets with imbalanced class distributions (e.g., a lot of background). A model that predicts everything as background might achieve high pixel accuracy but be useless.

#### 3.3 Mean Intersection over Union (mIoU)

*   **Concept:** The average IoU calculated across all semantic classes (for semantic segmentation) or across all annotated objects (for instance segmentation). This is a more robust metric than individual IoU, especially for datasets with multiple classes.
*   **Formula:**
    $$ \text{mIoU} = \frac{1}{N} \sum_{i=1}^{N} \text{IoU}_i $$
    *   Where $N$ is the number of classes, and $\text{IoU}_i$ is the IoU for class $i$.
*   **Example:** If you have segmentation for "car" and "person", mIoU would be the average of the IoU for cars and the IoU for persons.
*   **Importance:** Widely used as the standard evaluation metric for semantic segmentation tasks.

#### 3.4 Dice Coefficient (F1-Score for Segmentation)

*   **Concept:** Similar to IoU, it measures the similarity between two samples (masks in this case). It's also known as the F1-Score for segmentation.
*   **Formula:**
    $$ \text{Dice Coefficient} = \frac{2 \times |\text{Predicted} \cap \text{Ground Truth}|}{|\text{Predicted}| + |\text{Ground Truth}|} $$
    *   $|X|$ denotes the number of pixels in set $X$.
*   **Range:** 0 to 1. Higher Dice score indicates better overlap.
*   **Relationship with IoU:**
    $$ \text{Dice Coefficient} = \frac{2 \times \text{IoU}}{1 + \text{IoU}} $$
    *   This means Dice is always slightly higher than IoU for the same prediction.
*   **Use Case:** Often preferred in medical imaging segmentation due to its sensitivity to smaller structures.

### 4. Common Object Detection Evaluation Metrics

Object detection involves both localization and classification.

#### 4.1 Intersection over Union (IoU) for Bounding Boxes

*   **Concept:** Same as for segmentation, but applied to the **bounding boxes**. It measures the overlap between the predicted bounding box and the ground truth bounding box for a detected object.
*   **Formula:** Same as segmentation IoU, but areas are calculated for rectangles.
*   **Thresholding:** For an object detection to be considered a "correct detection" (True Positive), the IoU between the predicted and ground truth bounding box must exceed a predefined **IoU threshold** (e.g., 0.5).

#### 4.2 True Positives (TP), False Positives (FP), False Negatives (FN) in Object Detection

*   **True Positive (TP):** A correct detection.
    *   A bounding box is predicted.
    *   The predicted class matches the ground truth class.
    *   The IoU between the predicted and ground truth bounding box is above the IoU threshold.
*   **False Positive (FP):** An incorrect detection.
    *   A bounding box is predicted, but it doesn't correspond to any ground truth object (or the IoU is too low).
    *   A bounding box is predicted with the wrong class label.
*   **False Negative (FN):** A missed detection.
    *   A ground truth object exists, but no bounding box is predicted for it.

#### 4.3 Precision

*   **Concept:** Of all the objects the model *predicted* as a certain class, how many were *actually* that class and correctly localized? It measures the accuracy of the positive predictions.
*   **Formula:**
    $$ \text{Precision} = \frac{\text{True Positives (TP)}}{\text{True Positives (TP) + False Positives (FP)}} $$
*   **Interpretation:** High precision means the model has a low rate of false positives. When it detects something, it's likely correct.

#### 4.4 Recall (Sensitivity)

*   **Concept:** Of all the *actual* objects of a certain class in the image, how many did the model correctly *detect*? It measures the model's ability to find all relevant objects.
*   **Formula:**
    $$ \text{Recall} = \frac{\text{True Positives (TP)}}{\text{True Positives (TP) + False Negatives (FN)}} $$
*   **Interpretation:** High recall means the model has a low rate of false negatives. It's good at finding most of the objects.

#### 4.5 F1-Score

*   **Concept:** The harmonic mean of Precision and Recall. It provides a single metric that balances both.
*   **Formula:**
    $$ \text{F1-Score} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} $$
*   **Interpretation:** A high F1-Score indicates that the model has both high precision and high recall.

#### 4.6 Precision-Recall Curve

*   **Concept:** In object detection, models output a **confidence score** for each predicted bounding box. By varying a **confidence threshold**, we can get different combinations of precision and recall. The Precision-Recall Curve plots Precision on the y-axis and Recall on the x-axis for different confidence thresholds.
*   **Ideal Curve:** A curve that stays high on the y-axis for as long as possible (high precision) and then drops sharply.
*   **Area Under the Curve (AUC):** The area under the Precision-Recall curve is a single scalar value that summarizes the model's performance across all confidence thresholds.

#### 4.7 Average Precision (AP)

*   **Concept:** The average of precision values obtained at different recall levels. It's essentially the area under the Precision-Recall curve, but calculated more formally.
*   **Calculation:**
    1.  Sort all detections by their confidence scores in descending order.
    2.  Iterate through the sorted detections, treating each one as the "next" prediction.
    3.  For each prediction, calculate its precision and recall (based on all detections up to that point).
    4.  The AP is the integral of the precision-recall curve. Various methods exist for computing this integral (e.g., 11-point interpolation or all-points interpolation). The "all-points" method, as used in COCO, is generally preferred.
*   **Range:** 0 to 1. Higher AP is better.
*   **Per Class AP:** AP is typically calculated for each object class independently.

#### 4.8 Mean Average Precision (mAP)

*   **Concept:** The average of the Average Precisions (APs) across all object classes. This is the most common and comprehensive metric for evaluating object detection models.
*   **Formula:**
    $$ \text{mAP} = \frac{1}{N} \sum_{i=1}^{N} \text{AP}_i $$
    *   Where $N$ is the number of classes, and $\text{AP}_i$ is the Average Precision for class $i$.
*   **mAP@IoU Threshold:** Often, mAP is reported at a specific IoU threshold (e.g., mAP@0.5, meaning APs are calculated using an IoU threshold of 0.5). COCO datasets also report mAP averaged over multiple IoU thresholds (e.g., mAP@[.5:.05:.95] averages APs from IoU=0.5 to 0.95 with a step of 0.05).

### 5. Role of Confidence Scores and Bounding Box Regression

*   **Confidence Scores:**
    *   Output by object detection models, representing the model's belief that a bounding box contains an object of a particular class.
    *   Crucial for generating the Precision-Recall curve and calculating AP/mAP.
    *   **Thresholding:** A confidence threshold is used to decide whether to keep a prediction or discard it.
        *   *High threshold:* Fewer but more confident predictions (higher precision, lower recall).
        *   *Low threshold:* More predictions, including potentially incorrect ones (lower precision, higher recall).

*   **Bounding Box Regression:**
    *   The process of refining the coordinates of a predicted bounding box to more accurately enclose the ground truth object.
    *   The quality of bounding box regression directly impacts the IoU calculation. Better regression leads to higher IoU values, which are critical for classifying a detection as a TP.
    *   Metrics like AP and mAP implicitly evaluate the quality of bounding box regression because poor regression will result in low IoU values, failing to meet the threshold for TPs.

---

### 6. Trade-offs Between Different Evaluation Metrics

*   **Precision vs. Recall:** There's a fundamental trade-off.
    *   Increasing recall often decreases precision (by making more predictions, some of which will be wrong).
    *   Increasing precision often decreases recall (by being more selective and missing some objects).
    *   The F1-Score and the Precision-Recall curve/mAP help balance this trade-off.
*   **IoU Threshold:**
    *   A **lower IoU threshold** (e.g., 0.5) is more forgiving and will likely result in higher recall and AP/mAP, as more detections will be considered TPs. However, it might not be strict enough for precise localization.
    *   A **higher IoU threshold** (e.g., 0.75 or 0.9) is more stringent, requiring better bounding box localization. This will likely lead to lower recall and AP/mAP, as fewer detections will meet the criterion.
*   **Class Imbalance:**
    *   For segmentation, Pixel Accuracy can be misleading with imbalanced classes. mIoU and Dice are generally preferred.
    *   For object detection, mAP is robust to class imbalance as it's averaged per class.

---

### 7. Interpreting Results

*   **Segmentation:**
    *   **High mIoU/Dice:** Model is good at delineating object boundaries and overall shape.
    *   **Low mIoU/Dice for a specific class:** Model struggles with that particular class, possibly due to small size, complex shape, or class imbalance.
    *   **High Pixel Accuracy, Low mIoU:** Suggests the model is good at classifying background pixels but poor at segmenting foreground objects.
*   **Object Detection:**
    *   **High mAP:** Model is generally good at both localizing and classifying objects.
    *   **High Precision, Low Recall:** Model is confident when it detects, but misses many objects. It might be overly conservative.
    *   **Low Precision, High Recall:** Model finds most objects, but makes many false positive detections. It might be too aggressive.
    *   **High AP for a class:** Model performs well for that specific class.
    *   **Low AP for a class:** Model struggles with that specific class (e.g., small objects, rare objects, difficult appearance).

### Practice Questions

**Question 1 (Segmentation):**
You are evaluating a semantic segmentation model on an image with 1000 pixels. The ground truth for a "car" is 100 pixels. Your model predicts a "car" mask covering 120 pixels, with 90 of these correctly overlapping with the ground truth "car" pixels.

Calculate:
a) The IoU for the "car" class.
b) The Dice Coefficient for the "car" class.
c) If the remaining 900 pixels were correctly classified as background, what is the overall Pixel Accuracy?

**Question 2 (Object Detection):**
Consider an object detection model predicting bounding boxes for "dogs" and "cats". For the "dog" class, the model outputs the following (confidence, IoU with ground truth):
(0.9, 0.8), (0.7, 0.6), (0.5, 0.9), (0.3, 0.7), (0.1, 0.5)

Assume the ground truth contains two "dogs". The IoU threshold is 0.5.

a) What are the TP, FP, and FN counts for the "dog" class if a confidence threshold of 0.4 is used?
b) Calculate Precision, Recall, and F1-Score for the "dog" class at this confidence threshold.
c) How would these metrics change if the confidence threshold was lowered to 0.2? Explain why.

**Question 3 (Conceptual):**
Why is mIoU generally preferred over Pixel Accuracy for evaluating semantic segmentation models, especially in datasets with a significant amount of background?

### Answers to Practice Questions

**Answer 1 (Segmentation):**

*   **Ground Truth (GT):** 100 pixels
*   **Prediction (Pred):** 120 pixels
*   **Intersection:** 90 pixels (correctly overlapping)
*   **Union:** Pixels in GT + Pixels in Pred - Intersection = 100 + 120 - 90 = 130 pixels

a) **IoU:**
   $$ \text{IoU} = \frac{\text{Intersection}}{\text{Union}} = \frac{90}{130} \approx 0.692 $$

b) **Dice Coefficient:**
   $$ \text{Dice} = \frac{2 \times \text{Intersection}}{\text{Pixels in Pred} + \text{Pixels in GT}} = \frac{2 \times 90}{120 + 100} = \frac{180}{220} \approx 0.818 $$
   Alternatively, using the IoU relationship:
   $$ \text{Dice} = \frac{2 \times 0.692}{1 + 0.692} \approx \frac{1.384}{1.692} \approx 0.818 $$

c) **Pixel Accuracy:**
   *   Correctly classified foreground pixels (TP): 90 (pixels in intersection)
   *   Correctly classified background pixels (TN): 900 (total pixels - GT pixels - FP foreground pixels)
      *   FP foreground pixels = Predicted foreground pixels - TP foreground pixels = 120 - 90 = 30
      *   TN = 1000 (total) - 100 (GT foreground) - 30 (FP foreground) = 870.
      *   *Correction:* The question states "If the remaining 900 pixels were correctly classified as background". This means we have 100 foreground pixels in GT. Out of these, 90 are predicted correctly as foreground (TP). The remaining 10 are missed (FN). The predicted foreground has 120 pixels, so 120-90 = 30 are incorrectly predicted as foreground (FP).
      *   Correctly classified as foreground (TP) = 90
      *   Correctly classified as background (TN) = 1000 (total) - 100 (actual foreground) - 30 (false positives) = 870.
      *   *Wait, re-reading the question:* "If the remaining 900 pixels were correctly classified as background". This implies the total *non-car* pixels are 900.
      *   Total pixels = 1000.
      *   Ground Truth "Car" pixels = 100.
      *   Ground Truth "Background" pixels = 900.
      *   Predicted "Car" pixels = 120.
      *   Predicted "Background" pixels = 1000 - 120 = 880.
      *   Intersection (correctly predicted car) = 90.
      *   False Positives (predicted car, but actually background) = 120 (predicted car) - 90 (TP) = 30. These 30 are from the 900 actual background pixels.
      *   False Negatives (actual car, but predicted background) = 100 (GT car) - 90 (TP) = 10. These 10 are from the 100 actual car pixels.
      *   True Negatives (correctly predicted background) = 900 (actual background) - 30 (FP) = 870.
      *   Total correctly classified pixels = TP + TN = 90 + 870 = 960.
   $$ \text{Pixel Accuracy} = \frac{960}{1000} = 0.96 $$

**Answer 2 (Object Detection):**

*   **Ground Truth "dogs":** 2
*   **IoU Threshold:** 0.5
*   **Detections (confidence, IoU):** (0.9, 0.8), (0.7, 0.6), (0.5, 0.9), (0.3, 0.7), (0.1, 0.5)

a) **Confidence threshold = 0.4:**
   *   Detections above threshold: (0.9, 0.8), (0.7, 0.6), (0.5, 0.9), (0.3, 0.7)
   *   Check IoU against ground truth:
      *   (0.9, 0.8): IoU 0.8 > 0.5 -> TP
      *   (0.7, 0.6): IoU 0.6 > 0.5 -> TP
      *   (0.5, 0.9): IoU 0.9 > 0.5 -> TP
      *   (0.3, 0.7): IoU 0.7 > 0.5 -> TP
   *   We have 4 detections with IoU > 0.5. However, there are only 2 ground truth dogs.
   *   The model will match the highest confidence detections to ground truths first.
   *   The first two detections to exceed the IoU threshold and the confidence threshold are:
      *   (0.9, 0.8) -> Matches GT Dog 1 -> TP = 1
      *   (0.7, 0.6) -> Matches GT Dog 2 -> TP = 2
   *   The next detection (0.5, 0.9) has IoU 0.9 > 0.5, but both ground truth dogs are already matched. Thus, this becomes a False Positive. -> FP = 1
   *   The next detection (0.3, 0.7) has IoU 0.7 > 0.5, but again, both ground truth dogs are matched. -> FP = 2
   *   The last detection (0.1, 0.5) has IoU 0.5 > 0.5, but both ground truth dogs are matched. -> FP = 3
   *   Number of Ground Truth Dogs not detected = 0. -> FN = 0
   *   **TP = 2, FP = 3, FN = 0**

b) **Precision, Recall, F1-Score:**
   $$ \text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}} = \frac{2}{2 + 3} = \frac{2}{5} = 0.4 $$
   $$ \text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}} = \frac{2}{2 + 0} = \frac{2}{2} = 1.0 $$
   $$ \text{F1-Score} = 2 \times \frac{0.4 \times 1.0}{0.4 + 1.0} = 2 \times \frac{0.4}{1.4} = \frac{0.8}{1.4} \approx 0.571 $$

c) **Confidence threshold = 0.2:**
   *   All 5 detections are now above the threshold.
   *   The first two detections matching ground truths are still the same TPs: (0.9, 0.8) and (0.7, 0.6).
   *   The remaining 3 detections (0.5, 0.9), (0.3, 0.7), (0.1, 0.5) will be considered False Positives because both ground truth dogs are already accounted for.
   *   **TP = 2, FP = 3, FN = 0**.
   *   The Precision, Recall, and F1-Score are **the same** as in part (b) for this specific set of detections and ground truths, because the IoU threshold is still 0.5 and the same detections are matched to ground truths.
   *   **However**, if the ground truth had more objects, or if the confidence scores were distributed differently, lowering the confidence threshold would generally increase recall (by including more detections) and decrease precision (by including more false positives).

**Answer 3 (Conceptual):**
Pixel Accuracy can be misleading in segmentation tasks with imbalanced class distributions because it doesn't account for the class imbalance. If a dataset has 95% background pixels and 5% foreground pixels, a model that incorrectly predicts all pixels as background will achieve 95% Pixel Accuracy. While this sounds good, the model has failed entirely at segmenting the foreground objects. In contrast, mIoU calculates the IoU for each class separately and then averages them. This means that even if the background is classified perfectly, a low IoU for the foreground objects will significantly reduce the mIoU, providing a more accurate reflection of the model's performance on the task of interest (segmenting the objects). Dice Coefficient also suffers from this imbalance issue in a similar way to IoU.

---

### Important Points to Remember

*   **Ground Truth is Key:** All metrics are relative to accurate, human-annotated ground truth.
*   **IoU is Fundamental:** Whether for segmentation or object detection, IoU quantifies overlap.
*   **Segmentation vs. Object Detection:** Metrics differ based on the task's goal (pixel-wise vs. bounding-box-wise).
*   **mIoU for Segmentation:** The standard for evaluating semantic segmentation quality.
*   **mAP for Object Detection:** The standard for evaluating object detection quality, balancing localization and classification.
*   **Precision-Recall Trade-off:** Understand that improving one often degrades the other. Use F1-Score or mAP to balance.
*   **Confidence Thresholds:** Crucial for object detection evaluation, impacting TP/FP counts and ultimately AP/mAP.
*   **Context Matters:** Always consider the specific task, dataset, and desired outcome when interpreting metrics. A metric that is good for one application might not be for another.
