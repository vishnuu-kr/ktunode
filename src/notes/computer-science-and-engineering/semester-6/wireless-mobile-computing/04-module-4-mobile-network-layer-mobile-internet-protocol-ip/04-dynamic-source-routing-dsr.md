# Module 4: Mobile Network Layer – Mobile Internet Protocol (IP)
## Topic: Dynamic Source Routing (DSR)

**Description:** This module explores Dynamic Source Routing (DSR), a proactive routing protocol designed specifically for mobile ad hoc networks (MANETs). It is a key alternative to traditional routing protocols which are not well-suited to the highly dynamic topology of mobile networks.

**Learning Outcomes:**

*   Understand the fundamental principles of DSR.
*   Explain the route discovery and route maintenance mechanisms in DSR.
*   Analyze the advantages and disadvantages of DSR compared to other MANET routing protocols.
*   Describe the operation of DSR in a mobile ad hoc network environment.
*   Identify the mechanisms used by DSR to avoid routing loops and optimize routing.

---

### 1. Introduction to Dynamic Source Routing (DSR)

*   **Definition:** DSR is a simple and efficient routing protocol designed specifically for use in multi-hop wireless ad hoc networks of mobile nodes.  It allows nodes to dynamically discover and maintain routes to arbitrary destinations in the network.

*   **Key Characteristics:**
    *   **Reactive Routing (On-Demand):** Routes are only discovered when needed, reducing overhead compared to proactive routing protocols that maintain routes regardless of whether they're used.
    *   **Source Routing:** Each packet carries the complete ordered list of nodes through which the packet must pass to reach its destination. The intermediate nodes simply forward the packet based on the source route without needing to maintain routing tables.
    *   **No Periodic Routing Advertisements:**  DSR avoids periodic hello messages and routing table updates, minimizing bandwidth consumption.
    *   **Suitable for Highly Dynamic Networks:** Handles frequent changes in network topology due to node mobility.

*   **Core Mechanisms:** Route Discovery and Route Maintenance

### 2. Route Discovery

*   **Initiation:** When a node *S* (source) needs to send a packet to a destination node *D* and does not have a route to *D* in its route cache, it initiates a route discovery process.

*   **Route Request (RREQ) Message:**
    *   *S* broadcasts a Route Request message.  This message includes:
        *   *S*'s address
        *   *D*'s address
        *   A unique Request ID generated by *S*
        *   A "Route Record" (initially containing only *S*'s address)

*   **RREQ Propagation:**
    *   Each node receiving the RREQ:
        *   **Checks if it has already seen the RREQ:** This is done by comparing the (source address, request ID) pair with its own history. If it's a duplicate, the RREQ is discarded (to prevent loops).
        *   **If not a duplicate:**
            *   Appends its own address to the Route Record.
            *   If the node is the destination *D*, it creates a Route Reply.
            *   Otherwise, it rebroadcasts the RREQ.

*   **Route Reply (RREP) Message:**
    *   When the RREQ reaches *D*:
        *   *D* creates a Route Reply message.
        *   The Route Reply contains the Route Record from the RREQ, representing the path from *S* to *D*.
        *   *D* can send the RREP back to *S* in two ways:
            *   **Using a route it already knows to *S* (if available):**  This is the preferred method as it avoids additional route discovery.
            *   **By reversing the route contained in the Route Record:** This requires bidirectional links.

    *   When an intermediate node receives the RREP:
        *   It checks if it's the next hop on the reverse route indicated in the RREP.
        *   If so, it forwards the RREP towards *S*.

*   **Route Caching at the Source:**
    *   When *S* receives the RREP, it caches the route in its route cache.
    *   *S* then includes this route in the header of any data packets it sends to *D*.

*   **Multiple Routes:**  *S* may receive multiple RREPs (via different paths).  It can choose the "best" route based on metrics such as hop count, signal strength, or load.

**Example:**

Consider a network with nodes A, B, C, D, and E.  A wants to send data to E, but doesn't have a route.

1.  A broadcasts an RREQ with Source = A, Destination = E, and Route Record = [A].
2.  B receives the RREQ, appends its address, and rebroadcasts it with Route Record = [A, B].
3.  C receives the RREQ from B, appends its address, and rebroadcasts it with Route Record = [A, B, C].
4.  D receives the RREQ from C, appends its address, and rebroadcasts it with Route Record = [A, B, C, D].
5.  E receives the RREQ from D, recognizes itself as the destination, and creates an RREP containing the route [A, B, C, D, E].
6.  E sends the RREP back to A (possibly by reversing the route).
7.  A receives the RREP and caches the route [A, B, C, D, E]. A now includes this complete route in the header of all data packets it sends to E.

### 3. Route Maintenance

*   **Purpose:** To detect and react to broken routes due to node mobility.

*   **Route Error (RERR) Message:**
    *   When a node forwarding a data packet detects that the next hop in the source route is unreachable (e.g., due to link failure), it generates a Route Error message.

*   **RERR Propagation:**
    *   The RERR message includes:
        *   The address of the node that detected the error.
        *   The address of the unreachable next hop.
        *   The destination for which the route is now considered invalid.
    *   The node sends the RERR message back to the source node that originated the data packet. The RERR can be sent along the reverse of the source route in the original data packet, or using any other route known to the originator of the RERR.

*   **Route Cache Maintenance:**
    *   When the source node receives the RERR, it removes the broken route from its route cache.
    *   It may also remove any other routes that contain the broken link or the unreachable node.
    *   If the source still needs to communicate with the destination, it initiates a new route discovery process.

*   **Promiscuous Listening:**
    *   DSR nodes can overhear data packets not directly addressed to them. This allows them to passively learn about routes between other nodes.
    *   If a node overhears a data packet for which it knows a shorter route, it can send a gratuitous Route Reply to the source, informing it of the better route.

**Example:**

Assume A is sending data to E via the route [A, B, C, D, E].  If the link between C and D breaks:

1.  C detects the broken link when it attempts to forward a data packet to D.
2.  C generates a Route Error message indicating that the link between C and D is broken, and that E is unreachable.
3.  C sends the RERR message back to A.
4.  A receives the RERR and removes the route [A, B, C, D, E] from its cache.
5.  If A still needs to send data to E, it initiates a new route discovery.

### 4. Advantages of DSR

*   **Simple and Efficient:**  Easy to implement and maintain.
*   **Low Overhead:**  Avoids periodic routing updates, conserving bandwidth.
*   **Supports Mobile Ad Hoc Networks:** Adapts well to changing topologies.
*   **Multiple Routes:**  Route caching allows for exploration of multiple paths, increasing reliability.
*   **No Need for Sequence Numbers:**  Uses Request IDs to prevent loops.

### 5. Disadvantages of DSR

*   **Route Discovery Latency:**  The on-demand nature of route discovery can introduce delays when a route is needed.
*   **Overhead in Data Packets:** Source routing adds overhead to each data packet, as the complete route is included in the header. This overhead increases with route length.
*   **Stale Route Information:**  Route caches can contain stale information, leading to temporary routing errors.
*   **Susceptible to Attacks:**  Source routes can be manipulated by malicious nodes.
*   **Scalability Issues:** Route discovery can flood the network, and large source route headers impact network performance.
*   **Promiscuous listening can be power-consuming:** especially if the node isn't actively sending or receiving data.

### 6. DSR Optimization Techniques

*   **Route Caching:** Helps reduce the frequency of route discoveries.
*   **Gratuitous Route Replies:** Nodes overhear packets and provide shorter routes, if known.
*   **Link Layer Acknowledgements:** Confirm successful packet delivery at the link layer, allowing for faster detection of broken links.
*   **Route Salvage:** When an intermediate node detects a broken link in a source route, it can attempt to repair the route locally (if it knows an alternative path to the destination). If successful, it avoids the need for the source to initiate a new route discovery.

### 7. Comparison with Other MANET Routing Protocols

| Feature          | DSR                     | AODV                    |
|-------------------|--------------------------|-------------------------|
| Routing Approach | Reactive (On-Demand)     | Reactive (On-Demand)    |
| Routing Type     | Source Routing           | Hop-by-Hop              |
| Data Packet Overhead| Higher (source route) | Lower (routing table)   |
| Memory Usage      | Route Cache              | Routing Table           |
| Control Overhead  | Primarily during discovery | Periodic hello messages |
| Loop Avoidance    | Request IDs              | Sequence Numbers        |

**Key Differences:**

*   **DSR** uses source routing, while **AODV** uses hop-by-hop routing. This means DSR requires larger packet headers but avoids the need for intermediate nodes to maintain routing tables.
*   **AODV** uses sequence numbers to prevent routing loops, while **DSR** uses request IDs.
*   **AODV** typically has lower data packet overhead than DSR, especially for long routes. However, DSR can adapt more quickly to route changes in certain scenarios.

### 8. Important Points to Remember

*   DSR is a *reactive* routing protocol specifically designed for MANETs.
*   DSR uses *source routing*, where the entire route is included in the data packet header.
*   The core mechanisms of DSR are *route discovery* and *route maintenance*.
*   DSR aims to minimize control overhead by avoiding periodic routing updates.
*   DSR's main drawbacks are the overhead in data packets due to source routing, potential scalability issues, and potential security vulnerabilities.

### 9. Practice Questions and Exercises

**Question 1:** Explain the purpose of the Route Request (RREQ) message in DSR and what information it contains.

**Answer:**
The RREQ message is used to initiate the route discovery process in DSR.  It is broadcast by a source node that needs a route to a destination node. The RREQ contains:
* The source node's address
* The destination node's address
* A unique Request ID (to prevent loops)
* A Route Record (initially containing only the source node's address)

**Question 2:** Describe how a node receiving a Route Request (RREQ) message determines whether to forward the message or discard it.

**Answer:**
A node checks if it has already seen the RREQ by comparing the (source address, request ID) pair with its history of received RREQs. If the (source address, request ID) pair is found, then the node discards the RREQ. Otherwise, it appends its address to the Route Record, and rebroadcasts the message.

**Question 3:** What is a Route Error (RERR) message used for in DSR, and how does it impact the source node?

**Answer:**
A Route Error message is used to notify the source node that a previously used route is no longer valid, typically because a link along the route has broken.  When the source node receives the RERR, it removes the invalid route from its route cache.  If the source still needs to send data to the destination, it must initiate a new route discovery process.

**Question 4:** What are the advantages and disadvantages of source routing compared to hop-by-hop routing?

**Answer:**
**Advantages of Source Routing:**
* Simpler intermediate nodes: Intermediate nodes don't need to maintain routing tables.
* Faster Adaptation: Can adapt faster in some scenarios because the source knows the full path and can change it more rapidly.

**Disadvantages of Source Routing:**
* Higher data packet overhead:  The complete route is included in each data packet.
* Potential security vulnerabilities: Malicious nodes can manipulate the source route.

**Question 5:** How can DSR utilize promiscuous listening to optimize routing?

**Answer:**
DSR nodes can overhear data packets not directly addressed to them (promiscuous listening). If a node overhears a data packet for which it knows a shorter or better route, it can send a gratuitous Route Reply to the source, informing it of the improved route. This allows the source to update its route cache with the more efficient path.

**Question 6:**  Consider a MANET with nodes A, B, C, D, E. A wants to send data to E.  Suppose the route A -> B -> C -> D -> E is discovered. A sends a data packet to E.  If the link between C and D fails, explain step-by-step what happens, including the messages exchanged.

**Answer:**

1.  A sends a data packet to B with the source route [A, B, C, D, E].
2.  B receives the packet and forwards it to C according to the route.
3.  C receives the packet but detects that the link to D is broken. C cannot forward the packet.
4.  C generates a Route Error (RERR) message indicating that the link C -> D is broken, and E is unreachable via that route.
5.  C sends the RERR back to A, using any available path to A (or by reversing the source route in the original packet if possible and bidirectional links are available). Let's assume C has a route back to A via B. So, C sends RERR to B.
6. B forwards the RERR to A.
7.  A receives the RERR message.
8.  A invalidates the route [A, B, C, D, E] in its route cache.
9.  If A still needs to send data to E, it initiates a new route discovery process by broadcasting a new Route Request (RREQ).
