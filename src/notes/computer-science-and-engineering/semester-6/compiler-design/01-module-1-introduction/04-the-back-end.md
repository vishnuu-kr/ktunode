# Compiler Design - Module 1: Introduction - The Back End

**Learning Outcomes:**

*   Understand the role and responsibilities of the back end of a compiler.
*   Identify common target code representations.
*   Explain the concept of instruction selection and its challenges.
*   Describe basic code optimization techniques performed in the back end.
*   Discuss register allocation and its importance.

## I. Introduction to the Back End

*   **Definition:** The back end of a compiler is the part that takes the intermediate representation (IR) generated by the front end and translates it into target code (machine code or assembly code).

*   **Role & Responsibilities:**
    *   **Instruction Selection:** Choosing the appropriate machine instructions to implement the IR operations.
    *   **Register Allocation:**  Deciding which values should reside in registers and for how long.  Registers are fast memory locations within the CPU.
    *   **Code Optimization:**  Improving the generated code in terms of speed, size, or power consumption.
    *   **Instruction Scheduling:** Ordering instructions to minimize pipeline stalls and maximize performance (particularly important on pipelined processors).
    *   **Target Code Generation:**  Emitting the final machine code or assembly code in a format understood by the target machine.
    *   **Symbol Table Management:**  Maintaining the symbol table to resolve labels and addresses during code generation.

*   **Input:** Intermediate Representation (IR).  Common IR forms include:
    *   **Three-Address Code:** Instructions have at most three operands (e.g., `x = y + z`).  Easy to manipulate.
    *   **Static Single Assignment (SSA):**  Each variable is assigned a value only once.  Simplifies data flow analysis.
    *   **Abstract Syntax Tree (AST):**  Tree-like representation of the program structure.
    *   **Directed Acyclic Graph (DAG):**  Graphical representation of the dependencies between operations.

*   **Output:** Target code (machine code or assembly code)

## II. Target Code Representations

*   **Machine Code:**
    *   Binary representation of instructions directly executable by the CPU.
    *   Architecture-specific (e.g., x86, ARM, RISC-V).
    *   Difficult to read and debug directly.

*   **Assembly Code:**
    *   Human-readable representation of machine instructions.  Uses mnemonics (e.g., `MOV`, `ADD`, `JMP`).
    *   Still architecture-specific.
    *   Easier to understand and debug than machine code.
    *   Usually converted to machine code by an assembler.

*   **Intermediate Representation (IR):**  (Discussed above as input to back end) Acts as a bridge between the front end and the back end, allowing for compiler retargeting.  A single front end can be used with multiple back ends for different architectures, and vice versa.

*   **Example (Simple Addition):**

    *   **IR (Three-Address Code):**
        ```
        t1 = a + b
        c = t1 + 10
        ```

    *   **Assembly Code (x86):**
        ```assembly
        mov eax, a      ; Load the value of 'a' into register eax
        add eax, b      ; Add the value of 'b' to register eax
        mov t1, eax     ; Store the result in memory location 't1'
        mov eax, t1     ; Load the value of 't1' into register eax
        add eax, 10     ; Add the constant 10 to register eax
        mov c, eax      ; Store the result in memory location 'c'
        ```

    *   **Machine Code (Conceptual - actual machine code is binary):**
        ```
        B8 00 00 00 00   ; mov eax, a (Address of 'a' would replace the zeroes)
        03 05 00 00 00 00 ; add eax, b (Address of 'b' would replace the zeroes)
        ...
        ```

## III. Instruction Selection

*   **Definition:** The process of choosing the appropriate machine instructions to implement the operations specified in the IR.

*   **Challenges:**
    *   **Instruction Set Complexity:** Modern instruction sets offer a wide variety of instructions, making the selection process complex.
    *   **Target Architecture Variations:** Different architectures have different instruction sets and register sets.
    *   **Cost Modeling:**  Determining the "cost" of each instruction sequence (e.g., execution time, code size, power consumption).
    *   **Optimal Selection:** Finding the optimal sequence of instructions to implement a given IR operation is often an NP-complete problem.  Heuristics and approximations are used.

*   **Techniques:**
    *   **Tree Pattern Matching:**  Representing IR fragments and machine instructions as trees.  Matching tree patterns to find suitable instruction sequences.
    *   **Dynamic Programming:**  Breaking down the instruction selection problem into smaller subproblems and solving them optimally.
    *   **Graph-Based Techniques:** Representing the IR as a graph and using graph algorithms to find optimal instruction sequences.

*   **Example (Instruction Selection for `a = b * c + d` on x86):**

    *   **IR (Three-Address Code):**
        ```
        t1 = b * c
        a = t1 + d
        ```

    *   **Possible Assembly Code (x86):**
        ```assembly
        mov eax, b      ; Load the value of 'b' into register eax
        imul eax, c     ; Multiply eax by the value of 'c' (result in eax)
        add eax, d      ; Add the value of 'd' to register eax
        mov a, eax      ; Store the result in memory location 'a'
        ```

    *   **Alternative Assembly Code (using lea):**  The `lea` (load effective address) instruction can sometimes perform the addition and multiplication in a single step. This might be more efficient depending on the CPU and surrounding code.
        ```assembly
        mov eax, b
        imul eax, c
        lea eax, [eax + d]
        mov a, eax
        ```

## IV. Code Optimization

*   **Definition:** The process of improving the generated code to reduce execution time, code size, or power consumption.

*   **Categories:**
    *   **Machine-Independent Optimizations:** Performed on the IR and are not specific to any particular target architecture. Examples:
        *   **Constant Folding:** Evaluating constant expressions at compile time (e.g., `x = 2 + 3` becomes `x = 5`).
        *   **Dead Code Elimination:** Removing code that has no effect on the program's output (e.g., assigning a value to a variable that is never used).
        *   **Common Subexpression Elimination:** Identifying and reusing common subexpressions to avoid redundant computations (e.g., `x = a + b; y = a + b` becomes `t = a + b; x = t; y = t`).
        *   **Loop Unrolling:** Expanding the body of a loop by replicating it multiple times to reduce loop overhead.
        *   **Inlining:** Replacing function calls with the actual code of the function to eliminate function call overhead.
    *   **Machine-Dependent Optimizations:** Performed on the target code and are specific to the target architecture. Examples:
        *   **Register Allocation:**  Efficiently assigning variables to registers.
        *   **Instruction Scheduling:**  Reordering instructions to minimize pipeline stalls.
        *   **Peephole Optimization:**  Examining a small "window" of instructions and replacing inefficient sequences with more efficient ones.

*   **Example (Constant Folding and Common Subexpression Elimination):**

    *   **Original Code:**
        ```
        x = 2 * 3 + y
        z = 2 * 3 + y
        ```

    *   **After Constant Folding:**
        ```
        x = 6 + y
        z = 6 + y
        ```

    *   **After Common Subexpression Elimination:**
        ```
        t = 6 + y
        x = t
        z = t
        ```

## V. Register Allocation

*   **Definition:** The process of assigning variables to registers to reduce memory accesses and improve performance.

*   **Importance:** Registers are much faster than memory, so using registers effectively can significantly improve execution speed.

*   **Challenges:**
    *   **Limited Number of Registers:** The number of registers is limited, so not all variables can be allocated to registers.
    *   **Register Spilling:** When there are not enough registers available, some variables must be "spilled" to memory.  Spilling involves storing the variable's value in memory and loading it back when needed, which increases execution time.
    *   **Interference:**  Two variables interfere if they are both live at the same time and cannot be assigned to the same register.

*   **Techniques:**
    *   **Graph Coloring:**  Representing the register allocation problem as a graph coloring problem.  Variables are nodes, and edges connect interfering variables.  The goal is to color the graph with a minimum number of colors (registers).
    *   **Linear Scan Register Allocation:**  Scanning the program linearly and assigning registers to variables based on their liveness intervals.

*   **Liveness Analysis:**  Determines the "liveness" of a variable at each point in the program. A variable is live if its value might be used later. Liveness information is crucial for register allocation.

*   **Example (Simplified Register Allocation):**

    *   **Code:**
        ```
        a = b + c
        d = a * e
        f = d + g
        ```

    *   **Liveness Analysis (Simplified):**
        *   After line 1: `a` is live.
        *   After line 2: `d` is live.
        *   After line 3: `f` is live.

    *   **Possible Register Allocation (assuming 3 registers: r1, r2, r3):**
        ```assembly
        mov r1, b      ; a = b + c
        add r1, c
        mov a, r1       ; Store value of a in memory because we might need r1 later.  Alternatively, consider spilling b or c.
        mov r2, r1      ; d = a * e
        mul r2, e
        mov d, r2       ; Store value of d in memory.  Alternatively, spill a.
        mov r3, r2      ; f = d + g
        add r3, g
        mov f, r3
        ```

    *   **Optimization (Spilling a instead of storing a and immediately loading it back):**
        ```assembly
        mov r1, b      ; a = b + c
        add r1, c
        mov r2, r1      ; d = a * e  (a already in r1)
        mul r2, e
        mov d, r2       ; Store value of d in memory.
        mov r3, r2      ; f = d + g
        add r3, g
        mov f, r3
        ```

## VI. Important Points to Remember

*   The back end is crucial for generating efficient and correct target code.
*   Instruction selection, code optimization, and register allocation are key tasks performed in the back end.
*   The choice of IR can significantly impact the effectiveness of back-end optimizations.
*   Understanding the target architecture is essential for effective code generation.
*   Register allocation is a challenging problem, and heuristics are often used to find near-optimal solutions.

## VII. Practice Questions/Exercises

1.  **Explain the difference between machine-independent and machine-dependent optimizations.**  Give examples of each.
    *   **Answer:** Machine-independent optimizations are performed on the IR and are not specific to any particular target architecture (e.g., constant folding, dead code elimination). Machine-dependent optimizations are performed on the target code and are specific to the target architecture (e.g., register allocation, instruction scheduling).

2.  **What is register spilling and why is it necessary?**
    *   **Answer:** Register spilling occurs when there are not enough registers available to hold all the live variables.  Variables must be "spilled" to memory (stored in memory and loaded back when needed), which increases execution time. It is necessary because the number of registers is a finite resource.

3.  **Describe the role of liveness analysis in register allocation.**
    *   **Answer:** Liveness analysis determines which variables are "live" (their values might be used later) at each point in the program. This information is crucial for register allocation because it helps to identify which variables interfere with each other and cannot be assigned to the same register.

4.  **Consider the following IR code:**

    ```
    t1 = a + b
    t2 = t1 * c
    d = t1 + e
    f = t2 + d
    ```

    **Assuming you have only two registers available (r1 and r2), provide a possible register allocation strategy and the resulting assembly code (you can use simplified assembly for demonstration purposes).**
    *   **Answer:**
        ```assembly
        ; Allocate r1 for t1
        mov r1, a    ; t1 = a + b
        add r1, b

        ; t1 will be needed again so store it temporarily
        mov t1_mem, r1

        ; Allocate r2 for t2
        mov r2, r1    ; t2 = t1 * c; can't hold both at the same time
        mul r2, c

        ; d = t1 + e requires t1, load it back from t1_mem
        mov r1, t1_mem  ; Load it back
        add r1, e

        ; f = t2 + d
        mov r2, r2  ; load t2 as well
        add r2, r1  ; t2 + d

        mov f, r2

        ; d is no longer used, so register r1 is now free.
        ```

5.  **What are some of the factors that make instruction selection a challenging task?**
    *   **Answer:** Instruction set complexity, target architecture variations, cost modeling, and the need to find an optimal (or near-optimal) sequence of instructions.
