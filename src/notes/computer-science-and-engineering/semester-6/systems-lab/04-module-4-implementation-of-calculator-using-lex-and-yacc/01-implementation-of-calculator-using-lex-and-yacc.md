### 1. Introduction to LEX and YACC

**What are LEX and YACC?**

LEX and YACC are tools used in the development of compilers and interpreters. They automate the process of creating lexical analyzers and parsers, respectively, based on user-defined specifications.

*   **LEX (Lexical Analyzer Generator):**
    *   Takes a specification file (usually with a `.l` extension) as input.
    *   Generates a C source file for a lexical analyzer (scanner).
    *   The lexical analyzer's job is to read the input stream (source code) and break it down into a sequence of meaningful units called **tokens**.
    *   **Key Concept: Regular Expressions:** LEX uses regular expressions to define patterns that match different types of tokens.

*   **YACC (Yet Another Compiler-Compiler):**
    *   Takes a specification file (usually with a `.y` extension) as input.
    *   Generates a C source file for a parser.
    *   The parser's job is to take the sequence of tokens produced by the lexical analyzer and check if they conform to the defined grammar of the programming language.
    *   If the tokens form a valid structure, the parser builds an **Abstract Syntax Tree (AST)** or directly performs actions associated with the grammar rules.
    *   **Key Concept: Context-Free Grammars (CFGs):** YACC uses grammar rules, typically expressed in BNF (Backus-Naur Form) or EBNF, to define the structure of valid expressions.

**Why use LEX and YACC for a Calculator?**

A calculator is essentially a mini-compiler for arithmetic expressions.
*   **LEX** helps identify the basic components of an expression (numbers, operators, parentheses).
*   **YACC** helps understand how these components are put together to form a valid calculation and then evaluates it.

### 2. Implementing a Calculator using LEX

The `.l` file for LEX defines **tokens** using regular expressions.

#### 2.1 Structure of a LEX Specification File (`.l`)

A LEX specification file has three main sections, separated by double percent signs (`%%`):

1.  **Definitions Section:**
    *   Includes C preprocessor directives (`#include`).
    *   Defines symbolic names (macros) for regular expressions.
    *   Can include C functions and declarations.

2.  **Rules Section:**
    *   Contains pairs of **regular expressions** and associated **C actions**.
    *   When a regular expression matches a part of the input, the corresponding C action is executed.

3.  **User Subroutines Section:**
    *   Contains auxiliary C functions and code that can be called from the actions in the rules section.

```lex
%{
/* Definitions Section */
#include <stdio.h>
#include "y.tab.h" // Include header generated by YACC
%}

/* Rules Section */
%%
[0-9]+ { return NUMBER; } // Match one or more digits and return the NUMBER token
"+"    { return ADD; }    // Match '+' and return the ADD token
"-"    { return SUB; }    // Match '-' and return the SUB token
"*"    { return MUL; }    // Match '*' and return the MUL token
"/"    { return DIV; }    // Match '/' and return the DIV token
"("    { return LPAREN; } // Match '(' and return the LPAREN token
")"    { return RPAREN; } // Match ')' and return the RPAREN token
[ \t]+ ;                 // Ignore whitespace and tabs
\n     { return EOL; }    // Match newline and return EOL token (End Of Line)
.      { fprintf(stderr, "Invalid character: %s\n", yytext); } // Handle unexpected characters
%%

/* User Subroutines Section */
// No additional functions needed for this basic calculator
```

**Key Concepts and Definitions:**

*   **Token:** A fundamental unit of a programming language or expression. For a calculator, tokens include numbers, operators, and parentheses.
*   **Lexeme:** The actual sequence of characters in the input that matches a token.
*   **Regular Expression:** A sequence of characters that defines a search pattern.
*   **`yytext`:** A global C string variable in LEX that holds the lexeme currently matched by a rule.
*   **`return <token_name>;`:** When a rule matches, the C action typically returns a token type to the parser (YACC).
*   **`y.tab.h`:** This header file is generated by YACC and contains the definitions of the token types (e.g., `NUMBER`, `ADD`, `SUB`).

**Example:**

If the input is `123 + 45`, LEX will produce the following sequence of tokens:
1.  `NUMBER` (lexeme: "123")
2.  `ADD` (lexeme: "+")
3.  `NUMBER` (lexeme: "45")
4.  `EOL` (lexeme: "\n" - if present)

**Important Point to Remember:** The order of rules in LEX matters. More specific rules should generally appear before more general rules to avoid unintended matches. For example, `+` should come before a general `.` rule.

### 3. Implementing a Calculator using YACC

The `.y` file for YACC defines the **grammar** of the expressions and associates **actions** with grammar rules.

#### 3.1 Structure of a YACC Specification File (`.y`)

A YACC specification file also has three main sections, separated by double percent signs (`%%`):

1.  **Declarations Section:**
    *   `%{ ... %}`: C code to be included in the generated C file (e.g., `#include` statements, global variables).
    *   `%token <type> token_name ...`: Declares the tokens recognized by LEX and used by YACC. The optional `<type>` specifies the data type of the token's value (e.g., `int`, `double`).
    *   `%type <type> non_terminal_name ...`: Declares the data type of non-terminal symbols in the grammar.
    *   `%start start_symbol`: Specifies the start symbol of the grammar.
    *   `%left operator`, `%right operator`, `%nonassoc operator`: Defines operator precedence and associativity.

2.  **Grammar Rules Section:**
    *   Defines the grammar rules in the form: `non_terminal : production_rule { action } ;`
    *   **Non-terminal:** A grammatical symbol that can be further broken down.
    *   **Terminal:** A token recognized by LEX.
    *   **Production Rule:** A combination of terminals and non-terminals that defines the structure.
    *   **Action:** C code executed when a rule is successfully reduced.

3.  **User Subroutines Section:**
    *   Contains auxiliary C functions, including the `main` function and the `yyerror` function.
    *   **`yyerror(const char *s)`:** A mandatory function that YACC calls when a parsing error occurs.

```yacc
%{
/* Declarations Section */
#include <stdio.h>
#include <stdlib.h> // For exit()

// Declare tokens coming from LEX
%token NUMBER
%token ADD SUB MUL DIV
%token LPAREN RPAREN
%token EOL

// Declare non-terminal types
%type <val> expr term factor

// Operator precedence and associativity
%left ADD SUB      // Left-associative, lower precedence
%left MUL DIV      // Left-associative, higher precedence
%nonassoc NEG       // Unary minus (for potential future use, but not strictly needed for basic calc)

// Define the start symbol
%start calculation
%}

%%
/* Grammar Rules Section */

calculation : expr EOL { printf("Result: %d\n", $1); } ; // The entire calculation

expr        : term                     // An expression can be just a term
            | expr ADD term { $$ = $1 + $3; } // Addition: expr + term
            | expr SUB term { $$ = $1 - $3; } // Subtraction: expr - term
            ;

term        : factor                   // A term can be just a factor
            | term MUL factor { $$ = $1 * $3; } // Multiplication: term * factor
            | term DIV factor {
                if ($3 == 0) {
                    fprintf(stderr, "Division by zero!\n");
                    $$ = 0; // Or some error indicator
                } else {
                    $$ = $1 / $3;
                }
            } // Division: term / factor
            ;

factor      : NUMBER { $$ = $1; }           // A factor can be a number
            | LPAREN expr RPAREN { $$ = $2; } // A factor can be an expression in parentheses
            ;
%%

/* User Subroutines Section */

// This is where the global variables from y.tab.h are used.
// Specifically, $1, $2, $3 refer to the values of the symbols in a grammar rule.
// $$ refers to the value of the non-terminal on the left-hand side of the rule.
// For NUMBER, the value comes from the lexer.

// Custom yylex function to drive the lexer
int yylex(void) {
    extern int yylval; // Value of the current token
    int token;

    while ((token = yylex_internal()) != 0) { // yylex_internal is the actual lexer generated by LEX
        if (token == NUMBER) {
            yylval = atoi(yytext); // Convert the lexeme (string) to an integer
        }
        return token;
    }
    return 0; // End of input
}

// Error handling function
void yyerror(const char *s) {
    fprintf(stderr, "Error: %s\n", s);
}

// Main function
int main() {
    printf("Simple Calculator\n");
    printf("Enter expressions (e.g., 10 + (5 * 2))\n");
    printf("Type 'quit' or 'exit' to exit.\n");

    while (1) {
        printf("> ");
        yyparse(); // Start parsing the input
    }

    return 0;
}

// We need to link the LEXer and YACC parser.
// The `yylex_internal` function is the actual lexer generated by `lex.yy.c`.
// We need to make sure the lexer and parser interact correctly.
// The definition of `yylex()` above is crucial for this interaction.
// The `y.tab.h` file contains declarations for `yyparse()` and `yylex()`.
```

**Key Concepts and Definitions:**

*   **Non-terminal:** A symbol representing a grammatical construct (e.g., `expr`, `term`, `factor`).
*   **Terminal:** A token produced by LEX (e.g., `NUMBER`, `ADD`, `SUB`).
*   **Start Symbol:** The non-terminal that represents the entire input structure (e.g., `calculation`).
*   **Production Rule:** Defines how non-terminals can be expanded into sequences of terminals and non-terminals.
*   **`$$`:** Represents the value of the non-terminal on the left-hand side of the production rule. This is where we store the result of calculations.
*   **`$1`, `$2`, `$3`, ...:** Represent the values of the symbols on the right-hand side of the production rule, in order.
*   **Operator Precedence and Associativity:** Crucial for correctly interpreting expressions like `2 + 3 * 4`. YACC's `%left`, `%right`, and `%nonassoc` directives handle this.
    *   **Precedence:** Determines the order of operations. Multiplication and division have higher precedence than addition and subtraction.
    *   **Associativity:** Determines how operators of the same precedence are grouped. For example, `a - b - c` is usually left-associative, meaning `(a - b) - c`.
*   **`yylval`:** A global union variable defined in `y.tab.h` that stores the value associated with a token or non-terminal. We often store the numerical value of a number in `yylval`.
*   **`yyparse()`:** The main parsing function generated by YACC. It calls `yylex()` to get tokens and applies the grammar rules.
*   **`yyerror(const char *s)`:** The error reporting function.

**Example of Rule Evaluation:**

Consider the rule: `expr : expr ADD term { $$ = $1 + $3; } ;`

If the parser has successfully recognized an `expr` with value `10`, then encounters an `ADD` token, and then a `term` with value `5`, the action `{ $$ = $1 + $3; }` will execute.
*   `$1` will hold the value of the left `expr` (10).
*   `$3` will hold the value of the `term` (5).
*   `$$` will be assigned the result of `10 + 5`, which is `15`. This `15` is then associated with the non-terminal `expr` that was just recognized.

### 4. Generating and Compiling the Calculator

**Steps:**

1.  **Create the LEX file (e.g., `calculator.l`):**
    *   Contains the lexical rules and token definitions.

2.  **Create the YACC file (e.g., `calculator.y`):**
    *   Contains the grammar rules and actions.

3.  **Generate the Lexer Source File:**
    *   Command: `lex calculator.l`
    *   This creates `lex.yy.c` (the C source file for the lexer).

4.  **Generate the Parser Source File and Header:**
    *   Command: `yacc -d calculator.y`
    *   The `-d` option tells YACC to generate `y.tab.h`, which contains the token declarations needed by the lexer.
    *   This creates `y.tab.c` (the C source file for the parser) and `y.tab.h`.

5.  **Compile the C Source Files:**
    *   You need to compile both `lex.yy.c` and `y.tab.c` and link them together. You also need to include the `y.tab.h` header.
    *   Command: `cc lex.yy.c y.tab.c -o calculator -ll`
        *   `cc`: The C compiler (e.g., GCC).
        *   `lex.yy.c`: The lexer source file.
        *   `y.tab.c`: The parser source file.
        *   `-o calculator`: Specifies the output executable name.
        *   `-ll`: Links the lex library (often required by LEX-generated code).

6.  **Run the Calculator:**
    *   Command: `./calculator`

**Important Considerations for `y.tab.h` and `yylex`:**

*   **`y.tab.h`:** This header file contains the definitions of tokens (`#define NUMBER 257`, etc.) and the declaration of `yylval`. It must be included in your `.l` file if you want LEX to know about the token types.
*   **Interfacing Lexer and Parser:** The `main` function in `y.tab.c` is a default one. We usually override it with our own `main` in the `.y` file. The `yyparse()` function expects to get tokens by calling `yylex()`. The `yylex()` function (which we often define ourselves in the `.y` file to handle token values) must return the token type and set `yylval` appropriately. The default `yylex()` generated by LEX just returns the token and `yytext`. We need to bridge this by having our custom `yylex` call the internal lexer (`yylex_internal`) and process the results.

**Modified `yylex` in `.y` file:**

A common pattern to integrate LEX and YACC properly is to have the `.y` file provide the `yylex` function that drives the lexer generated by LEX:

```yacc
/* In calculator.y */
%{
#include <stdio.h>
#include <stdlib.h>

// Declarations as before...

// This function will be called by yyparse() to get the next token.
// It drives the lexer generated by LEX.
int yylex(void) {
    extern int yylval; // Value of the current token
    int token;

    // The actual lexer generated by LEX is available as yylex_internal()
    // if you don't redefine yylex in your .l file.
    // However, it's common practice to define yylex in the .y file
    // to manage token values.
    // If you include y.tab.h in your .l file, the lexer will call yyerror
    // if it sees an unrecognized character.
    // The lexer, when matching a NUMBER, will populate yytext.

    while ((token = yylex_internal()) != 0) { // Use yylex_internal if you don't have a custom yylex in .l
        if (token == NUMBER) {
            // The lexer matched a number.
            // yytext contains the string representation of the number.
            // We need to convert it to an integer and store it in yylval.
            yylval = atoi(yytext); // yylval is declared in y.tab.h
        }
        // Return the token type to the parser
        return token;
    }
    return 0; // End of input
}

// yyerror function as before...
void yyerror(const char *s) { /* ... */ }

// main function as before...
int main() { /* ... */ }

%}
// Grammar rules...
%%
```

**To make `yylex_internal` work, you don't define `yylex` in `calculator.l` if you provide it in `calculator.y`.** Or, more cleanly, `lex.yy.c` will define `yylex`. When you compile, the `y.tab.c` file often contains a default `main` and links against the lex library. The `yylex` that `y.tab.c` calls is expected to be provided by `lex.yy.c`.

A common setup:
1.  `calculator.l` defines tokens and returns them, and sets `yylval` for `NUMBER`.
2.  `calculator.y` defines the grammar, includes `y.tab.h`, defines `yyerror`, and provides `main`.
3.  You compile both: `cc calculator.l y.tab.c -o calculator -ll`
    *   `lex.yy.c` gets generated, and `calculator.l` should include `y.tab.h`.
    *   Inside `calculator.l`, the `NUMBER` rule would look like:
        ```lex
        [0-9]+ { yylval = atoi(yytext); return NUMBER; }
        ```
    *   Now, when `cc` compiles them, `y.tab.c` (which contains `yyparse`) will correctly call the `yylex` generated by `lex.yy.c`.

Let's adjust the `.l` file based on this common practice:

**Revised `calculator.l`:**

```lex
%{
#include <stdlib.h> // For atoi
#include "y.tab.h"  // Include the header generated by YACC
%}

/* Rules Section */
%%
[0-9]+    { yylval = atoi(yytext); return NUMBER; } // Store value and return token
"+"       { return ADD; }
"-"       { return SUB; }
"*"       { return MUL; }
"/"       { return DIV; }
"("       { return LPAREN; }
")"       { return RPAREN; }
[ \t]+    ; // Ignore whitespace and tabs
\n        { return EOL; }
.         { fprintf(stderr, "Invalid character: %s\n", yytext); }
%%

// No user subroutines needed here if yylval is set in the rules.
// The yylex function itself is generated by LEX.
```

### 5. Practice Questions and Exercises

**Question 1:**

What is the primary role of LEX in the context of building a calculator?

**Answer:**
LEX's primary role is to perform **lexical analysis**. It reads the input expression, breaks it down into a sequence of tokens (like numbers, operators, and parentheses) based on predefined patterns (regular expressions), and returns these tokens to the parser.

---

**Question 2:**

What is the primary role of YACC in the context of building a calculator?

**Answer:**
YACC's primary role is to perform **syntax analysis** (parsing). It takes the sequence of tokens from LEX and checks if they conform to the defined grammar rules for arithmetic expressions. If the syntax is valid, it can then perform actions, such as evaluating the expression.

---

**Question 3:**

Explain the purpose of `y.tab.h` and where it is generated.

**Answer:**
`y.tab.h` is a header file generated by YACC (when the `-d` option is used). Its purpose is to provide the C preprocessor definitions of the token types (e.g., `NUMBER`, `ADD`, `SUB`) that YACC recognizes and expects from LEX. This header file is then included in the LEX source file (`.l`) so that the lexer knows the numerical values of the tokens it should return to the parser.

---

**Question 4:**

Consider the following grammar rule in YACC:
`expr : expr ADD term { $$ = $1 + $3; } ;`
If `expr` has a value of `20`, `ADD` is the `+` token, and `term` has a value of `5`, what will be the value of `$$`?

**Answer:**
`$$` will be `25`. This is because `$1` refers to the value of the left `expr` (20), and `$3` refers to the value of `term` (5). The action `$$ = $1 + $3;` calculates `20 + 5`.

---

**Question 5:**

Write the LEX rule for recognizing a sequence of one or more digits and assigning its integer value to `yylval`.

**Answer:**
```lex
[0-9]+    { yylval = atoi(yytext); return NUMBER; }
```
*(Assuming `NUMBER` is a token defined in `y.tab.h` and `atoi` is used for conversion.)*

**Question 6 (Challenge):**

Extend the calculator grammar to support exponentiation (`^`) with right-associativity and higher precedence than multiplication.

**Answer:**

**In `calculator.y` (add to declarations):**

```yacc
%token EXP // Assuming EXP is defined in calculator.l
%right EXP // Define EXP as right-associative
```

**Add to grammar rules:**

```yacc
/* Add to term or a new non-terminal for exponentiation */
term        : factor
            | term MUL factor { $$ = $1 * $3; }
            | term DIV factor {
                if ($3 == 0) {
                    fprintf(stderr, "Division by zero!\n");
                    $$ = 0;
                } else {
                    $$ = $1 / $3;
                }
            }
            | term EXP factor { $$ = pow($1, $3); } // Need to include <math.h> for pow
            ;

/* Also need to potentially modify factor if parentheses need to be handled */
factor      : NUMBER { $$ = $1; }
            | LPAREN expr RPAREN { $$ = $2; }
            ;

/* Need to add EXP token declaration */
%token EXP
```

**In `calculator.l` (add the token rule):**

```lex
/* ... other rules ... */
"^"       { return EXP; } // Or use pow if yylval is used for values
/* ... */
```

**Important Note:** For `pow()`, you'll need to include `<math.h>` in the YACC declarations and link with `-lm` during compilation: `cc lex.yy.c y.tab.c -o calculator -ll -lm`. Also, `yylval` might need to be a `double` if using `pow`.

### 6. Important Points to Remember

*   **File Extensions:** Use `.l` for LEX files and `.y` for YACC files.
*   **Separators:** Use `%%` to separate the sections in both `.l` and `.y` files.
*   **Token Definitions:** LEX defines tokens using regular expressions, and YACC declares them using `%token`.
*   **Grammar Rules:** YACC defines the syntax of expressions using context-free grammar rules.
*   **`y.tab.h`:** Crucial for communication between LEX and YACC. LEX needs it to know the token definitions.
*   **`yylval`:** The mechanism for passing values (like numerical values of numbers) from LEX to YACC.
*   **Operator Precedence and Associativity:** Use `%left`, `%right`, and `%nonassoc` in YACC to ensure correct parsing of complex expressions.
*   **Error Handling:** Implement `yyerror` in YACC to report syntax errors gracefully. LEX handles unrecognized characters.
*   **Compilation Order:** Generate C files from `.l` and `.y` first, then compile and link them.
*   **Linking Libraries:** Remember to link with `-ll` for the lex library and `-lm` for the math library if needed.
*   **`yyparse()`:** The core function that drives the parsing process.
