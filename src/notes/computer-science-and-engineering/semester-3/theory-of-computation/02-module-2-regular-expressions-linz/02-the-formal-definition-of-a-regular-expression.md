## THEORY OF COMPUTATION - Module 2: Regular Expressions (Linz) - Formal Definition of a Regular Expression

### Learning Outcomes:

*   Understand the formal definition of a regular expression.
*   Identify valid and invalid regular expressions based on the formal definition.
*   Construct regular expressions from given descriptions.
*   Understand the language generated by a given regular expression.

### 1. Key Concepts and Definitions

*   **Regular Expression (RE):** A sequence of characters that defines a search pattern. These patterns are used for matching strings of text.  Formally, they provide a notation for describing regular languages.

*   **Regular Language:** A language that can be described by a regular expression or, equivalently, accepted by a finite automaton (DFA or NFA).

*   **Alphabet (Σ):** A finite, non-empty set of symbols. For example, Σ = {0, 1} or Σ = {a, b, c}.

*   **Empty String (ε):** A string with zero characters. It's not an element of the alphabet but a string formed from the alphabet.

*   **Empty Set (∅):**  A set containing no elements.  The language represented by the regular expression representing the empty set contains no strings.

*   **Formal Definition of a Regular Expression (Linz):** Let Σ be an alphabet.  The following are the rules for defining regular expressions over Σ, along with the languages they represent:

    *   **Base Cases:**
        *   **ε (Epsilon):** Represents the language {ε}.  This language contains only the empty string.
        *   **a (for any a ∈ Σ):** Represents the language {a}.  This language contains only the string consisting of the single symbol 'a'.
        *   **∅ (Empty Set):** Represents the language { } (the empty set).  This language contains no strings.

    *   **Recursive Cases (Operations on Regular Expressions):**  If `r` and `s` are regular expressions, then the following are also regular expressions:
        *   **(r + s):**  Represents the language L(r) ∪ L(s). This is the *union* (or sometimes denoted `r | s`) of the languages represented by `r` and `s`. It accepts any string that is accepted by either `r` or `s` (or both).
        *   **(rs):** Represents the language L(r)L(s). This is the *concatenation* of the languages represented by `r` and `s`. It accepts any string that can be formed by concatenating a string accepted by `r` followed by a string accepted by `s`.
        *   **(r\*):** Represents the language L(r)\*. This is the *Kleene star* (or Kleene closure) of the language represented by `r`. It accepts any string formed by concatenating zero or more strings accepted by `r`.  That is, L(r)\* = {ε} ∪ L(r) ∪ L(r)L(r) ∪ L(r)L(r)L(r) ∪ ...
        *   **(r):** Represents the same language as `r`, L(r). Parentheses are used for grouping and precedence control.

*   **Operator Precedence:**  Kleene star (*) has the highest precedence, followed by concatenation, and then union (+). Parentheses are used to override this default precedence.

*   **Language Generated by a Regular Expression (L(r)):** The set of all strings that can be matched by the regular expression `r`.

### 2. Identifying Valid and Invalid Regular Expressions

Based on the formal definition, we can identify valid and invalid regular expressions:

**Valid Regular Expressions (over Σ = {a, b}):**

*   `a`
*   `b`
*   `ε`
*   `∅`
*   `(a + b)`
*   `(ab)`
*   `a*`
*   `(a + b)*`
*   `a(ba)*b`
*   `((a + ε)b*)`

**Invalid Regular Expressions (over Σ = {a, b}):**

*   `(a + )`  Missing operand for the union operator.
*   `a**`  Kleene star cannot be applied to another Kleene star directly; grouping required.
*   `(a - b)` Subtraction is not a defined operation in regular expressions.
*   `a+b`   While commonly used, for strict adherence to the Linz definition, parentheses are typically used to ensure correct precedence and clarity, especially in more complex expressions. `(a+b)` is preferred.
*   `a?`  '?' (zero or one occurrence) is shorthand, but not part of the fundamental definition. It can be represented by `(ε + a)`.
*   `a{2}`  Curly braces for repetition count are shorthand, not fundamental.  It can be represented by `aa`.

**Important Note:** Many tools and programming languages extend the basic definition of regular expressions with shorthand notations (e.g., `?`, `+`, `[a-z]`, `{n}`), character classes, and other features.  However, the *formal* definition provides the foundation.  Any regular expression in a "richer" syntax can theoretically be translated into an equivalent expression using only the basic operators.

### 3. Constructing Regular Expressions from Given Descriptions

Let's build some regular expressions (over Σ = {0, 1}):

*   **All strings that start with 0:**  `0(0 + 1)*`
*   **All strings that end with 1:**  `(0 + 1)*1`
*   **All strings containing the substring "11":**  `(0 + 1)*11(0 + 1)*`
*   **All strings that have an even number of 0s:**  `(1*01*01*)*`  (Note: This one is trickier. It ensures pairs of 0s are present, possibly separated by any number of 1s.)
*   **All strings that start and end with the same symbol:** `0(0+1)*0 + 1(0+1)*1 + 0 + 1`
*   **All strings that have at least one 1:**  `0*1(0 + 1)*`

### 4. Understanding the Language Generated by a Given Regular Expression

Let's consider some regular expressions and their corresponding languages:

*   **r = `0*`:**  L(r) = {ε, 0, 00, 000, 0000, ...} (All strings consisting of zero or more 0s)
*   **r = `(0 + 1)`:** L(r) = {0, 1} (Strings containing either 0 or 1)
*   **r = `(0 + 1)*`:** L(r) = {ε, 0, 1, 00, 01, 10, 11, 000, 001, ...} (All possible strings over the alphabet {0, 1})
*   **r = `1(0 + 1)*1`:** L(r) = {11, 101, 111, 1001, 1011, 1101, 1111, ...} (All strings that start and end with 1)
*   **r = `(01)*`:** L(r) = {ε, 01, 0101, 010101, ...} (All strings consisting of zero or more repetitions of "01")

### 5. Practice Questions/Exercises with Answers

**Exercise 1:**

Which of the following is a valid regular expression over the alphabet Σ = {a, b}?

a)  `a++`
b)  `(a + b)*`
c)  `(a*b)`
d)  `(a + b)(`
e)  Both b and c.

**Answer:** e) Both b and c.

**Exercise 2:**

Write a regular expression over the alphabet Σ = {0, 1} that represents the language of all strings that contain the substring "001".

**Answer:**  `(0 + 1)*001(0 + 1)*`

**Exercise 3:**

Describe the language represented by the regular expression `(a + b)a*`. Assume the alphabet is Σ = {a, b}.

**Answer:** The language consists of all strings that start with either 'a' or 'b', followed by zero or more 'a's.  Examples: a, b, aa, ba, aaa, baaa, etc.

**Exercise 4:**

True or False: The regular expression `(a + b)*` represents the language of all possible strings (including the empty string) over the alphabet Σ = {a, b}.

**Answer:** True

**Exercise 5:**

Provide a regular expression (over Σ = {a, b}) for the language of strings containing at least one `a` and at least one `b`.

**Answer:** `a(a+b)*b + b(a+b)*a + (a+b)*a(a+b)*b + (a+b)*b(a+b)*a`

(Explanation: This accounts for all possibilities: string starts with 'a' then has 'b' or starts with 'b' then has `a`. There are ways to simplify this (e.g.  `a+b*ab+b*ba)` but the above is more clearly derived from the requirements.)

### 6. Important Points to Remember

*   The formal definition of regular expressions is recursive, building complex expressions from simpler ones.
*   Understanding operator precedence is crucial for correctly interpreting regular expressions.  Use parentheses for clarity, even when not strictly required.
*   While many extended notations exist, always remember the core components of the formal definition.
*   Regular expressions are powerful tools for pattern matching and text manipulation, but their expressive power is limited to regular languages.

By understanding these concepts, definitions, examples and practice exercises, you'll be well-equipped to work with regular expressions and their associated languages within the context of Theory of Computation.
