# THEORY OF COMPUTATION: Module 2 - Regular Expressions (Linz): Inherent Ambiguity

These notes cover the concept of inherent ambiguity within the context of regular languages, drawing from the textbook "An Introduction to Formal Languages and Automata" by Peter Linz.

## 1. Learning Outcomes

By the end of this module, you should be able to:

*   Understand the definition of ambiguity in context-free grammars.
*   Understand the concept of inherent ambiguity.
*   Determine whether a given grammar is ambiguous.
*   Recognize examples of inherently ambiguous languages.
*   Explain why regular languages cannot be inherently ambiguous.

## 2. Key Concepts and Definitions

### 2.1. Ambiguity in Context-Free Grammars (CFGs)

*   **Definition:** A context-free grammar (CFG) *G* is said to be *ambiguous* if there exists at least one string *w* in *L(G)* (the language generated by *G*) that has *two or more different parse trees* or, equivalently, *two or more different leftmost derivations*.

*   **Parse Tree:** A hierarchical representation of the derivation of a string according to a grammar.

*   **Leftmost Derivation:** A derivation where, at each step, the leftmost variable is replaced according to a production rule.

*   **Example:**
    Consider the grammar G:
        *   S -> aSb | SS | ε

    The string "abab" can be generated by two different parse trees (or two different leftmost derivations):

    *   **Derivation 1:** S => aSb => a(aSb)b => aabb
    *   **Derivation 2:** S => SS => aSbS => aSb => aabb

    Therefore, the grammar *G* is ambiguous.

### 2.2. Inherent Ambiguity

*   **Definition:** A context-free language *L* is said to be *inherently ambiguous* if *every* context-free grammar that generates *L* is ambiguous.  This means you can't find *any* unambiguous grammar for that language.

*   **Important Implication:**  It's not enough to find one ambiguous grammar for a language to conclude it's inherently ambiguous. You need to prove that *every possible* grammar for that language must be ambiguous.  This is a much harder task.

### 2.3. Regular Languages and Ambiguity

*   **Theorem:**  All regular languages are *not inherently ambiguous*.

*   **Explanation:**  Regular languages can be defined by Deterministic Finite Automata (DFAs). DFAs, by definition, have a single, deterministic path for any given input string.  This deterministic behavior can be directly translated into an unambiguous context-free grammar.

*   **Proof Sketch (Simplified):** For every DFA *M* recognizing a regular language *L*, we can construct an unambiguous CFG *G* as follows:

    *   Each state *q<sub>i</sub>* in *M* becomes a variable *A<sub>i</sub>* in *G*.
    *   If *δ(q<sub>i</sub>, a) = q<sub>j</sub>*  (where *δ* is the transition function of *M*), then add the production *A<sub>i</sub> -> aA<sub>j</sub>* to *G*.
    *   If *q<sub>i</sub>* is an accepting state, add the production *A<sub>i</sub> -> ε* to *G*.
    *   The start symbol of *G* is *A<sub>s</sub>*, where *q<sub>s</sub>* is the start state of *M*.

    This constructed grammar generates the same language as the DFA, and because the DFA is deterministic, the grammar is unambiguous. Since any regular language has an equivalent DFA, it follows that any regular language has an equivalent unambiguous CFG and thus cannot be inherently ambiguous.

## 3. Examples of Inherently Ambiguous Languages

While regular languages are *not* inherently ambiguous, context-free languages *can* be. Here are some examples:

*   **L = {a<sup>n</sup>b<sup>n</sup>c<sup>m</sup> | n, m ≥ 0} ∪ {a<sup>n</sup>b<sup>m</sup>c<sup>m</sup> | n, m ≥ 0}**

    *   This language contains strings of the form a<sup>n</sup>b<sup>n</sup>c<sup>m</sup> and a<sup>n</sup>b<sup>m</sup>c<sup>m</sup>.  The problem arises when n = m.  Strings like "aabbcc" can be parsed as either an a<sup>n</sup>b<sup>n</sup>c<sup>m</sup> string (where n = 2, m = 2) or as an a<sup>n</sup>b<sup>m</sup>c<sup>m</sup> string (where n = 2, m = 2). Any grammar trying to cover both cases will inevitably have ambiguity in these overlapping strings.

*   **L = { a<sup>i</sup>b<sup>j</sup>c<sup>k</sup> | i = j or j = k }**

    *   Similar to the previous example, the inherent ambiguity arises from the overlap when i=j and j=k (i.e., i=j=k).  The string a<sup>n</sup>b<sup>n</sup>c<sup>n</sup> can be generated in two different ways: once by the "i = j" part and once by the "j = k" part.

## 4. Why Regular Languages Cannot Be Inherently Ambiguous

The core reason regular languages are not inherently ambiguous is their direct connection to DFAs:

*   **Deterministic Nature:** DFAs process strings in a deterministic manner.  For a given input, there is only one possible path the DFA can take.
*   **Unambiguous Grammar Construction:** This deterministic nature allows us to construct an *unambiguous* context-free grammar directly from the DFA. Since we can *always* find an unambiguous CFG for a regular language, it cannot be inherently ambiguous.

## 5. Identifying Ambiguity in a Grammar

*   **Attempt to derive a string in multiple ways:** The most common technique is to try and find a string that can be generated by the grammar in two different ways. This can be done by creating two different parse trees or by finding two different leftmost (or rightmost) derivations.

*   **Use Parser Generators:** Tools like ANTLR, Yacc, or Bison can detect ambiguity in grammars during compilation. However, these tools can only identify ambiguity; they cannot prove inherent ambiguity.

*   **Look for patterns:** Certain grammar patterns can be indicators of potential ambiguity, such as productions like `S -> S S`, `S -> a S a`, or cases where the same variable can derive multiple similar structures.

## 6. Practice Questions and Exercises

**Question 1:**  Consider the grammar G: S -> aSb | bSa | ε.  Is this grammar ambiguous?

**Answer 1:** Yes. The string "ababa" can be derived as follows:

*   S => aSb => a(bSa)b => ababa
*   S => bSa => b(aSb)a => ababa

Therefore, G is ambiguous.

**Question 2:** Is the language L = {a<sup>n</sup>b<sup>n</sup> | n ≥ 0} inherently ambiguous? Why or why not?

**Answer 2:** No. This language is context-free but *not* inherently ambiguous.  We can construct an *unambiguous* CFG for it:

*   S -> aSb | ε

This grammar generates the language with only one possible parse tree for each string.

**Question 3:** Explain why regular languages cannot be inherently ambiguous.

**Answer 3:** Regular languages can be defined by DFAs. DFAs are deterministic, meaning that for a given input, there is only one possible path the DFA can take. This determinism allows us to construct an equivalent *unambiguous* context-free grammar directly from the DFA. Because we can always construct an unambiguous CFG for a regular language, no regular language is inherently ambiguous.

**Question 4:**  The following grammar generates a simplified version of arithmetic expressions: E -> E + E | E * E | id.  Is this grammar ambiguous? Why?

**Answer 4:** Yes, this grammar is ambiguous.  Consider the string "id + id * id".  It can be parsed in two different ways, leading to different operator precedence:

*   (id + id) * id  (Grouping the addition first)
*   id + (id * id)  (Grouping the multiplication first)

The ambiguity arises because the grammar doesn't specify operator precedence or associativity.

## 7. Important Points to Remember

*   **Ambiguous Grammar vs. Inherently Ambiguous Language:**  A grammar is ambiguous if it can generate a string in multiple ways.  A language is *inherently* ambiguous if *every* grammar for it is ambiguous.

*   **Regular Languages and Unambiguity:**  All regular languages have an equivalent unambiguous CFG and therefore are not inherently ambiguous.

*   **Proving Inherent Ambiguity:**  Proving that a language is inherently ambiguous is a complex task; you need to demonstrate that *no* unambiguous grammar can generate the language.  This is usually done using pumping lemma techniques or other advanced methods.

*   **Examples are Key:**  Understanding the examples of inherently ambiguous languages is helpful for recognizing the characteristic patterns that lead to this property.

These notes provide a solid foundation for understanding inherent ambiguity within the context of regular languages and context-free grammars. Remember to review the examples carefully and work through the practice problems to solidify your understanding. Good luck!
