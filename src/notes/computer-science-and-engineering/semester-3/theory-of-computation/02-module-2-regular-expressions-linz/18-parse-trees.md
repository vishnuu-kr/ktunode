# THEORY OF COMPUTATION - Module 2: Regular Expressions (Linz) - Topic: Parse Trees

## Learning Outcomes:

*   Understand the concept of parse trees in the context of regular expressions.
*   Be able to construct a parse tree for a given regular expression.
*   Be able to evaluate a parse tree to determine the language accepted by the regular expression.
*   Understand the relationship between parse trees and the structure of regular expressions.

## 1. Introduction to Parse Trees

*   **Definition:** A parse tree (also called a derivation tree or syntax tree) is a graphical representation of the syntactic structure of a string according to a formal grammar. In the context of regular expressions, it visually represents how a particular string is derived from the regular expression.

*   **Purpose:**  Parse trees help visualize how a regular expression breaks down into smaller, manageable components and how those components combine to accept a specific string. They make it easier to understand the structure of a regular expression and its corresponding language.

*   **Key Components:**
    *   **Root Node:**  Represents the entire regular expression.
    *   **Internal Nodes:** Represent operations (concatenation, union, Kleene star) and sub-expressions.
    *   **Leaf Nodes:** Represent terminal symbols (symbols from the alphabet) or the empty string (ε).

## 2. Constructing Parse Trees for Regular Expressions

*   **General Approach:** We build the tree bottom-up, starting from the smallest sub-expressions (single characters or ε) and combining them according to the operators in the regular expression.

*   **Construction Rules (Examples):**

    *   **Single Symbol (a ∈ Σ):**  The tree consists of a single node labeled 'a'.

        ```
        a
        ```

    *   **Empty String (ε):** The tree consists of a single node labeled 'ε'.

        ```
        ε
        ```

    *   **Concatenation (R.S):**  Create a root node labeled '.'.  The left subtree represents R and the right subtree represents S.

        ```
              .
             / \
            R   S
        ```

    *   **Union (R + S):** Create a root node labeled '+'. The left subtree represents R and the right subtree represents S.

        ```
              +
             / \
            R   S
        ```

    *   **Kleene Star (R*):** Create a root node labeled '*'.  The subtree represents R.

        ```
              *
             /
            R
        ```

*   **Operator Precedence:** Parentheses are used to override the default operator precedence (Kleene star > concatenation > union).  Build the tree according to the operator precedence and the parentheses structure.

*   **Example 1:  Regular Expression: `(a+b).c`**

    1.  `a`:

        ```
        a
        ```

    2.  `b`:

        ```
        b
        ```

    3.  `a + b`:

        ```
              +
             / \
            a   b
        ```

    4.  `c`:

        ```
        c
        ```

    5.  `(a + b) . c`:

        ```
                    .
                   / \
                  +   c
                 / \
                a   b
        ```

*   **Example 2: Regular Expression: `a.(b*+c)`**

    1. `a`:
        ```
        a
        ```
    2. `b`:
        ```
        b
        ```
    3. `b*`:
        ```
              *
             /
            b
        ```
    4. `c`:
        ```
        c
        ```
    5. `b* + c`:
        ```
               +
              / \
             *   c
            /
           b
        ```
    6. `a.(b* + c)`:

        ```
                  .
                 / \
                a   +
                   / \
                  *   c
                 /
                b
        ```

## 3. Evaluating Parse Trees

*   **Purpose:**  To determine if a given string is accepted by the regular expression represented by the tree.

*   **Process:**  Traverse the tree, starting from the leaves and working towards the root. At each node, apply the corresponding operation to the strings generated by its subtrees.

*   **Evaluation Rules:**

    *   **Leaf Node (a):** The string 'a' is accepted.

    *   **Leaf Node (ε):** The empty string is accepted.

    *   **Concatenation (.):** The strings accepted by the left subtree are concatenated with the strings accepted by the right subtree.

    *   **Union (+):** The strings accepted by the left subtree are combined (union) with the strings accepted by the right subtree.  Any string accepted by either subtree is accepted.

    *   **Kleene Star (*):**  The empty string (ε) and any concatenation of zero or more strings accepted by the subtree are accepted.  (e.g., if subtree accepts "a", "aa", "aaa", etc., are also accepted)

*   **Example: Parse Tree for `(a+b).c` with input string "ac"**

    1. Start at the leaf nodes. `a` accepts "a", `b` accepts "b", and `c` accepts "c".
    2. The '+' node combines "a" and "b", accepting the strings "a" and "b".
    3. The '.' node concatenates the strings accepted by the left subtree ("a", "b") with the string accepted by the right subtree ("c"). This results in the strings "ac" and "bc".
    4. Since "ac" is one of the resulting strings, the input string "ac" is accepted by the regular expression.

*   **Important Note:** Evaluation focuses on whether the entire tree represents a string that *matches* the input.  A single successful path through the tree leading to a successful match is sufficient for acceptance.

## 4. Relationship between Parse Trees and Regular Expression Structure

*   The structure of the parse tree directly mirrors the structure of the regular expression. Each operator in the regular expression becomes an internal node in the tree.
*   Parse trees provide a visual representation of the syntactic structure of the regular expression, making it easier to understand the order of operations and how different parts of the expression contribute to the overall language.
*   Parse trees can be used to check the validity of a string against a regular expression by tracing a path from the root to the leaves and verifying that the string can be generated according to the rules defined by the tree.
*   The parse tree makes explicit the order in which the operations are applied.  This can be vital in understanding why a regular expression behaves the way it does.

## 6. Answers to Practice Questions

1.  **Parse tree for `a.(b+c)*`:**

    ```
                  .
                 / \
                a   *
                   /
                  +
                 / \
                b   c
    ```

2.  **Parse tree for `(a.b)* + c`:**

    ```
                  +
                 / \
                *   c
               /
              .
             / \
            a   b
    ```

3.  **Parse tree for `a*.b` accepting "aaaaab":**

    ```
                 .
                / \
               *   b
              /
             a
            / \
           a   a
          / \
         a   a
    ```

4.  **Regular expression represented by the tree:** `a*.b`

5.  **String "aba" and regular expression `(a+b)*a`:**

    Yes, the string "aba" belongs to the language.  Here's a possible parse tree:

    ```
                  .
                 / \
                *   a
               /
              +
             / \
            .   b
           / \
          a   +
             / \
            ε   b   <-- this branch isn't used, but it demonstrates alternatives
        ```

    In this parse tree, the `*` operator generates `ab` from `a+b`.  Then, `aba` is generated when combined with the final `a`.  While other tree configurations are possible that might not match, this one demonstrates that "aba" *can* be generated, thus belonging to the language.

## 7. Important Points to Remember

*   Parse trees provide a visual aid for understanding regular expression structure.
*   Construction is bottom-up, following operator precedence.
*   Evaluation is also bottom-up, applying operations at each node.
*   Multiple parse trees can exist for a given string and regular expression, especially with Kleene star. The regular expression accepts the string if *at least one* parse tree exists.
*   Understanding operator precedence (Kleene star > concatenation > union) is crucial for correct parse tree construction.
*   Parentheses are used to override precedence.
