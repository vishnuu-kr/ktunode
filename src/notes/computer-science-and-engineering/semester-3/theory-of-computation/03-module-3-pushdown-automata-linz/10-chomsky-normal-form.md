# THEORY OF COMPUTATION - Module 3: Pushdown Automata - Topic: Chomsky Normal Form (CNF)

**Description:** This module delves into the concept of Chomsky Normal Form (CNF), a standardized form for Context-Free Grammars (CFGs), and its significance in simplifying parsing and other computations related to CFGs.

**Learning Outcomes:**

Upon completion of this topic, you should be able to:

*   Define Chomsky Normal Form (CNF).
*   Understand the benefits of converting a CFG to CNF.
*   Describe the steps involved in converting a CFG to CNF.
*   Apply the conversion process to transform a given CFG into CNF.
*   Verify that the converted grammar in CNF generates the same language as the original grammar (excluding the empty string, if applicable).

## 1. Introduction to Chomsky Normal Form (CNF)

*   **Definition:** A context-free grammar (CFG) is in *Chomsky Normal Form (CNF)* if every production rule is of one of the following two forms:

    *   `A -> BC` where A, B, and C are variables (non-terminals) and B, C ≠ Start Symbol
    *   `A -> a` where A is a variable and `a` is a terminal.

*   **Note on Start Symbol:**  The start symbol *cannot* appear on the right-hand side of any production rule.  To ensure this, it might be necessary to create a new start symbol.
*   **Significance:** CNF simplifies parsing algorithms (like CYK algorithm), grammar analysis, and other computations involving CFGs. It provides a structured and uniform representation that allows for efficient processing.

## 2. Benefits of Converting to CNF

*   **Parsing Simplification:** CNF facilitates efficient parsing algorithms, particularly bottom-up parsing methods like the CYK (Cocke-Younger-Kasami) algorithm.  The fixed structure of production rules makes it easier to build parsing tables and determine if a string belongs to the language generated by the grammar.
*   **Algorithm Efficiency:**  The restricted form of productions (exactly two variables or a single terminal) can improve the time complexity of certain algorithms that operate on CFGs.
*   **Proof Simplification:**  CNF can simplify proofs and arguments related to CFGs, as the standard form provides a consistent framework.
*   **Unambiguity (Indirectly):** While CNF doesn't guarantee unambiguity, it's a crucial step in many techniques for analyzing or transforming CFGs related to ambiguity.

## 3. Conversion Process: Converting a CFG to CNF

The process of converting a CFG to CNF typically involves these steps:

1.  **Eliminate Null Productions (A -> ε):**
    *   Identify all null-producing variables (variables that can derive ε).
    *   For each production `A -> B`, if `B` is null-producing, add `A -> ε` to the grammar.
    *   After adding all necessary null productions, remove all original null productions *except* from the start symbol `S` if `ε` is in the language. If `ε` is in the language, then the start symbol CAN derive `ε`, and you must create a new start symbol `S'` and the productions `S' -> S | ε` where S is the old start symbol.
    *   For each production containing `B`, add a new production where `B` is removed.  For instance, if `A -> xByCz` and `B` is null-producing, add `A -> x yCz` as well.
2.  **Eliminate Unit Productions (A -> B):**
    *   Identify all unit productions.
    *   For each unit production `A -> B`, find all productions `B -> γ`, where γ is a string of terminals and/or variables.
    *   Add `A -> γ` to the grammar for each such production.
    *   Remove the original unit production `A -> B`.
3.  **Eliminate Terminals in Right-Hand Sides (except for A -> a):**
    *   For each terminal `a` appearing on the right-hand side of a production with more than one symbol, create a new variable `X_a` and a production `X_a -> a`.
    *   Replace each occurrence of `a` in the original production with `X_a`.  Example:  `A -> bCd` becomes `A -> X_b C X_d`, with `X_b -> b` and `X_d -> d`.
4.  **Eliminate Long Productions (A -> BCD...):**
    *   For each production with more than two variables on the right-hand side, introduce new variables to break down the production into a series of productions with exactly two variables on the right-hand side.
    *   For example, `A -> BCDE` can be replaced with the following productions:
        *   `A -> B X1`
        *   `X1 -> C X2`
        *   `X2 -> DE`

## 4. Example: Converting a CFG to CNF

Let's convert the following CFG to CNF:

```
S -> aSa | bSb | a | b | ε
```

**Step 1: Eliminate Null Productions**

*   S -> ε is a null production. Because ε is in the language, we must create a new start symbol S' and the production S' -> S | ε.
*   The grammar now becomes:
    *   `S' -> S | ε`
    *   `S -> aSa | bSb | a | b`

**Step 2: Eliminate Unit Productions**

*   S' -> S is a unit production. Replacing S with its productions:
    *   `S' -> aSa | bSb | a | b | ε`
    *   `S -> aSa | bSb | a | b`

**Step 3: Eliminate Terminals in Right-Hand Sides (except for A -> a)**

*   Create `X_a -> a` and `X_b -> b`.
*   Replace 'a' and 'b' in productions with more than one symbol on the RHS:
    *   `S' -> X_a S X_a | X_b S X_b | a | b | ε`
    *   `S -> X_a S X_a | X_b S X_b | a | b`
    *   `X_a -> a`
    *   `X_b -> b`

**Step 4: Eliminate Long Productions**

*   `S' -> X_a S X_a` becomes:
    *   `S' -> X_a A1`
    *   `A1 -> S X_a`
*   `S' -> X_b S X_b` becomes:
    *   `S' -> X_b A2`
    *   `A2 -> S X_b`
*   `S -> X_a S X_a` becomes:
    *   `S -> X_a A3`
    *   `A3 -> S X_a`
*   `S -> X_b S X_b` becomes:
    *   `S -> X_b A4`
    *   `A4 -> S X_b`

**Final CNF Grammar:**

```
S' -> X_a A1 | X_b A2 | a | b | ε
S -> X_a A3 | X_b A4 | a | b
A1 -> S X_a
A2 -> S X_b
A3 -> S X_a
A4 -> S X_b
X_a -> a
X_b -> b
```

## 5. Practice Questions/Exercises

**Question 1:** Convert the following CFG to CNF:

```
S -> AB
A -> aA | b
B -> bB | a
```

**Answer:**

**Step 1: No Null Productions**

**Step 2: No Unit Productions**

**Step 3: Eliminate Terminals in RHS (except A -> a)**

*   `S -> AB`
*   `A -> X_a A | b`
*   `B -> X_b B | a`
*   `X_a -> a`
*   `X_b -> b`

**Step 4: Eliminate Long Productions**

*   `S -> AB`
*   `A -> X_a A | b`
*   `B -> X_b B | a`
*   `X_a -> a`
*   `X_b -> b`

The CNF grammar is:

```
S -> AB
A -> X_a A | b
B -> X_b B | a
X_a -> a
X_b -> b
```

**Question 2:** Convert the following CFG to CNF:

```
S -> ASA | aB
A -> B | S
B -> b
```

**Answer:**

**Step 1: No Null Productions**

**Step 2: Eliminate Unit Productions**

*   `A -> B | S` becomes: `A -> b | ASA | aB` (since `B -> b` and `S -> ASA | aB`)
*   Grammar now:
    *   `S -> ASA | aB`
    *   `A -> b | ASA | aB`
    *   `B -> b`

**Step 3: Eliminate Terminals in RHS (except A -> a)**

*   `S -> ASA | X_a B`
*   `A -> b | ASA | X_a B`
*   `B -> b`
*   `X_a -> a`

**Step 4: Eliminate Long Productions**

*   `S -> A S1`
    *   `S1 -> SA`
    *   `S -> X_a B`
*   `A -> b`
    *   `A -> A S1`
        *   `S1 -> SA`
    *   `A -> X_a B`
*   `B -> b`
*   `X_a -> a`

The final CNF grammar is:

```
S -> A S1 | X_a B
S1 -> SA
A -> b | A S1 | X_a B
B -> b
X_a -> a
```

**Question 3:**  Explain why it is crucial to eliminate null productions before eliminating unit productions when converting a CFG to CNF.

**Answer:**

If you eliminate unit productions *before* null productions, you might miss opportunities to introduce new productions that would be necessary after eliminating null productions.  For example:

Suppose you have the grammar:

`S -> A`
`A -> B | ε`
`B -> a`

If you first eliminate the unit production `S -> A`, you get:

`S -> B | ε`
`A -> B | ε`
`B -> a`

Then, if you eliminate null productions *afterwards*, you would get

`S' -> S | ε`
`S -> B`
`A -> B`
`B -> a`

which is still not in CNF since it has unit productions!

If you had instead eliminated the null productions *first*, you'd have:

`S -> A`
`A -> B`
`A -> ε`

Eliminating unit productions would then lead you to replace `S -> A` with `S -> B | ε`. Then we'd have:

`S' -> S | ε`
`S -> B`
`B -> a`

Which after eliminating that final unit production and changing the terminal is:

`S' -> S | ε`
`S -> X_a`
`X_a -> a`

Which, after eliminating the unit production, becomes:
`S' -> S | ε`
`S -> a`
`X_a -> a`

**Question 4:** True or False: Every context-free language can be generated by a CFG in CNF.

**Answer:** True, *except* for languages that contain the empty string, ε, but do not contain any other strings. Any language that includes epsilon as a possibility can be converted to CNF by creating a new start symbol that can be derived with epsilon.

## 6. Important Points to Remember

*   The order of conversion steps matters.  Always eliminate null productions first, then unit productions, then terminals on the RHS (except for `A -> a`), and finally long productions.
*   The CNF conversion process preserves the *language* generated by the grammar (except possibly for the empty string).  This is a crucial property; the converted grammar should still accept the same strings as the original grammar.
*   The conversion process is not necessarily unique.  There might be multiple valid CNF grammars for a given CFG.
*   The CYK parsing algorithm relies heavily on grammars being in CNF for its efficient operation.
