# THEORY OF COMPUTATION - Module 4: Turing Machines (Kozen) - Chomskian Hierarchy

These notes cover the Chomskian Hierarchy, a classification of formal grammars that provides a useful framework for understanding the power of different computational models.  We'll focus on its relationship to Turing Machines and other simpler automata.

**Learning Outcomes:**

*   Understand the four levels of the Chomskian Hierarchy: Type-0 (Recursively Enumerable), Type-1 (Context-Sensitive), Type-2 (Context-Free), and Type-3 (Regular).
*   Describe the types of grammars, languages, and automata associated with each level.
*   Explain the relationship between the Chomskian Hierarchy and Turing Machines.
*   Recognize the inclusion relationship between the levels of the hierarchy (i.e., that each level is a subset of the level above it).
*   Provide examples of languages belonging to each level of the hierarchy.
*   Apply knowledge of the hierarchy to classify a given language.

## 1. Introduction to the Chomskian Hierarchy

The Chomskian Hierarchy, named after linguist Noam Chomsky, is a classification of formal grammars and the languages they generate. It provides a framework for understanding the complexity and expressive power of different formal languages. The hierarchy is organized into four levels:

*   **Type-0 (Recursively Enumerable Languages)**
*   **Type-1 (Context-Sensitive Languages)**
*   **Type-2 (Context-Free Languages)**
*   **Type-3 (Regular Languages)**

The hierarchy is ordered from most general (Type-0) to most restrictive (Type-3).  Each level is a proper subset of the level above it: Regular Languages ⊆ Context-Free Languages ⊆ Context-Sensitive Languages ⊆ Recursively Enumerable Languages.

## 2. Type-0: Recursively Enumerable Languages (RE)

*   **Grammar:** Unrestricted grammars (also known as phrase structure grammars).  These grammars have no restrictions on the form of their production rules.

*   **Production Rules:**  of the form `α → β`, where α and β are strings of terminals and non-terminals, and α must contain at least one non-terminal symbol.

*   **Languages:** Recursively Enumerable Languages (RE) (also called Turing-Recognizable languages)

*   **Automaton:** Turing Machines (TM)
    *   A Turing Machine can *recognize* any RE language. "Recognize" means the TM halts and accepts if the input string is in the language. The TM may halt and reject, or loop forever, if the input string is *not* in the language.

*   **Key Characteristics:**
    *   Most powerful type of grammar.
    *   Can generate any language that a Turing Machine can recognize.
    *   Languages are *Turing-Recognizable* (or recursively enumerable), but not necessarily *Turing-Decidable*.  A language is Turing-Decidable (or recursive) if there exists a Turing Machine that halts on all inputs, accepting those in the language and rejecting those not in the language.  RE languages may not have such a Turing Machine.
    *   Equivalent to algorithms.

*   **Example Language:** The Halting Problem is a classic example of a recursively enumerable language that is *not* recursive (i.e., it is RE but not Decidable).  Let `HALT = {<M, w> | M is a Turing Machine and M halts on input w}`.

## 3. Type-1: Context-Sensitive Languages (CSL)

*   **Grammar:** Context-Sensitive Grammars

*   **Production Rules:** of the form `αAβ → αγβ`, where A is a non-terminal, α and β are strings of terminals and non-terminals (possibly empty), and γ is a non-empty string of terminals and non-terminals.  The non-terminal `A` can only be replaced by `γ` in the context of `α` and `β`. Also, a special case is allowed: `S -> ε` if S does not appear on the right-hand side of any production rule.

*   **Languages:** Context-Sensitive Languages (CSL)

*   **Automaton:** Linear Bounded Automata (LBA)
    *   An LBA is a Turing Machine with a tape of a fixed length, proportional to the length of the input. It cannot use more space than is provided by the input.

*   **Key Characteristics:**
    *   The length of the right-hand side of a production rule must be greater than or equal to the length of the left-hand side, *except* for the production `S -> ε`.  This is what makes them "context-sensitive."
    *   CSL are a subset of recursively enumerable languages (RE).
    *   All CSL are Turing-Decidable (meaning there exists a Turing Machine that always halts, accepting strings in the language and rejecting strings not in the language).
    *   Recognized by Linear Bounded Automata (LBA).

*   **Example Language:**  `L = {a^n b^n c^n | n ≥ 1}`  This language cannot be generated by a context-free grammar but *can* be generated by a context-sensitive grammar.

## 4. Type-2: Context-Free Languages (CFL)

*   **Grammar:** Context-Free Grammars

*   **Production Rules:** of the form `A → γ`, where A is a non-terminal and γ is a string of terminals and non-terminals.  The non-terminal `A` can be replaced by `γ` regardless of the surrounding context.

*   **Languages:** Context-Free Languages (CFL)

*   **Automaton:** Pushdown Automata (PDA)

*   **Key Characteristics:**
    *   The left-hand side of a production rule is a single non-terminal symbol.
    *   Important for defining programming language syntax and parsing.
    *   Recognized by Pushdown Automata (PDA).
    *   A subset of context-sensitive languages (CSL).

*   **Example Language:**  `L = {a^n b^n | n ≥ 0}` This language is context-free. A context-free grammar for this language is:
    *   `S → aSb | ε`

## 5. Type-3: Regular Languages (RL)

*   **Grammar:** Regular Grammars (Right-Linear or Left-Linear)

*   **Production Rules:**
    *   **Right-Linear:**  `A → aB` or `A → a`, where A and B are non-terminals and a is a terminal.
    *   **Left-Linear:**  `A → Ba` or `A → a`, where A and B are non-terminals and a is a terminal.

*   **Languages:** Regular Languages (RL)

*   **Automaton:** Finite Automata (DFA or NFA)

*   **Key Characteristics:**
    *   Simplest type of grammar.
    *   Recognized by Finite Automata (DFA or NFA).
    *   A subset of context-free languages (CFL).
    *   Can be described by regular expressions.

*   **Example Language:** `L = {a^n b | n ≥ 0}` This language is regular. A regular expression for this language is `a*b`.  A right-linear grammar is:
    *   `S → aS | b`

## 6.  Relationship between the Chomskian Hierarchy and Turing Machines

The Chomskian Hierarchy provides a direct relationship to the power of different computational models, culminating in the Turing Machine:

*   **Turing Machines (TMs) can recognize any Type-0 (Recursively Enumerable) language.**  However, TMs may not halt on all inputs for Type-0 languages.
*   **Linear Bounded Automata (LBAs) can recognize any Type-1 (Context-Sensitive) language.** LBAs are Turing Machines with limited memory (bounded by the input size) and always halt.
*   **Pushdown Automata (PDAs) can recognize any Type-2 (Context-Free) language.**  PDAs are less powerful than TMs because they have limited memory (a stack).
*   **Finite Automata (FAs) can recognize any Type-3 (Regular) language.** FAs have no memory beyond their current state.

This shows a progression of computational power.  Each level of the hierarchy represents a type of machine that can perform a certain class of computations.  As you move up the hierarchy, the machines become more powerful.

## 8. Important Points to Remember

*   The Chomskian Hierarchy is a *strict* hierarchy. This means each level is a *proper subset* of the level above it.  There exist languages that are RE but not CSL, CSL but not CFL, and CFL but not Regular.
*   The hierarchy is related to the *power* of different computational models. More complex machines can recognize more complex languages.
*   Understanding the Chomskian Hierarchy is crucial for classifying the difficulty of recognizing or generating different languages.
*   Not all Recursively Enumerable (RE) languages are Turing-Decidable.  This means a Turing Machine might loop forever trying to determine if a string *not* in the language is actually outside the language. Context-Sensitive Languages (CSL) *are* Turing-Decidable.

## 10. Answers to Practice Questions/Exercises

1.  **Language Classification:**

    a)  `L1 = {a^n b^m | n > m > 0}`: **Context-Free**.  A PDA can compare the number of `a`s and `b`s on its stack.
        * CFG: `S -> aSb | aB`, `B -> ab | b`
    b)  `L2 = {0^n 1^n 2^n | n ≥ 0}`: **Context-Sensitive**. This language cannot be recognized by a PDA. It requires remembering two counts.
    c)  `L3 = {w | w is a string of 0s and 1s, and w has an equal number of 0s and 1s}`: **Context-Free**.  This is a classic example of a language generatable by a CFG, but not a Regular grammar
        * One possible CFG: `S -> 0S1 | 1S0 | ε`
    d)  `L4 = {a^n | n is prime}`: **Context-Sensitive**.  Determining primality is generally not possible with simple automata (like PDA or FA). This one is tricky.
    e)  `L5 = {w w | w ∈ {a, b}*}`: **Context-Sensitive**. Recognizing that `w` is equal to a repeat of itself `ww` require potentially unbounded memory or comparison. A PDA cannot recognize this.
    f) `L6 = {a^n b^n c^m | n,m >= 0}`: **Context-Free**. A PDA can be constructed to compare a's to b's and then handle an arbitrary number of c's.
        * CFG: `S -> AB, A -> aAb | ε, B -> cB | ε`

2.  **Turing-Recognizable vs. Turing-Decidable:**

    *   **Turing-Recognizable (RE):** A language is Turing-Recognizable if there exists a Turing Machine that *halts and accepts* if the input string is in the language. If the input string is *not* in the language, the TM may halt and reject *or* loop forever.
        *   **Example:** The Halting Problem (`HALT = {<M, w> | M halts on input w}`). A TM can simulate M on w. If M halts, the TM accepts. However, if M loops, the TM will also loop, so it doesn't halt on all inputs that are *not* in HALT.
    *   **Turing-Decidable (Recursive):** A language is Turing-Decidable if there exists a Turing Machine that *always halts* (either accepting or rejecting) for any input string.
        *   **Example:**  `L = {0^n 1^n | n ≥ 0}` is decidable. A TM can check if the input is of the correct form, count the number of 0s and 1s, and halt with accept or reject.

3.  **Context-Free but not Regular:**

    *   `L = {a^n b^n | n ≥ 0}`. This language is Context-Free because a PDA can be constructed to push an 'a' onto the stack for each 'a' in the input and then pop an 'a' for each 'b'.  A finite automaton cannot remember the count of 'a's to compare it with the number of 'b's.

4. **Grammar Language Types**

    a) `S -> aSb | ab`: **Context-Free** (CFG)

    b) `S -> aA, A -> bS, A -> c`: **Regular** (right-linear grammar). We can also construct a DFA or NFA to recognize the same language: a(bc)*
        This grammar generates the regular language "a(bc)*"

    c) `S -> aBC, BC -> abc`: **Context-Sensitive**. Although it *appears* CF, the presence of the production rule `BC -> abc` makes it context sensitive, specifically type-1. While other productions could produce the same language that is lower on the chomsky heirarchy, this particular grammar is only of type-1.
