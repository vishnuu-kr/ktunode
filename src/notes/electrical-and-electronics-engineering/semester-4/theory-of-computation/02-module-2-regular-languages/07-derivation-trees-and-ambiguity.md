## 1. Introduction to Grammars and Derivation

A **grammar** is a formal system used to describe a language. It consists of a set of production rules that specify how strings in the language can be generated.

### 1.1 Formal Grammar Components

A formal grammar $G$ is typically defined as a 4-tuple: $G = (V, T, P, S)$, where:

*   $V$: A finite set of **variables** (or non-terminals). These are symbols that can be replaced by other symbols.
*   $T$: A finite set of **terminals**. These are the symbols that form the actual strings of the language. $V \cap T = \emptyset$.
*   $P$: A finite set of **production rules**. Each rule is of the form $\alpha \rightarrow \beta$, where $\alpha$ is a string of variables and terminals, and $\beta$ is a string of variables and terminals. In the context of context-free grammars (which we will use to illustrate derivation trees), $\alpha$ must contain at least one variable, and $\beta$ can be any string of variables and terminals.
*   $S$: The **start symbol**, which is a variable in $V$. The derivation of a string begins with the start symbol.

### 1.2 Derivation

A **derivation** is a sequence of applications of production rules starting from the start symbol to produce a string in the language.

*   If $\alpha \rightarrow \beta$ is a production rule, and $u \alpha v$ is a string of variables and terminals, then we say $u \alpha v$ **directly derives** $u \beta v$. This is denoted as $u \alpha v \Rightarrow u \beta v$.
*   A **derivation** of a string $w$ is a sequence of strings $w_0, w_1, \dots, w_n$ such that $w_0 = S$ (the start symbol), $w_i \Rightarrow w_{i+1}$ for $0 \leq i < n$, and $w_n = w$. This is denoted as $S \Rightarrow^* w$.

## 2. Derivation Trees

A **derivation tree** (also known as a parse tree) is a graphical representation of a derivation of a string from a grammar. It visually shows the hierarchical structure of how a string is generated.

### 2.1 Structure of a Derivation Tree

A derivation tree for a grammar $G = (V, T, P, S)$ and a string $w \in L(G)$ has the following properties:

*   **Root:** The root of the tree is the start symbol $S$.
*   **Internal Nodes:** Each internal node is labeled with a variable from $V$.
*   **Leaf Nodes:** Each leaf node is labeled with a terminal from $T$ or with the empty string $\epsilon$ (if applicable).
*   **Children of a Node:** If a node is labeled with a variable $A$, and there is a production rule $A \rightarrow X_1 X_2 \dots X_k$ in $P$, then $A$ has $k$ children, labeled from left to right with $X_1, X_2, \dots, X_k$. If $X_i$ is a variable, it's an internal node. If $X_i$ is a terminal, it's a leaf node. If $A \rightarrow \epsilon$, then $A$ has a single child labeled $\epsilon$.
*   **In-order Traversal:** Reading the labels of the leaf nodes from left to right yields the string $w$ that was derived.

**Important Note:** Derivation trees are most commonly associated with **Context-Free Grammars (CFGs)**, where production rules are of the form $A \rightarrow \beta$. While regular languages can be generated by regular grammars, which are a subset of CFGs, the concept of derivation trees helps in understanding the structure of generated strings.

---

### 2.2 Example: Derivation Tree for a Context-Free Grammar

Let's consider a simple CFG that generates strings of balanced parentheses:

$G_1 = (V=\{S\}, T=\{ '(', ')' \}, P=\{ S \rightarrow (S) | SS | \epsilon \}, S)$

Let's derive the string `(())`:

**Derivation 1 (Leftmost):**
1.  $S \Rightarrow (S)$
2.  $S \Rightarrow ((S))$
3.  $S \Rightarrow ( (S S) )$
4.  $S \Rightarrow ( ( (S) S ) )$
5.  $S \Rightarrow ( ( ( \epsilon ) S ) )$
6.  $S \Rightarrow ( ( ( ) S ) )$
7.  $S \Rightarrow ( ( ( ) (S) ) )$
8.  $S \Rightarrow ( ( ( ) ( \epsilon ) ) )$
9.  $S \Rightarrow ( ( ( ) ( ) ) )$

This derivation is not quite correct for generating `(())`. Let's try a more direct one.

**Derivation 2 (Correct for `(())`):**
1.  $S \Rightarrow (S)$
2.  $S \Rightarrow ((S))$
3.  $S \Rightarrow (())$  (Applying $S \rightarrow \epsilon$)

**Derivation Tree for `(())`:**

```
      S
     /|\
    ( S )
     /|\
    ( S )
       |
      (epsilon)
```

**Explanation of the Tree:**

*   The root is $S$.
*   The first $S$ derives $(S)$. So, the root $S$ has children '(', $S$, ')'.
*   The second $S$ derives $(S)$. So, this internal $S$ node has children '(', $S$, ')'.
*   The third $S$ derives $\epsilon$. So, this internal $S$ node has a single child labeled $\epsilon$.
*   The leaf nodes read from left to right: '(', '(', $\epsilon$, ')', ')', which forms `(())`.

---

### 2.3 Properties of Derivation Trees

*   **Every string in $L(G)$ has at least one derivation tree.**
*   **The structure of the derivation tree reflects the grammatical structure of the derived string.**
*   **A derivation tree can be directly constructed from a derivation sequence by arranging the production rule applications hierarchically.**

## 3. Ambiguity in Grammars

A grammar is considered **ambiguous** if there exists at least one string in the language that can be generated by the grammar in two or more different ways. This means that a single string can have multiple distinct derivation trees.

### 3.1 Definition of Ambiguity

A grammar $G$ is **ambiguous** if there exists a string $w \in L(G)$ such that there are at least two distinct leftmost derivations or at least two distinct rightmost derivations for $w$. Alternatively, if $w$ has two or more distinct derivation trees.

**Important Note:** The "distinctness" of derivation trees can be subtle. Two derivation trees are distinct if they differ in the order of productions applied or in the choice of productions applied, leading to different structures.

### 3.2 Detecting Ambiguity

Detecting ambiguity in a grammar can be challenging. For context-free grammars, if a grammar is ambiguous, it implies that the language it generates might not be regular.

**Key Signs of Potential Ambiguity:**

*   **Recursive rules with multiple "alternatives":** Rules like $A \rightarrow \alpha A \beta | \gamma A \delta | \dots$ can often lead to ambiguity if not carefully constructed.
*   **"Plus" or "star" operators in conjunction with other operations without clear precedence:** For example, in arithmetic expression grammars, not specifying operator precedence correctly can lead to ambiguity.

### 3.3 Example: Ambiguous Grammar

Consider a grammar for arithmetic expressions involving addition and multiplication:

$G_2 = (V=\{E, T\}, T=\{'+', '*', '(', ')', id\}, P=\{ E \rightarrow E + T | T, T \rightarrow T * id | id \}, E)$

Let's try to derive the string `id + id * id`.

**Derivation 1 (Leftmost):**
1.  $E \Rightarrow E + T$
2.  $E \Rightarrow T + T$
3.  $T \Rightarrow id + T$
4.  $T \rightarrow id + T * id$
5.  $T \rightarrow id + id * id$

**Derivation Tree 1:**
```
      E
     /|\
    E + T
   /   /|\
  T   T * id
 /   /
id  id
```
This derivation tree corresponds to the interpretation `id + (id * id)`.

**Derivation 2 (Leftmost):**
1.  $E \Rightarrow T$
2.  $T \Rightarrow T + T$
3.  $T \Rightarrow T * id + T$  (This step is not possible in leftmost)

Let's try a different approach to find a second derivation. We need to explore different choices of production rules.

**Let's use a rightmost derivation for clarity, or a different leftmost application.**

Consider the structure intended by operator precedence: $E \rightarrow E + T$ and $T \rightarrow T * id$. This implies multiplication has higher precedence.

Let's re-examine the grammar and attempt to find two distinct leftmost derivations:

$G_2 = (V=\{E, T\}, T=\{'+', '*', '(', ')', id\}, P=\{ E \rightarrow E + T | T, T \rightarrow T * id | id \}, E)$

String: `id + id * id`

**Derivation Tree A (interpreting `id + (id * id)`):**

```
      E
     /|\
    E + T
   /   /|\
  T   T * id
 /   /
id  id
```
This is derived by: $E \Rightarrow E + T \Rightarrow T + T \Rightarrow id + T \Rightarrow id + T * id \Rightarrow id + id * id$.

**Derivation Tree B (interpreting `(id + id) * id` - if the grammar allowed this):**

Let's see if we can force a different parse.
Suppose we used $E \rightarrow T$ earlier.

**Derivation Attempt for `(id + id) * id`:**

1.  $E \Rightarrow T$
2.  $T \Rightarrow T * id$  (This implies the outermost operation is `*`)
3.  $T \Rightarrow T + T * id$ (This step is not possible if the first T is already `id`)

This grammar, as written, is designed such that the structure implicitly enforces precedence. The problem arises when the grammar *allows* multiple structural interpretations.

Let's use a classic example of an ambiguous grammar:

$G_3 = (V=\{S\}, T=\{ 'a', 'b' \}, P=\{ S \rightarrow aSb | ab | \epsilon \}, S)$

This grammar generates strings of the form $a^n b^n$ for $n \ge 0$.

Let's derive the string `aabb`:

**Derivation 1:**
1.  $S \Rightarrow aSb$
2.  $S \Rightarrow aaSbb$
3.  $S \Rightarrow aababb$ (Applying $S \rightarrow \epsilon$)

**Derivation Tree 1:**
```
      S
     /|\
    a S b
     /|\
    a S b
       |
      (epsilon)
```

**Derivation 2:**
1.  $S \Rightarrow S S$  (Wait, $G_3$ doesn't have $S \rightarrow SS$)

Let's correct the example to be explicitly ambiguous.

Consider the grammar for expressions again, but this time, let's make it ambiguous by simplifying it.

$G_4 = (V=\{E\}, T=\{'+', 'a'\}, P=\{ E \rightarrow E + E | a \}, E)$

This grammar generates strings like `a + a + a`.

Let's derive `a + a + a`:

**Derivation Tree A (interpreting `(a + a) + a`):**

```
      E
     /|\
    E + E
   /|   |
  E+E   a
 /|
a a
```
This is derived by: $E \Rightarrow E + E \Rightarrow E + E + E \Rightarrow a + E + E \Rightarrow a + a + E \Rightarrow a + a + a$. (This is not a leftmost derivation step-by-step, but the tree structure is key.)

Let's show two *leftmost* derivations for `a + a + a`:

**Leftmost Derivation 1:**
1.  $E \Rightarrow E + E$
2.  $E \Rightarrow E + E + E$ (leftmost $E$ to $E+E$)
3.  $E \Rightarrow a + E + E$
4.  $E \Rightarrow a + a + E$
5.  $E \Rightarrow a + a + a$

**Derivation Tree 1 (for `(a + a) + a`):**
```
       E
      /|\
     E + E
    /|   |
   E+E   a
  /|
 a a
```

**Leftmost Derivation 2:**
1.  $E \Rightarrow E + E$
2.  $E \Rightarrow E + E + E$ (rightmost $E$ to $E+E$ from the original E) -- this is confusing if not careful about which E you expand.

Let's be precise.
$E \Rightarrow E + E$
From the first $E$: $E \Rightarrow E + E$. So we have $(E + E) + E$.
From the second $E$: $E \Rightarrow a$. So we have $(E + a) + E$.
From the third $E$: $E \Rightarrow a$. So we have $(E + a) + a$.
From the first $E$ again: $E \Rightarrow a$. So we have $(a + a) + a$.

**Derivation Tree 2 (for `a + (a + a)`):**

```
       E
      /|\
     E + E
    /   /|
   a   E + E
      /|
     a a
```
This is derived by: $E \Rightarrow E + E \Rightarrow a + E \Rightarrow a + E + E \Rightarrow a + a + E \Rightarrow a + a + a$. (Again, this needs careful leftmost step-by-step derivation.)

**Let's show the two leftmost derivations explicitly for `a + a + a` using $G_4$:**

$G_4 = (V=\{E\}, T=\{'+', 'a'\}, P=\{ E \rightarrow E + E | a \}, E)$

**String: `a + a + a`**

**Leftmost Derivation 1 (producing `(a+a)+a`):**
1.  $E \Rightarrow E + E$
2.  $E \Rightarrow E + E + E$ (applying $E \rightarrow E+E$ to the leftmost $E$)
3.  $E \Rightarrow a + E + E$ (applying $E \rightarrow a$ to the leftmost $E$)
4.  $E \Rightarrow a + a + E$ (applying $E \rightarrow a$ to the next $E$)
5.  $E \Rightarrow a + a + a$ (applying $E \rightarrow a$ to the rightmost $E$)

**Derivation Tree 1:**
```
       E
      /|\
     E + E
    /|   |
   a  E  a
      |
      a
```
(The structure is `(a+a)+a`)

**Leftmost Derivation 2 (producing `a+(a+a)`):**
1.  $E \Rightarrow E + E$
2.  $E \Rightarrow E + (E + E)$ (applying $E \rightarrow E+E$ to the *rightmost* $E$)
3.  $E \Rightarrow a + (E + E)$ (applying $E \rightarrow a$ to the leftmost $E$)
4.  $E \Rightarrow a + (a + E)$ (applying $E \rightarrow a$ to the first $E$ in the right part)
5.  $E \Rightarrow a + (a + a)$ (applying $E \rightarrow a$ to the last $E$)

**Derivation Tree 2:**
```
       E
      /|\
     E + E
    /   /|
   a   E  a
      /|
     a  a
```
(The structure is `a+(a+a)`)

Since `a + a + a` has two distinct derivation trees (and thus two distinct leftmost derivations), the grammar $G_4$ is **ambiguous**.

### 3.4 Consequences of Ambiguity

*   **Lack of Unique Interpretation:** The primary consequence is that the structure of a string cannot be uniquely determined by the grammar. This is problematic for applications where the structure is important, such as compilers parsing programming languages.
*   **Implication for Regular Languages:** While ambiguity is a property of context-free grammars, it's important to note that **regular languages are always generated by unambiguous grammars**. If a language can only be generated by an ambiguous grammar, it cannot be a regular language.

**Example:** The language of all strings with an equal number of 'a's and 'b's is context-free, but it requires an ambiguous grammar to generate it in a straightforward way. Languages like $\{a^n b^n | n \ge 0\}$ can be generated by unambiguous context-free grammars. However, the grammar $G_3$ provided earlier, $S \rightarrow aSb | ab | \epsilon$, is actually unambiguous for $a^n b^n$.

A common example of an ambiguous context-free language is the set of valid arithmetic expressions where precedence and associativity are not strictly enforced by the grammar rules.

## 4. Relationship to Regular Languages

*   **Regular Languages and Unambiguity:** All regular languages can be generated by **unambiguous** context-free grammars, specifically by **regular grammars**. Regular grammars are a subset of context-free grammars, where production rules are of the form $A \rightarrow aB$ or $A \rightarrow a$ (right-linear) or $A \rightarrow Ba$ or $A \rightarrow a$ (left-linear), where $A, B$ are variables and $a$ is a terminal (or $\epsilon$).

*   **Ambiguity and Non-Regularity:** If a language can be generated by a grammar, and *all* possible grammars for that language are ambiguous, then the language is *not* regular. However, the converse is not entirely true: a language can be context-free and still be generated by an ambiguous grammar.

*   **Finite Automata (FAs) and Regular Grammars:** The equivalence of Finite Automata (DFA/NFA), regular expressions, and regular grammars means that if a language can be described by any of these, it can be described by all. These representations are inherently unambiguous. A string derived from a regular grammar has a unique parse tree.

**Kozen, Chapter 4 (Context-Free Grammars):** Kozen discusses context-free grammars and their properties. While the focus of this topic is on derivation trees and ambiguity, it's worth noting that for regular languages, the structure is simpler and doesn't lead to the kind of structural ambiguity seen in more complex CFGs.

**Hopcroft, Motwani, Ullman, Chapter 5 (Context-Free Grammars):** This textbook also provides a detailed account of context-free grammars, including the concept of ambiguity and its implications. They emphasize that if a language has an ambiguous grammar, it doesn't necessarily mean it's not context-free, but it highlights a structural complexity.

**Sipser, Chapter 5 (Context-Free Grammars):** Sipser introduces context-free grammars and their relationship to pushdown automata. He also covers ambiguity and its definition, showing how multiple parse trees can arise for a single string.

## 6. Answers to Practice Questions

**Answer 1:**
(a) Derivation of `aabb`:
1.  $S \Rightarrow aSb$
2.  $S \Rightarrow aaSbb$
3.  $S \Rightarrow aababb$ (applying $S \rightarrow \epsilon$)

(b) Derivation Tree for `aabb`:
```
      S
     /|\
    a S b
     /|\
    a S b
       |
      (epsilon)
```

(c) This grammar is **unambiguous**. For any string $a^n b^n$, there is only one sequence of productions that can derive it, and consequently, only one derivation tree. The structure is straightforward: each application of $S \rightarrow aSb$ adds an 'a' at the beginning and a 'b' at the end, with the derivation of the inner string.

**Answer 2:**
Derivation of `ab`:
1.  $S \Rightarrow aA$
2.  $A \Rightarrow bS$ (This is not the correct rule to use from `aA`)
Let's retry:
1.  $S \Rightarrow aA$
2.  $A \Rightarrow \epsilon$

Derivation Tree for `ab`:
```
      S
     /|\
    a A
      |
     (epsilon)
```
The grammar is unambiguous for the string `ab`. There's only one path to derive it.

**Answer 3:**
(a)
*   **Derivation Tree 1** (from the notes): Corresponds to the interpretation `(a + a) + a` (left-associative). The leftmost `+` operation is performed last in terms of tree structure.
*   **Derivation Tree 2** (from the notes): Corresponds to the interpretation `a + (a + a)` (right-associative). The rightmost `+` operation is performed last in terms of tree structure.

(b) To enforce left-associativity for addition, we can modify the grammar similar to how context-free grammars for expressions are made unambiguous:

**Unambiguous Grammar for Left-Associative Addition:**
$G_{4\_unamb} = (V=\{E, T\}, T=\{'+', 'a'\}, P=\{ E \rightarrow E + T | T, T \rightarrow a \}, E)$

In this grammar:
*   $E$ represents an expression.
*   $T$ represents a term (in this simple case, just 'a').
*   The rule $E \rightarrow E + T$ directly enforces left-associativity because the leftmost $E$ is the one that recursively expands, placing the addition on the left.

Example derivation for `a + a + a` with $G_{4\_unamb}$:
1.  $E \Rightarrow E + T$
2.  $E \Rightarrow E + T + T$ (applying $E \rightarrow E+T$ to the left $E$)
3.  $E \Rightarrow T + T + T$ (applying $E \rightarrow T$ to the left $E$)
4.  $E \Rightarrow a + T + T$ (applying $T \rightarrow a$ to the leftmost $T$)
5.  $E \Rightarrow a + a + T$ (applying $T \rightarrow a$ to the middle $T$)
6.  $E \Rightarrow a + a + a$ (applying $T \rightarrow a$ to the rightmost $T$)

The derivation tree for this unambiguous grammar will only have one structure, reflecting `(a + a) + a`.

## 7. Important Points to Remember

*   **Derivation trees** provide a visual representation of how a string is generated by a grammar, showing the hierarchical application of production rules.
*   **Ambiguity** in a grammar means a string can have multiple distinct derivation trees, leading to different interpretations of its structure.
*   **Regular languages are always generated by unambiguous grammars.** If a language can only be generated by an ambiguous grammar, it cannot be regular.
*   While ambiguity is a characteristic of some context-free grammars, it's not a defining characteristic of all context-free languages.
*   Detecting ambiguity is important for applications like compiler design, where a unique parse is required.
*   Grammars can be modified to remove ambiguity and enforce desired properties like operator precedence and associativity.
