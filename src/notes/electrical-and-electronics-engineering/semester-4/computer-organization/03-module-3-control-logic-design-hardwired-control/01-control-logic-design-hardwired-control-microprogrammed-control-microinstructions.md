## Computer Organization: Module 3 - Control Logic Design

### Topic: Hardwired Control vs. Microprogrammed Control: Microinstructions and Microprogram Sequencing

---

### 1. Introduction to Control Logic Design

The control unit is the brain of the computer, responsible for directing the operation of the processor and other components. It generates the necessary control signals to execute instructions. There are two primary approaches to designing the control unit: **Hardwired Control** and **Microprogrammed Control**.

*   **Hardwired Control:** In this approach, the control signals are generated directly by combinational logic circuits. The logic is "hardwired" into the hardware.
    *   **Pros:** Faster execution speed as signals are generated directly.
    *   **Cons:** Less flexible; modification requires hardware changes. Difficult to implement complex instruction sets.
    *   **Reference:** Hamacher et al. (5/e), Chapter 6.1.
    *   **Course Outcome Alignment:** CO4 (Demonstrate the control signals required for the execution of a given instruction) - Hardwired control directly maps instruction execution to specific control signals.

*   **Microprogrammed Control:** In this approach, the control signals are generated by a sequence of microinstructions stored in a special memory called the **control memory (CM)**. Each instruction in the processor's instruction set is implemented by a sequence of microinstructions.
    *   **Pros:** Highly flexible; easier to add new instructions or modify existing ones by changing the microprogram. Simpler to design complex instruction sets.
    *   **Cons:** Slower execution speed due to the overhead of fetching microinstructions from control memory.
    *   **Reference:** Hamacher et al. (5/e), Chapter 6.2. Mano (PHI, 2004), Chapter 7. Mano (PHI, 2007), Chapter 7.
    *   **Course Outcome Alignment:** CO2 (Illustrate the register transfer logic, Processor logic design) - Microprogrammed control is a key method for implementing processor logic and register transfers. CO4 (Demonstrate the control signals required for the execution of a given instruction) - Microprograms define the sequence of control signals for instruction execution.

### 2. Microprogrammed Control

Microprogrammed control replaces the complex combinational logic of hardwired control with a control memory that stores a sequence of microinstructions.

#### 2.1. Microinstructions

A **microinstruction** is a low-level instruction that specifies a particular operation (or a set of operations) to be performed by the processor's components. A sequence of microinstructions that performs a specific task, such as fetching, decoding, or executing an instruction, is called a **microprogram**.

*   **Structure of a Microinstruction:** A microinstruction typically consists of:
    *   **Control Fields:** These fields generate the actual control signals that activate functional units, transfer data between registers, and control ALU operations.
    *   **Sequencing Fields:** These fields specify how to determine the next microinstruction to be fetched.

*   **Representation of Control Signals:**
    *   **Vertical Microprogramming:** Uses fewer bits per microinstruction. Control signals are encoded, requiring decoding logic to generate the actual signals. This is more compact but slower due to decoding.
    *   **Horizontal Microprogramming:** Uses more bits per microinstruction, with each bit directly controlling a specific control signal. This is faster but requires wider microinstructions and more control memory.
    *   **Hybrid Approaches:** Combine aspects of both vertical and horizontal microprogramming to balance speed and memory usage.

*   **Reference:** Hamacher et al. (5/e), Chapter 6.2.1. Mano (PHI, 2004), Chapter 7.1.

#### 2.1.1. Microinstruction Format Example

Consider a simplified example of a microinstruction format:

| Field Name        | Description                                            | Example Value | Control Signals Generated                                           |
| :---------------- | :----------------------------------------------------- | :------------ | :------------------------------------------------------------------ |
| **ALU Operation** | Specifies the arithmetic or logic operation for the ALU | `ADD`         | `ALU_ADD`, `ALU_SRC1_REG`, `ALU_SRC2_IMM`                        |
| **Register Write**| Specifies the destination register for ALU output      | `R1`          | `REG_WRITE_ENABLE`, `DEST_REG_R1`                                 |
| **Memory Read**   | Indicates if data needs to be read from memory         | `YES`         | `MEM_READ_ENABLE`                                                 |
| **Memory Write**  | Indicates if data needs to be written to memory        | `NO`          | `MEM_WRITE_ENABLE`                                                |
| **Next Address**  | Specifies the address of the next microinstruction    | `0101`        | (Used for sequencing)                                               |
| **Branch Condition** | Condition for branching                                | `ZERO_FLAG`   | (Used for conditional branching)                                    |

**Key Point:** The fields in a microinstruction directly correspond to the control signals needed to perform a specific step in instruction execution.

#### 2.1.2. Control Memory (CM)

*   **Purpose:** Stores the microprograms.
*   **Implementation:** Typically implemented using ROM (Read-Only Memory) or PROM (Programmable Read-Only Memory) for fixed microprograms, or RAM (Random Access Memory) for dynamically updatable microprograms (e.g., writable control store).
*   **Address:** Each microinstruction is stored at a unique address in the control memory.

#### 2.1.3. Control Unit Components

A microprogrammed control unit typically includes:

1.  **Control Memory (CM):** Stores the microinstructions.
2.  **Sequencer:** Determines the address of the next microinstruction to be fetched.
3.  **Microinstruction Register (MIR):** Holds the currently fetched microinstruction.
4.  **Decoder (for Vertical Microprogramming):** Decodes the control fields to generate the actual control signals.

### 3. Microprogram Sequencing

Sequencing is the process of determining the address of the next microinstruction to be fetched from the control memory. This is a crucial aspect of microprogrammed control.

#### 3.1. Basic Sequencing

The simplest form of sequencing is **sequential fetching**. If a microinstruction does not have a sequencing field that dictates a change, the control unit fetches the next microinstruction from the next sequential address.

*   **Control Address Register (CAR):** This register holds the address of the current microinstruction being executed. After fetching a microinstruction, the CAR is typically incremented to point to the next microinstruction in sequence.

#### 3.2. Branching

Branching allows the microprogram to alter its flow based on certain conditions, similar to conditional jumps in machine language.

*   **Conditional Branching:** The decision to branch is based on the status of flags or other conditions within the processor (e.g., zero flag, carry flag, interrupt request).
    *   **Mechanism:** A microinstruction contains a field that specifies a condition to check. If the condition is met, the CAR is updated with a new address (provided in the microinstruction); otherwise, it proceeds to the next sequential address.
    *   **Example:** If the ALU result is zero, branch to a specific microinstruction to handle zero-related actions.

*   **Unconditional Branching:** The control unit always branches to a specified address, regardless of any condition.
    *   **Mechanism:** The microinstruction specifies the target address, and the CAR is updated unconditionally.

*   **Subroutine Calls:** Allows for modularity in microprogramming. A microinstruction can cause a jump to a subroutine and store the return address in a special register (often part of the sequencer).
    *   **Mechanism:** The microinstruction provides the address of the subroutine. The return address (current CAR + 1) is pushed onto a microprogram stack. Upon completion of the subroutine, a special "return" microinstruction retrieves the return address from the stack and loads it into the CAR.

#### 3.3. Sequencing Techniques

*   **Branching based on Instruction Opcode:** The first microinstruction for any instruction is typically fetched based on the opcode of the machine instruction. This involves mapping the opcode to the starting address of the corresponding microprogram in control memory.
    *   **Example:** If the machine instruction is `ADD R1, R2`, the opcode is decoded, and this decoded information is used to generate the address of the first microinstruction for the `ADD` operation. This often involves a **mapping ROM** or a dedicated logic circuit.

*   **Incrementing the CAR:** The CAR is incremented to fetch the next microinstruction in sequence, unless a branch is taken.

*   **Loading the CAR:** The CAR can be loaded with a new address from a microinstruction's address field, a status bit, or the microprogram stack.

#### 3.4. Implementing Sequencing Logic

The sequencer is responsible for implementing these sequencing techniques. It typically comprises:

*   **Control Address Register (CAR):** Holds the address of the next microinstruction.
*   **Incrementer:** To increment the CAR for sequential fetching.
*   **Branch Logic:** To evaluate branch conditions and select the next address.
*   **Microprogram Stack:** To store return addresses for subroutine calls.
*   **Address Selection Mux:** To choose the source for the next CAR value (incremented value, branch address, stack top, etc.).

**Reference:** Hamacher et al. (5/e), Chapter 6.2.2. Mano (PHI, 2004), Chapter 7.2.
