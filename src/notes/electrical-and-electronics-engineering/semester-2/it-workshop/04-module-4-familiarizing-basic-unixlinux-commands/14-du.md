# IT WORKSHOP: Module 4 - Familiarizing Basic Unix/Linux Commands

## Topic: `du` - Disk Usage Command

Welcome, everyone, to Module 4 of our IT Workshop! Today, we're diving into the world of Unix/Linux commands, and our focus is on a really practical tool called `du`. You might wonder, why is understanding disk usage important? Well, think about your own computer. Have you ever seen that dreaded "disk full" message? Or perhaps you've wondered where all that space on your hard drive has gone? The `du` command is our detective tool in the Linux world to answer exactly those questions. It helps us understand how much space files and directories are taking up. This is directly relevant to **CO2: Make use of the command line of Linux operating system and shell programming.** By learning `du`, we're gaining a vital skill for navigating and managing our Linux environment efficiently.

### What is `du`? Understanding Disk Usage

The name `du` itself is short for **Disk Usage**. It's a fundamental command-line utility that reports the disk space used by files and directories. Imagine you have a big backpack, and you want to know how much each section of your backpack is contributing to its overall weight or volume. `du` does something similar for your computer's storage.

When we talk about "disk usage," we're really talking about how many blocks of data are being occupied on your storage device (like your hard drive or SSD) by the files and directories you've created or downloaded. This is tied to **CO1: Experiment with the fundamental hardware components of a computer and how to interface them with software systems.** While `du` doesn't directly manipulate hardware, it provides a software interface to query information about the underlying storage hardware's utilization.

### How `du` Works: The Basics

At its core, `du` traverses through specified directories and calculates the total size of the files within them. If you don't specify a directory, it defaults to the current directory you are in.

Let's start with the simplest form:

```bash
du
```

If you run this command in your home directory, you'll see a lot of output, usually a list of numbers followed by directory names. Each number represents the disk space used by that directory. By default, these numbers are in **kilobytes (KB)**.

Now, this default output can be a bit overwhelming, right? It's like getting a list of every single item in your backpack, along with its individual weight, without a grand total. For exam purposes, you'll often be asked to summarize this or make it more readable.

### Making `du` More Readable and Informative

This is where the options (or "flags") for `du` become incredibly useful. They're like giving your backpack-weighing tool special settings.

#### 1. Human-Readable Output (`-h`)

This is probably the most important option for everyday use. Instead of showing sizes in bytes, kilobytes, megabytes, or gigabytes as raw numbers, `-h` displays them in a human-readable format.

```bash
du -h
```

When you run `du -h`, you'll see outputs like `4.0K`, `1.2G`, `500M`, etc. This makes it much easier to quickly scan and understand which directories are the "heavyweights." This option directly aids in **CO2**, as it makes interpreting the output of a command-line tool much more efficient.

**Analogy:** Imagine you're a chef and you need to measure ingredients. You wouldn't want to measure flour in individual grains of wheat; you'd want to measure it in cups or grams. The `-h` option is like using cups and grams for disk space – it makes the measurements intuitive.

**Exam Tip:** Always remember to use `-h` when you want to quickly grasp the size of things. It's a common practice and often expected in practical tasks.

#### 2. Summarizing the Total (`-s`)

Often, you don't need to see the size of every single subdirectory. You just want to know the *total* disk usage for a specific directory. This is where the `-s` (summarize) option comes in handy.

```bash
du -s
```

If you run `du -s` in your current directory, you'll get just one number – the total disk space used by everything in that directory and its subdirectories.

Now, you can combine these!

```bash
du -sh
```

This command is your best friend for quickly checking the total size of your current directory in a human-readable format. It's like asking, "How much does my whole backpack weigh?" and getting a single, clear answer. This is essential for understanding your overall disk footprint, linking back to **CO1** by providing insights into resource utilization.

**Relatable Example:** Let's say you're managing your photo library. You might navigate to your "Pictures" folder and run `du -sh Pictures/`. This will tell you the total space your entire photo collection is occupying, making it easier to decide if you need to archive some older photos.

#### 3. Apparent Size vs. Disk Usage (`-b`, `--apparent-size`)

This is a slightly more advanced but important distinction, especially if you're dealing with files that have been "sparse" or compressed.

*   **Default `du` behavior (without `--apparent-size` or `-b`)**: It reports the disk space actually allocated on the disk. This includes block sizes, file system overhead, etc.
*   **`--apparent-size` or `-b`**: This option reports the "apparent size" of files, which is closer to what you'd see if you listed files with `ls -l`. It represents the actual number of bytes in the file, without considering block allocation.

So, why the difference? File systems allocate space in blocks. If a file is only 100 bytes, but the smallest block size is 4KB, the file system will allocate a full 4KB block for it. `du` (by default) will report 4KB. `--apparent-size` would report 100 bytes.

**When is this important?** When you're trying to understand the *real* size of your data versus how much space the system has reserved for it. For most day-to-day use, the default is fine, but in scenarios where you're optimizing storage or dealing with very large, potentially sparse files, understanding this difference is key. This delves into the lower-level aspects related to **CO1**.

**Quick Recall Tip:** Think of it as:
*   Default `du`: How much space the *storage system* is using for your files.
*   `du --apparent-size`: How much space the *files themselves* would occupy if there were no block allocation.

#### 4. Controlling Depth (`--max-depth`)

Sometimes, you don't want to see the usage of every single subdirectory, but you might want to see the usage of the top-level directories and their immediate contents. The `--max-depth` option is perfect for this.

```bash
du -h --max-depth=1
```

This command will show you the disk usage of the current directory and its immediate subdirectories, but it won't go any deeper. It's like only looking at the main compartments of your backpack and not the small pockets within them.

**Relatable Example:** Imagine you have your "Documents" folder organized with many subfolders for different projects. If you run `du -sh Documents/`, you get one total. If you run `du -h --max-depth=1 Documents/`, you can see how much space "Project Alpha," "Project Beta," and "Personal," etc., are taking up individually, without getting lost in the details of each project's sub-folders. This is incredibly useful for identifying which top-level areas are consuming the most space, a core aspect of **CO2**.

### Using `du` with Specific Directories and Files

You don't always have to be in the directory you want to check. You can specify the path:

```bash
du -sh /home/yourusername/Downloads
```

This will give you the summarized, human-readable disk usage of your Downloads folder, no matter where you are currently located in the terminal.

You can also check the size of individual files:

```bash
du -h my_important_document.txt
```

This will show you the disk space used by that specific file.

### Common `du` Scenarios and Exam Relevance

Understanding `du` is crucial for many practical tasks and is often tested in exams:

1.  **Finding Large Files/Directories:** You'll frequently be asked to identify which directories are consuming the most space on a system. This usually involves a combination of `du` and other commands like `sort` and `head`.
    *   Example: `du -h --max-depth=1 | sort -hr` - This command will list the disk usage of the current directory's subdirectories, sort them in reverse human-readable order (largest first), and show you the top ones. This directly tests your ability to combine commands for analysis, a key skill in **CO2**.
2.  **Disk Quotas:** In server environments, users often have disk quotas. `du` is essential for monitoring your usage against these limits.
3.  **System Maintenance:** Before performing backups or cleanups, you need to know what's taking up space. `du` is your primary tool for this.

**Remember this:** When asked to find "what's eating up space," `du` is almost always the first command you’ll reach for.

### Summary of Key `du` Options

Here's a quick reference for the most common options:

*   `-h`: Human-readable output (e.g., `1K`, `234M`, `2G`).
*   `-s`: Summarize (display only a total for each argument).
*   `--max-depth=N`: Print the total for a directory (or file, with depth 0) only if it is N or fewer levels below the command line argument; --max-depth=0 is the same as --is a file.
*   `-b`: Same as `--apparent-size`, print sizes in bytes.

**Remember this:** `du -sh` is your go-to for quickly checking the total size of a directory in a readable format.

### Sample Questions with Answers

**Question 1 (Conceptual):** What is the primary purpose of the `du` command in Unix/Linux?

**Answer:** The primary purpose of the `du` command is to display the disk space usage of files and directories. It helps users understand how much storage space is being consumed by different parts of the file system.

**Reasoning:** This question tests the basic understanding of the command's function. It directly relates to the core definition and practical utility of `du`.

---

**Question 2 (Exam-Oriented):** You are asked to find the total disk space used by your `Documents` directory and all its subdirectories, and you want the output to be easily readable (e.g., in MB or GB). Which command would you use?

**Answer:** `du -sh ~/Documents`

**Reasoning:**
*   `-s` (summarize) is used to get only the total size of the `Documents` directory, not the size of every single subdirectory within it.
*   `-h` (human-readable) is used to display the size in an understandable format like KB, MB, or GB, rather than raw bytes or blocks.
*   `~/Documents` specifies the target directory. The `~` is a shortcut for the current user's home directory.

This question tests the practical application of the most common and useful options together.

---

**Question 3 (Conceptual/Application):** Explain the difference between the default output of `du` and the output of `du --apparent-size`. When might you prefer to use `--apparent-size`?

**Answer:**
The default output of `du` reports the disk space *actually allocated* on the file system. This takes into account the block size used by the file system. For example, a 100-byte file might be reported as using 4KB if the file system's block size is 4KB.

The `du --apparent-size` option reports the *apparent size* of files, which is the actual number of bytes in the file itself, regardless of the file system's block allocation.

You might prefer to use `--apparent-size` when you want to know the exact byte count of your files, for instance, to verify the size of downloaded data or to compare the logical size of files with their actual disk consumption in a more granular way, especially when dealing with very large files or sparse files where the difference can be significant.

**Reasoning:** This question probes deeper into the nuances of `du`'s behavior and requires understanding the concept of file system block allocation, directly touching upon **CO1**'s theme of interfacing with hardware (via the file system). It tests understanding beyond just basic usage.

---

**Question 4 (Exam-Oriented):** How would you list the disk usage of the current directory and its immediate subdirectories, sorted by size from largest to smallest, in a human-readable format?

**Answer:** `du -h --max-depth=1 | sort -hr`

**Reasoning:**
*   `du -h --max-depth=1`: This part calculates the human-readable disk usage for the current directory (`.`) and only its immediate subdirectories (depth 1).
*   `|`: This is a pipe, which sends the output of the `du` command as input to the `sort` command.
*   `sort -hr`: The `sort` command sorts the lines.
    *   `-h` tells `sort` to interpret human-readable numbers (like `1K`, `234M`, `2G`).
    *   `-r` tells `sort` to sort in reverse order, meaning from largest to smallest.

This question is designed to assess the ability to chain commands using pipes and to apply specific options for a practical analytical task, a core component of **CO2**.
