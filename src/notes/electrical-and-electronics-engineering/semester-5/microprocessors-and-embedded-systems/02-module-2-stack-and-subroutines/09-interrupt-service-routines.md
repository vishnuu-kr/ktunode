### 1. Introduction to Interrupts

*   **Definition:** An interrupt is an event that causes a microprocessor to stop its current task and divert its attention to a specific event or condition. This event is typically an external signal from a peripheral device or an internal condition that requires immediate attention.
*   **Purpose:** Interrupts are crucial for efficient operation of microprocessors in embedded systems because they allow the processor to respond to external events in real-time without constantly polling (checking) the status of every peripheral. This frees up the processor to perform other tasks.
*   **Analogy:** Imagine you are reading a book (your main program). Suddenly, the doorbell rings (an interrupt). You pause reading, go to the door, deal with the visitor (interrupt service routine), and then return to your book where you left off.

---

### 2. Types of Interrupts

Microprocessors, including the 8085 (as discussed in Gaonkar and Ram), typically categorize interrupts into two main types:

*   **Maskable Interrupts:**
    *   These interrupts can be temporarily ignored or "masked" by the microprocessor.
    *   The programmer has control over whether these interrupts are serviced.
    *   This is useful for critical operations where the processor should not be interrupted.
    *   **Examples (8085):** INTR, RST 7.5, RST 6.5, RST 5.5.
*   **Non-Maskable Interrupts (NMI):**
    *   These interrupts cannot be ignored by the microprocessor.
    *   They are typically reserved for critical events that require immediate handling, such as power failure detection.
    *   **Example (8085):** NMI.

**Further Classification (based on source and priority):**

*   **Hardware Interrupts:** Generated by external hardware devices (e.g., keyboard input, timer overflow, data ready signal from a peripheral).
    *   **Maskable Hardware Interrupts:** INTR, RST 7.5, RST 6.5, RST 5.5 (8085).
    *   **Non-Maskable Hardware Interrupts:** NMI (8085).
*   **Software Interrupts:** Generated by executing a specific instruction in the program. These are often used for system calls or error handling.
    *   **Example (8085):** RST 0 to RST 7 instructions. These are predefined interrupt vectors.

**Priority of Interrupts (8085):**

Microprocessors often have a priority scheme for interrupts. If multiple interrupts occur simultaneously, the processor will service the one with the highest priority.

*   **8085 Priority Order (Highest to Lowest):**
    1.  NMI (Non-Maskable Interrupt)
    2.  RST 7.5 (Maskable, edge-triggered)
    3.  RST 6.5 (Maskable, level-triggered)
    4.  RST 5.5 (Maskable, level-triggered)
    5.  INTR (Maskable, level-triggered, requires an interrupt acknowledge cycle)

*   **Importance of Priority:** Ensures critical events are handled first. For example, an NMI indicating a power failure would take precedence over a keyboard press.

### 3. Interrupt Handling Mechanism

When an interrupt occurs, the microprocessor follows a systematic process:

1.  **Interrupt Detection:** The microprocessor continuously monitors its interrupt request lines.
2.  **Interrupt Acknowledgement (if applicable):** For maskable interrupts like INTR, the processor might send out an interrupt acknowledge signal to identify the interrupting device and receive an instruction (usually an RST instruction) from it.
3.  **Disable Further Interrupts (Temporary):** To prevent nested interrupts from corrupting the return address, the processor temporarily disables further interrupts (or at least those of equal or lower priority). This is often done automatically by hardware or by the first instruction in the ISR.
4.  **Save Current State:** The processor needs to return to its original task after servicing the interrupt. Therefore, it saves the current program counter (PC) value. This is crucial to resume execution from the exact point where it was interrupted.
5.  **Jump to Interrupt Service Routine (ISR):** The processor determines the starting address of the ISR for the specific interrupt that occurred. This address is called an **interrupt vector**.
    *   For vectored interrupts (like RST instructions or NMI), the vector address is fixed or determined by the interrupting device.
    *   For non-vectored interrupts (like INTR in 8085), the processor might fetch an instruction from the interrupting device that points to the ISR.
6.  **Execute ISR:** The processor executes the instructions within the ISR. The ISR performs the specific task required by the interrupt event (e.g., reading data from a keyboard, updating a timer).
7.  **Restore State:** After the ISR completes, the processor retrieves the saved PC value from the stack (or wherever it was stored).
8.  **Re-enable Interrupts:** The processor re-enables interrupts, allowing it to respond to new interrupt requests. This is often done by an interrupt return instruction (e.g., `RETI` in 8085, which also pops the flag register).
9.  **Resume Execution:** The processor resumes execution of the main program from the instruction that would have been executed next if the interrupt had not occurred.

### 4. The Role of the Stack in Interrupt Handling

The stack plays a vital role in interrupt handling, particularly in saving the processor's context.

*   **Saving the Program Counter (PC):** When an interrupt occurs, the microprocessor pushes the current PC value onto the stack. This allows the processor to return to the exact instruction it was executing before the interrupt.
*   **Saving Other Registers (Optional but Recommended):** For more robust interrupt handling, it's often necessary to save the contents of other important registers (like accumulator, flags, general-purpose registers) onto the stack at the beginning of the ISR. This is because the ISR might modify these registers, and their original values are needed to resume the interrupted program correctly.
*   **Restoring Registers and PC:** At the end of the ISR, the saved register values are popped back from the stack, followed by the PC value.

**Instructions:**
*   **`PUSH`:** Pushes a register pair onto the stack.
*   **`POP`:** Pops a register pair from the stack.
*   **`HLT`:** Halts the processor.
*   **`EI`:** Enables interrupts.
*   **`DI`:** Disables interrupts.
*   **`RETI`:** Return from Interrupt (special instruction in 8085, performs `RET` and enables interrupts).
*   **`RET`:** Return from Subroutine.

**Example (Conceptual 8085 ISR entry):**

```assembly
; Assume interrupt has occurred and PC is pushed to stack
; --- Start of ISR ---
DI               ; Disable further interrupts (if not already done)
PUSH PSW         ; Save Accumulator and Flags
PUSH B           ; Save B register pair
PUSH D           ; Save D register pair
PUSH H           ; Save H register pair

; ... ISR code to handle the interrupt ...

POP H            ; Restore H register pair
POP D            ; Restore D register pair
POP B            ; Restore B register pair
POP PSW          ; Restore Accumulator and Flags
EI               ; Re-enable interrupts
RETI             ; Return from interrupt
; --- End of ISR ---
```

**Important Note:** For the 8085, the `RETI` instruction is specifically designed for interrupt returns and automatically re-enables interrupts. For a standard `RET` instruction used in subroutines, interrupts must be explicitly enabled using `EI` after the `POP` operations.

### 5. Interrupt Service Routines (ISRs) in Embedded Systems (Arduino Context)

Embedded systems like those based on Arduino Uno often utilize interrupts to handle events efficiently.

*   **Arduino's `attachInterrupt()`:**
    *   Arduino provides functions to easily set up interrupt handlers. The `attachInterrupt()` function is commonly used.
    *   **Syntax:** `attachInterrupt(digitalPinToInterrupt(pin), ISR, mode);`
        *   `digitalPinToInterrupt(pin)`: Converts a digital pin number to its corresponding interrupt number.
        *   `ISR`: The name of the function that will be executed when the interrupt occurs. This is the user-defined Interrupt Service Routine.
        *   `mode`: Specifies when the interrupt should trigger. Common modes include:
            *   `LOW`: Trigger when the pin is low.
            *   `CHANGE`: Trigger when the pin changes from low to high or high to low.
            *   `RISING`: Trigger when the pin goes from low to high.
            *   `FALLING`: Trigger when the pin goes from high to low.

*   **ISR Constraints in Arduino:**
    *   **Speed:** ISRs should be as short and fast as possible. They should perform essential tasks and exit quickly.
    *   **No `delay()`:** You cannot use `delay()` inside an ISR. `delay()` internally relies on interrupts and can cause re-entrancy issues or block other interrupts.
    *   **Limited Serial Communication:** While possible, using `Serial.print()` or other blocking serial functions inside an ISR is generally discouraged as it can be slow and interfere with interrupt timing.
    *   **Variable Access:** If an ISR needs to modify a global variable that is also used by the main `loop()`, it's good practice to declare that variable as `volatile`. This tells the compiler that the variable's value can change unexpectedly (e.g., by an ISR), preventing the compiler from optimizing away reads of the variable.

*   **Example (Arduino Uno):**

Let's say you want to count button presses using an interrupt.

```cpp
// Global variable to store the count
volatile unsigned long buttonPressCount = 0;

// The Interrupt Service Routine (ISR)
void countButtonPress() {
  // ISRs should be fast. Avoid complex operations.
  buttonPressCount++; // Increment the counter
}

void setup() {
  Serial.begin(9600);

  // Define pin modes
  pinMode(2, INPUT_PULLUP); // Button connected to pin 2, use internal pull-up resistor

  // Attach the interrupt
  // Trigger the ISR when the button is pressed (pin goes from HIGH to LOW)
  attachInterrupt(digitalPinToInterrupt(2), countButtonPress, FALLING);
}

void loop() {
  // Main program logic
  // You can read buttonPressCount here and do other things
  Serial.print("Button pressed ");
  Serial.print(buttonPressCount);
  Serial.println(" times.");

  delay(500); // Main loop does other work, but ISR handles button press instantly
}
```

**Explanation:**

*   The `buttonPressCount` variable is declared `volatile` because it's modified by the ISR and read by the main `loop()`.
*   The `countButtonPress()` function is the ISR. It's very short and just increments the `buttonPressCount`.
*   In `setup()`, pin 2 is configured as an input with a pull-up resistor. This means the pin will be HIGH when the button is not pressed and LOW when it is pressed (assuming the button connects the pin to ground).
*   `attachInterrupt(digitalPinToInterrupt(2), countButtonPress, FALLING);` tells the Arduino to call `countButtonPress()` whenever pin 2 transitions from HIGH to LOW.
*   The `loop()` function continuously prints the current count. The ISR will update the count in the background without stopping the `loop()`'s execution.

### 6. ISRs and Subroutines

ISRs are essentially specialized subroutines. The key difference lies in **how they are invoked**:

*   **Subroutines:** Called explicitly by a `CALL` instruction within the main program flow. The program explicitly decides when to execute a subroutine.
*   **ISRs:** Called implicitly by hardware or software events (interrupts). The processor diverts execution to the ISR based on external stimuli.

**Interplay:**

*   An ISR can itself call other standard subroutines.
*   The mechanism for saving and restoring the processor state (especially the PC) is similar, but ISRs typically use specific interrupt return instructions (like `RETI`) and often handle saving/restoring of more registers than a simple subroutine call.
*   The stack is crucial for both, but its role in managing the return address and context for interrupts is more critical due to the non-deterministic nature of interrupt arrival.

---

### 7. Key Concepts and Definitions Summary

*   **Interrupt:** An event that temporarily halts normal program execution to handle a specific condition or external signal.
*   **Interrupt Service Routine (ISR):** A dedicated piece of code that handles a specific interrupt.
*   **Maskable Interrupt:** An interrupt that can be ignored by the CPU.
*   **Non-Maskable Interrupt (NMI):** An interrupt that cannot be ignored by the CPU.
*   **Interrupt Vector:** The memory address of the ISR for a specific interrupt.
*   **Interrupt Priority:** The order in which interrupts are serviced if multiple occur simultaneously.
*   **Interrupt Masking:** The act of disabling certain interrupts.
*   **Interrupt Acknowledgement:** A signal from the CPU to an external device indicating that an interrupt request has been received.
*   **`volatile` Keyword (C/C++):** Used for variables that can be changed by external means (like interrupts) or by hardware, ensuring the compiler doesn't optimize away reads/writes.
*   **`attachInterrupt()` (Arduino):** A function to register an ISR for a specific pin and trigger condition.

---

### 8. Important Points to Remember

*   **ISRs must be FAST:** Minimize the work done inside an ISR. Offload complex tasks to the main loop.
*   **Avoid Blocking Functions in ISRs:** Do not use `delay()`, `Serial.print()`, or other long-running/blocking functions within an ISR.
*   **Use `volatile`:** Declare global variables that are modified by ISRs and accessed by the main program as `volatile`.
*   **Stack Usage:** Be mindful of how much stack space your ISRs might consume, especially if they involve nested calls or saving many registers.
*   **Interrupt Enable/Disable:** Understand when to enable and disable interrupts (`EI`, `DI` in 8085; implicit handling in Arduino's `attachInterrupt` and context switching).
*   **Return Mechanism:** Use the correct return instruction (`RETI` for 8085 interrupts) to ensure proper restoration of the CPU state.

### Answers to Practice Questions

**A. Multiple Choice Questions:**

1.  **c) NMI**
2.  **b) To resume execution of the main program after the ISR.**
3.  **c) volatile**
4.  **c) Using `delay(100);`**
5.  **b) Returns from an interrupt and re-enables interrupts.**

**B. Short Answer Questions:**

1.  **Maskable Interrupts:** Can be enabled or disabled by the programmer using instructions like `EI` and `DI`. The CPU can ignore them. **Non-Maskable Interrupts (NMI):** Cannot be disabled by software. They are typically reserved for critical events.
2.  When RST 7.5 occurs:
    *   The CPU finishes the current instruction.
    *   Interrupts are automatically disabled (`DI` effect).
    *   The current PC is pushed onto the stack.
    *   The CPU jumps to the pre-defined vector address for RST 7.5 (which is 003CH).
    *   The ISR at 003CH is executed.
    *   The ISR typically saves other registers, performs its task, restores registers, and uses `RETI` to return.
3.  ISRs must be short and efficient because they interrupt the normal flow of the main program. Long ISRs can lead to missed interrupts, increased latency, and a generally unresponsive system. Complex tasks should be deferred to the main loop.
4.  The stack is used to save the current state of the microprocessor (primarily the Program Counter, and often other registers) before executing the ISR. This allows the processor to return to the exact point of interruption after the ISR is finished.
5.  `attachInterrupt(digitalPinToInterrupt(pin), ISR, mode)` registers a function (`ISR`) to be called when a specific digital pin changes state according to the `mode`. Common modes are `LOW`, `CHANGE`, `RISING`, and `FALLING`, specifying the trigger condition for the interrupt.

**C. Programming Exercise (Conceptual Pseudocode):**

**a) Main Program Pseudocode (8085):**

```assembly
START:
    DI          ; Disable all interrupts initially

    ; Initialize stack pointer (assuming stack is at a known location)
    LXI SP, STACK_TOP_ADDRESS

    ; Enable specific interrupts (e.g., INTR, if others are disabled by default)
    ; For RST 3, it's a specific instruction, not typically enabled/disabled by EI/DI
    ; However, if using INTR, you'd need to handle ACK and provide RST 3 instruction

    EI          ; Enable interrupts

WAIT:
    HLT         ; Halt the processor until an interrupt occurs
    JMP WAIT    ; If HLT is interrupted, execution resumes here, then loops back to HLT
```

**b) Interrupt Service Routine (ISR) Pseudocode (for RST 3):**

```assembly
RST3_ISR:
    ; Save current register contents onto the stack
    PUSH PSW    ; Save Accumulator and Flags
    PUSH B      ; Save B register pair
    PUSH D      ; Save D register pair
    PUSH H      ; Save H register pair

    ; --- ISR Task ---
    MVI C, 01H  ; Load port address into C register for OUT instruction
    MVI A, 01H  ; Assume INTR line is active HIGH, OUT 01H to acknowledge
    OUT 00H     ; Output to Port 00H (Interrupt Acknowledge Port - conceptual)
                ; In 8085, INTR requires an interrupt acknowledge cycle that
                ; prompts the interrupting device to send an instruction (like RST 3)

    ; Read data from I/O port 01H into Accumulator
    MVI C, 01H  ; Load port address 01H into C register for IN instruction
    IN C        ; Read data from port 01H into Accumulator

    ; Store the data into memory location 2000H
    MOV M, A    ; Move content of Accumulator to memory location pointed by HL pair.
                ; Requires HL to be initialized to 2000H.
    LXI H, 2000H ; Load HL with the memory address 2000H
    MOV M, A     ; Store the accumulator content at memory address 2000H

    ; --- Restore register contents ---
    POP H       ; Restore H register pair
    POP D       ; Restore D register pair
    POP B       ; Restore B register pair
    POP PSW     ; Restore Accumulator and Flags

    RETI        ; Return from interrupt, re-enabling interrupts
```

*(Note: The actual implementation for INTR acknowledgement on 8085 is more nuanced, involving interrupt acknowledge cycles. The pseudocode above simplifies the data reading and storage part as the primary focus is ISR structure).*
