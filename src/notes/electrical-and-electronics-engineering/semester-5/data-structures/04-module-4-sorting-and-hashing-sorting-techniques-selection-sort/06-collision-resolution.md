# Data Structures: Module 4 - Sorting and Hashing: Collision Resolution

## 1. Introduction to Hashing and Collisions

Hashing is a technique used to store and retrieve data efficiently. It maps keys to indices in a hash table, allowing for average O(1) time complexity for insertion, deletion, and search operations. However, when two different keys are mapped to the same index, a **collision** occurs. Resolving these collisions is crucial for the efficient functioning of hash tables.

**Key Concepts:**

*   **Hash Function:** A function that converts a key into an index in the hash table.
*   **Hash Table (or Hash Map):** An array-like data structure that stores key-value pairs.
*   **Collision:** When two or more keys hash to the same index.

**Reference:**

*   *Fundamentals of Data Structures in C* by Horowitz, Sahni, and Anderson-Freed (Chapter 9: Hashing) discusses the concept of hashing and collisions.
*   *Classic Data Structures* by Samanta D (Chapter 7: Hashing) provides a foundational understanding of hashing principles.

## 2. Collision Resolution Techniques

When collisions occur, we need strategies to store and retrieve colliding elements. These techniques aim to minimize the impact of collisions and maintain the efficiency of hash table operations.

### 2.1. Separate Chaining

In Separate Chaining, each slot in the hash table points to a linked list (or another data structure like a tree) that stores all the elements that hash to that particular slot.

**Key Concepts:**

*   **Linked List:** Each index in the hash table points to the head of a linked list.
*   **Insertion:** When a new key-value pair is inserted, it's added to the linked list at the hashed index.
*   **Search:** To search for a key, we hash the key, go to the corresponding linked list, and traverse it to find the key.
*   **Deletion:** Similar to search, we locate the element in the linked list and remove it.

**How it works:**

1.  **Hash the key** to get an index.
2.  If the index is empty, create a new linked list at that index and add the element.
3.  If the index is not empty, **append the new element to the existing linked list**.

**Example:**

Consider a hash table of size 10 and the hash function `h(key) = key % 10`.
If we insert keys: 12, 22, 35, 47, 52.

*   `h(12) = 12 % 10 = 2`. Slot 2 gets `12`.
*   `h(22) = 22 % 10 = 2`. Slot 2 already has `12`. A linked list is formed at slot 2: `12 -> 22`.
*   `h(35) = 35 % 10 = 5`. Slot 5 gets `35`.
*   `h(47) = 47 % 10 = 7`. Slot 7 gets `47`.
*   `h(52) = 52 % 10 = 2`. Slot 2 already has `12 -> 22`. The linked list becomes `12 -> 22 -> 52`.

**Advantages:**

*   Simple to implement.
*   Hash table never gets full, as linked lists can grow indefinitely.
*   Performance degrades gracefully with increasing load factor.

**Disadvantages:**

*   Requires extra space for pointers in the linked lists.
*   Can be slower than open addressing if linked lists become long.

**Textbook/Reference Integration:**

*   *Fundamentals of Data Structures in C* (Horowitz, Sahni, Anderson-Freed) provides a detailed explanation and pseudocode for Separate Chaining.
*   *Data Structures: A Pseudocode Approach with C* (Gilberg, Forouzan) also offers clear illustrations and implementations.

### 2.2. Open Addressing (Closed Hashing)

In Open Addressing, all elements are stored directly within the hash table itself. When a collision occurs, we probe for an alternative empty slot in the table according to a specific probing sequence.

**Key Concepts:**

*   **Probing:** The process of searching for an empty slot when a collision occurs.
*   **Probe Sequence:** The sequence of indices generated by the probing mechanism.
*   **Load Factor:** The ratio of the number of elements to the size of the hash table. It's crucial for open addressing that the load factor remains less than 1.

**Types of Probing:**

#### 2.2.1. Linear Probing

In Linear Probing, if a collision occurs at index `h(key)`, we check the next consecutive slots `(h(key) + 1) % table_size`, `(h(key) + 2) % table_size`, and so on, until an empty slot is found.

**Probe Sequence:** `h(key, i) = (h(key) + i) % table_size`, where `i = 0, 1, 2, ...`

**Example:**

Consider a hash table of size 10 and the hash function `h(key) = key % 10`.
Insert keys: 12, 22, 35, 47, 52.

*   `h(12) = 12 % 10 = 2`. Slot 2 gets `12`. Table: `[_, _, 12, _, _, _, _, _, _, _]`
*   `h(22) = 22 % 10 = 2`. Collision at slot 2.
    *   Probe 1: `(2 + 1) % 10 = 3`. Slot 3 is empty. Slot 3 gets `22`. Table: `[_, _, 12, 22, _, _, _, _, _, _]`
*   `h(35) = 35 % 10 = 5`. Slot 5 gets `35`. Table: `[_, _, 12, 22, _, 35, _, _, _, _]`
*   `h(47) = 47 % 10 = 7`. Slot 7 gets `47`. Table: `[_, _, 12, 22, _, 35, _, 47, _, _]`
*   `h(52) = 52 % 10 = 2`. Collision at slot 2.
    *   Probe 1: `(2 + 1) % 10 = 3`. Slot 3 has `22`.
    *   Probe 2: `(2 + 2) % 10 = 4`. Slot 4 is empty. Slot 4 gets `52`. Table: `[_, _, 12, 22, 52, 35, _, 47, _, _]`

**Problem: Primary Clustering**
Linear probing suffers from **primary clustering**, where long runs of occupied slots build up. This increases the average probe length, degrading performance.

**Textbook/Reference Integration:**

*   *Classic Data Structures* (Samanta D) explains linear probing with examples and discusses its clustering issue.
*   *Theory and Problems of Data Structures* (Lipschuts S. - Schaum’s Series) provides a good overview of the mechanics of linear probing.

#### 2.2.2. Quadratic Probing

Quadratic Probing attempts to alleviate primary clustering by using a quadratic offset in the probe sequence.

**Probe Sequence:** `h(key, i) = (h(key) + c1*i + c2*i^2) % table_size`, where `c1` and `c2` are constants (often `c1=0, c2=1` or `c1=1/2, c2=1/2`). A common simple form is `h(key, i) = (h(key) + i^2) % table_size`.

**Example:**

Using the same table and hash function as before (size 10, `h(key) = key % 10`), inserting 12, 22, 35, 47, 52. Let's use `h(key, i) = (h(key) + i^2) % 10`.

*   `h(12) = 2`. Slot 2 gets `12`. Table: `[_, _, 12, _, _, _, _, _, _, _]`
*   `h(22) = 2`. Collision at slot 2.
    *   Probe 1 (`i=1`): `(2 + 1^2) % 10 = 3`. Slot 3 is empty. Slot 3 gets `22`. Table: `[_, _, 12, 22, _, _, _, _, _, _]`
*   `h(35) = 5`. Slot 5 gets `35`. Table: `[_, _, 12, 22, _, 35, _, _, _, _]`
*   `h(47) = 7`. Slot 7 gets `47`. Table: `[_, _, 12, 22, _, 35, _, 47, _, _]`
*   `h(52) = 2`. Collision at slot 2.
    *   Probe 1 (`i=1`): `(2 + 1^2) % 10 = 3`. Slot 3 has `22`.
    *   Probe 2 (`i=2`): `(2 + 2^2) % 10 = (2 + 4) % 10 = 6`. Slot 6 is empty. Slot 6 gets `52`. Table: `[_, _, 12, 22, _, 35, 52, 47, _, _]`

**Advantages:**

*   Reduces primary clustering.

**Disadvantages:**

*   **Secondary Clustering:** If two keys hash to the same initial slot, they will follow the same probe sequence.
*   May not probe all slots in the table, especially if the table size is not a prime number. Careful selection of table size and constants is required.

**Textbook/Reference Integration:**

*   *Introduction to Data Structures with Applications* (Tremblay & Sorenson) discusses quadratic probing and its probing patterns.
*   *Advanced Data Structures* (Brass) might touch upon more sophisticated probing techniques and their theoretical properties.

#### 2.2.3. Double Hashing

Double Hashing uses a second hash function to determine the step size for probing. This further reduces clustering by ensuring that keys that initially hash to the same slot follow different probe sequences.

**Probe Sequence:** `h(key, i) = (h1(key) + i * h2(key)) % table_size`, where `h1(key)` is the primary hash function and `h2(key)` is a secondary hash function. `h2(key)` must never return 0 and should be relatively prime to the table size to ensure all slots are probed.

**Example:**

Consider a hash table of size 10.
Primary hash function: `h1(key) = key % 10`.
Secondary hash function: `h2(key) = 7 - (key % 7)` (ensures `h2(key)` is between 1 and 7, and not 0 for values > 7).

Insert keys: 12, 22, 35, 47, 52.

*   `h1(12) = 2`. Slot 2 gets `12`. Table: `[_, _, 12, _, _, _, _, _, _, _]`
*   `h1(22) = 2`. Collision at slot 2.
    *   `h2(22) = 7 - (22 % 7) = 7 - 1 = 6`.
    *   Probe 1 (`i=1`): `(2 + 1 * 6) % 10 = 8`. Slot 8 is empty. Slot 8 gets `22`. Table: `[_, _, 12, _, _, _, _, 22, _, _]`
*   `h1(35) = 5`. Slot 5 gets `35`. Table: `[_, _, 12, _, _, 35, _, 22, _, _]`
*   `h1(47) = 7`. Slot 7 gets `47`. Table: `[_, _, 12, _, _, 35, _, 22, 47, _, _]`
*   `h1(52) = 2`. Collision at slot 2.
    *   `h2(52) = 7 - (52 % 7) = 7 - 3 = 4`.
    *   Probe 1 (`i=1`): `(2 + 1 * 4) % 10 = 6`. Slot 6 is empty. Slot 6 gets `52`. Table: `[_, _, 12, _, _, 35, 52, 22, 47, _, _]`

**Advantages:**

*   Significantly reduces both primary and secondary clustering.
*   Generally offers the best performance among open addressing techniques.

**Disadvantages:**

*   Requires a second hash function, which needs to be carefully chosen.
*   More complex to implement than linear or quadratic probing.

**Textbook/Reference Integration:**

*   *Data Structures and Algorithms* by Aho, Hopcroft, and Ullman might discuss the theoretical underpinnings of double hashing.
*   *Fundamentals of Data Structures in C* (Horowitz, Sahni, Anderson-Freed) provides a good coverage of double hashing.

## 3. Deletion in Open Addressing

Deletion in open addressing is tricky. Simply removing an element can break the probe sequence for other elements that might have collided with the deleted element.

**Problem:** If we mark a slot as empty after deletion, subsequent searches for keys that were placed *after* the deleted element in its probe sequence might terminate prematurely, wrongly concluding that the element is not present.

**Solution: Lazy Deletion (Tombstones)**

Instead of physically removing the element, we mark the slot with a special marker (e.g., `DELETED` or a sentinel value) called a **tombstone**.

*   **Insertion:** When inserting, a tombstone slot is treated as empty and can be overwritten.
*   **Search:** When searching, a tombstone slot is treated as occupied, and the probe sequence continues. The search only stops when the key is found or an *truly* empty slot is encountered.

**Important Considerations:**

*   Tombstones can accumulate, leading to longer probe sequences even if the table isn't full.
*   Periodically rehashing or rebuilding the table can help clear out tombstones.

**Textbook/Reference Integration:**

*   *Fundamentals of Data Structures in C* (Horowitz, Sahni, Anderson-Freed) details the problem of deletion in open addressing and the tombstone solution.

## 4. Performance Analysis of Collision Resolution

The performance of hashing and collision resolution techniques is often analyzed using the **load factor (α)**.

*   **Load Factor (α):** `α = number of elements / table size`.

**Separate Chaining:**

*   **Average successful search:** `O(1 + α/2)` (assuming uniform hashing)
*   **Average unsuccessful search:** `O(1 + α)` (assuming uniform hashing)
*   Performance degrades linearly with `α`.

**Open Addressing:**

The analysis for open addressing is more complex and depends on the probing strategy.

*   **Linear Probing:**
    *   **Average successful search:** `O(1 / (1 - α))`
    *   **Average unsuccessful search:** `O(1 / (1 - α)^2)`
    *   Highly sensitive to load factor, especially when `α` approaches 1.
*   **Quadratic Probing & Double Hashing:**
    *   **Average successful search:** `O(1 / (1 - α))`
    *   **Average unsuccessful search:** `O(1 / (1 - α))`
    *   Generally better than linear probing, but still degrades as `α` increases.

**Important Point to Remember:**

*   For open addressing, it's crucial to keep the load factor low (e.g., below 0.7 or 0.75) to maintain good performance.
*   When the load factor gets too high, the hash table should be **rehashed** (resized and all elements reinserted).

## 5. Practice Questions and Exercises

**Question 1:**

Explain the concept of a hash collision. Why is it important to resolve collisions?

**Answer 1:**
A hash collision occurs when two different keys are mapped to the same index in a hash table by the hash function. It's important to resolve collisions because if not handled, multiple elements would try to occupy the same memory location, leading to data loss or incorrect retrieval. Effective collision resolution ensures that all elements can be stored and retrieved accurately, maintaining the efficiency of the hash table.

**Question 2:**

Describe the Separate Chaining method for collision resolution. What are its main advantages and disadvantages?

**Answer 2:**
In Separate Chaining, each slot in the hash table points to a linked list that stores all elements hashing to that slot.
*   **Advantages:** Simple to implement, hash table doesn't get "full" (performance degrades gracefully), less sensitive to load factor than open addressing.
*   **Disadvantages:** Requires extra memory for pointers, can be slower if linked lists become very long, potentially worse cache performance.

**Question 3:**

What is primary clustering? Which open addressing technique suffers from it, and how can it be mitigated?

**Answer 3:**
Primary clustering is a phenomenon in linear probing where occupied slots form contiguous blocks (clusters). If a key hashes into a cluster, it must traverse the entire cluster to find an empty slot, increasing the average probe length. Linear probing suffers from primary clustering. Quadratic probing and double hashing are techniques that mitigate primary clustering.

**Question 5:**

If you are using open addressing and need to delete an element, what strategy should you employ to avoid breaking search chains? Briefly explain this strategy.

**Answer 5:**
You should employ **Lazy Deletion** (or use **Tombstones**). Instead of physically removing the element from its slot, mark the slot with a special "deleted" marker.
*   During insertion, a deleted slot can be treated as empty and overwritten.
*   During search, a deleted slot is treated as occupied, and the search continues along the probe sequence. The search only terminates if the key is found or a truly empty (never occupied) slot is encountered.

## 6. Important Points to Remember

*   **Collisions are inevitable** in hashing unless the hash table is infinitely large or the number of keys is very small.
*   **Separate Chaining** uses auxiliary data structures (like linked lists) to handle collisions. It's simpler and more forgiving with higher load factors.
*   **Open Addressing** stores all elements within the hash table itself, requiring probing to find alternative slots during collisions.
*   **Linear Probing** suffers from primary clustering, leading to performance degradation.
*   **Quadratic Probing** reduces primary clustering but can suffer from secondary clustering.
*   **Double Hashing** is generally the most efficient open addressing technique as it minimizes both primary and secondary clustering.
*   **Deletion in Open Addressing** requires special handling (lazy deletion/tombstones) to maintain search integrity.
*   **Load Factor (α)** is a critical metric for hash table performance. Keeping `α` low is essential for open addressing.
*   **Rehashing** (resizing the table and reinserting elements) is necessary when the load factor becomes too high.
*   The choice of **hash function** and **collision resolution technique** significantly impacts the overall efficiency of a hash table.
